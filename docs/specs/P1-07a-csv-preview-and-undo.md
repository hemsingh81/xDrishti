# P1-07a — CSV preview (review step) and undo

- **Status:** Approved (owner, 2026-10-12) · decision [ADR 0017](../adr/0017-trading-calendar-eod-schedule-quality-adjustments-and-csv-undo.md) §6 · **Phase:** P1 — the preview and undo parts of **P1-07/P1-08** (profiles, folder watch, CLI stay there) · depends on P1-17a
## Backend
1. `GET /api/data/csv/files` — the folder's files with state `pending | loaded | changed` (changed = loaded but size/modified differ), size, modified, parsed symbol, mapped instrument (id/symbol) or `unknown/ambiguous`, rows/first/last bar/loaded-at for loaded ones.
2. `POST /api/data/csv/preview {files[] (max 20)}` — dry run of the real reader and rules per file (no writes): rows read, first/last bar, trading days, repaired/rejected counts with the first 10 examples and reasons, the alignment/session verdict (pass or the refusal message), symbol mapping, the first 5 rows (OHLCV), whether it would insert/update/keep existing bars (counts against stored). Limits: rows scanned capped per request (full count for ≤ 1 M rows else sampled and said so), safe messages, path-traversal safe.
3. `POST /api/data/refresh` gains `csvFiles?: string[]` (load only these files; names validated against the folder listing) — the review step's "Load selected".
4. **Undo:** `POST /api/data/csv/files/{name}/undo` (step-up NOT required, session + CSRF; confirm in the UI) removes the file's `csv`-source bars of its instrument within the file's recorded [first, last] range through `market.undo_csv_bars(instrument_id, from_ts, to_ts)` — a `SECURITY DEFINER` function owned by `xd_owner`, `SET search_path` pinned, deleting only `source = 'csv'` rows of that one instrument/range (Dhan rows stay), `EXECUTE` revoked from PUBLIC and granted to `xd_app` only; `xd_app` keeps NO direct DELETE/TRUNCATE (test as `xd_app`); then marks the range dirty (bar_coverage), un-records the file (`csv_files`), refreshes coverage and starts the aggregate phase as a job; audited ("CSV load of <file> undone, N bars removed"); 409 while a job runs; 404 unknown/never-loaded file. Values an earlier load overwrote are not restored (stated in docs and UI).
5. Tests: listing states, preview counts vs real load (equal), refusal verdicts (shifted fixture), preview never writes (row counts unchanged), `csvFiles` filter incl. unknown name and traversal attempts, undo removes only csv rows (Dhan rows kept), range bounds, aggregates rebuilt, re-load after undo restores the data, function privileges (xd_app cannot DELETE directly, cannot call with other roles' escalation, search_path injection test), audit text without leakage; contract; docs 05 §3 and 17.
## Frontend (Data screen, CSV step)
The **CSV files** step gets **Review files**: dialog listing files (pending first; search; state chips; unknown symbols flagged), select files → **Preview** (per file panel: rows, range, repaired/rejected with examples, alignment verdict, first rows, would insert/update counts) → **Load selected** (starts the job) ; loaded files get **Undo** (confirm dialog saying exactly what is removed and that overwritten values are not restored, plus the aggregate rebuild). Tests, a11y, responsive, lazy.
