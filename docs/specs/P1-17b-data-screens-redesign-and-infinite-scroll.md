# P1-17b — Redesign the Data screens (dense, essentials first) and replace paging with infinite scroll everywhere

- **Status:** Approved (owner, 2026-10-12: "Redesign this UI … show only important information and cover max things on the screen … remove paging from the grid, use lazy loading with infinite scroll"; answers: both Data screens, every paged grid in the app)
- **Phase:** P1 — frontend only; no API change (the list endpoints keep `page`/`pageSize`; the grid loads the next page as the owner scrolls)

## Goals
1. One screen of information instead of a long scrolling page: the essentials visible at a glance, details one click away.
2. The tables get the room: they fill the remaining viewport height and load more rows while scrolling; no pager anywhere.

## Shared Grid: infinite scroll (replaces `pagination`)
- New prop `infinite?: { total: number; hasMore: boolean; loadingMore: boolean; onLoadMore: () => void; error?: string | null; onRetryMore?: () => void }` and no `pagination` prop (removed at the end of the story; `GridPagination.tsx` deleted).
- A sentinel row inside the scroll container (IntersectionObserver rooted at the body, ~400 px margin) calls `onLoadMore` when it nears the viewport; at most one request at a time; a failed load shows an inline "Could not load more rows — Retry" row and stops auto-loading until retried.
- Footer: a slim status line "Showing 100 of 3,204" (`aria-live="polite"`, updated as pages arrive) and a small spinner in the sentinel row while loading; no rows-per-page control, no page buttons.
- Semantics: `aria-rowcount` = total, `aria-rowindex` = position in the whole list; keyboard End/PageDown at the last loaded row asks for more; a changed sort/filter/query starts a new list and scrolls to the top (the roving tab stop returns to the first row). Rows stay memoised; selection by id survives loading more.
- Hook `useInfiniteRows` in `shared/lib` over TanStack `useInfiniteQuery` (pages from the existing endpoints, page size 100 unless the endpoint caps lower; `getNextPageParam` from `total`, `page`, `pageSize`); returns `rows`, `total`, `hasMore`, `fetchNextPage`, `isFetchingNextPage`, `isPending`, `isError` and the load-more error. Query keys keep their roots so invalidation still works; filters/sort live in the key.
- Every currently paged grid migrates: Instruments (selection across loaded pages unchanged; "select all N results" keeps using its own read-all mutation), Portfolio holdings, Data coverage, corporate actions, gaps, CSV review file list, Data quality instruments. URL state keeps filters and sort but no longer `page`/`size`.

## Data & import — layout (no page scroll on desktop)
1. **Slim header row:** title, one compact **status ribbon** and the **Update data** split button. The ribbon replaces the freshness card, the four tiles and the automatic-update strip: **Last tick** (IST date-time + "5 h ago", success/warning icon + text — the one highlighted item), instruments with data (+ "N behind" in warning), 1-minute bars (compact), covered period, Data account chip (Connected / Reconnect), and "Auto 15:50 · next Tue 13 Oct" with its last result as a tooltip/popover. Everything wraps cleanly and collapses to the first three items on phones.
2. **Pipeline strip:** the three steps as one horizontal row of compact step chips (icon + name + key number + last-run time + status), each opening a details popover (full counts, repaired/rejected, unknown symbols, rejection examples, gaps, timeframe bar counts, job warnings); while a job runs the strip shows an inline progress bar and phase message and the Update button shows the spinner. **Review files** and **View gaps** are actions inside the CSV/Dhan popovers (the CSV step also keeps a badge with the pending count).
3. **Needs attention line** (only when something needs the owner, one row, dismissible by acting): "2 calendar proposals · 3 suggested corporate actions · 12 open gaps" with links that switch to the matching tab.
4. **Tabs under the strip, the active tab fills the rest of the viewport:** **Coverage** (default; the infinite grid with search, status chips, Has-gaps toggle), **Calendar** (proposals first, upcoming, add/refresh), **Corporate actions** (status filter chips Suggested/Applied/Ignored with counts, the infinite grid, Add / Import / Detect), **Gaps** (the infinite grid, status chips), **Runs** (history list with trigger chips and job warnings). Tabs carry badges (proposals, suggestions, open gaps) and URL state (`?tab=`); the existing deep links (`?section=actions`, `?gaps=open`, `?id=`) keep working and map to the tabs.
5. Dense defaults: compact density, fewer columns (columns with low value move into the row's drawer/tooltip), text that is not essential removed or moved behind an info icon (long explanations become helper popovers), numbers tabular, no full-width cards for single facts.

## Data quality — layout
1. **Slim header row:** title, last-run text, **Run checks**; a single **summary ribbon**: score, Passed / Warnings / Failed / Not checked as inline status chips that double as the status filter, and the **Gate** chip (OK / Blocked / Open with failures) with the reasons and limits in a popover.
2. **The table fills the viewport** (infinite grid): symbol, name, status, score, coverage, missing minutes, aggregates (dots), checked-at; search and chip filters in the toolbar; row click opens the existing Inspect drawer unchanged (width fixed so nothing clips).
3. **Run history** moves into a drawer/popover from the header ("Run history"); the corporate-actions alert and the other notices become one line under the ribbon, only when present.

## Acceptance criteria
1. No `Pagination` control remains in the app; `grep` for the removed props finds nothing; the shared Grid documents the infinite mode; every listed grid loads further pages by scrolling, keeps its selection/sort/filters, shows "Showing N of total", handles loading/empty/error/load-more-error, and is covered by tests (observer mocked: intersecting → next page requested once; sort change resets; error row retry).
2. The Data & import screen shows the ribbon, pipeline strip, attention line and tabs described above; at 1440×900 and 1920×1080 the first screen shows status, pipeline and the start of the coverage table without page scrolling; at 360 px it stays usable; all existing behaviours (job watching, review/undo, calendar, actions, gaps, deep links, notices, polling) still work and keep their tests (adapted).
3. The Data quality screen follows the layout above; Inspect, fix actions, run history and polling unchanged.
4. `scripts/check.sh` green; initial bundle ≤ 200 KB gzip; docs/design/13 describes the new layout; a visual check in light and dark at desktop and phone widths.
