## Goal
The system measures, per cell, what worked, learns a calibrated probability of success for each candidate, watches itself for drift, and lets the owner change a learning knob and replay it with honest comparison rules, all in-process in .NET. Like P3 to P5, P6 first proves the machinery and its honesty rules; what it can *conclude* is bounded by about 2.1 years of data, no hold-out and modelled fills (ISS-19, ISS-18), and every learning output says so. P6 learns from **replayed history** (simulated trades). Learning from the owner's real fills needs paper and live trading (P10, P11) and is not P6.

## The seam (the decision the slices share)
**Fact.** Everything P6 learns from is a `SimTrade` in `research.sim_trades` plus the bars and context of its decision day. P4-06 already selects exits by out-of-sample folds and P5 already judges by gates; both use pure Domain code with no clock and no I/O.

**D1. Learning is a pure core behind ports, in a new `Learning` area.** Pure pieces in `Domain/Learning` (cell statistics, labels, folds for models, calibration metrics, drift, lifecycle, experiment comparison rules); orchestration in `Application/Learning` (one handler per use case, a `LearningRunner` job in the style of `LabRunner`); I/O behind ports in `Application/Abstractions/Learning` (`ITrainingSetStore`, `IModelStore`, `ILearningLog`, `IModelTrainer`); **ML.NET only in an Infrastructure project** implementing `IModelTrainer`/`IModelScorer`, so Domain and Application keep the dependency rule and the Architecture tests stay green (a new rule: only `XDrishti.Learning.MlNet` references `Microsoft.ML*`). A model is never trained or scored from Domain.

**D2. Decision-time features are a side table, not a change of `SimTrade`.** To train, each trade needs the features known at its decision minute. Populating `EntrySnapshotJson` would change the trade record (schema 6, golden files, run keys). Recommended: a separate extractor reads the stored bars and the context as of the decision minute (the same point-in-time frame the scanner used, so no look-ahead by construction) and writes `research.trade_features` keyed by `(sim run key, trade key)`; `SimTrade` stays at schema 5. Costs one more pass over bars per run (UNVERIFIED size), saves a schema bump. Alternative rejected: filling `EntrySnapshotJson` in the walker (touches the oracle, P3-08, and every golden file).

**D3. One fold definition for everything that decides.** Cell choice, exit choice (existing), the model, the meta-label threshold, entry windows and experiments all use the purged expanding walk-forward of ADR 0054 (embargo/purge from `max hold`), parameterised by `exit_walk_forward`-style options, not a new splitter. Only test windows count; tuning only inside train windows (doc 09 §2, §6).

**D4. The model must earn its place.** A model version is *eligible* only if, on out-of-sample folds, it beats both baselines (the cell-stats-only score and a logistic regression) on a stated metric (log loss and Brier, with AUC reported) by more than a margin, **and** its expected calibration error is ≤ `max_calibration_error_pp` (5), **and** it was trained on ≥ `min_trades`. Else the system keeps using cell statistics (doc 09 §1, `must_beat_baseline`). The comparison is a pure function with a hand table.

**D5. Honest limits ride along.** Every model card, cell row, lesson and experiment verdict prints the data range, the number of folds, the number of trades and "replayed history, modelled fills, in-sample on the data shown" where true. A verdict cannot say "better" on fewer folds than the minimum (like P5-03).

**D6. Learning changes are records, not edits.** Each automatic or owner change appends to `learning_changelog` (insert-only for `xd_app`) with evidence; a *revert* is a new row. Live strategies and stored versions are never edited by learning (P5 immutability; doc 09 §5).

## Acceptance criteria (of the phase; each slice carries its own list)
1. **Meta-model beats baselines OOS (roadmap exit).** On purged out-of-sample folds, the champion model beats both the cell-stats-only score and logistic regression on log loss and Brier by the stated margin, with the fold table, the trade count and the data range printed; if it does not, the system reports "not eligible" and keeps cell statistics (D4). The test is a hand-table of the rule and a seeded end-to-end run on fixtures; the real-data result is reported whichever way it falls and never tuned until it passes.
2. **Calibration error ≤ 5 pp (roadmap exit and gate).** Expected calibration error of the champion's `p_win` on out-of-sample data, over equal-mass bins, is ≤ 5 pp, computed by a pure function with hand-computed cases; a model that exceeds it is not eligible.
3. **Replay in < 10 minutes (roadmap exit).** Changing one learning knob and replaying the last 12 months out-of-sample on the owner's data, with the comparison of §12, completes in < 10 minutes on the M4 Pro container limits, timed and written in the ADR; the replay uses the same trades and days for both sides.
4. **Honest comparison.** An experiment can say "better" only with ≥ `min_folds_better` of the folds, total-R drop ≤ 10 %, after the live gap, and above the multiple-testing margin; fewer folds than the minimum cap the verdict at "inconclusive" and say why (D5).
5. **No leak.** A property test shows no feature, label or cell statistic used at a decision date contains data from that date's future; cell stats for a decision use `as_of < decision date`; the regime is read as of the previous session.
6. **Determinism.** Same training set, seed and options give the same model bytes' hash and the same scores; save/load round trip equal.
7. **Layers.** Only the ML.NET project references `Microsoft.ML*`; `Architecture.Tests` stay green with the new rule added, none relaxed.
8. **No silent change.** Every learning change is a changelog row with evidence; none edits a stored strategy version; revert is a new row; `xd_app` has insert-only on changelog, model versions, lessons and ledger-like tables (grants test).
9. **Regimes.** With P3-01d built, trades and cells carry the regime and the Lab `by_regime` block is filled; without it every output says "regime unavailable", never a guess.
10. Every slice ends with `scripts/check.sh` green, `scripts/gen-api.sh` for API changes, a `reviewer` pass, an ADR where it decides, and `scripts/build-docs.sh`.

## Non-functional
Training: minutes (doc 09 §8; the spike: 0.5 s for 100,000 rows, so the feature extraction and the walk-forward dominate, not the trainer). Single-row scoring well below 1 ms. Experiment replay < 10 min (criterion 3). Deterministic by seed and fixed thread count. Models and features hold no secret and no account data. Logs carry the run id, stage, counts, never a feature row. Memory within the container limit (spike peak 303 MB at 100,000 rows).

## Honest limits (read this before any P6 number)
- **Data.** About 2.1 years: files start between 2024-04-01 and 2024-12-18 and end 2026-04-30 (ISS-19). With the P4-06 fold rule (9 months minimum train, 3-month tests) that gives about **5 or 6 out-of-sample test windows**; the roadmap's experiment rule of "12 folds, 8 better" and the config `walk_forward` of 3 training years **cannot be met**. Monthly test windows would give about 12 folds but each is small and the folds then overlap in what they learn from; either way the per-fold trade counts are small for any single cell.
- **Sample.** Three strategies, a few thousand trades at most (UNVERIFIED), split by style × side × strategy × timeframe × exit × regime: most cells will stay below `min_trades` 30, and a regime split multiplies that by up to nine. Shrinkage toward the parent group is what keeps cell stats from being noise, and many cells will honestly read "not enough evidence".
- **No hold-out.** Every decision uses out-of-sample *folds* of data the owner has already looked at (ISS-19); the models, the thresholds and the strategies were all shaped on the same 2.1 years. A model that "beats baselines OOS" here beats them on folds of seen data, not on future data. This is stated on every model card.
- **Modelled fills, costs.** Fills are modelled (ISS-18) and the charge sheet may not be the owner's (ISS-25); the label is a modelled outcome. The replayed history includes no real overrides, no real slippage.
- **One regime history.** 2024 to 2026 is a particular market; a regime-conditioned statistic with three trend states × three volatility states may have no HIGH-vol DOWN days at all. Coverage is printed.
- **Multiple testing.** More strategies (P6-17), more cells, more models and more experiments are more trials; the ledger and the experiment margin count them, and the plan treats a positive result as a lead, not a proof.
- **The frozen-model counterfactual** is at most about one year of "stopped learning" on this data.
- **Survivorship.** Members as of today (ISS-22) apply to every dataset.

## Risks
1. **The model does not beat the baselines.** Likely on this data and a legitimate outcome; the exit criterion then fails by design, not by a bug. Mitigation: D4 and criterion 1 report it honestly; the owner decides whether to extend the data (ISS-19) or accept "cell stats only" for P7. The spike's LightGBM underperformance means hyperparameters and feature design get real time in P6-06.
2. **Leakage.** Features at decision time, cell stats as of a date, calibration slices and purged folds are the classic traps; mitigated by the point-in-time rule (criterion 5), the property test and the independent baseline.

5. **Scale of the phase.** About 57 agent-days against 5 weeks; the cut order protects the exit.
6. **ML.NET specifics.** Native LightGBM library on linux/arm64 and the container (verified in the spike for one configuration, not in the app image); deterministic multi-thread training; model size is trivial.
