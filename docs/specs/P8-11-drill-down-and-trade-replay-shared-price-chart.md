## Goal
From a number the owner doubts, one path to the evidence: a heatmap cell or a basket row opens a **cell detail**, its **trade list**, and one **trade replay** that draws the stored trade on its own bars with entry, stop, target, every leg and the exit, beside the facts and the decision-time features the trade has (and a word where it has none). The same `PriceChart` is what ticket charts use in P8-14.

## Scope
**In:**
- Backend (`Application/Reporting`, `Infrastructure`, `Api/Endpoints/ReportsEndpoints` extension): `GET /api/reports/trades/{runKey}/{ordinal}` (one stored trade with legs, costing, bars of its window at a chosen timeframe, features); new read members `IRunStore.ReadTradeAsync` and `ITradeFeatureStore.ReadOneAsync`; pure `Domain/Reporting/TradeReplayWindow` and `ReplayCoherence`.
- Frontend: `shared/ui/chart/PriceChart.tsx` (lazy wrapper) + `PriceChartCanvas.tsx` (the only importer of `lightweight-charts`), `priceChartModel.ts` (pure), an ESLint restriction, `features/reports` additions: `/reports/cell` (cell detail), `/reports/trades/:runKey/:ordinal` (replay), the trade list on the Grid, one `ChartTable` for the events.
- The first per-chunk budgets in the bundle guard (see Non-functional).
**Out:** exit comparison and MAE/MFE scatter content (P8-10; this slice shows a `not_evaluable` line naming P8-10 until the catalogue marks them built), regime split (`unavailable`), editing or re-running a trade, trail path of a trade that has none stored (the stored record has the legs and `exit_reason`; a trail's level path is not stored: said on screen), live prices (P12), ticket charts (P8-14), screenshots/exports (P8-20).

## Acceptance criteria
1. Given a stored closed trade with no legs, when `GET /api/reports/trades/{runKey}/{ordinal}` is called, then the answer holds the trade fields (entry, stop, target or null, exit, exit reason, R exact, R filled, slippage R, MAE, MFE, sessions held and unseen, fills, entry fill, tick fallback), `legs` empty, and bars from the open of the previous session to the close of the exit session at the trigger timeframe; `coherence.state = ok` when the first bar at or after the entry minute opens within one tick of the stored entry price. *`GetTradeReplayHandlerTests`, `TradeReplayApiTests`.*
2. Given a trade with legs (entry, add, partial exit, final exit), then `legs` are in the record's order with time, kind, exact and filled price, share and reason, and the chart model has one marker per leg (an entry/add/exit shape each, the text carrying kind and share). *`PriceChartModelTests`.*
3. Given a gap through the stop (exit price is the open of a minute beyond the stop), then the exit marker sits at the exit price, the stop line stays at the stored stop and the event table says "exit at 412.30, gap through the stop 415.00". *`PriceChartModelTests`.*
4. Given a swing trade held across three sessions, then the window covers all of them plus the configured sessions before and after, the event table lists the sessions held and the unseen count, and the chart note says the time axis skips nights and weekends. *`TradeReplayWindowTests`.*
5. Given the stored entry price no longer matches the current bars (data changed, a corporate action applied later), then `coherence.state = entry_mismatch`, the page shows the warning "the bars no longer match this stored trade" with both prices, and the chart is still drawn. Given no bars in the window, then `coherence.state = no_bars`, no chart is drawn, the events table and facts are. *`ReplayCoherenceTests`, `TradeReplayPage.test.tsx`.*
6. Given a trade whose run is costed, then net R and the total charges in rupees are shown **only** with the basis words of P8-06 (net only if the charge sheet is confirmed; otherwise "costed on sheet X, not confirmed as yours" beside gross); given a gross run, then no net figure and no zero. *`TradeReplayPage.test.tsx`.*
7. Given `research.trade_features` holds the row, then the feature table lists the 36 stored features by group (bars, context, plan) with the value; a NaN stored value (every `context` feature today) is `unavailable` with the reason "market context not built (P3-01d/e)"; given no row, then "No decision-time features stored for this trade (run `xd learn features`)" and no digit. *`TradeFeatureViewTests`, `TradeReplayPage.test.tsx`.*
8. Given `timeframe` outside 1m, 5m, 15m, 1h, 1D, or sessions before/after outside 0 to 3 (1D: 0 to 60 sessions), then 422 `reports.invalid` with the field; given more than 5,000 bars, then 422 `reports.window_too_large` (no silent downsampling); an unknown run or ordinal is 404 `reports.not_found`. *`TradeReplayApiTests`.*
9. Given the cell detail URL (`/reports/cell?...ReportQuery params&cell=`), then it shows the cell's evidence block, KPI tiles and equity from the P8-06 endpoints with that query, the R distribution, "Exit comparison" and "MAE / MFE" as `not_evaluable: built in P8-10` until built, "Regime split" as `unavailable`, and the paged trade list (virtualised Grid, 50 per page, keyboard rows). A cell below the minimum shows `insufficient` with n and still lists its trades. *`CellDetailPage.test.tsx`.*
10. Given a keyboard-only user, then Tab reaches the timeframe tabs, "Previous event" / "Next event" and the chart; each event button moves the crosshair to that bar and a polite live region says "Exit, 14:35, price 412.30, share 100%". The chart is never the only carrier of information: the event table and a collapsed "Bars (n)" table (first 500 rows, said) carry the same numbers. *`PriceChartA11y.test.tsx`.*
11. Given dark mode, then the chart colours come from theme tokens (grid, text, up, down, stop, target lines), up candles are hollow and down candles filled (never colour alone), and each price line has its text label on the axis. *`priceChartTheme.test.ts` (contrast pairs added to `contrast.test.ts`).*
12. Given the page source of the feature, then no import of a mutation or a non-GET call exists, `lightweight-charts` is imported only by `PriceChartCanvas.tsx` (ESLint `no-restricted-imports` and `boundaries.test.ts`), server text is rendered as text (a markup test per free-text field), and the attribution link is present. *D6 test, lint, `PriceChart.test.tsx`.*
13. Given `npm run size`, then the first-load guard number is unchanged (no eager code is added except the route definitions, measured and printed in the PR) and the new lazy chunks are within their budgets (Non-functional).

## Contract
- **API (read only, session-protected, a GET):** `GET /api/reports/trades/{runKey}/{ordinal}?openAtEnd=false&timeframe=&before=&after=` → `TradeReplayView` (operation id `GetTradeReplay`):
  `runKey, ordinal, openAtEnd, tradeKey, basis ('gross'|'net'), trade { strategyId, instrumentId, symbol, side, tradeDate, triggerTimeframe, decisionAt, entryAt, entryPrice, entryFilledPrice, stopPrice, targetPrice|null, exitAt, exitPrice, exitFilledPrice, exitReason, rExact, rFilled, slippageR, maeR, mfeR, sessionsHeld, sessionsUnseen, fills, entryFill, tickFallback, basketIds[] }`, `legs[] { at, kind, price, filledPrice, share, reason }`, `costing|null { sheetId, quantity, totalCharges, costR, rNet, confirmed }`, `chart { timeframe, adjusted: true, adjustedThrough, from, to, barCount, bars[] { t, o, h, l, c, v }, coherence { state: ok|entry_mismatch|no_bars, entryStored, entryOnBars|null, detail } }`, `features { state: value|unavailable, version, items[] { name, source, state, value|null, reason|null } }`, `evidence` (the P8-06 block: population = this run key, range, n = 1, basis, limits), `limits[]`. Times are ISO-8601 instants (`DateTimeOffset`, as the other views); bar `t` is epoch seconds. Problem codes: `reports.not_found` (404), `reports.invalid` (422), `reports.window_too_large` (422). The trade list is `GET /api/reports/trades` of P8-06 (rows carry `runKey`, `ordinal`, `openAtEnd`: **UNVERIFIED**, P8-06 must expose the three key columns of `research.sim_trades`; if it names them otherwise, use its names).
- **Data:** none new. Reads `research.sim_runs`, `sim_trades`, `sim_trade_legs`, `sim_trade_leg_charges`, `research.trade_features`, `market.bars` through ports. No migration. `scripts/gen-api.sh` in the same change.
- **Ports:** `IRunStore.ReadTradeAsync(runKey, openAtEnd, ordinal, ct)` → `RunTrade?` (legs and costing materialised as `PageTradesAsync` does); `ITradeFeatureStore.ReadOneAsync(runKey, tradeKey, featureVersion, ct)` → `TradeFeatureRow?`. Bars: existing `IBarStore.ReadAsync` (1-minute, range), `IAdjustmentFactors` (the replay's own adjustment, as `BuildTradeCardsHandler` states it), Domain `MinuteAggregator`, `TradingCalendar`.
- **UI:** `/reports/cell` and `/reports/trades/:runKey/:ordinal`, lazy routes in `app/router.tsx` (no nav entry; reached from P8-08/09 heatmaps and rows; Back returns with the filters). Prototype: the Reports drill-down of `docs/prototype/assets/app-pages-3.js` (UNVERIFIED line), deliberate differences: honest states, no demo numbers. States: loading, error, 404 "Trade not found", empty list, `no_bars`.
- **Events/jobs:** none.

## Non-functional
- Replay endpoint p95 under 300 ms for a 1m window of 13 sessions (4,900 bars) on the seeded fixture (measured, written in the ADR; the 1,000-bars-per-call limit of the data endpoint does not apply: that endpoint has no from/to, see Decisions). Trade list rows: 50 per page, keyset, at most one page per request.
- Bundle: `PriceChartCanvas` lazy chunk (library plus wrapper) at most **65,000 bytes gzip** (measured library: 52.6 KB gzip with `createChart`, `CandlestickSeries`, `createSeriesMarkers` plus fancy-canvas, 2026-10-24); replay route chunk at most 15,000 bytes gzip; cell detail route at most 20,000 bytes. `size.mjs` gains `lazyBudgets` (prefix, bytes) that **fail** on breach; first-load number unchanged.
- Chart: at most 5,000 candles drawn (the endpoint refuses more); resizes with its container (`autoSize`); `prefers-reduced-motion` has no effect (no animation is used).
- Security: GET only, session required; no secret or account number in the view (a simulated trade has no account); logs carry `runKey` prefix (8 hex), ordinal, timeframe, bar count and ms, never prices.
- Time: IST on every label (`Intl` `Asia/Kolkata`), `pinClock` in tests that show relative time; the chart's time axis is formatted by `localization.timeFormatter` and `timeScale.tickMarkFormatter`, never by shifting the data.

## Test plan
- **Unit (Domain):** `TradeReplayWindowTests` hand table: intraday 15m entry 10:15 exit 11:30 on a 5-session fixture gives from = previous session 09:15, to = exit session 15:30 (and `after` extends by whole sessions); swing across a weekend skips non-sessions via the calendar; 1D defaults 20 sessions. `ReplayCoherenceTests`: entry within one tick = ok; 0.6 tick off after a split = mismatch; no bars; short exit side.
- **Pure frontend:** `priceChartModel` builds candles, price lines (stop, target, entry; none when null, never zero), markers per leg (shape by kind and side), the event rows and the summary sentence; property: marker count = legs + 1 when legs absent (entry and exit), times strictly within the bars' range or flagged "outside window".
- **Application:** handler with fakes: 404, invalid, too large, stale features, costed and gross, openAtEnd.
- **Integration (Testcontainers):** seeded run (one intraday trade with legs and charges, one gap-through-stop trade, one 3-session swing trade, bars for each; a corporate action after the run for the mismatch case); contract snapshot; 401 without a session.
- **Frontend (Vitest + MSW, clock pinned):** every acceptance case above; the canvas module is replaced by a stub (`src/test/chartStub.tsx` pattern) that records `setData`, markers and lines so the tests assert what would be drawn; keyboard path; light and dark token contrast; markup in `reason` and `detail`.
- **Architecture:** `ReportsArchitectureTests` unchanged and green; `Domain/Reporting` has no I/O; the new members add no order-named identifier.
- **Real-data check (reported, not asserted):** open three real trades of the owner's newest run at 360 and 1440 px (P8-16 procedure) and note whether the stored entry price matches the bars (`coherence`).

## Decisions (researched)
1. **Q15: Lightweight Charts, pinned exactly `lightweight-charts@5.2.1`.** Facts read 2026-10-24: npm `latest` is 5.2.1, published 2026-08-12 (10 weeks old); license Apache-2.0 (`npm view lightweight-charts license`); one dependency, `fancy-canvas@2.1.0`; the production ES build is 189 KB minified and **60.3 KB gzip** by itself, **52.6 KB gzip** as measured by bundling `createChart`, `CandlestickSeries` and `createSeriesMarkers` with rolldown (the tool the repo builds with), against the ECharts core already in the app (the `installCanvasRenderer` chunk is 150 KB gzip, lazy). API fit for the need: `chart.addSeries(CandlestickSeries)`, `series.createPriceLine({ price, color, lineStyle, title })` for stop, target and entry, `createSeriesMarkers(series, markers)` for entry, add, partial and final exits with text and shape, `localization.timeFormatter` / `timeScale.tickMarkFormatter` for IST, `autoSize`, `chart.setCrosshairPosition` for the keyboard buttons, `series.update` for the live bars that P12 will want. Sources: https://www.npmjs.com/package/lightweight-charts and https://github.com/tradingview/lightweight-charts (package README and `dist/typings.d.ts` of 5.2.1, read 2026-10-24). **Why not ECharts:** it can draw candlesticks with `markPoint`/`markLine` for about +10 KB on top of a core that is loaded anyway, and it avoids a dependency, but its category axis, zoom and crosshair are built for analytics, live bar updates are heavy, and the design already says price charts use Lightweight Charts (doc 13 §4); P8-14 and P12 reuse the same component, so the better price tool is the lasting choice. The component hides the library behind `PriceChartProps` so a swap touches one file.
2. **Licence duty, honoured.** The README states the licence requires the "attribution notice" from the NOTICE file and a link to https://www.tradingview.com/ on a page that is visible to users. `attributionLogo` defaults to true and meets the link duty on the chart; the NOTICE sentence ("TradingView Lightweight Charts™ Copyright (с) 2025 TradingView, Inc. https://www.tradingview.com/", read from the repo's NOTICE at v5.2.1 on 2026-10-26; **correction at build: the "с" of "(с)" is the Cyrillic letter U+0441 in the file, not a Latin c, and the code keeps it as published**; the npm package ships no NOTICE file) is added to the footer text of the replay page and to the third-party notices of `docs/engineering/README.md` (ADR 0125). The owner is not asked: this is a condition of use, not a choice.
3. **A new range read of bars, not the data endpoint.** `GET /api/data/instruments/{id}/bars` returns only the latest `take` (max 1,000) bars, newest first, with no `from`/`to`: it cannot show a trade of last March. The replay therefore reads 1-minute bars by range from `IBarStore.ReadAsync`, adjusts them by the same factors the replay used, and aggregates with the Domain `MinuteAggregator` to the chosen timeframe, server side (the browser computes no bar). Adding `from`/`to` to the data endpoint was rejected: it would change a contract used by the Data screen for a research need.
4. **Adjusted prices and a coherence check instead of a bar-stream hash.** The stored trade is in adjusted prices (P3-04c). The check that the bars are unchanged since the run (hash of the whole stream) needs the run record and a read of the whole window; the replay instead compares the stored entry price with the first bar at or after the entry minute (within one tick, `tickFallback` honoured) and says so when it differs. Cheap, honest, and it names the likely cause (a later corporate action or a re-fetch).
5. **No downsampling.** The endpoint refuses windows above 5,000 bars (`reports.window_too_large`) and the screen then offers a larger timeframe; a silently thinned candle series is a quiet lie.
6. **Hollow up, filled down.** Colour is never alone (P8-00 accessibility rules); stop and target lines carry titles ("Stop 415.00"); markers carry text.
7. **Feature snapshot rule.** Shown only from `research.trade_features` (catalog `tf-1`, 36 stored values, `NaN` = unknown). `entry_snapshot_json` on the trade is always null so far (stored record says "reserved"), so it is not read. Context features are `NaN` until P3-01d/e: they are listed as `unavailable`, never as 0.
8. **Drill-down is pages, not a drawer.** A drawer is poor at 360 px and cannot hold a chart plus a 50-row Grid; pages keep Back working with the filters in the URL (P8-00 D4).
9. **Rejected:** a trail-path line for trailing exits (not stored: reconstructing it would be a second simulation in the browser); showing R "in rupees" (needs quantity from costing; shown only where the costing exists).

## Risks and honest limits
- A simulated trade on **replayed history with modelled fills**: the chart shows bars the trade was simulated on, not a fill the owner got. The page says "simulated trade, replayed history" in its header and in `limits`.
- Overnight gaps are not drawn to scale (the library's time axis is by bar index); the page says so for any multi-session window.
- If the data changed since the run, the picture and the stored trade may disagree; `entry_mismatch` catches the common case, not every case.
- Adding the library is a supply-chain surface (one package plus fancy-canvas); pinned exact, lazy, one importer, reviewable.
- Rendering was never seen in a browser by an agent for earlier phases; P8-16 covers this screen at four widths.
