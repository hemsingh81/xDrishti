## Assumptions (taken as recommended)
1. **What exists (read).** P6-09: the band detector (20-trade non-overlapping windows, alarm after 3 checks below `mean - 1.645 sd sqrt(1/20 + 1/N_ref)`, clear at the half-way point), a one-sided CUSUM (k 0.5, h 10, cap 2h, clear 0.5h), the calibration detector (100 outcomes every 50, gap above 5 pp **and** above 2.5 SE, 3 in a row), all **replay only, read only, proposals only** ("Auto-pause is therefore not done"). P6-12: retrained against frozen on the same later trades, day-clustered standard errors, judged windows, a fixed take rule (score at or above that side's own train base rate), "no difference" is an answer. `CellState` has `Paused` ("stopped by drift or loss limits; still graded, may recover in shadow"), which is exactly "paper size zero".
2. **ML is advisory** (`AdvisoryPWin`, display only), so the three arms below pick the **same** candidates and differ only in the probability and in the take rule applied afterwards.
3. The edge series is CF-08's graded shadow set; features and the champion's P(win) are stored there pre-open, so the other arms can be scored later without hindsight (the frozen model's artifact hash is in the epoch's configuration fingerprint, P10-05).
4. Thresholds are proposals in versioned settings (CF-00 home); `unavailable` is never a pass.

## Decisions (researched)
**D1. Decay monitor on forward series.** On each strategy's edge series (and the behavioural paper series beside it) compute, over **non-overlapping** windows of 60 trades (the unit P6-09 uses, with a longer window for a steadier mean): the window mean net R; alert when it is below `mu_ref - 1.5 * sigma * sqrt(DEFF / 60 + 1 / N_ref)` where `mu_ref`, `sigma`, `N_ref` come from the out-of-sample plus hold-out trades of the Lab result and `DEFF` is the design effect of CF-01 (placeholder `1 + (m - 1) * 0.3`). Also report the P6-09 CUSUM on the same series and a by-quarter table (trades, mean net R, share of quarters below -0.05 R). *Why:* the research proposed `mu_ref - 1.5 SE` with `SE = 1/sqrt(60)` ignoring that `mu_ref` is itself estimated and that same-day candidates are correlated; P6-09's band already carries both errors, and this adds the second. *Rejected:* overlapping rolling windows (consecutive alerts would be one event counted many times); a bare `-0.08 R` line (not tied to the strategy's own reference).
**D2. Kill rules at strategy level.** Any one of: (a) **cost stress** (CF-05 formula) negative on the trailing 100 edge trades: `net(1.5) = net(1) - 0.5 c < 0` with `c = mean(chargesR + |SlippageR|)`; (b) **drawdown** of the edge series larger than **2 times** the 95th percentile of the max drawdown in R of composition-matched draws **at the series' own n** (the P10-04 way; a drawdown grows with n, so the backtest's stored N is the wrong comparison); (c) **decay alert twice in a row** (two consecutive completed 60-trade windows). The CF-09 failure boundary is a fourth input that creates a **proposal only** (never executed by the auto setting) because it already hard-fails the scorecard. Action: all cells of the strategy move `Paper/Active -> Paused` through the P6-08 lifecycle, changelog row with the numbers. *Why:* the research lists these three; the proposal is always produced, execution is a choice.
**D3. Auto and manual, as the standing rule says.** `confidence.kill.auto` default **OFF**: OFF writes a proposal and a bell notice (P8-15 mechanism); ON executes the demotion, recorded actor `auto` with the settings snapshot, never an owner approval. Turning it ON is an owner act with a fresh password. **Re-enable** (`Paused -> Paper/Active`) is always an owner act with a fresh password, needs the failing condition cleared and Gate R / Gate S of CF-11 (not enforcing yet means a visible warning), and has no auto setting because it raises risk.
**D4. Is the loop helping? Three arms on the same candidates.** (A) **frozen**: the champion fixed at the epoch's start, (B) **retrained**: the champion now, (C) **no-ML**: take every candidate (today's behaviour, since ML is advisory). For arm A and B a candidate is taken when its score is at or above that arm's own train base rate (the P6-13 / P6-12 rule, no searched threshold). Per candidate the arm's value is `R` if taken, 0 if skipped. Paired differences `d_i` are summed by trade day and resampled by **day** (2000 seeded draws). Report mean difference per candidate, the 90 % interval and `P(first arm better)`; `P >= 0.95` "helps", `P <= 0.05` "hurts", otherwise "no measurable difference"; fewer than 20 distinct days is "inconclusive". "No difference" is an answer. *Why:* P6-12 answers the frozen-versus-retrained question on stored replay data; the forward shadow set gives the same question new, unseen candidates and adds the no-ML arm the programme actually cares about. *Rejected:* comparing log loss only (the owner cares about R); letting an arm choose its own threshold on the shadow data (leak).
**D5. Learning curve.** Out-of-time gain `g(n) = base-rate log loss - model log loss` (positive is better) on a **fixed** later test block (the last 25 % of the development rows, never the hold-out), for models refit on the first `n = 50, 100, 150, ...` rows (purge and embargo as P6-05). With 4 or more points fit a line to the last 3 to 5 and call it **rising** if `slope - 1.645 SE > 0`, **flat** if `slope + 1.645 SE < min_slope` (0.002 per 50 rows, proposal), else **unclear**; with 3 points show the slope as "unclear". If rising, project the rows needed to reach a target gain of 0.01. "Flat" is reported as "more data will not help this recipe".
**D6. Calibration drift, monthly.** Rolling ECE and the gap test stay P6-09's (100 outcomes every 50). Add the **reliability slope**: the coefficient of the logistic regression of the outcome on `logit(p_hat)` over the trailing 200 outcomes (ideal 1); alarm when it is below 0.8 or above 1.2 **and** farther than 2 standard errors from 1 (below 200 outcomes the slope is shown, never alarmed). An alarm creates a CF-10 rollback proposal (fall back to the base-rate probability); this slice does not roll back by itself.
**D7. Decision-quality lift.** Share of owner-approved tickets whose model score was in the top half of that night's candidates, and mean net R of the top half against the bottom half of the shadow set (a lift check), with the standard error. Report only; it describes the owner's alignment with the score and the score's usefulness, and feeds nothing automatic.

## Goal
The owner is told when a live-forward edge is wearing out, with the rule and the numbers, can have a failing strategy stopped (manually, or automatically if they choose), and can see whether the learning loop is actually earning its keep or doing nothing.

## Scope
**In:** Domain `DecayMonitor`, `KillRules`, `ThreeArmLoopTest` (uses `PairedDayBootstrap` of CF-10), `LearningCurve`, `ReliabilitySlope`, `DecisionLift`; Application `EvaluateDecayHandler`, `ProposeKillHandler`, `ApplyKillHandler` (manual and auto), `GetLoopReportHandler`, service `decay-monitor` (starts paused), settings, endpoints, verbs `xd learn decay|loop|curve`; migration; two lazy tabs ("Decay", "Loop") on the Learning screen; ADR; docs; `gen-api`.
**Out:** re-enabling automatically (never); changing P6-09 or P6-12 behaviour; model rollback execution (CF-10); sequential test (CF-09); any consumer of the loop result that changes ranking or size; any order.

## Acceptance criteria
1. **Decay threshold by hand.** `mu_ref = +0.12`, `sigma = 1.0`, `N_ref = 320`, window 60. With `DEFF = 1`: `sqrt(1/60 + 1/320) = 0.140684`, `1.5 x 0.140684 = 0.211026`, threshold **-0.0910**; ignoring the reference error (`1.5 / sqrt(60) = 0.193649`) it would be -0.0736 (the research note's "-0.08" is that figure rounded loosely). With `DEFF = 2.5` (6 candidates a day, rho 0.3): `sqrt(2.5/60 + 1/320) = 0.211641`, threshold **-0.1975**. A window mean of -0.10 alerts at `DEFF = 1` and not at `DEFF = 2.5` (unit).
2. **Windows.** 130 graded trades make 2 completed windows (60 + 60) and 10 pending; "twice in a row" needs two consecutive completed windows below threshold; a window above in between resets (unit).
3. **Kill rule a by hand.** `c = 0.12`: `net(1) = 0.05` gives `net(1.5) = 0.05 - 0.06 = -0.01` (demote); `0.07` gives `+0.01` (keep); exactly `0.06` gives 0.00 (keep, the test is strictly negative). Fewer than 100 graded trades: not evaluated (never a demotion) (unit).
4. **Kill rule b by hand.** The 95th percentile of the matched max drawdown at n is 8 R: observed 17 R demotes (above 16); 16.0 R does not; the percentile comes from draws at the series' own n (unit with a constructed table).
5. **Proposal and execution.** Any rule firing writes a proposal (rule, numbers, strategy, cells) and a notice; with `confidence.kill.auto` OFF (default, no row) nothing else changes (integration); ON: the cells move to `Paused`, a changelog row records actor `auto`, the rule, the numbers and the setting hash; the owner is never recorded as the approver; the CF-09 failure boundary creates a proposal that the auto setting never executes (integration).
6. **Re-enable.** `Paused -> Paper` without a fresh password: 403; with it and the failing condition cleared: allowed with the Gate R warning or block of CF-11; no code path re-enables automatically (architecture test over the lifecycle handlers).
7. **Loop arms by hand.** 80 paired candidates, frozen mean 0.10, retrained 0.12, paired sd 0.8: `SE = 0.8 / sqrt(80) = 0.0894`, `z = 0.02 / 0.0894 = 0.2236`, normal approximation `P = 0.5885`: no measurable difference. Exact oracle by enumeration: three trade days with paired differences (0.01 units) `+10, -5, +20`: of the `3^3 = 27` resamples of three days, 4 have a non-positive sum (`-15`: 1; two `-5` and one `+10`: 3), so `P(better) = 23 / 27 = 0.8519`: below 0.95, "no measurable difference"; fewer than 20 distinct days: "inconclusive" (unit).
8. **Same trades.** The three arms score exactly the same candidate set (recording-scorer test, as P6-12 AC1); a candidate an arm skips contributes 0 to that arm; a day-clustered resample keeps whole days together (property).
9. **Learning curve by hand.** Gains `-0.004, 0.001, 0.005` at n = 50, 100, 150: slope `0.45 / 5000 = 0.00009` per row (0.0045 per 50 rows); fitted line `0.000667 + 0.00009 (n - 100)`; the target 0.01 is reached at `n = 100 + 0.009333 / 0.00009 = 203.7`, "about 54 more rows" from 150; with only these 3 points the verdict is "unclear" (no SE). A series `0.004, 0.0041, 0.0039, 0.0040` gives "flat" with `min_slope = 0.002` and a tight SE (unit).
10. **Reliability slope oracle.** Predictions of 0.2 and 0.8 with 100 outcomes each and observed win rates 0.35 and 0.65 give intercept 0 and slope `logit(0.65) / logit(0.8) = 0.619039 / 1.386294 = 0.4465` (below 0.8: overconfident); observed 0.2 and 0.8 give slope 1.0; at 200 outcomes the alarm also needs `|slope - 1| > 2 SE`. The gap test keeps the P6-09 numbers: predicted 0.58 against observed 0.46 is 12 pp; with `n = 100` it is not a breach (2.5 SE = 12.46 pp), with `n = 200` it is (8.81 pp) (unit).
11. **Decision quality.** Top half `n = 20` mean +0.25, bottom half `n = 20` mean -0.05, sd 1.2: lift 0.30, `SE = 1.2 x sqrt(1/20 + 1/20) = 0.3795`, `z = 0.79` (not significant, said so); 21 of 30 approved tickets in the top half is 70 % against 50 % by chance (`z = (0.7 - 0.5) / sqrt(0.25 / 30) = 2.19`) (unit).
12. **Nothing else moves.** P6-09 and P6-12 outputs are byte-identical with and without this slice (golden); no clock, no unseeded random in any calculator; no trade rows or secrets in logs; Architecture tests green.

## Non-functional
All calculators are linear in the trades (hundreds) except the bootstrap (2000 draws over tens of days: milliseconds) and the learning curve (a handful of refits of the existing trainer; bounded by P6-06 training time, run on request or weekly, not nightly). Deterministic seeds (sha256 of strategy id and purpose). Security: owner session, CSRF, fresh password on re-enable and on settings.

## Test plan
Unit (Domain): every hand table, boundary equalities, windows, bootstrap enumeration, OLS slope, logistic slope. Unit (Application): proposals, auto versus manual, re-enable refusal, arms scoring with a recording scorer. Integration: grants, lifecycle changes and changelog `auto`, endpoints, determinism. Frontend (MSW): both tabs. Architecture: no auto re-enable; Domain purity.

## Risks
Few trades make every window mean noisy; a threshold at 1.5 SE fires falsely about 7 % of windows on a stationary strategy (one-sided), and twice in a row about 0.4 % (assuming independent windows): that is the reason for the twice-in-a-row rule. The reference sigma from a short out-of-sample set is itself uncertain. The no-ML arm is "take all" only while ML is advisory.

## Review fixes 2026-10-27
1. **Needs and order:** CF-10c (bootstrap) and CF-10d (rollback executor, ECE); build order 10c, CF-12, 10d.
2. **Three-arm labels (D4):** A versus B and B versus C are reported **separately**, each with "helps" at `P >= 0.95` and "hurts" at `P <= 0.05`; the interval shown is a two-sided 90 % interval, read together with the one-sided 0.95 statement (they are the same cut).
3. **Kill rule a** evaluates daily on the trailing 100 trades with overlapping windows; it needs at least 20 **new** trades since the previous evaluation before it can fire again, so one run of bad trades is not counted many times.
4. **Kill rule b** uses the factor 2 on the 95th percentile at the series' own n; the 2 is a proposal and is stated next to the number in the proposal text.
