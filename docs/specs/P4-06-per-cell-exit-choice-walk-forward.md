## Goal
For one cell (strategy, timeframe, side, style; regime `*` until P6), pick from the candidate exits of a P4-05 comparison the one with the best out-of-sample risk-adjusted expectancy, say how stable that choice is across walk-forward folds, and say "no choice" when the sample is too small. The result is a record that is printed, exported and, with `--store`, kept. Like all of P4, this tests the selection procedure; the choice is **in-sample on the data shown** (about 2.1 years, 4 to 6 folds) and is not evidence of an edge.

## What exists and what does not (read 2026-10-22)
- **Exists:** the walkers of all seven policies and both overlays (ADR 0049 to 0052), run-record schema 6, `SimTrade` schema 5 with `Legs`, the result store with insert-only `sim_runs`/`sim_trades` and a unique `(run_id, trade_key)` (ADR 0045), `SimulationEngine.Version` `sim-6`.
- **Does not exist:** any selection code, any fold code, a definition of `downside_dev_R` (docs name it, none defines it; P4-05 D6 proposes one), a "declared default exit" of a strategy (the model has an ordered `exits` list and no default field; UNVERIFIED by a read of `StrategyDefinition`), and **any way for a verb to choose an exit** — `BuiltInStrategies` writes a fixed `FIXED_RR` into each built-in and `ISimulationEngine.Prepare` has no exits argument. P4-05 D1 adds `--exit`; this spec consumes it and adds nothing to the verbs' ways of choosing an exit except the selection flag of D1 below.
- **Doc 16 disagrees with the data.** `walk_forward: { train_years: 3, test_months: 3, embargo_sessions: 5 }` cannot run on 2.1 years of data (P4-00 D7); this slice changes the doc (D3).

## Definitions
A *candidate*, a *cell* and the *trade key* are P4-00 D2's and P4-05's. A *fold* is a train set and a test set of trades; "entry date" is the date of the entry fill of a trade; a *session* is a trading-calendar session. The unit of R is P4-05 D6's (`RNet` for a costed run, `RFilled` for a gross run, labelled which). All dates are IST.

**D1. Input.** The in-memory result of a P4-05 comparison for one cell: for each candidate, its trades (open-at-end trades excluded) with entry date, exit date, `R` in the run's unit, and its candidate id, plus the parameter coordinates of each candidate (policy, the name and value of the list parameters it came from). Chosen by `--select-exit` on `simulate` (UNVERIFIED name; question 1), which implies the comparison of P4-05 and needs two or more candidates. **Trades are taken from the ungated comparison walk of P4-05 D4** so that each fold's candidates see the same entries; the result says "overlap not gated" for a swing cell. Reading a stored comparison instead is a later slice (question 1).

**D2. Folds (P4-00 D7, recommended).** Let the first and last entry date of the run's window be `a` and `z`. **Expanding train** from `a`; **test windows of 3 calendar months**; the first test window starts no earlier than `a + min_train_months` (default 9 months, rounded to a month start); consecutive test windows tile with no gap up to `z`; a final window shorter than 1 month is dropped and counted. **Embargo** of 5 sessions: the train set of a fold holds the trades with entry date at least 5 sessions before the test window starts **and an exit date before the test window starts** (a swing trade that would still be open at the test start is purged, not embargoed by its entry only; question 3). The trades of a test window are those with entry date inside it. With 214 files from 2024-04 to 2026-04 this gives about 4 to 6 folds (P4-00 D7; UNVERIFIED until run). A run with fewer than 2 folds yields no stability statement (D8) and says why.

**D3. Configuration and doc 16.** `walk_forward` in doc 16 becomes `{ mode: expanding, min_train_months: 9, test_months: 3, embargo_sessions: 5 }` for the exit choice, with the 3-year rolling form kept as the later default once the backfill gives 5 years (ISS-19). This is a design change: doc 16 is edited, [ADR 0054](../adr/) records it (the number is the next free after 0053, UNVERIFIED) and `scripts/build-docs.sh` regenerates `docs/site`. The four values are inputs of the selection and are written in the record; flags `--min-train-months`, `--test-months`, `--embargo-sessions`, `--lambda`, `--min-trades` override them for a run and are echoed.

**D4. The objective (P4-00 D8; doc 16 `selection_objective`).** `score(c, S) = mean_R(c, S) − λ · downside_dev_R(c, S)` over the trades `S` of candidate `c`, λ = 0.5, `downside_dev_R` as P4-05 D6 (`sqrt(mean(min(R, 0)²))`, target 0; question 4). On `RNet` when the run is costed with a sheet and on `RFilled` labelled gross otherwise; the choice and the report never mix the two.

**D5. Minimum sample and "no choice".** A candidate takes part in a fold's choice only if it has at least `min_trades` (30, doc 09) trades in the train set; a fold in which fewer than 2 candidates qualify has **no choice** for that fold. A fold is *thin* (excluded from the stability fraction, listed) when its test set has fewer than `min_trades` trades of the chosen candidate. The cell has a **final choice** only if the full-sample choice (D6) qualifies and at least 2 folds are not thin; otherwise the cell is "no choice" and falls back to the default exit (D6). The minimum is per cell and per fold, not a pooled total (question 5).

**D6. The choices.** Per fold: the winner on the train set by D7. **Final (in-sample) choice:** the winner by D7 on **all** the trades of the cell, reported as in-sample; **out-of-sample evidence:** the pooled test-window result of the per-fold winners (each fold's test trades under its own train-time winner), next to the pooled test-window result of the default exit and of every single candidate, so the owner sees whether the walk-forward procedure beat just fixing one candidate in advance. The **default exit** is the first candidate listed in the strategy's `exits` (UNVERIFIED that the order is meaningful in the model; for a built-in the default is its own `FIXED_RR`; question 6). A cell with "no choice" is shown as such and uses the default.

**D7. The plateau rule (precise; P4-00 D8 deferred it here).** Candidates that come from one list parameter of one policy form a **line** ordered by the value (`rr` 1.5, 2, 2.5, 3). Candidates of different policies or with different non-list parameters are not neighbours. For candidate `c` with train score `s(c)` and standard error `se(c)` = the standard error used is that of the **mean R** alone, `sd(R)/√n` (UNVERIFIED that this is the right scale for the score; question 7):
1. `c` is **on a plateau** if every neighbour `n` (the one or two adjacent on its line) satisfies `s(n) ≥ s(c) − se(c)`; a candidate with no neighbour (a one-value line: `PARTIAL_TRAIL`, `PYRAMID`, a single `rr`) is **isolated**, never on a plateau by this test and flagged "no neighbours".
2. The winner is the highest-scoring candidate among those **on a plateau**; if none is on a plateau, the highest-scoring candidate overall, flagged **lone peak** (and, with the report, as such in every fold it wins); ties break by the lower sort key of the candidate id (deterministic).
3. With `prefer_plateau: false` the winner is the highest score.
The rule is a function of the train set only; it reads no test trade.

**D8. Stability across folds.** From the winners `w_1 … w_k` of the non-thin folds: a fold is **in agreement** with the modal winner `m` if `w_i = m` or `w_i` is a **neighbour** of `m` on its line (D7). The choice is **stable** if (a) agreement ≥ `stable_folds_pct` (60, doc 16 `min_positive_folds_pct`; the key is reused with a new meaning, which the doc 16 edit names; question 5) of the non-thin folds **and** (b) the modal winner has a positive out-of-sample score in ≥ 60 % of the folds it won or was in agreement with (a candidate that keeps winning but loses money out of sample is not a stable edge, it is a stable loss). Otherwise **unstable**, with the reason printed. With 4 to 6 folds this is weak evidence and the report says so in a fixed line: "k folds; the 60 % rule on k folds can pass by chance about p of the time" with `p` the exact probability under uniform random winners among the n candidates, computed in the record (not asserted). The report also prints the winner per fold, the train and test score of each fold's winner, the pooled out-of-sample figures of D6, and the number of lone peaks.

**D9. The record.** `ExitSelection` schema 1 (a new record, not a change to `SimulationRun`): the cell, the comparison's `entries_key` and member run ids (P4-05 D10), the inputs (folds, embargo, λ, `min_trades`, unit gross or net), the folds with their dates and counts, per-fold train/test tables for each qualified candidate, the winners, the plateau/lone-peak flags, the final choice or "no choice", the default exit, the pooled out-of-sample figures, the stability verdict and reason, and the banner lines: P3's lines, "the choice is in-sample on the data shown (about 2.1 years, no hold-out) and is not evidence of an edge" (P4-00 criterion 9), "k folds only", and "overlap not gated" for swing. Deterministic bytes: no clock, no random; the same inputs give the same record text. Export: `exit-selection.json` and `exit-selection.csv` (one row per fold and candidate) in the run folder, format `xd-sim-export-4` of P4-05 (UNVERIFIED: P4-05's format number).

**D10. Storage.** With `--store`, one row in `research.exit_selections (id, selection_key char(64), comparison_id, strategy_id, timeframe, side, style, regime, chosen_candidate_id null, stable bool null, record_json text, record_sha256, created_at)` and one row per fold-candidate in `research.exit_selection_folds`, in one transaction; the key is the hash of the comparison's `entries_key`, the member run keys and the inputs of D3 (idempotent: the same again is `already stored`, a different record under the key is a conflict logged at error); insert-only for `xd_app` (`MakeAppendOnlyForAppRole`, grants per table; the standing rule of ADR 0045 D7 and `ResearchGrantsTests` extended), a stored selection is removed by the owner as `xd_owner`. `record_json` is `text` for the reason of ADR 0045 D1. Migration `AddExitSelections`. A selection whose comparison was not stored is refused at `--store` by name (the foreign key would dangle). UNVERIFIED: the port shape (`IRunStore` or a sibling); ISS numbers and event ids are taken from the next free ones at build.

**D11. Properties and oracle.** (a) **No look-ahead in the choice:** the winner of a fold is a function of its train trades only — perturbing, removing or reordering any test trade, or any trade whose exit date is on or after the test start, leaves every train-time choice unchanged (negative control: a variant that scores on test trades must fail). (b) **Fold geometry:** test windows are disjoint, tile from the first test start, never overlap the train set of their own fold, and every train trade ends before its test window starts and at least 5 sessions earlier by entry. (c) **Candidate order independence:** permuting candidates changes no choice (ties by id). (d) **Determinism.** (e) **Scale invariance:** multiplying every R by a positive constant changes no choice. The **oracle** (P3-08 style, an independent second implementation from D2 to D8 only) agrees on every field of the record over at least 5,000 seeded comparisons.

## Acceptance criteria
1. **Nothing else moves.** Without `--select-exit`, every run, golden and stored byte of P4-05 is unchanged.
2. **Folds (D2).** On a calendar fixture (a window from 2024-04-01 to 2026-04-30, an NSE calendar with holidays) the fold dates, the train/test counts, the dropped short window and the purged swing trades equal a hand-computed table; fewer than 2 folds gives "no stability statement".
3. **The objective and the plateau (D4, D7).** A hand-computed table of at least 20 cases (a plateau winner over a higher lone peak; no plateau; ties; isolated candidates; `prefer_plateau: false`; a two-line grid) gives the winner and the flags exactly; `downside_dev_R` equals the hand value to the printed precision.
4. **Minimum sample (D5).** A cell with candidates below 30 trades is excluded; a fold with fewer than 2 qualified candidates is "no choice"; a thin fold is excluded from the fraction; a cell with no final choice shows "no choice" and uses the default, and says so in the banner.
5. **Planted signal (P4-00 criterion 8).** In a synthetic series where one candidate exit is better than the others by a margin that survives the noise (planted), that exit wins **every** fold, the final choice is it, and the stability report says stable. In a **noise-only** series (all candidates drawn from one distribution) the report says unstable on at least `X` % of 1,000 seeded series, where `X` is **set by measurement before approval of the build** and fixed in the test (UNVERIFIED; the chance a random 60 % rule passes on 4 to 6 folds is not small, which is why D8(b) exists, and the test must show the rate, not assume it).
6. **Seed and boundary (P4-00 criterion 8).** Changing the seed changes only the trades; moving a fold boundary by one session changes only the folds it touches (a test names which); changing `λ` changes the scores and nothing in the folds.
7. **Properties and oracle (D11).** All hold; the negative control of D11(a) fails; the oracle agrees over 5,000 seeded comparisons.
8. **The record and the banner (P4-00 criterion 9).** The record carries the inputs, the folds, the per-fold tables, the verdict and the lines of D9, including the exact chance-pass probability of D8; the in-sample line is present in the summary, the record and the CSV; a test that removes the line fails.
9. **Store (D10).** A selection round-trips; the same again is `already stored`; a conflict is `store.run_conflict`-style and logged; a selection with an unstored comparison is refused; the tables are insert-only for `xd_app`; `Down` of the migration is tested.
10. **End to end.** `simulate --strategy ORB --exit FIXED_RR:rr=1.5|2|2.5|3 --select-exit --gross` on a seeded Testcontainers fixture prints the folds, the winners, the stability verdict and the banner; with the real-data run the owner can open `exit-selection.csv` and the per-candidate trades (the real run is the owner's; no number from it is quoted outside its folder before the hand check of P4-00 question 4).
11. **Performance.** Selection over 8 candidates × 50,000 trades each takes under 1 s on the reference machine (UNVERIFIED target; the folds are a pass over sorted arrays) and allocates nothing per trade after the sort.
12. `scripts/check.sh` green; a `reviewer` pass with no blocker or major; ADR 0054 and the docs (08 §3, 09 §1, 16 `walk_forward` and `selection_objective`, 18-roadmap, the oracle log) done and `scripts/build-docs.sh` run.

## Non-functional
Pure function of the comparison's trades and the inputs: no clock, no random, no network, no I/O except the existing store write. Selection time is negligible next to the walks (AC 11). Logs carry the cell, counts, the chosen candidate id and the verdict; never a trade or a record text. No secret.

## Test plan
Unit: fold geometry on a calendar, embargo and purge, objective, downside deviation, minimum sample, fallback, plateau on lines (hand table), stability fraction and its chance-pass probability, the record text. Property: D11 with negative controls. Planted-signal tests (AC 5, 6) over seeded synthetic comparisons (a generator in the test project, no walker needed: the selection takes trades). Oracle: D11. Integration (Testcontainers): the verb with a comparison, the store, idempotency, conflict, grants, migration up/down. Edge cases: one fold; zero folds; all candidates below the minimum; ties; a candidate with no trades in a fold; a swing trade that spans a test start; identical candidates (refused upstream); the window shorter than `min_train_months`; `prefer_plateau: false`; a one-value line; λ = 0.

## Open questions (for the owner; each with a recommendation)
1. **Input and surface (D1).** `--select-exit` on `simulate` computing in memory from the comparison it just ran, or a separate verb reading a stored comparison? Recommended: the flag, in memory; the store has no reader of whole runs (ADR 0045), the selection needs only per-trade R, dates and ids, and a later verb can read the stored comparison when P5 needs it.
2. **Approve P4-05 first.** This spec depends on P4-05 D1 (a way to choose exits from a verb), D4 (ungated comparison), D9 and D10 (stored legs and comparisons). Recommended: approve P4-05, answer its questions, then re-read this spec's D1, D9 and D10 against it; the walk-forward cannot be exercised on real data without P4-05.
3. **Embargo and purge of swing trades (D2).** Purge every train trade whose exit is not before the test start, as well as the 5-session embargo on entry? Recommended: yes (a train trade still open at the test start shares information with the test); it costs a few train trades per fold.
4. **Downside deviation (D4).** Semi-deviation with target 0 over all trades, on net R when costed? Recommended: yes (the same definition as P4-05 D6); doc 08 and ADR 0054 will define it.
5. **Thresholds (D5, D8).** Minimum 30 trades per candidate in train and per chosen candidate in test; "stable" = ≥ 60 % of non-thin folds in agreement **and** a positive out-of-sample score in ≥ 60 % of them; λ = 0.5. Accept, or wait for more data (ISS-19)? Recommended: accept, print the chance-pass probability in every report, and say in every report that 4 to 6 folds is weak evidence (P4-00 question 3). Reusing doc 16's `min_positive_folds_pct` for agreement (instead of its other meaning) is an edit of that doc; the alternative is a new key `stable_folds_pct`, which I recommend.
6. **The fallback exit (D6).** "The first candidate listed in `exits`" (for a built-in, its own `FIXED_RR`), since the model has no default field. Recommended: yes for P4; a default field is a model change (Amendment 2 of ADR 0036) that stored strategies (P3-02d) should decide.
7. **The standard error in the plateau rule (D7).** `sd(R)/√n` of the mean R, neighbours within one of it. Recommended: yes as the simplest honest scale; the P4-00 text says "within one standard error" and nothing more, so this is my reading and is **UNVERIFIED** as the owner's intent. A bootstrap interval is the alternative, rejected for cost and for non-determinism unless seeded.
8. **How far to trust the fold count (ISS-19).** Run the Dhan backfill toward about 5 years (P4-00 question 2, the allow-list change is your security decision) before using the choice for anything? Recommended: yes before any choice is acted on; P4-06 can be built and tested on 2.1 years because the planted-signal tests do not need real data.
9. **Cut line.** If P4 runs late, simplify D7 to the best candidate with the stability report kept (P4-00 question 6). Recommended: yes, and nothing else in P4 depends on the plateau rule.
