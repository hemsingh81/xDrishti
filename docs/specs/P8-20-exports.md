- **Status:** Draft (written 2026-10-24; decisions below were researched under the owner's delegation; the owner's Approved is still needed before an agent builds it)
- **Phase / roadmap row:** P8 — Reports & UI, slice P8-20 of [P8-00](P8-00-reports-and-ui-plan.md) (Q4, D8)
- **Design refs:** docs/design/13-reports-and-ui.md §3 ("Any report: CSV/Excel"; notifications "only if you enable one") · 19 §4, §5 (personal use only) · 04 §3 (every action audited) · P3-04b1 (the existing export library and `CsvRow`), P5-06 / ADR 0063 (the inert Lab HTML), P8-00 D1 (evidence block), D3 (six states), D8
- **Needs:** P8-18 (the capability gate and fresh-password helper), P8-06 (**built**, ADR 0100: the report read handlers whose results are exported, `Application/Reporting`: `GetReportGroupsQuery`, `GetReportPivotQuery`, `GetReportWhatWorksQuery`, `GetReportEquityQuery`, `PageReportTradesQuery`, each taking a checked `ReportQuery` made from `ReportQueryInput`), P8-05 (built: the pure engine and its states), P8-01 (built: kit). An ADR at build time (next free ADR number at build time).
- **Size:** 3 agent-days
- **Safety:** **yes.** Data leaves the app as a file on the owner's device. It stops for the owner. The capability `exports` defaults OFF.

## Assumptions (the safest answer that still serves the goal)
1. **What may leave: research tables only.** The tables the Reports and Learning screens already show from stored simulations: report groups, pivot, what-works ranking, equity series, simulated trades of a report, Setups cells, the experiment ledger. **Not** portfolio, holdings, imported or real trades, journal, plan tickets, allocations, grades, fills, accounts, autonomy history, audit events, the weekly PDF pack (all stay a later owner decision, as P8-00 Q4 recommends; design change: doc 13 §3 "Exports & delivery" is narrowed by an "as built" note, ADR at build time).
2. **No export without the table's own evidence.** Every file carries the Evidence block of P8-00 D1 (basis, population, date range, n, folds where relevant, unavailable inputs, limits). A table without evidence cannot be exported (the exporter takes the same typed result as the screen; a result that lacks evidence does not type-check, as `EvidenceBlock`).
3. **Same numbers as the screen.** The server exports by calling the **same application query handler** with the same query object the screen's GET uses (P8-00 D4 `ReportQuery`), never a second implementation. A test compares the exported numbers with the GET JSON.
4. **POST, not GET.** An export writes an audit row and a log line, and a GET must change nothing (`SessionCookie` comment, SameSite=Lax rationale). So `POST /api/exports/{kind}` with CSRF; the browser fetches the bytes and saves them (blob download); nothing is stored by the server and nothing is stored in the browser beyond the file the owner saves.
5. **Gate and password.** Server-enforced capability `exports` (default OFF; ON needs the fresh password; OFF does not). The export request itself needs session + CSRF, not a password: it reveals what the owner can already see on screen (decision D5).
6. **No cloud, no e-mail, no clipboard magic, no push** (doc 13 §3, P8-00 Q4, Q6). The only destination is the browser's download.

## Goal
The owner can download the research table they are looking at as a CSV (for a spreadsheet) or a static HTML page (to keep or print), with the evidence and limits inside the file, safe to open in a spreadsheet, containing nothing about accounts, with the app recording only what kind and how many rows.

## Scope
**In:** `POST /api/exports/{kind}`; `ExportTable` model and per-kind mappers in Application; `ReportCsvWriter` and `ReportHtmlWriter` in `XDrishti.SimExport` (reusing `CsvRow` and `Html`); the formula-injection hardening of `CsvRow.Text` (full-width triggers, leading-space look-through); caps; rate limit; audit; `ExportMenu` component in a new feature `exports` used by the report screens; tests, ADR, docs.
**Out:** XLSX/PDF, zip folders (the Lab's zip exists and is untouched), portfolio / plan / journal / audit exports, scheduled or e-mailed exports, a signed or watermarked file, an export of a chart as an image, importing the file back.

## Acceptance criteria
1. Given the capability `exports` is OFF or has no row, when `POST /api/exports/{kind}` is called, then 403 `capabilities.off`, nothing is built, no log of content. Given ON and a kind outside the whitelist (`report-groups`, `report-pivot`, `report-what-works`, `report-equity`, `report-trades`, `cells`, `experiments`), then 422 `exports.kind_unknown`. *Integration.*
2. Given a valid request, when the CSV is built, then it equals byte for byte the file built again from the same stored runs and the same query (no timestamp, no random, no machine name inside); the numbers parse back equal to the GET JSON of the same query. *Integration + property.*
3. **Evidence is inside the file.** The CSV starts with preamble lines beginning `# ` (basis with the charge-sheet confirmation if net, population run keys, date range, n, folds, unavailable inputs with reasons, every `limits` string, `table-rows`, `table-sha256`) and ends with `# end of export, rows N`; the HTML has the same block above the table. A result without evidence is a compile-time impossibility and a 500-free 422 `exports.no_evidence` at runtime for a mapper that returns none. *Unit + integration.*
4. **Non-values are never digits.** A metric column is written as three cells: `<id>` (a number only for `value` and `provisional`, empty otherwise), `<id>_state` (`value|provisional|insufficient|unavailable|not_evaluable|empty`), `<id>_reason`. A property test over every state asserts a non-value row has an empty number cell and a state word, and that no cell reads `0`, `NaN`, `Infinity` or `-` for a non-value. *Property + unit.*
5. **Formula injection (OWASP).** Given text cells (symbol, strategy id, run label, notes, reasons) that start with `=`, `+`, `-`, `@`, TAB, CR, LF, the full-width `＝ ＋ － ＠`, or whitespace followed by one of them, when written, then the cell gains a leading apostrophe; control and format characters (NUL, bidi, zero-width) are dropped first; commas and quotes are quoted per RFC 4180; numbers are only ever written from numeric types in the invariant spelling. A corpus test (OWASP's own examples such as `=cmd|' /C calc'!A0`, `@SUM(1+1)*cmd|' /C calc'!A0`, `=HYPERLINK("http://e","x")`, `+1+1`, `-2+3`, a tab then `=1`, `＝1+1`, ` =1`) writes each into every text column of every kind, parses the file back with a strict RFC 4180 reader, and asserts that no **text-column** cell's first non-space character is a trigger. Numeric cells are out of this assertion: `CsvRow.Number` appends the invariant spelling raw, so a negative number legitimately starts with `-`; a separate property asserts numeric cells are produced only from numeric types and match the canonical number pattern. The `# ` preamble lines (limits, run labels, unavailable reasons, population) go through the same stripping: CR, LF, TAB and every control/format character are replaced by a space (never dropped, so words do not join) **before** the cell is written, so a newline can never end the comment line and start a data row; a test plants `\n=cmd|...` and `\r\n1,2,3` in a limits string and in a run label and asserts the file still has the exact preamble line count. *Unit + corpus + property.*
6. **Nothing about accounts.** The real proof is structural: the *architecture test* (exporters reference only the reporting DTO namespaces; no account, portfolio, plan, journal, broker or secrets namespace) and the *reflection test* on column names; they hold for every future kind. The canary test below is a smoke test only (it can pass trivially if a leak uses another spelling) and is not the evidence. A canary test seeds an account with the client id `CANARY-CLIENT-9`, the access token `CANARY-TOKEN-9`, the e-mail `canary@example.test`, a holding and a balance, runs every kind and format, and asserts none of the canary strings or the account/holding/balance values occur in any output byte or in any log line; a reflection test asserts the column set of every kind contains no name matching `account|client|token|email|balance|holding|quantity_held|password|secret`. *Integration + reflection.*
7. **Download headers.** `Content-Type` `text/csv; charset=utf-8` or `text/html; charset=utf-8`; `Content-Disposition: attachment` with a **server-made ASCII name** `xd-<kind>-<yyyyMMdd>-<8 hex of table-sha256>.csv|.html` (never from the request; the date from `TimeProvider` in India time); `X-Content-Type-Options: nosniff`; `Cache-Control: no-store`; for HTML also `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox`. A test reads the header values and the absence of `Set-Cookie`. *Integration.*
8. **Caps, never silent.** CSV above 100,000 rows or 25 MB, HTML above 5,000 rows or 5 MB: 413 `exports.too_large` with the row count and the sentence "narrow the filters"; the file is never truncated. The export streams rows from the reader (no 500,000-trade list in memory beyond the cap check by count first). *Integration with a synthetic large run.*
9. **Count-only logging and audit.** One log event (id from the next free block, proposed 4940-4949) with kind, format, rows, bytes, ms; one `account_events` row `ReportExported` with detail `kind=report-groups format=csv rows=42` (no filter values, no symbols, no run keys, no content); a refused request logs only its code. A test captures logs and events for all kinds and asserts no symbol, run key or number from the table occurs. *Integration.*
10. **Rate limit.** 6 exports a minute and 1 at a time per session: 429 `auth.rate_limited`. *Integration.*
11. **Frontend and write-path guard.** `ExportMenu` renders nothing while the capability is OFF or unknown; ON shows "Export CSV / Export HTML" with the sentence "A file will be saved on this device, outside the app's protection. It contains research tables only."; the click does the POST with the same URL-state query, saves the blob through a temporary `<a download>` and revokes the object URL; failure shows the problem text (403/413/422/429); nothing is kept in query cache or storage. The read-only guard (`features/learning/readOnly.test.ts` forbids every `@/features/` import today) is amended here with an explicit allow-list: report/learning folders may import `ExportMenu` from `@/features/exports` and nothing else, and the shared guard of P8-18 criterion 15 (case-insensitive; `post`, variable-method `fetch`, `sendBeacon`) passes with `exports` as one of the two allowed writer features. A planted violation in a report folder fails it. *Vitest + MSW.*
12. `scripts/gen-api.sh` run; existing `TradesCsv` and other golden CSV outputs are byte-identical except for cells starting with a newly covered trigger (a golden test proves it); `scripts/check.sh` green.

## Contract
- **API:** `POST /api/exports/{kind}` body `{format:"csv"|"html", query:{...the screen's ReportQuery or the kind's own filters, same field names as the GET}}` -> 200 file; errors above plus 422 `reports.invalid` / `reports.run_overlap` / `reports.mixed_basis` / `reports.net_not_confirmed` exactly as the GET of the same query (the exporter reuses the handler, so it fails the same way). Summary text lists every code. `exports.too_large` is 413.
- **Data:** no table, no migration. `AccountEventType.ReportExported` appended. Setting: capability `exports` (P8-18's store), default OFF. Configuration `Exports:MaxCsvRows=100000`, `MaxHtmlRows=5000`, `MaxCsvBytes=26214400` (values may be lowered, not raised above these).
- **UI:** `frontend/src/features/exports/` (`ExportMenu`, `useExport`, `index.ts`), rendered in the toolbar of What works, group/pivot/basket comparison, Setups and the Experiments tab. Wording constants live in one file. Placement of the menu in the screens of P8-02/08/09 is part of this slice (a one-line import each).
- **Events/jobs:** none; the build runs inside the request.

## Non-functional
Budget: a 10,000-row CSV in under 1 s on the seeded fixture (measured and reported, not asserted for the owner's data); memory bounded by the row cap; no new package (`CsvRow`, `Html`, `System.Text` only). Security: session, CSRF, capability, rate limit; the file name is not user input (no path, no header injection); the HTML is inert (no script, link, image, frame; every dynamic string through `Html.Text`). Observability: criterion 9 only.

## Test plan
- **Unit:** `CsvRow.Text` truth table including the new triggers and look-through; `ReportCsvWriter` golden file for a hand-worked 3-row table (one `value`, one `insufficient`, one `unavailable`) written in the spec's fixture below; `ReportHtmlWriter` golden; filename builder; cap checks.
- **Property:** random strings (including bidi, zero-width, control characters, quotes, commas, newlines) in every text column round-trip through a strict RFC 4180 parser to `sanitised(original)` with the prefix rule, never to a cell that starts with a trigger; random doubles are written in the canonical numeric spelling.
- **Integration:** each kind x format with the corpus; canary; headers; 413 on a synthetic over-cap run; rate limit; logs/events; same-numbers test against GET JSON; capability matrix.
- **Architecture:** the exporters depend on `Application` reporting DTOs and `SimExport` only; no reference to account, portfolio, plan, journal, broker or secrets namespaces; `Domain/Reporting` still has no I/O; the no-order test unchanged.
- **Frontend:** `ExportMenu` states, blob save with a stubbed `URL.createObjectURL`, error mapping, the allow-list guard, markup in problem text.
- **Fixture (hand-worked):** three groups `ORB|15m` (n=40, expectancy 0.12 R, value), `VWAP|5m` (n=9, insufficient with note "n 9 of at least 15"), `BASE|1D` (exit not recorded, unavailable). Expected CSV rows: `ORB|15m,40,0.12,value,` / `VWAP|5m,9,,insufficient,n 9 of at least 15` / `BASE|1D,0,,unavailable,exit not recorded for run <key>`; no `0` in an expectancy cell of the last two rows.

## Decisions (researched)
- **D1 Formats.** CSV and the static HTML only. Reason: a spreadsheet and a printable page cover the use ("Any report: CSV/Excel", doc 13 §3); XLSX needs a library (supply chain) and carries macro/format surface; PDF needs a renderer. Rejected: XLSX/PDF now. Source: doc 13 §3; `CsvRow.cs`, `ReportHtml.cs` (opened).
- **D2 Evidence as a preamble of `#` lines, not a second file.** Reason: the owner copies a CSV alone; a separate evidence file gets lost. `#` lines are skipped by common tools (`pandas comment='#'`, R `comment.char`) and shown as text in a spreadsheet; the closing `# end of export` line makes truncation visible. Rejected: zip with README (loses the evidence on unzip-and-forget), no preamble (violates D1 of P8-00).
- **D3 Injection defence.** The existing writer already strips control/format characters and prefixes `' ` for `= + - @ TAB CR LF` (P3-04b1). OWASP's CSV Injection page lists the same triggers plus the full-width `＝ ＋ － ＠` and says to quote fields, prepend a single quote and double inner quotes, and warns quoting alone may not survive a re-save in Excel; this slice adds the full-width set and the leading-space look-through and keeps the apostrophe prefix. Numbers are never produced from strings. Source: https://owasp.org/www-community/attacks/CSV_Injection (redirects to community.owasp.org/attacks/CSV_Injection; read 2026-10-24). Rejected: the tab-inside-quotes variant (it stays in the data and breaks programmatic imports, as OWASP notes).
- **D4 Filename and disposition.** Server-generated ASCII name, `attachment`; the framework writes both `filename` and `filename*` forms when needed. MDN: send both parameters, avoid percent escapes in plain `filename`, strip path characters, never trust client text for a name. Source: MDN Content-Disposition (read 2026-10-24); RFC 4180 CSV rules as the existing writer cites them (not re-read here).
- **D5 No password per export.** An export shows what the screen shows. Cost of a password per export would be friction with no protection (a hijacked session can read the same JSON). The protection is the OFF-by-default capability (password to turn on), the audit, the rate limit and the cap. Rejected: password per export.
- **D6 Caps.** 100,000 rows / 25 MB CSV is above any realistic report of this system (the largest, trades of one run, is bounded by the cap check and the owner narrows the filter); never truncating avoids a file that looks complete.
- **D7 Lab downloads stay as built.** `GET /api/lab/runs/{id}/report/html` and `/folder` predate the gate and are inert strategy reports. They are not moved under `exports` here (that would hide a built feature by default); listed in the report as a follow-up the owner may choose.

## Risks and honest limits
- A saved file is outside the app: it can be copied, synced or e-mailed by the owner's own tools. The gate controls whether the app offers a file and records that it did; it cannot stop the owner copying what is on screen.
- Spreadsheet behaviour is not under our control: a defused cell is text with a leading apostrophe; re-saving can change that. The corpus test proves what we write, not what Excel does later.
- A report exported as `gross` is gross; `net` appears only with the owner's confirmed charge sheet (ISS-25); the file says which, in the preamble.
- The exported numbers describe the stored past on replayed history (about 2.1 years, modelled fills, no hold-out): the limits are in the file; they do not make it a forecast or advice (doc 19 §5).
- Exports of strategies and cells reveal the owner's research edge to whoever gets the file.
