- **Status:** Approved (owner, 2026-10-11: "select a date while importing each holding … option to auto refresh … new holdings on later runs get today as added date … if nothing is added the default date is 1st Jan 2025"; design details below are mine — object to any) · decision [ADR 0012](../adr/0012-holdings-acquisition-dates-and-returns-model.md)

- **Follows:** P1-16/16e (accounts, tokens, default buckets) · **Feeds:** [P2-05](P2-05-returns-and-xirr-per-holding-and-total.md)

## Goal
From the Portfolio screen the owner imports the holdings of a connected Dhan account, giving each an acquisition date (default 1 Jan 2025), and keeps them in sync — by hand or automatically — with new holdings and quantity changes handled by clear rules.

## Dhan API (docs read 2026-10-11)
`GET https://api.dhan.co/v2/holdings`, header `access-token` → array of `{exchange, tradingSymbol, securityId, isin, totalQty, dpQty, t1Qty, mtf_t1_qty, mtf_qty, availableQty, collateralQty, avgCostPrice, lastTradedPrice}`. No date, no previous close. Needs the account's stored access token (vault, P1-16c); when the account is not connected or the token is expired the import/sync fails with the existing "not connected" semantics. Rate limits are far above what this uses. Add the host/path to the broker allow-list (GET, https, exact path, no query).

## Design
1. **Tables (`portfolio` schema, migration, grants):** `holdings` (id, account_id, bucket_id, instrument_id nullable, exchange, security_id, isin, trading_symbol, name, qty, avg_cost, last_price, last_price_at, status `open|closed`, first_seen_at, closed_at, synced_at); `holding_lots` (id, holding_id, acquired_on date, qty, unit_cost, source `import|added|manual`, uses_default_date bool, closed_on, close_price, close_qty-style columns for FIFO partial closes, estimated bool); `holding_syncs` (id, account_id, trigger `manual|auto|import`, started_at, finished_at, status `succeeded|failed|skipped`, counts new/increased/decreased/closed/unchanged, error, requested_by); account settings (extend `portfolio_settings`): `refresh_mode` (`off|interval|daily`), `refresh_interval_minutes` (5|15|30|60), `refresh_daily_time_ist`.
2. **Import (explicit, first time per account; also usable to add missing holdings later):** `POST /api/accounts/{id}/holdings/preview` → fetches from Dhan without saving → `{rows:[{key (isin or securityId+exchange), symbol, name, exchange, qty, avgCost, lastPrice, mapped (instrument id/canonical symbol or null), alreadyImported, suggestedDate}], defaultDate}`; `defaultDate` = 2025-01-01 when the account has no holdings, otherwise today (IST). `POST /api/accounts/{id}/holdings/import {defaultDate, rows:[{key, acquiredOn?}]}` re-fetches inside one transaction (stateless — no stale preview), creates holdings + one lot each (date = the row's `acquiredOn` else `defaultDate`; marked `uses_default_date` when it came from the default), bucket = the account's default bucket (or the account's chosen default), skips unknown keys, returns counts. Dates validated (not in the future, not before 1990-01-01).
3. **Sync rules (manual "Sync now" and automatic), same command:** fetch; for each Dhan row: *new* → holding + lot dated **today IST** (`source added`, not default-date); *qty increased* → add a lot dated today, unit cost = max(0, (newQty×newAvg − oldQty×oldAvg) / Δqty), falling back to the last price when not positive; *qty decreased* → close lots FIFO for Δqty at the last price, `estimated = true`; *unchanged* → update last price/time; *missing* → close FIFO as above, holding `closed`. Average cost and quantity always equal Dhan after a sync. Idempotent (re-running with the same data changes nothing but prices/time). Everything in one transaction per account; failure leaves data untouched and records the run. Holdings that do not map to the instrument master are kept and flagged (`mapped=false`).
4. **Per-lot date edit:** `PUT /api/holdings/{id}/lots/{lotId} {acquiredOn}` (validated; clears `uses_default_date`; recalculation is automatic because returns are computed on read), `GET /api/holdings/{id}/lots`.
5. **Auto refresh:** `PUT /api/accounts/{id}/portfolio` gains `refreshMode`, `refreshIntervalMinutes`, `refreshDailyTimeIst` (validated: interval one of 5/15/30/60; daily time HH:mm); a hosted service in `xd-api` (thin; calls the same sync command through the handler) evaluates each Portfolio-role account every minute with a fake-clock-testable schedule (market hours Mon–Fri 09:15–15:30 IST for `interval`, one catch-up run after the daily time if missed that day); skips accounts that are not connected (records at most one `skipped` run per day), never overlaps runs for an account (advisory lock + unique "running" row), manual runs allowed anytime. `GET /api/accounts/{id}/holdings/sync-status` → last run, next scheduled run, mode. Default for a new account: **off** (the owner turns it on).
6. **API:** `GET /api/holdings?accountId&bucketId&status&q&page&pageSize&sort` (rows with lots summary: lotCount, earliestAcquiredOn, usesDefaultDate flag; returns fields come with P2-05), `GET /api/holdings/summary?accountId`; all session-protected, no step-up (reading/syncing public portfolio data); import/sync/date edits audited in `accounts.account_events` (counts only, no secrets).
7. **Security/limits:** no token or Dhan raw payload is logged or returned; response bodies capped (5 MB), 30 s timeout, no redirects; allow-list test proves only `/v2/holdings` is added; instruments mapped by ISIN (preferred) then `securityId`+exchange segment.
8. **Docs:** 12 §3 rewritten (owner-set dates, rules, auto refresh), 04 §1 (portfolio settings), 16, 17 (allow-list), P1-16e's note text in the UI/doc replaced (the UI work is in the frontend step).

## Acceptance criteria
1. Preview returns Dhan's holdings without saving; import creates holdings + lots with the chosen/default dates (default 2025-01-01 when the account is empty, today otherwise), flags default-date lots, rejects future/ancient dates, is atomic and idempotent per key.
2. Sync rules verified by tests: new holding → today; increase → new lot at implied cost (and fallback); decrease → FIFO closes with `estimated`; missing → closed; unchanged → prices only; a second identical run changes nothing; failure rolls back and records the run.
3. Auto refresh: off by default; interval mode only runs inside market hours (Mon–Fri 09:15–15:30 IST) at the configured spacing; daily mode runs once after the configured time and catches up once if missed; skips not-connected accounts with one skipped record per day; never overlaps; fake-clock tests for all (IST edge cases).
4. Holdings that cannot be mapped to the master are kept and flagged; mapping prefers ISIN.
5. Allow-list, no-leak (marker scan of responses/logs/audit), access matrix (401), grants for `xd_app`; contract regenerated; migration added; docs updated; `scripts/check.sh` green; reviewer no blockers/majors; a real import against the owner's Dhan account verified by the owner.
