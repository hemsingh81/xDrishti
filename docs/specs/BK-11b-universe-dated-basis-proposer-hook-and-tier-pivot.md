- **Size:** 3 agent-days (dated replay and structured fields 1.2, proposer hook and auto option 0.8, tier pivot 0.6, tests 0.4)
- **Safety:** no for trading. Nothing is selected, sized or ordered differently. A universe restriction stays a **proposed hypothesis**; this slice applies nothing, changes no scan scope and runs no experiment from it. The automatic proposer is OFF by default and records `auto`.

## Goal
A simulation on a basket with dated membership replays each day with that day's members and says so in structured fields; a stable tier observation can become one proposed hypothesis by the owner's act (or the auto option); and the reports can pivot by liquidity tier.

## Scope
**In:** (1) basis `dated` in the simulator (`members(asOf = day)` per replayed day) as a request option, with the structured record `SimulationRun.UniverseBasis` and a run-key line only when used; (2) a proposer hook from a `universe-links` observation to one hypothesis; (3) the `universe` report dimension with a per-trade tier computed by the BK-11 tagger; tests; ADR.
**Out:** applying a restriction, changing a scan scope, running a `scope` hypothesis (the experiment runner refuses it with the reason until a later slice); changing the tier definition (owner Q1 of ADR 0261 stays open); CF-02 shrinkage for tier cells (Q2); new stored columns on `sim_trades`; changing existing run keys, records or SimExport goldens.

## Acceptance criteria
### AC 8 — dated basis and structured fields
1. **Unchanged by default.** Given a simulation request without `membersBasis` (every existing caller), the run key, the stored run record and every SimExport golden (`tests/XDrishti.SimExport.Tests`) are byte-identical to today; the label stays `UniverseLabels.Basket(...)`.
2. **Dated replay.** Given `membersBasis: dated` (CLI `xd simulate --basket <id> --members dated`, Lab picker option) on a basket with dated membership (BK-01/03/05 rows with `valid_from`/`valid_to`; at least two membership days, the ADR 0263 rule), then for each replayed day D the engine takes only the instruments in `MembersAsync(basketId, null, asOf: D)`; an instrument enters on its first member day and its open position is closed by the normal exit rules, never force-closed by leaving (stated; a leaver keeps no new entries). By hand: members {A,B} until 2026-03-31, {A,C} from 2026-04-01; a signal of B on 2026-04-02 is not taken, a signal of C on 2026-03-30 is not taken, both are taken on their member days.
3. **Fallback is stated, never silent.** Given `dated` on a basket without dated membership for the window start, the run is refused 422 `simulation.members_not_dated` with the first dated day; the owner can rerun with `single_snapshot`. No run is ever labelled `dated` with today's members.
4. **Structured fields.** A run with `membersBasis` stores `SimulationRun.UniverseBasis = { universe_basket_id, universe_params_hash (null for manual and index baskets; for a derived basket the `params_hash` of the version in force at the window start), members_as_of (the run date for `single_snapshot`, null for `dated`), universe_basis ('dated'|'single_snapshot'), member_days_hash (SHA-256 of the ordered (day, instrument) pairs used, `dated` only) }`, readable from `GET /api/lab/runs/{key}` and the run export, not only as label text; the label for `dated` is "members as of each day (dated); basket <id>; params <hash or ->".
5. **Run key line only when used.** Such a run adds one key line `umembers` = basis | member_days_hash (or members_as_of) | params hash, as `rstrength` does (ADR 0263); two dated runs over different membership histories are different runs; the key never depends on the owner's mutable settings (the registered list is not in it, ADR 0261 point 9).
6. **Never called point in time unless dated.** Every view (Lab run, report header, export) prints "single snapshot, survivorship applies" for `single_snapshot` and "point in time (dated members)" only for `dated`; a test scans the view models for the phrase "point in time" on a `single_snapshot` run.
7. **Trials.** A dated run on a basket is a ledger row like any other (ADR 0207); a different basis changes the plan hash, so it is a `replan` row and counts; `GET /api/lab/strategies/{id}/universe-trials` counts (basket, basis) distinct; a repeat counts once.

### AC 11 — proposer hook
8. **From an observation only.** `xd learn hypothesis propose --from-universe-link <tierCellKey> --baseline <runKey> --reason <text>` (owner, CLI, as the other proposals) and `POST /api/cells/universe-links/{key}/propose` (session, CSRF token, fresh password, P8-19 owner act, account event `HypothesisProposed`) create one hypothesis only when the link's stored row has `observation` true (tier read in place of the parent, ≥ `learning.universe_link_min_trades` trades, `universe_verdict` stable). Otherwise 422 `learning.not_an_observation` with the reason (thin, not read, hold-out insufficient or unstable).
9. **One knob, one cell, nothing applied.** The hypothesis has source `universe` (8 characters; the column check is widened in the migration if it lists values: UNVERIFIED), cell = the `*` parent cell key, knob `scan_scope` of new kind `ExperimentKnobKind.Scope`, baseline `*`, candidate the tier (`liq_high` etc.), rationale "ORB, 15m: stronger on liq_high (lower bound 0.53 vs 0.44, n 30/200; hold-out stable)" from the stored numbers; state `proposed`; the open limit (`HypothesisLifecycle.ProposalRefusals`) applies. A second proposal for the same (cell, tier) while one is open is 409 `learning.hypothesis_exists`. Starting an experiment for a `Scope` knob is refused 422 `learning.knob_not_runnable` ("a scope experiment is not built"); accepting it records a verdict only.
10. **Auto option, default OFF.** `learning.universe_link.auto_propose` (`Stored`, Advanced, safer direction `none`, not learnable; no row = OFF), changed only by `PUT /api/universe/settings` with a fresh password (the existing BK-11 settings path, `research.universe_settings_changes`). When ON, `xd learn cells --by-universe` proposes each new observation as actor `auto`, with the setting row id and hash in the rationale record; never recorded as the owner; the open limit still applies; an observation whose inputs are `unavailable` or `insufficient` is never proposed. When OFF nothing is proposed automatically.

### AC 12 — tier pivot
11. **The dimension is available when tiers exist.** `groups?lens=universe` and the pivot builder accept `universe` when the tier source has a tier table for the report's trades; each trade's tier is computed with `UniverseTagger.TagAsync` from sessions strictly before the trade's decision date (the same date and function the cell statistics use, so a trade's report tier equals its cell tier: a test asserts this on the fixture). Buckets: `liq_high`, `liq_mid`, `liq_low`, `unknown`, `unavailable` (the last two always shown with counts). Which `ReportTrade` field is the decision date (`EntryDate` or a stored signal date) is UNVERIFIED; the build uses the field the cell statistics' `TradeDate` comes from.
12. **Refused with the reason otherwise.** With no tier source or fewer than 30 eligible shares on every date, 422 `reports.dimension_unavailable` with the reason "no liquidity tier for these trades" (the current refusal text is replaced by this case only); `Regime` and `Account` keep their refusals.
13. **Masking and fence.** Buckets under 30 trades are masked by the server as everywhere in P8; only research runs are tagged (ADR 0243); a training-run report (ADR 0250) refuses `universe` with the reason.
14. **No look-ahead (property).** Appending sessions after a trade's decision date changes no trade's report tier (truncation test, as BK-11 AC 4).
15. **Regression and performance.** Every report without `universe` returns the same JSON as today; tagging 20,000 report trades under 2 s (BK-11 AC 14 budget).

## Contract
- **Domain:** `UniverseBasisRecord` (the fields of AC 4); `UniverseLabels.Dated(basketId, paramsHash)`; `RunAssembler` line `umembers`; `DatedMembers.On(day)` (pure lookup over member intervals); `ExperimentKnobKind.Scope`; `HypothesisSource.Universe`; `ReportDimension.Universe` bucketed from a tier map.
- **Application:** `SimulationRequest.MembersBasis` (null | `dated` | `single_snapshot`); `ResolveUniverseAsync` reads intervals once (`IBasketQueries` member history; the exact reader UNVERIFIED, BK-01 `membersKnownSince`); `ProposeFromUniverseLinkCommand/Handler` building `ProposeHypothesisCommand`; the report handler gets a tier map from `IUniverseSeriesSource` + `UniverseTagger` when the lens is asked.
- **Data:** migration `AddUniverseBasisAndScopeKnob` with `Down`: nullable `universe_basis_json` on the run header table (or the record JSON if the run record already stores structured blocks as `RelativeStrength` is: UNVERIFIED which; prefer the record, no column) and the hypothesis `source`/`knob_kind` check widened if such checks exist. No change to `sim_trades`.
- **API:** simulation and Lab run requests gain optional `membersBasis`; `simulation.members_not_dated` 422; `POST /api/cells/universe-links/{key}/propose`; `learning.not_an_observation` 422, `learning.hypothesis_exists` 409, `learning.knob_not_runnable` 422; `universe` lens in reports. `scripts/gen-api.sh`.
- **UI:** Lab run form "Members: as of the run date | dated (point in time)" (disabled with the reason when the basket has no dated rows); Setups universe-links row "Propose as hypothesis" (owner-act dialog with password); pivot builder `universe` entry. Match the prototype's Lab and Learning screens.
- **Events/jobs:** none new; the auto proposer runs inside `xd learn cells --by-universe`. Log: dated run (basket, days, members), proposals made (count, actor kind).

## Non-functional
A dated run reads member intervals once per run (no per-day query); memory stays within the simulator's per-instrument budget. Security: owner acts as above; no password in logs.

## Test plan
- **Unit:** `DatedMembers.On` with the AC 2 hand case; label and key line; `Scope` knob refusal paths; tier bucketing.
- **Golden:** every existing SimExport golden and run-key test unchanged (AC 1).
- **Application (fakes):** refusal of `dated` without dated rows; the proposer refuses a non-observation and a duplicate; auto ON/OFF and the `auto` actor; report tier equals cell tier.
- **Integration (Testcontainers):** a dated basket replayed end to end; the propose endpoint with and without the password; the universe pivot with masking.
- **Properties:** truncation (AC 14); a dated run with constant membership gives the same trades as `single_snapshot` on the same members.
- **Architecture:** no type of this slice changes a strategy's scan scope, a cell state or selection; no order-named member.
