## Goal
One scan of a built-in strategy over a window, then every candidate exit the owner names walked over the **same entries and the same minutes**, one result per candidate and a table that puts them side by side; plus the MAE/MFE table of doc 08 §3 that says whether the stop, the target and the trail activation are sound. The owner can run it from the existing verb and open the table, the per-candidate trades and the per-policy cards. Like all of P3 and P4, this says the mechanics are right; it does not say that any strategy has an edge.

## What the code does today (read 2026-10-22)
- `Simulator.Create(definition, timeframe, fills)` accepts exactly **one** exit set per side (one candidate of the seven, one value in each list, at most `time_stop`) and refuses two candidates or a list of two values by name (`simulation.unsupported_exit`, `Simulator.RefuseWhatItCannotRun`; UNVERIFIED line, read from `SimulatorCodes` and the `Create` body). `Simulator.Run` scans a side once (`EntryScanner`) and walks each candidate with `TradeWalker.Walk(candidate, bars, rules, exitContext)`; the swing path passes the candidates through `PositionGate.Apply`.
- `ExitTape` is built from a feature list (`new ExitTape(features)`), so a tape holding the union of the features of several exit sets is possible in principle (UNVERIFIED that the scanner can be given a union; it takes the columns from one compiled side today).
- **No verb can choose an exit.** `simulate` and `verify-pack` take `--strategy <built-in id>` and `--param name=value`; `BuiltInStrategies.Table` builds each definition with a fixed exit: `OrbV1`, `VwapPullback` and `BaseBreakoutV1` each write `[new ExitSpec(ExitPolicy.FixedRr, [rr])]`, and the only exit knob a verb has is the `rr` parameter. `ISimulationEngine.Prepare(strategyId, parameters, timeframe, fills)` has no exits argument. So ADR 0050 to 0052 ran every new policy through `Simulator.Run`, the replay and the exporter in tests only. This spec must close that gap (D1).
- `SimTrade` is schema 5 (`Legs` last, null for a one-fill trade); `SimulationEngine.Version` is `sim-6`; the run record is schema 6; export format `xd-sim-export-3`. The result store (`research.sim_runs`, `research.sim_trades`, ADR 0045) has **no column for legs**, so `simulate --store` refuses a run that has a trade with legs (ADR 0049 decision 9, ADR 0050). Both exit-reason migrations (`AddTimeStopExitReason`, `AddEmaExitReason`) exist in `XDrishti.Infrastructure/Migrations`, so the enum already round-trips.

## Definitions
Notation as P4-02 to P4-04. A *candidate* and a *cell* are P4-00 D2's; the cell's regime is `*`. A *comparison* is one run of one strategy, window, timeframe, fill rules and cost choice with N ≥ 1 candidates.

**D1. Choosing an exit from a verb.**
- `--exit <spec>`, repeatable, `spec = POLICY[:name=value[,name=value…]]` with the policy named as in doc 08 (`FIXED_RR`, `PARTIAL_BE`, `PARTIAL_TRAIL`, `ATR_TRAIL`, `STRUCTURE_TRAIL`, `EMA_TRAIL`, `PYRAMID`) and the parameter names of the model tables (P3-02b2). A list parameter is written `name=1.5|2|2.5` and expands to one candidate per value (P4-00 D2); a `PYRAMID` ladder is the policy's own shape and is written `add_at_rr=1|2` and **is not** expanded (P4-04 D1). Example: `--exit FIXED_RR:rr=1.5|2|2.5 --exit PARTIAL_BE:book_pct=50,t1_rr=1,t2_rr=2|3`.
- `--time-stop min_progress_rr=0.5,intraday_bars=6` (or `swing_sessions=2`) is the overlay, applied to every candidate (doc 16 `exits.overlays`); `event_exit` stays refused by name.
- **No `--exit`: today's behaviour byte for byte** (the built-in's own `FIXED_RR` from `--param rr`). With **one** candidate the verb runs the ordinary single-exit run with that exit in place of the built-in's (the exits of a built-in are replaced; its entry, stop and time rules are not). With **two or more** the verb runs the comparison.
- The `rr` parameter and `--exit FIXED_RR:rr=…` together are refused by name (usage error, exit 2): two sources for one value.
- Behind it: `ISimulationEngine.Prepare` gains an optional `ExitChoice?` (a Domain value: the candidates, as the model's `ExitSpec` list, and the overlay); a built-in definition is produced by `BuiltInStrategies` with its `exits` and `overlays` replaced. The stop, the entry and the time rules are untouched, which is what makes the entries the same (D3). The port change is the one ADR 0037 and the port's own comment foretell; the shape still gives way to stored strategies (P3-02d). UNVERIFIED: the number of callers of `Prepare` and of `BuiltInStrategies.Create`; the hash that keys a run (the run key) must include the exit choice, which the run key's current inputs may not (UNVERIFIED; a run with and without `--exit` must never share a key).

**D2. One scan, N walks.** A new entry point on `Simulator` (name UNVERIFIED, e.g. `CreateComparison`) takes a definition whose `exits` list holds N expanded candidates, checks each with the refusals of `RefuseWhatItCannotRun` (a candidate it cannot run is refused by name with the index of the candidate in its path), and holds one compiled side. `Run` scans each side once, with an exit tape of the **union** of the features the candidates read, then walks every `EntryCandidate` once per candidate with that candidate's `IExitRule`. `Simulator.Create` is unchanged for a plain run, so the refusals of P4-02 to P4-04 stand and their tests are untouched. The scan cost is paid once; N walks are N times the walk cost (target of P4-00: N = 8 within about 3 times one run; UNVERIFIED, no timed P3 run exists yet).

**D3. Same entries (P4-00 D3, criterion 2).** For intraday strategies every candidate walks the **identical** list of `EntryCandidate`s and every pair of trades with the same `trade_key` is identical in every field of the entry (instant, price, fill, stop, quantity inputs, trigger bar); candidates differ only in exit fields (`ExitReason`, exit instant and price, legs, target, R fields, MAE, MFE, costs). The `trade_key` is the key the store already has; a test pins that it does not depend on the exit.

**D4. The gate and the common set (swing).** The position gate holds an instrument until the last leg, so a candidate that exits earlier frees the instrument earlier and **admits entries that a slower candidate had to skip**. The entries then differ between candidates and a difference of means is not a difference of exit only. Recommended (question 2):
- the **comparison walk is ungated**: every candidate walks every entry, overlaps allowed, the same `EntryCandidate` list as D3, and the table says "gate not applied in the comparison; an overlap is a limit named in the banner";
- each candidate additionally reports the number of entries that the gate would have skipped for it (the gated count, from the `PositionGate` run that today's path makes), so the owner sees the cost of the overlap;
- a single-exit run (D1) is gated as today.
Intraday strategies are not gated (a trade leaves on its entry date) and are unaffected.

**D5. The common set for paired figures.** A trade of one candidate can be skipped for quantity or cost (`SkippedQuantity`, `SkippedCost`) while the same entry is taken under another (the charge depends on the exit orders). The **common set** is the entries taken under every candidate. Every comparison figure is printed twice: on each candidate's own trades, and on the common set (the paired comparison; the difference of a candidate from the first candidate on each common entry, with its count). Entries that are not common are listed by count per candidate.

**D6. The comparison table.** Per candidate: id (`FIXED_RR{rr=2}`, a stable spelling of policy and values, plus `+time_stop` when the overlay is on), trades, wins, win rate, mean R, median R, downside deviation, total R, profit factor if defined, average hold, share by `ExitReason`, the counters of the policy (`PartialsTaken`, `StopLoosenIgnored`, `AddsTaken` …, all existing), cost figures if costed (mean `CostR`, mean `RNet`). The unit is `RFilled` for a gross run and `RNet` for a costed run, labelled which. **Downside deviation** is `sqrt(mean(min(R, 0)²))` over the same trades, target 0 (UNVERIFIED: doc 08 and 16 name `downside_dev_R` but do not define it; question 5). Open-at-end trades are not in the statistics, as in the store (ADR 0045 D1). The table is in the run record, in `comparison.csv`, and printed by the verb.

**D7. The MAE/MFE diagnostics (doc 08 §3).** Per candidate and per cell, from the trades of the comparison:
1. the share of winners whose adverse excursion before their best point exceeded 0.8R and 1.2R (stop soundness);
2. the median MFE, and the share of trades whose MFE reached 1R, 2R and 3R (target soundness);
3. the **giveback**: for trades with MFE ≥ 1R, the median of `MFE − RExact`, and the share that gave back more than half of their MFE (trail activation).
A *winner* is a trade with `RExact > 0` (question 4). Counts per cell, the cell being the run (one strategy, timeframe, side, style, regime `*`). Printed to the printed precision with their sample sizes; a cell below 30 trades is printed with "n < 30" and no reading sentence.

**D8. Censoring, said out loud.** Excursions are measured on the path the **walk** took, so they are censored by the walk's own exit: under `FIXED_RR` with a target at 2R no trade shows an MFE above 2R, so "the share reaching 3R" is 0 by construction; and a stop at 1R ends the trade at 1R of adverse excursion, so "winners dip beyond 1.2R" cannot be seen with that stop. The table therefore prints, beside each figure, the **censor level** (the target in R, the stop in R, or "none" for a trail) and refuses a reading sentence for a figure beyond it. Optional diagnostic walk (question 3, recommended): `--diagnose` adds one extra walk per entry that is **not a candidate**: the same entry and the same initial stop distance `R0`, **no target**, exit at the stop widened to `diag_stop_r × R0` (default 2.0; the entry quantity and R stay in the unit of the real stop's `R0`) or at the square-off/`MAX_HOLD`, gross, recorded in its own table "diagnostic walk (not a candidate; not costed)". It exists only to read the uncensored tail of MFE and the adverse excursion beyond 1R; it is never selected, stored as a candidate or fed to P4-06.

**D9. Storing legs.** `research.sim_trades` gains the legs of a trade. Recommended (question 6): a child table `research.sim_trade_legs (run_id, open_at_end, ordinal, leg_ordinal, kind, reason, at, price, filled_price, share, quantity, charge…)` — one row per leg, insert-only like its parent (ADR 0045 D7: `MakeAppendOnlyForAppRole`, grants per table, the standing test `ResearchGrantsTests` extended), foreign key to `sim_trades` without cascade. Migration `AddSimTradeLegs`. The columns follow the `Leg` and `LegCharges` records (UNVERIFIED: their exact members; a test compares the column list with the properties, as `TradeColumns` does for `SimTrade`). `simulate --store` stops refusing a run with legs. The read side (`IRunStore` reads) returns the legs.

**D10. Storing a comparison.** A comparison is stored as **one ordinary run per candidate** (each a normal `sim_runs` row with its own run key, which includes the exit choice, D1) plus one row in a new `research.sim_comparisons (id, entries_key, created_at, member run ids/candidate ids, diagnostics text, record_sha256)` that names the members and the common-set counts. The `entries_key` is the hash of strategy, parameters, window, timeframe, universe, fill rules and engine version — everything but the exit — so that two runs with the same `entries_key` are comparable by the join on `trade_key` (ADR 0045 D2). Idempotent on the same key, insert-only, a conflict is `store.run_conflict` as for a run. Migration `AddSimComparisons`. Rejected: one run holding N candidates' trades (it changes the primary key `(run_id, open_at_end, ordinal)` and every reader).

**D11. Records and versions.** Run record schema **7** with a `comparison` block (the candidates, the table of D6, the common-set counts, the diagnostics of D7, the optional diagnostic table of D8) null for a single-exit run; export format `xd-sim-export-4` with `comparison.csv` and `trades-<candidate-id>.csv` (the first candidate's file keeps the name `trades.csv`; UNVERIFIED which spelling the folder writer prefers); `SimTrade` stays schema 5; **`SimulationEngine.Version` stays `sim-6`** because no walk rule changes (a test: every candidate's trades equal the trades of the same candidate run alone, D12 property). The banner of a comparison gains: "candidates compared on the same entries; the best row is in-sample on the data shown and is not evidence of an edge (P4-00 criterion 9)", "gate not applied in the comparison (swing)" and the censor lines of D8. No number from a real-data comparison is quoted outside its run folder before the hand check of P4-00 question 4 for these policies (the owner's decision; unchanged here).

**D12. Properties and oracle.** (a) **Alone equals together:** over seeded series, for each of the seven policies, a candidate walked inside a comparison of N candidates produces trades equal in every field to the same candidate run alone through `Simulator.Create` (no leakage between candidates, independent of order). (b) **Order independence:** permuting the candidates permutes only the order of the results. (c) **Same entries (D3).** (d) **Common set** is symmetric and equal to the intersection computed by the oracle. (e) **Look-ahead** (P4-00 D9) holds with a union tape: a candidate does not read a feature that only another candidate asked for (a test with a tape column no candidate of it reads). (f) The oracle gets the comparison arithmetic (D5, D6, D7) from this text only and agrees on a seeded fixture; the walk rules are already covered by the oracles of P4-01 to P4-04. No new leak property for the walk, with a negative control for (a): a deliberately shared-state rule must fail it.

## Acceptance criteria
1. **Today's runs do not move.** Without `--exit`, every run, golden, banner and stored byte of P4-04 is unchanged except the new schema/format version lines.
2. **A verb chooses an exit (D1).** `simulate --strategy ORB … --exit PARTIAL_BE:…` and every one of the seven policies run end to end on a seeded fixture (single-exit run); `--exit FIXED_RR:rr=1.5|2|2.5` makes three candidates; `--time-stop` applies to all; the refusals (unknown policy or parameter, a list on a parameter that is not a candidate list, `rr` together with `--exit`, `event_exit`, two candidates of one policy with identical values) are usage errors that name the flag and the value, exit 2.
3. **Same entries (P4-00 criterion 2).** On a seeded series, two candidates' trades with equal `trade_key` are equal in every entry field and differ only in exit fields; the keys are equal sets (intraday), and for swing the candidate walks are ungated (D4) with the gated counts printed.
4. **Alone equals together (D12a, b)** over at least 5,000 seeded series per policy, negative control failing.
5. **The table (P4-00 criterion 6).** On a seeded fixture the comparison table (trades, wins, win rate, mean R, downside deviation, plus the common-set figures) equals a **hand-computed** table to the printed precision, for gross and for a costed run with a TEST sheet; for one real-data run with `--gross` the owner can open `comparison.csv`, the per-candidate trades and a per-policy card.
6. **The diagnostics (P4-00 criterion 7).** On a seeded fixture the share of winners with adverse excursion beyond 0.8R and 1.2R, the median MFE and the shares reaching 2R and 3R equal hand-computed values, and the censor levels are printed; a figure beyond a censor level carries no reading sentence; with `--diagnose` the uncensored tail is printed in its own labelled table.
7. **Legs are stored (D9).** A run with partials, a trail and a pyramid round-trips through `--store` and the read handlers with its legs equal in every field; the child table is insert-only for `xd_app` (extended `ResearchGrantsTests`); the migration `Down` is tested in a transaction as in ADR 0045 D9.
8. **A comparison is stored (D10).** The same comparison again is `already stored`; a different record under the same key is `store.run_conflict`; the members join on `trade_key`; the entries key excludes the exit and includes everything else (a test changes each input in turn).
9. **Versions (D11).** The engine line, the schema versions and the banner lines of a comparison are as written; the engine stays `sim-6`; the oracle's claim line is unchanged.
10. **Performance.** The `FIXED_RR` single-run path stays within 5 % of its P4-04 throughput (the explicit benchmark of ADR 0051, run by hand on a quiet machine); a comparison of 8 candidates over a seeded fixture costs one scan plus 8 walks (a test counts scanner steps: the scan runs once).
11. `scripts/check.sh` green; a `reviewer` pass with no blocker or major; ADR 0053 and the docs (08 §2 and §3, 09 §1, 11, 16 `exits`, 18-roadmap, the oracle log, `docs/engineering` if a rule is added) done and `scripts/build-docs.sh` run.

## Non-functional
One scan for N candidates; the union tape holds only the features some candidate reads; a walk allocates no more per minute than today (explicit benchmark kept). A comparison of 8 candidates over 214 instruments targets about 3 times one P3 run (UNVERIFIED; no timed P3 run). Deterministic bytes by seed. No secret, no network; no new data leaves the machine. Logs: counts and ids, never a trade or a record text (ADR 0045 D10).

## Test plan
Unit: the flag parser (every refusal, expansion of lists, ladders not expanded), the port and the definition built from a choice, the entries key, the common set, the comparison statistics, downside deviation, the diagnostics and their censoring, the union tape. Property: D12 (a) to (e), each with a negative control. Oracle: D12 (f). Integration (Testcontainers, as P3-04b2 and P3-10): the verbs end to end with each policy; store and read legs; store a comparison, idempotency and conflict; grants; migration up and down. Hand tables: the comparison table and the diagnostics (AC 5, 6), written before the code. Edge cases: one candidate; two identical candidates (refused); a candidate that makes no trade; a candidate whose trades are all open-at-end; a swing overlap (a trade open when the next entry fires); an entry skipped for cost under one exit only; a cell below 30 trades.

## Open questions (for the owner; each with a recommendation)
1. **The verb surface (D1).** `--exit POLICY:name=value` (repeatable, `|` for candidate lists) on the existing verbs, or a new `compare` verb? Recommended: the flags on `simulate`/`verify-pack`; a verb that does one thing per run keeps the usage text and the exit codes, and a single `--exit` is useful on its own (it is the first way to run a partial or a pyramid from the command line at all).
2. **The gate in a swing comparison (D4).** Ungated (every candidate sees every entry, overlaps allowed, gated counts printed) or gated (each candidate trades as it could, entries differ)? Recommended: ungated for the comparison, gated for a single run; it keeps "same entries" true and the paired figures meaningful, at the price of a named limit that overstates the number of simultaneous positions.
3. **The diagnostic walk (D8).** Add `--diagnose` (no target, stop at `diag_stop_r × R0`, default 2.0, gross, not a candidate) in this slice, or print censored figures only? Recommended: add it, as the optional last cut; without it two of the three questions of doc 08 §3 ("do winners dip 1.2R", "what share reaches 3R") cannot be answered from a `FIXED_RR` run at all.
4. **The definition of a winner (D7).** `RExact > 0` on the candidate's own trade, or "reached +1R before the stop" on the diagnostic walk? Recommended: `RExact > 0` for the table of a candidate, and "MFE ≥ 1R before the stop" on the diagnostic walk; both are printed with their names.
5. **Downside deviation (D6).** `sqrt(mean(min(R, 0)²))` with target 0 over all trades of the sample (a standard semi-deviation), on `RNet` when costed and `RFilled` otherwise. Recommended: yes; the docs name the term but never define it, so the definition goes into doc 08 and ADR 0053 and P4-06 reuses it.
6. **Where legs are stored (D9).** A child table, a `jsonb` column on `sim_trades`, or flat columns for up to 11 legs? Recommended: the child table (queryable, no width limit, `jsonb` would lose the number spelling that the digests need, ADR 0045 D1); the cost is one more insert-only table and one more join on reads.
7. **How a comparison is stored (D10).** One run per candidate plus a `sim_comparisons` header, or leave comparisons unstored for now and let P4-06 compute in memory? Recommended: store, with `--store`; P4-06 needs a stable thing to name its input by, and the join on `trade_key` is why ADR 0045 kept the unique key. The alternative saves a migration and loses the audit copy.
8. **The size of a comparison run.** Eight candidates over 214 instruments is roughly eight times the rows of one P3 run in the store (a 200,000-trade run was 132 MiB, ADR 0045). Recommended: accept; keep every run (ADR 0045 D8), re-check the 2 GB trigger of D3 there after the first real comparison. Your disk headroom is UNVERIFIED.
9. **Engine version.** Keep `sim-6` because no walk rule changes (D11)? Recommended: yes; bump only if the property D12a finds a difference, and then it is a bug to fix, not a version.
10. **Approval order.** P4-06 reads what this slice stores. Recommended: approve P4-05 first; P4-06 is written to depend on D1, D9 and D10 as proposed here, and must be re-read if any of them changes.
