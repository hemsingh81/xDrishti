## Spike (0.5 d, 2026-10-24; read from the code and checked by the tests below)
Where the facts a report needs live, found before any endpoint was written:
1. **Trades.** `research.sim_trades` holds one row per trade: the signal key (`trade_key` = `strategy|symbol|side|decision date`), strategy, trigger timeframe, side, instrument, symbol, `trade_date` (India date of the entry), `exit_epoch_seconds` (the India exit date is `SessionClock.DateOf` of it), `r_filled` (gross R from the filled prices; what `CellSourceReader` uses), `r_net` (null for a gross trade), `sessions_held`, `basket_ids` (uuid array) and `open_at_end` (closed trades are `false`; a report counts only those). The reader pattern of P3-10 (`RunStore.StreamTradesAsync`) is a plain Npgsql reader with no change tracker; the report reader is the same with fewer columns and several runs.
2. **Runs.** `research.sim_runs` holds, as typed columns, the run key, strategy, window (`from_date`, `to_date`), `universe_kind` (`instrumentlist` or `basket`) and `universe_label`, instrument counts, `trade_count` (closed), `open_at_end_count`, `costs_sheet_id` (null = gross: **the costed flag**), `created_at`. It stores **no basket id, no style and no exit**.
3. **Basket.** `basket_ids` on a trade is filled from the universe of the run: **none for an explicit list of instruments, the one basket for a basket run** (`RunTrade` doc, `RunAssembler`). So the first stored trade of a basket run names the basket of the run, which is how the universe of a basket run is told apart (`basket:<id>`); a list run is `list:<label>:<instruments>:<ran>` (the header does not keep the members, so two lists of equal size and label are not told apart: a limit, stated in the ADR). The column is an array, so a trade in two baskets is storable and the engine groups it under each; the writer of today puts at most one. Two basket runs of one strategy over baskets that share an instrument hold the same signal and the population rule refuses them (P8-05): to compare overlapping baskets the owner names runs that do not overlap in signals.
4. **Style.** Not a run column: it is the **stored strategy's style** (`lab.strategies.style`, `intraday` or `swing`), joined by the run's strategy id. Null when the strategy is not stored.
5. **Exit.** Not a column of a trade or of a run: it exists only as the **candidate id** (`FIXED_RR{rr=2}`) of a run that is a member of a stored comparison (`research.sim_comparisons.member_run_keys` with `member_candidate_ids`). A run in none is `not recorded`; a run in comparisons that name different candidates is `not recorded` too (never a guess). This is the "comparison row" source of P8-00 D5. Source printed on the run: `stored strategy`, `stored comparison <key>`.
6. **Windows.** `from_date` and `to_date`, inclusive, feed the engine's overlap rule.
7. **Charge sheet confirmation.** There is **no stored owner confirmation of the charge sheet** today (the sheet is `platform.app_settings` key `research.cost_sheet.<id>`; its optional `checked` text is a bill check, not the owner's confirmation). P8-06 reads one settings row `reports.charge_sheet_confirmation` = `{"sheet_id","rates_sha256","confirmed_on"}` (the hash of the rates, because the cost sheet store overwrites a sheet in place: a confirmation of a name would cover other rates) and nothing writes it in this slice: the owner's act of confirming (a verb in the pattern of `cost-sheet`) is a later, separate decision. Until it exists every report is gross and net is `unavailable` with the reason. A confirmation naming a sheet that is not stored, malformed, without a rates hash, or whose hash is no longer the stored sheet's counts as not confirmed; a net report needs runs whose stored sheet id and rates hash (`costs_rates_sha256`) are the confirmed ones and never covers an empty run set.
8. **Size.** Not known on the owner's database (not queried); measured on a synthetic run in the ADR.

## Goal
The stored simulation runs become readable over HTTP, honestly: the runs a report may use, the headline figures, groups, pivot, equity and drawdown, R distribution, auto-insights, "what works" and the closed trades, all from one query model, every answer with its evidence block and the six states, none of them able to print a number for a non-value, to double-count a trade or to call a report net on a caller's say-so.

## Scope
**In:** the port `IReportTradeSource` (+ `IChargeSheetConfirmationSource`) in `Application/Abstractions/Reporting`; the Infrastructure reader `ReportTradeSource` (streamed projection, no change tracker, filters as parameters) and `ChargeSheetConfirmationStore`; `Application/Reporting` (the query model `ReportQuery` with its whitelist, the default run set, the loader, nine query handlers, the wire views, two log events); `Domain/Reporting` additions the endpoints need (equity and drawdown series, R distribution, a slice of the trade list; a faster population build); `ReportsEndpoints` (GET only); the contract and the typed client; tests; ADR 0100.
**Out (not in this slice):** any write, any export, any screen, any job; the owner's act of confirming the charge sheet; a stored pre-aggregation; basket buy-and-hold (P8-07); net rupees, Sharpe and exposure (not in the engine); regime and account (refused with the reason); the exit-comparison read for P8-10.

## Acceptance criteria
1. `GET /api/reports/runs` lists every stored run, newest first, with strategy, universe, window, costed or gross, style and exit with their sources, closed and open-at-end counts, whether the default run set takes it and why not, and whether net is possible; with no stored run the list is empty and net is `unavailable` with the reason. *`ReportsApiTests`, `ReportHandlersTests`, `RunSelectionTests`.*
2. `GET /api/reports/summary`, `/groups`, `/pivot`, `/equity`, `/distribution`, `/insights`, `/what-works` and `/trades` all take the one query (runs, basis, lens, strategy, timeframe, side, style, exit, basket, symbol, from, to, metric, limit, cursor), and on the hand-worked fixture (two runs, three baskets, one instrument in two baskets) give the figures worked by hand: 93 trades, +11 R in all; basket 1 62 trades +2 R, basket 2 30 trades -6 R, basket 3 31 trades +9 R, not additive; RPTA 62 trades +2 R, RPTB 31 trades +9 R. *`ReportsApiTests`, `ReportHandlersTests`.*
3. Every answer carries the evidence block (basis, n, dates, runs used with their facts, whether the run set was the default, the limits, the unavailable inputs, duplicates dropped, trades still open at the end left out, what was confirmed for a net report). *`ReportHandlersTests.Every_answer_carries_the_evidence_block_with_its_limits`.*
4. A figure is `value`, `provisional`, `insufficient`, `unavailable`, `not_evaluable` or `empty`; a number exists only for the first two and is finite; a thin group has no equity curve and no distribution bins, only the reason; a pivot gap is `empty`, never zero; the empty store gives `empty` everywhere and reads no trade. *`ReportHandlersTests`, `ReportSeriesTests`.*
5. A name the whitelist does not know (lens, metric, basis, run key, filter value, date, limit, cursor) is 422 `reports.invalid` and says which; regime and account are 422 `reports.dimension_unavailable` with the reason; an unknown run is 404 `reports.not_found`. *`ReportQueryTests`, `ReportsApiTests`.*
6. The population rule holds over HTTP: a second run of one strategy and universe with an overlapping window and the same labels is 409 `reports.run_overlap`; gross and costed runs together are 409 `reports.mixed_basis`; the same signal under different exit labels needs the exit in the lens (422 `reports.double_count`). *`ReportsApiTests`, `ReportHandlersTests`.*
7. **A report is net only by the owner's stored confirmation.** No parameter, header or body can supply one: with `basis=net` and any number of smuggled `confirmed`, `sheet_id` or header values the answer is 422 `reports.net_not_confirmed` while nothing is stored; with the stored confirmation a net report over runs costed with that very sheet is made and prints what was confirmed; over a run costed with another sheet or other rates, over a gross run, or over no run at all, it is 422 `reports.net_unavailable`; a malformed confirmation, or one naming no stored sheet, counts as not confirmed. An architecture test fails if a request, query, command, body, input, filter or params type carries a charge sheet confirmation or a flag named for one, if the Api names the confirmation at all, or if any Application type but the loader and the runs list reads it. *`ReportsApiTests`, `ReportHandlersTests`, `ReportQueryTests`, `ReportingArchitectureTests`, `ReportEndpointsArchitectureTests`.*
8. Only closed trades are counted and the trade list is the very set the figures came from: paged in the order of the exits (1 to 1,000, default 100), a cursor, each trade once; trades open at the end are left out and counted in the evidence. *`ReportsApiTests`, `ReportHandlersTests`.*
9. The endpoints are GET only, behind the session (401 without), and write nothing: no command handler, no write SQL. *`ReportsApiTests`, `ReportEndpointsArchitectureTests`.*
10. The same stored runs give the same answer whatever order the store returns them. *`ReportHandlersTests`, `ReportSeriesTests`.*
11. Time and memory are measured: p95 of every report and the peak memory of one request (and of six at once) on a synthetic run of 500,000 trades, written in ADR 0100 against the 1 GB container limit, met or not. *`ReportsPerformanceTests` (explicit), ADR 0100.*
11a. The load is bounded: runs holding more than 500,000 closed trades are refused before any trade is read (422 `reports.too_large`); one report at a time holds a population (a waiting request honours its cancellation); the caps on groups, cells, curves and distributions stop the pass at the first group past them. *`ReportHandlersTests`, `ReportSeriesTests`, `ReportsPerformanceTests`.*
11b. The trade-list cursor belongs to its report (422 for another); the curve and the summary agree on the drawdown; each endpoint declares only the parameters it uses. *`ReportHandlersTests`, `ReportsApiTests`, `ReportSeriesTests`.*
12. The contract and the typed client are regenerated; layers and the no-order rule stay green. *`scripts/gen-api.sh`, `Architecture.Tests`.*

## Contract
- **API (all GET, session-protected, tag Reports):** `/api/reports/runs` · `/summary` · `/groups` · `/pivot` · `/equity` · `/distribution` · `/insights` · `/what-works` · `/trades`. Query: `runs` (64-hex keys, comma separated), `basis` (`gross`|`net`), `lens` (comma separated dimensions: `basket instrument strategy timeframe side style exit month weekday`, at most 3; `regime` and `account` are named and refused with the reason), `strategy`, `timeframe`, `side`, `style`, `exit` (semicolon separated), `basket`, `symbol`, `from`, `to` (entry dates `yyyy-MM-dd`), `metric` (pivot figure, snake case, default `expectancy_r`), `limit` (1 to 1,000), `cursor` (`o<offset>.<hash>`, from the previous page). Each endpoint declares only the parameters it uses; strategy, symbol, exit and basket match exactly and case-sensitively. Errors (RFC 7807 with `code`): 422 `reports.invalid`, `reports.too_large`, `reports.net_not_confirmed`, `reports.net_unavailable`, `reports.dimension_unavailable`, `reports.double_count`; 404 `reports.not_found`; 409 `reports.run_overlap`, `reports.mixed_basis`.
- **Data:** none. No table, no migration. Reads `research.sim_runs`, `research.sim_trades`, `research.sim_comparisons`, `lab.strategies`, `platform.app_settings` (the stored confirmation) and the stored cost sheet (to check the confirmed id exists).
- **UI:** none (P8-08 onward).
- **Events/jobs:** none. Log events 4800 `reports.loaded` (kind, runs, trades, basis, ms) and 4801 `reports.refused` (kind, code): no trade, symbol, strategy or figure.

## Non-functional
Streamed projection, no change tracker, filters pushed to the store as parameters; the pages of the trade list never exceed 1,000; caps on the answer enforced inside the pass (2,000 groups, 10,000 pivot cells, 200 distributions, 40 curves, 2,000 cells; more is refused, not cut); at most 500,000 closed trades per request and one population in memory at a time; p95 and peak memory measured on 500,000 synthetic trades (target 1 s, see ADR 0100). All times through `TimeProvider`.

## Test plan
Unit: the query whitelist, the default run set, the handlers behind fake ports (hand-worked figures, every refusal, the states, the evidence, paging, net by confirmation only), the new engine parts (hand tables and a property over seeded random populations); architecture: GET only, the confirmation has one reader, the port names no database type, no request type carries a confirmation; integration (Testcontainers): the fixture stored through the real store, every endpoint, 401, 404, 409, 422, the smuggling attempts; performance: 20,000 trades always, 500,000 explicit.

## Open questions
None. Recorded for later: the owner's act of confirming the charge sheet (a verb); a stored pre-aggregation if the p95 of ADR 0100 is not met on the owner's data; the owner's data size is not yet read.
