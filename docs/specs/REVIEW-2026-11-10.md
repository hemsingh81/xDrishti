# Review of the not-yet-built specs, 2026-11-10

Scope: BK-00, BK-01, BK-03 to BK-12; CF-04 Parts B and C; P13-00 with the planned slices P13-01 to P13-10 (P13-05 is built and was used as ground truth); P14-14, P14-15; P3-01d (the probe and the conditional d2/d3); P8-16 (the remaining C14 items).

Ground truth was the code on `main` (318a3b5b), BK-01 on `feature/bk-01` (read only) and ADRs 0193 to 0255.

Method: each changed spec has a `## Review 2026-11-10` section. Factual corrections were applied there, or in place where a line was plainly wrong. No Status line was changed. Owner questions are listed below and nothing was decided for the owner.

## Built facts the specs predate (used throughout)
- **Recovery classes (AU-01, ADR 0240).** Every registered `IScheduledService` declares `Convergent`, `LatestOnly`, `Dated` or `TimeBound`, and is pinned in `RecoveryClassTableTests`. `Dated` is refused until AU-02 settles a first-start baseline. BK-01 on its branch adds `system-baskets` as `LatestOnly`. The depth and tick recorders are `TimeBound`. `history-eod` is `Convergent`.
- **Settings catalog (AU-08, ADR 0242, 0246).** Every configuration section bound at start-up needs an Internal section descriptor in `SettingsRegistry`; an architecture test fails a section without one. A stored owner switch gets a `Stored` descriptor, tier Advanced. If no safer direction is declared, every change counts as loosening and needs the owner's password. Essential is capped at eight and five are used. The learned allow-list has six `Confidence:` keys (ADR 0247) and no BK, P13 or P14 key is on it.
- **Training fence (AU-11, ADR 0243).** Run, ledger and `aiv` readers take `purpose = 'research'` at the data access. `SimAllBackfillGate` (AU-12) waits while a bar-history job (`IDataJobStore`) or a recovery pass runs.
- **Auto scope (ADR 0251).** A basket in the scope is expanded at the nightly run with members as of now: `AutoScopeResolver` calls `MembersAsync(id, null, null)`.
- **CF-05 (ADR 0229, 0230, 0223, 0224).** `LiquidityTiers` (`Domain/Research`): tier A from Rs 100 crore, B from Rs 20 crore, otherwise C, on the 20-session median traded value. The capacity share is `CapacityDailyShare` 0.005 of that median, and readiness row 14 counts a trade above it as a breach.
- **CF-02 (ADR 0204).** `NormalShrinkage` uses a leave-one-out parent along the chain `star`, `strategy`, `system`. It runs in `ReportOnly`; `Gate` is refused until the lower bound is validated.
- **CF-06 (ADR 0207).** The ledger counts every look (`TrialCounts`), and the universe is part of the plan hash. The honest count enters `Factor` only with `CountInFactor` ON (default OFF). The locked hold-out block is fixed at the first Lab post and is open-ended from its start.
- **CF-10 (ADR 0217, 0220).** A model influences a decision only through one gate, and is promoted only by the ADR 0220 rule.
- **ADR 0193.** `CellId` has `Universe` (reserved, only `*`) and `Expression`. Keys are written with the fewest trailing parts, and only cash cells reach decision paths.
- **P3-01e is built** (`BreadthCalculator`). P6-02 is built (ADR 0146; regime read through `IContextFigures`). P7-16 and P7-16b are built (ADR 0135, 0173). P9-02/03/05/09 are built (ADR 0137, 0138, 0139, 0143). P13-05 is built (ADR 0183).
- **ADR numbers.** The BK-00 reservations 0106, 0107 and 0108 collide with existing ADRs. BK-01 is 0254 (on its branch) and BK-02 is 0255; later slices take the next free number. None of the 11 items removed by AU-06/07 (ADR 0245) is used by these specs.

## Owner questions (with recommendation)
1. **BK order.** Build BK-05 before BK-03? BK-05 needs only BK-01. Built in the planned order, BK-03's basket 13 can have no member, because a missing flag is not a pass (ADR 0255). *Recommended: yes, BK-01, BK-05, BK-03, BK-04.*
2. **BK-03 intraday baskets (4, 12 and 11's intraday variant).** No live 1-minute bars exist, so the 09:20/09:30 live freeze of AC 6 cannot be built. *Recommended:* form them after the close from stored 1-minute bars before the formation time, labelled `formed_after_close` for simulation and report use only, and drop the live freeze (about −0.5 d). The alternative is a separate slice that builds `bars_1m_live` first.
3. **BK-03 / AU-16.** Should `AutoScopeResolver` expand basket members as of the plan session instead of now, so that a derived version effective on the next session is used? *Recommended: yes, as a small AU-16 follow-up with a reviewer pass. It touches the decision path.*
4. **BK-04 / BK-01.** Add `fetchEnabled` and `derivedEnabled` to `GET /api/baskets` (in BK-01 before merge, or in BK-03)? *Recommended: yes, in BK-03, one field each.* Otherwise BK-04 shows the disabled state only after a 409.
5. **BK-05 lot sizes.** Write NSE file lots into P14-01's `options.lot_sizes` (widen `source` with `nse_file`, unconfirmed) instead of a new `market.fo_lot_sizes`? *Recommended: yes, −0.5 d.* The cross-check stays a warning, and the master stays primary.
6. **Q-cap (BK-06, 07, 10).** Use one capacity share across the app: `Confidence:CostStress:CapacityDailyShare` (0.005) and `LiquidityTiers.Median`, with BK-10's owner setting allowed only to tighten below it? *Recommended: yes.* Otherwise the plan can suggest a size that readiness row 14 counts as a breach. BK-10 AC 4's numbers then halve (q_cap 100).
7. **BK-11 Q1, the tier.** Use CF-05's tiers (A/B/C as `liq_high`/`liq_mid`/`liq_low`) instead of terciles? *Recommended: yes, so "liquidity tier" has one meaning; the Lab already tiers every trade (ADR 0223).* Decision 3 rejected rupee cuts, so this reverses it.
