- **Status:** Approved (owner: P8-00 questions answered as recommended; read-only build). Built 2026-10-24.
- **Phase / roadmap row:** P8 — Reports & UI, slice P8-02 of [P8-00](P8-00-reports-and-ui-plan.md), 4 d (frontend and docs only)
- **Design refs:** docs/design/13-reports-and-ui.md §1 (Learning screen), §1c to §1e · docs/design/09-learning-engine.md §7 (cell lifecycle), §9 to §14 · P8-00 D1, D3, D6, D7, D10 and the accessibility rules · [P8-01](P8-01-analytics-kit-and-bundle-guard.md) (the kit) · ADR 0098 · prototype `docs/prototype/assets/app-pages-4.js` (`cells`, page frame)

## Assumptions (taken as recommended)
1. **Safety.** Read only (P8-00 Q1, Q2, Q8 as recommended): GET calls only, no control that changes a lesson, a hypothesis, a changelog row or a cell state, starts a job (the prototype's "Run weekly retrain now" and "New experiment" buttons are deliberately not built), exports or places anything. A test fails if the feature folder calls a write or imports a mutation (P8-00 D6).
2. **No backend change, no new dependency, no new token.** Every figure comes from the endpoints that exist: `GET /api/learning/overview`, `/api/cells`, `/api/cells/{key}`, `/api/changelog`, `/api/changelog/cell-state`. The contract is not regenerated.
3. **No composite health score** (P8-00 D10, Q12). The prototype's "Learning health 0 to 100" ring is not built; each part is shown with its own count and state.
4. **Fields the endpoints do not have are shown as not available, never invented:**
   - *Credible lower bound of **expectancy*** does not exist; the cell row carries the **win-rate** credible bounds (`winRateLower`, `winRateUpper`, at `credibleLevel`). The heatmap and the drawer show "Win-rate lower bound" and say so; no expectancy interval is computed in the browser.
   - A *data range of the trades behind a cell* is not on the row (only `asOf`). The evidence block prints "range not stated".
   - A *count of cells per lifecycle state* has no endpoint (`/api/changelog/cell-state` answers one cell). The funnel is built from the snapshot's cells (all are `research` until a changelog row says otherwise, ADR 0073) and one `cell-state` read per cell that has changelog rows, capped at 30 reads; cells beyond the cap, or whose read failed, are counted in a labelled "state not read" bucket, never put in a stage.
   - A *regime* is `*` (all regimes) until P6-02; the heatmap row label omits it when `*`.
5. **Heatmap shape.** The cell key is `strategy|timeframe|side|style|exit|regime`, so a (strategy, timeframe) pair holds several cells and the browser must not average them. Rows are therefore **strategy with side, style, exit (and regime if not `*`)**; columns are **timeframes**; each tile is exactly one stored cell. A combination with no cell says "No cell". The window selector (all / 250d / 60d) is the server filter `window`.
6. **A cell below `minTrades` never reads as a winner.** The server's `enough` flag decides. A tile that is not enough prints no expectancy and no bound: it is drawn as the kit's `insufficient` state ("n 12 of at least 30"), hatched, and labelled "Not enough". The drawer does the same for every derived statistic of that window; only the counts (n, wins, effective n) are printed as numbers.
7. **Only Overview and Setups tabs exist** in this slice. The other tabs of P8-00 (Lessons, Experiments, Journey, Plan vs actual, Smart rules, Autonomy, Models, Digest) arrive with P8-03 to P8-13 and are named, with their slices, on the Overview tab.
8. **Bundle.** The screen is a lazy route (its own chunk). The only eager changes are the route definition and the removal of the "coming in phase P8" label of the Learning nav entry, which is the only eager cost (measured below). `useUrlState` (deferred to this slice by P8-01) lives in `shared/analytics`, imported by path, so it is not in the entry chunk.

## Goal
The owner opens Learning and sees, honestly, what the learning engine holds (counts and newest verdicts, "nothing yet" as an ordinary answer) and which setups (cells) have enough evidence, with the thin ones visibly marked, a lifecycle funnel, the changelog, and one cell in full, all from stored records and without a way to change any of it.

## Scope
**In:** `frontend/src/features/learning/` (`api`, `components`, `lib`, `index.ts`, tests); `shared/analytics/useUrlState.ts`; route `learning` (lazy) and nav entry without the phase label; this spec, the roadmap row, a line in doc 13 and ADR 0099 only if a decision was taken (none expected).
**Out (not in this slice):** the other Learning tabs; a "Run now", retrain, experiment or digest button; any write; an expectancy interval; per-trade data (no endpoint, P8-06); Reports screen (P8-08); a heatmap in ECharts (the heatmap is a real table, which is its own screen-reader fallback, and costs no chart chunk).

## Acceptance criteria
1. **Frame.** Given `/learning` then a page header, an "Overview" and a "Setups" tab (WAI-ARIA tabs, keyboard operable) are shown; the tab is `?tab=overview|setups` (default overview, an unknown value falls back to overview; a `?cell=` link without a tab opens Setups); changing the tab pushes a history entry, so Back returns.
2. **Overview tiles.** Given the overview then six tiles are shown: Cell rows (three windows per cell; with the snapshot date), Models, Experiments, Hypotheses, Lessons, Changelog. A section with `counted` 0 is "No records yet" (a word, never "0"); a section with `truncated` shows the count as *provisional* with the reason (the newest 200 only); the split (name and count) and the newest record's label, stored verdict, detail and date are text under the tile; a champion is named when there is one. The limits strings of the server are printed in the evidence block.
3. **Empty overview.** Given `cellRows` 0 and `cellsAsOf` null then the snapshot tile says "No records yet" and the page says "No snapshot yet; run `xd learn cells`"; no tile prints a digit for a missing thing.
4. **Heatmap.** Given cell rows then a table (strategy rows by timeframe columns) shows one button per cell. Given `enough` then the tile prints the recency-weighted expectancy (signed, in R), n and the win-rate lower bound, with the word "Enough"; the tint follows the sign of the printed figure and the sign is text. Given not `enough` then the tile is hatched, labelled "Not enough" and prints "Insufficient data, n X of at least N", no expectancy and no bound. Given a combination without a cell then "No cell". Each button's accessible name is "strategy, timeframe, side, style, exit: expectancy or insufficient, n, win-rate lower bound, enough or not enough".
5. **Window selector.** Given the selector (All, Last 250 days, Last 60 days) then the cells are requested with that `window`; the window is `?window=all|250d|60d` (default all, unknown falls back).
6. **Evidence on each view.** Given any data view (heatmap, funnel, timeline, drawer) then an `EvidenceBlock` or its compact form shows n, range, basis (net or gross from the row's `basis`; mixed or unknown prints "Basis not stated" with a limits line), the snapshot key and as-of date as "Data used", and the server's limits text.
7. **Lifecycle funnel.** Given cells and changelog rows then the funnel lists Research, Candidate, Paper, Active, Paused, Retired with the number of cells in each, as text with a bar that is decoration; states are read with `/api/changelog/cell-state` per cell that has changelog rows; the "state not read" bucket appears only when it is not empty; only cells of the newest snapshot are counted (cells the changelog names that are not in it are said apart), so the stages add up to the cells printed; when the changelog read returned its 200-row limit the research count is shown with the word Provisional and the reason (an upper bound: older rows can only move a cell out of research); a cell state with `problems` is flagged in words; the caption says a state is a record and that nothing acts on it. Given no snapshot then the empty state, not a row of zeros.
8. **Changelog timeline.** Given changelog rows then the newest are listed newest first with when (India time), kind, subject, from-state to to-state, actor, reason and evidence ids, all as text (markup in a reason is shown as characters); a revert names the row it reverts; "may be more" is said when the query returned its limit; none yet says "No records yet".
9. **Cell drawer.** Given `?cell=<key>` (set by clicking a tile, closed with the close button or Escape, which removes it) then a dialog opens with the cell's windows as columns and n, wins, effective n, raw win rate, posterior win rate, lower and upper bound, expectancy, profit factor, max drawdown, MAE and MFE quantiles as rows, each in its honest state (a window that is not enough prints only the counts); the knobs (minimum trades, credible level, half-life, prior strength); the basis; the lifecycle state, the moves the lifecycle allows next (information, with the note that moves are made with `xd learn lifecycle`, not here), rows replayed, problems; and that cell's changelog. A cell that is not in the newest snapshot (404) says so.
10. **States.** Given loading then a loading state per section; given a failed request then the error message of the problem (per section, the page stays); given an empty snapshot then "No snapshot yet; run `xd learn cells`".
11. **Non-values.** Given any figure that is missing (`null` expectancy, profit factor, quantiles), not enough, or not read, then a word is drawn (kit states), never "0", "NaN" or a bar of zero width that reads as flat.
12. **Read only.** No control writes: the feature folder contains no `POST`, `PUT`, `PATCH`, `DELETE` call and no `useMutation`. Test: `readOnly.test.ts`.
13. **Accessibility and layout.** Tables scroll inside their own labelled, focusable region; the heatmap row header stays visible while scrolling sideways; tile buttons are at least 44 px tall below 480 px; focus ring from the theme; the drawer is a labelled dialog that traps and returns focus (MUI); status is never colour alone (Enough, Not enough, signs and words); dark mode uses theme palette functions only; contrast of text on the tile tints and on the hatching is tested in both modes (`heat.test.ts`). No horizontal page scroll was checked in a real browser at 360, 768, 1440 and 2560 px (see "Browser evidence").
14. **Bundle.** The screen is a lazy chunk. Measured on the same machine with the same build, main (baa9ef27) against this slice: guarded first load (entry + modulepreload, gzip level 6) **195,197 B (195.2 KB, 4.8 KB spare) before, 195,395 B (195.4 KB, 4.6 KB spare) after, +198 B**: the lazy route definition and its dependency list in the entry chunk (+155 B) and `useQueries` joining the shared TanStack chunk (+43 B). Always needed at first paint 205.1 KB before, 205.3 KB after. The Learning screen itself is a 11.0 KB gzip lazy chunk (plus MUI Drawer, ToggleButton and Table chunks shared with other lazy screens). The WARNING band (under 3 KB) is not reached.

## Contract
- **API:** none new. Uses `GET /api/learning/overview`, `GET /api/cells?window=`, `GET /api/cells/{key}`, `GET /api/changelog?subjectKind=&subject=&limit=`, `GET /api/changelog/cell-state?cell=`. Problem codes shown as their title: `learning.invalid` (422), `learning.cell_not_found` (404).
- **Data:** none. **Events/jobs:** none (no hub event, no polling; the queries refetch on window focus as the app's default).
- **UI:** `/learning` (lazy route), tabs `?tab=`, `?window=`, `?cell=`. Prototype match: page header, six tiles, tabs bar, heatmap card plus lifecycle funnel card, changelog table; deliberate differences: honest states, no health score, no action buttons, no demo data.

## Non-functional
No server work added. The heatmap is a table of buttons (hundreds of cells at most on this data; not virtualised, stated). Queries use the app's cache; the funnel reads at most 30 `cell-state` calls. No log events. Text from the server is rendered as text.

## Test plan
Vitest + Testing Library + MSW; queries by role, label and text; no real clock (dates in fixtures are printed as written; no relative time).
- Overview: empty store; thin (a few records, one section truncated); full (champion, splits). Non-value words: no digit for "No records yet".
- Setups: empty snapshot; thin (every cell below the minimum: no expectancy digit anywhere, all "Not enough"); full (mixed enough and not enough, one "No cell", a null expectancy as "Not available"); the window selector requests `window=250d` and writes the URL; an unknown `?tab` / `?window` falls back; Back after a tab change.
- Funnel: no changelog rows (all research), rows with states, a failed `cell-state` read goes to "state not read", cap note.
- Drawer: opens from a tile and from `?cell=`, a not-enough window prints counts only, 404, Escape clears the URL.
- Timeline: order, revert, markup as text, "may be more".
- Errors per endpoint; loading.
- `readOnly.test.ts`; `heat.test.ts` (contrast, light and dark); `useUrlState.test.tsx`; router test that `/learning` is no longer the coming-soon page.

## Open questions
None for this slice. Carried: an expectancy credible interval and a per-state cell count would be API additions (P8-06 / a later P6 follow-up); the owner may ask for them.

## Browser evidence and what was not verified
- **Seen in a real browser (Chrome 155 headless, 2026-10-24)** against the Vite dev server and a throwaway mock API with made-up cells (not the owner's data): Overview and Setups at 360, 768, 1440 and 2560 px, the cell drawer at 360 and 1440 px, and Setups in dark mode at 1440 px. At all four widths `document.documentElement.scrollWidth` equalled the viewport width (no horizontal page scroll); the heatmap scrolls inside its own region with the strategy column sticky; hatched tiles are labelled "Not enough" and carry no figure. Screenshots were kept outside the repository and are not committed.
- Two defects found by looking and fixed: the tile figure's "No records yet" and "Provisional" were drawn at the 22 px figure size (now body size, a hook in `NonValue` and `MetricTile`); max drawdown was printed with a plus sign (now unsigned).
- **Not verified:** touch targets and real touch behaviour (no device); a screen reader (the semantics are asserted by role and name in jsdom only); keyboard order across a large heatmap (every tile is a tab stop; a roving-focus grid was not built, a follow-up for P8-16 if the real snapshot has hundreds of cells); behaviour on the owner's real data (size of the snapshot, whether the funnel's 30-read cap is enough); dark-mode contrast was tested by numbers (`heat.test.ts`) and seen once, not measured in the browser.
