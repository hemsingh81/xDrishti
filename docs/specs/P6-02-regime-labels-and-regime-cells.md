## Goal
Every trading day has a regime label (one of the nine of doc 07 §6) **only where the stored context is ready**, read from data strictly before that day; every closed trade can be tagged with the label of its entry day; cell statistics can be split by regime with their own counts, their honest "not enough evidence" state and their basis; the Lab `by_regime` block shows numbers instead of "unavailable".

## Scope
**In:** (1) pure `RegimeLabel` and `RegimeLabeler` (a `ContextRead` to a label or an unavailable reason); (2) `IContextFigures.AsOfManyAsync` (many dates, one cache check); (3) regime tags on trades (pure, in the use case, not stored on the trade); (4) regime cells in `learn cells --by-regime` and `ComputeCellStatsCommand.ByRegime` (default off), with a regime coverage block; (5) `GET /api/data/regimes` (labels per day and counts) and `GET /api/cells/regimes` (regime rows of the newest snapshot that has them); existing cell reads keep returning the `*` cells only; (6) the Lab `by_regime` block lit (structured buckets beside the text line); (7) tests, docs, ADR 0146.
**Out (not in this slice):** the Reports `regime` dimension (hot path with allocation and size guards; its message is corrected and the dimension stays unavailable: P6-02b); the `regime` training feature (the trade-feature extractor adapter still passes no context: P6-02b); the `against_regime` loss tag (P6-15b, needs the tag on the loss input); regime as a shrinkage parent (CF-02); a regime gate on plans or tickets (P7); any frontend change (no lazy chunk, the entry bundle stays at its size); a stored per-day regime table (D3: derived on read from `market.context_daily`, which is insert-only and prefix-stable).

## Acceptance criteria
1. **Where ready.** Given stored context days, when the label of date d is asked, then it is the regime of the latest stored day strictly before d (`IContextFigures.AsOfAsync`), with its code 1 to 9, name (`UP_LOW_VOL` … `DOWN_HIGH_VOL`) and `Basis` (`index_and_vix` or `index_only`); never a value dated d or later.
2. **Unavailable, never a default.** Given no stored day, d on or before the first stored day, a latest day older than the age bound, a context the library refuses, or a day whose `regime` is not ready (fewer than 265 days), then the label is `unavailable` with the reason (`no_context`, `before_history`, `stale`, `context_invalid`, `regime_not_ready`) and no code or name. No fallback to the previous label, to `RANGE_NORMAL_VOL` or to `*` is ever made.
3. **No look-ahead (property).** For 40 seeds: truncating or changing every stored day dated d or later leaves the label of d (and of every earlier date) unchanged; appending days leaves earlier labels unchanged (prefix property).
4. **Names are the library's.** The nine names and codes in the Domain equal `Regime.Name(1..9)` of the indicator library (a test fails when they differ).
5. **Basis never mixed.** Given trades labelled `index_and_vix` and trades labelled `index_only` in the same regime, then they fall in two different regime cells: the regime part of the key is `NAME` for `index_and_vix` and `NAME~index_only` for `index_only`; no cell holds both, and the view prints the basis of every regime row.
6. **Trade tags.** Given closed trades of stored runs, when tagged, then each trade's label is the label of its entry date (D2); trades with an unavailable label are counted by reason and appear in no regime cell; the counts (labelled by basis, unavailable by reason) are in the outcome and printed by the verb.
7. **Regime cells.** Given `--by-regime`, then for each `*` cell the snapshot also holds one row per (regime part, window) that has at least one trade, with `n`, wins, the Bayesian posterior and interval of P6-01 and the `enough` flag (n at least `min_trades`, default 30); a regime cell below the minimum reads "not enough evidence" exactly like a `*` cell; the sum of `n` over a `*` cell's regime cells plus its unavailable trades equals the `n` of the `*` cell in the same window (a test).
8. **No double counting.** The prior of the system and of each strategy is computed from the `*` cells only; adding regime cells changes no `*` row (a test compares a snapshot with and without the flag).
9. **Existing readers are unchanged.** `GET /api/cells`, `/api/cells/{key}` for a `*` key, the lifecycle, the selection, the plan and the digest read only `*` cells; a snapshot with regime cells gives them the same rows as without (a test). `GET /api/cells/regimes` returns the regime rows with `regimeName`, `regimeBasis` and the same evidence fields.
10. **Idempotent.** The same inputs give the same snapshot key; the key of a run without `--by-regime` is byte-for-byte the key of before this slice; with the flag the key text also holds a hash of the labels used, so a changed label set gives a new snapshot and an identical one writes nothing.
11. **Labels per day endpoint.** `GET /api/data/regimes?from=&to=` returns for each session in the range (default the last 60, at most 400 sessions) its label or unavailable reason and the day of the context it came from; plus counts per regime and basis over the range, the first date on which a label exists, the first date with `index_and_vix` and the sentence "read before the day; the index is NIFTY 50; derived from 1-minute bars". 422 `data.invalid_range` for a bad range.
12. **Lab `by_regime`.** Given a robust run, when the out-of-sample trades are tagged, then `byRegime` (the text) summarises the buckets and `byRegimeBuckets` lists for each regime part: trades, mean R, total R, `enough` (30 or more trades) and an `insufficient` note; trades with no label are counted per reason as `unavailable`; with no stored context the text is `unavailable: <reason>` and the buckets are empty. The verdict, the gates and the sweep are untouched.
13. **Report message corrected.** `ReportErrors.DimensionUnavailable(Regime)` and the insight no longer say "no market context is stored"; they say the regime is not a report dimension yet and point to the regime cells; the dimension stays unavailable.
14. **API contract.** `scripts/gen-api.sh` run; the changed schemas are `CellStatsView` (two computed read-only fields), the new endpoints and `RobustnessView` (`byRegimeBuckets`, optional).

## Contract

(`XDrishti.Domain.Learning`): `RegimeTally` (labelled by basis, unavailable by reason), `RegimeCellBuilder` (regime cells of the `*` cells given tagged trades; pure).
- **Application:** `IContextFigures.AsOfManyAsync(IReadOnlyCollection<DateOnly>)` → `IReadOnlyDictionary<DateOnly, ContextRead>`; `RegimeTags` (internal; dates of trades to labels in one call); `ComputeCellStatsCommand.ByRegime` (default false); `CellStatsOutcome.Regime` (`RegimeTally?`); queries `GetRegimeLabelsQuery`, `ListRegimeCellsQuery`; `RobustnessView.ByRegimeBuckets`.
- **Infrastructure:** `ContextFiguresAdapter.AsOfManyAsync` (one stamp read, one build, a loop); `CellStatsStore.ListRegimeLatestAsync`; the existing `ListLatest*` add `AND regime = '*'`.
- **Data:** none. `research.cell_stats.regime` is `varchar(64)` with no check and already holds `*`; the new parts fit. No migration.
- **API:** `GET /api/data/regimes`, `GET /api/cells/regimes` (read only, `ApiJsonContext`, contract regenerated). **CLI:** `xd learn cells --by-regime`. **UI:** none.
- **Settings:** none new (`min_trades` and the other knobs are P6-01's; the Lab minimum for a regime bucket is the same `min_trades` default 30).

## Non-functional
Labelling 3,000 trades: one stamp read, one cached context, a dictionary of at most 1,300 dates; under 50 ms in the unit test. The regime cells add at most 18 parts per `*` cell (9 regimes × 2 bases) and in practice a handful. No price or trade detail is logged.

## Test plan
Domain: labeler states table (all five reasons and the available case), property tests for no look-ahead and prefix (40 seeds), names equal the library's, `CellPart`, the regime cell builder (sums, basis split, unavailable counted), calculator parity with and without regime cells. Application: handler with a fake `IContextFigures` (tag by entry date, outcome tally, key unchanged without the flag), Lab robustness buckets and the no-context text, report message. Infrastructure/integration (Testcontainers): `AsOfManyAsync` equals `AsOfAsync` per date, `ListLatest*` return only `*`, `ListRegimeLatestAsync`, the two endpoints. Existing tests stay green.

## Decisions
**D1 — a label is a read of the context as of the day, not a stored fact.** `RegimeLabel.Of(d, IContextFigures.AsOfAsync(d))`. The context table is insert-only and the library's regime is a pure function of the days before d, so a stored copy would add a second source of truth and a migration for nothing. Rejected: `research.trade_regimes` (P6-00's option).
**D2 — the decision day of a trade is its entry date.** Entries are at the close of the trigger bar, so the entry date is the decision date; the label read is the one before that date (the previous session's context), which is what a live decision could have known. A swing trade is labelled once, at entry, and keeps it.
**D3 — five reasons, no default.** `no_context`, `before_history`, `stale` are the reasons of `ContextRead`; `context_invalid` is its `Invalid`; `regime_not_ready` is the case where the day exists but fewer than 265 days precede it. They are shown, counted and never replaced.
**D4 — the basis is part of the cell.** The regime part is `NAME` for `index_and_vix` and `NAME~index_only` for `index_only`. Reason: P3-01d D2 settled that `regime_vol` falls back to the index percentile when the VIX percentile is not ready, so the same name means a different thing in the first year of VIX history; mixing them in one cell would be exactly the silent mix the owner forbade. The cost is thinner cells, which the `enough` flag states. Rejected: a separate basis column (a migration and a seventh key part everywhere) and a flag on the row (a key that hides the split).
**D5 — regime cells shrink toward the strategy rate, like the `*` cells.** The prior is computed from the `*` cells only (acceptance 8). The chain regime cell → `*` cell → strategy → system belongs to CF-02 (empirical Bayes); P6-02 does not change the shrinkage model.
**D6 — regime cells are optional and default off.** `--by-regime` (command `ByRegime`). A snapshot with them is a superset of one without (same `*` rows). The snapshot key text gets `|regime=<sha>` only when the flag is on, so no stored key changes.
**D7 — readers of the newest snapshot see only `*` cells.** The store's `ListLatest*` add `regime = '*'`; regime rows have their own read. Reason: selection, plan, digest and lifecycle index cells by strategy/timeframe/side and would pick a regime row as a duplicate. Rejected: a separate table (a migration for a column value) and a flag in every consumer (many chances to forget).
**D8 — the Lab block keeps its text and gains buckets.** `byRegime` stays a string (stored results and the frontend read it); `byRegimeBuckets` is added as an optional list so old stored results still load. No frontend change: the page keeps showing the text, which now carries the figures.
**D9 — the Reports dimension is cut.** The report engine's bucketing is the hot path of the allocation and 1M-trade guards, and its source reads trades through a raw reader; adding a per-trade regime there needs its own measured slice (P6-02b). The unavailable message is corrected so it does not claim there is no context.
**D10 — no regime on the training set yet.** `regime` is a context-sourced catalog name; the extractor adapter passes no `MarketContext`. Lighting it needs the days read in `ExtractTradeFeaturesHandler` and the training-set rule for unknown features re-checked (P6-02b).
**D11 — the nine names are duplicated in the Domain, pinned by a test.** Domain cannot reference the indicator library (ADR 0039); a test in the indicator test project asserts equality with `Regime.Name`.
**D12 — thin history is shown, not hidden.** The endpoint and the verb print the first date with any label, the first with `index_and_vix`, and how many days each regime has; a regime with no day appears with 0 (P6-00 risk: a HIGH-vol DOWN regime may have no day at all).
