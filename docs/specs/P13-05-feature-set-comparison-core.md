## Goal
One pure function answers, for any feature extension, "does adding it to `tf-1` improve out-of-sample net R per candidate under the ADR 0075 take policy, by more than a margin widened for the number of looks?", and says KEEP, DROP, INCONCLUSIVE or NOT_EVALUABLE with the missing quantity named. P13 (`md-1`, monthly folds) and P15 (`ev-1`, `fu-1`, `llm-1`, quarterly folds) use the same code and write to the same two tables, created once here.

## Verified facts (read 2026-11-02 in `backend/src`)
- `TradeFeatureCatalog.Version = "tf-1"`: 36 stored (`research.trade_features`, column `feature_values double precision[]`) + 5 cell features = 41 values per `TrainingRow`. `TrainingDataBuilder.Build(set, stored, cells, required, provenance)` drops and counts rows with a required feature unknown, never fills; `TrainingData.Id` is SHA-256 of `training-data/1`, the label-set id, `tf-1`, provenance, the required names and every row's key and values. Its one production caller is `TrainingDataLoader` (Application/Learning). The champion's lineage records this id (ADR 0070).
- `WalkForwardValidator.Cuts` uses `ExitSelector.Windows`: windows start on the first day of a month `MinTrainMonths` after the first trade, are `TestMonths` long, **not aligned to calendar quarters**; the embargo is `EmbargoDays` **calendar days** (default 7); purge = resolved instant + `HoldOut.BarSeconds` (60) before the first test decision. `CheckRows` refuses duplicate keys, bad labels, non-finite R, ragged feature width, and rows on or after `HoldOutStart` (`validation.holdout_touched`).
- `MetaPolicyEvaluator` (ADR 0075) chooses a threshold per fold **only from out-of-fold scores of earlier folds** (`MetaPolicyOptions`: `MinKeptShare` 0.5, `ThresholdStep` 0.05, `MinThresholdRows` 30, `MinLiftR` 0.02); a fold with fewer earlier scores is not evaluable, so **the first test fold never has a threshold**. The threshold search (`ThresholdsFor`, `Choose`) is `private`.
- `IScorerFactory.Fit(train)` is deterministic by contract; the champion recipe is `MlNetScorerFactory` in `XDrishti.Learning.MlNet` (not Domain; one thread, fixed seed, PAV calibration on a held-back slice of the train rows). Trees accept NaN; `LogisticScorer` maps non-finite values to 0 after scaling.
- `MetricsCalculator.Compute(scores, labels, bins)` gives log loss, Brier, AUC, ECE in pp. `MultipleTesting.Factor(N) = 1 + 0.25·log2 N` (Domain/Lab). `SeededRandom` (SplitMix64, Domain/Lab) and `MonteCarlo` (an i.i.d. trade bootstrap, no blocks) exist; **no block bootstrap exists**.
- `ITestLedger` (Application/Abstractions/Lab): `AppendAsync(LedgerRow)` is idempotent on `RunId` (`uq_test_ledger_run` on `lab_run_id`, no foreign key to `lab.lab_runs`), `CountVariantsAsync(strategyId)` = distinct `strategy_hash` (char(64) hex) of the family. `lab.test_ledger` is insert-only for `xd_app`; the AI view `aiv.test_ledger` left-joins `lab.lab_runs`.
- **Neither `research.trade_features_ext` nor `research.extension_evaluations` exists.** Default privileges (`deploy/db/init/10-roles.sh`) give `xd_app` SELECT, INSERT, UPDATE, DELETE on every new table; insert-only is made by `GrantTableToAppRole` + `MakeAppendOnlyForAppRole` per table. `xd_exec` has no USAGE on `research` (only execution, platform, trading, workflow, accounts, market, portfolio: `AddExecutionRecord`); `xd_mcp_read` has USAGE on `research` for column-level grants on report-source tables (`AddAiToolAccess`; `ReadOnlyRolesTests`), so a new research table must simply not be granted to it.
- **`values` is a reserved word in PostgreSQL**; P13-00's column name `values` is changed to `feature_values`, as in `research.trade_features`.

**Plan corrections found while verifying (also in the Review fixes of P13-00 and P15-00):** (1) the primary metric of P13-00 item 5 says "per taken candidate" while its power formula (item 9) and ADR 0075 use **per candidate**; per candidate is used (a ratio over taken trades rewards taking fewer). (2) The first test fold has no earlier scores for a threshold, so 6 evaluable folds need **7 test folds**: P13's history need becomes 2 + 7 + 2 = **11 months** (recording from 2026-12-01 → evaluable 2027-11-01). (3) The embargo of P13-00 is in **sessions**, which `ValidationOptions` cannot express; the core takes the session list. (4) Quarterly folds for P15 must be **calendar quarters** (a season), which `ExitSelector.Windows` does not give; the core cuts its own calendar folds and leaves the P6-05 geometry untouched.

## The rules
**Rows.** Input is one list of `ValidationRow` with the **B** width (41 `tf-1` values then the extension values) plus `BaseWidth` 41; model A sees `Features[..BaseWidth]` of the same rows. So the rows, labels, R, dates, folds, train sets, calibration slices and seeds are identical by construction; the recipe is **one** `IScorerFactory` fitted twice per fold (A and B differ only in columns). The core sorts rows by (trade date, decision instant, key, ordinal) first; nothing depends on input order.

**`TrainingDataBuilder` extension group.** New optional last parameter `ExtensionGroupInput? extension = null` (group, `IReadOnlyDictionary<string, double[]>` values by trade key, required extension names, default none). With null: rows, counts and `Id` are **byte-identical** to today (the `IdOf` text is unchanged), so `tf-1` training sets and the champion's lineage stay valid. With a group: a labelled trade without an extension row is dropped and counted (`DroppedNoExtension`), a required extension value unknown drops it (counted per name as today), other unknown extension values stay NaN (never filled); values are appended after the 41; `TrainingData` gains `Extension` (id, version, names; null by default) and the id text gains one line `ext:<version>:<names>` only when a group is given.

**Folds (`CalendarFolds`).** Unit `Month` (P13) or `Quarter` (P15: January, April, July, October). The first test window starts on the first unit boundary at least `MinTrainMonths` after the first row date (P13 2, P15 12); a window is used only when the session list covers its last session (an incomplete last window is dropped and counted). Train = rows before the window, minus the **embargo** (rows on the last `EmbargoSessions` sessions before the window start, from the caller's trading sessions; P13 3, P15 5) and minus the **purge** (resolved instant + 60 s ≥ the window's first decision). A fold with fewer than `MinTrainTrades` (30) train rows is skipped with the reason. Rows on or after `HoldOutStart` are refused (`extensions.holdout_touched`), as `CheckRows` does.

**Take policy and deltas.** Per fold both models are fitted on the train rows and score the test rows (probabilities must be finite in [0, 1], else `validation.bad_probability`). Each model's threshold for fold *k* is chosen by `TakeThreshold.Choose` from **its own** out-of-fold scores of folds before *k* (ADR 0075: maximise net R per candidate, keep ≥ 50 %). A fold is **evaluable** when both models have a threshold. Per row `d = (take_B − take_A) · R`; ΔR of a fold or pooled = mean of `d` over its rows (net R per candidate, on the set's basis, labelled gross unless the basis is net). A **flip** is a row with `take_A ≠ take_B`. Secondary: pooled Δ log loss, Δ Brier (B − A) over all used test folds (evaluable or not), ECE of B in pp, sign of ΔR per evaluable fold, measured `E[R² | flip]`, flip share f, naive SE `sqrt(f · E[R² | flip] / n)` and the bootstrap SE (their ratio is printed as the design effect).

**Bootstrap (`BlockBootstrap`).** Paired: a draw resamples **blocks** with replacement (the number of blocks drawn = the number of blocks), each block carrying all its rows' `d`; the draw's ΔR = sum of drawn `d` ÷ rows drawn. Blocks are keyed and sorted before drawing: P13 blocks of `BlockSessions` consecutive sessions (default **1 = a day**), and the same bound also at **5 sessions** as a stated sensitivity; P15 blocks are **seasons** (calendar quarters). Draws 10,000, generator `SeededRandom(seed)`, seed **1337** (in the record). One-sided 90 % bounds: lower = the 1,000th smallest draw, upper = the 9,000th (positions `ceil(0.10·B)` and `ceil(0.90·B)`, 1-based). Fewer than 2 blocks → the bound is `unavailable` (never a value).

**Ledger count and multiple testing (D6).** The family is `ext:<version>` (for example `ext:md-1`). `ExtensionTrial` builds the canonical trial text (base `tf-1`, extension version and the names used, recipe name and options hash, label rule version, take-policy options, fold unit, block rule) → `trial_hash` (SHA-256 hex) and a deterministic ledger run id (the first 16 bytes of SHA-256 of `ext-ledger/1`, the trial hash and the data window, as a UUID) so a re-run appends nothing. The caller appends the `LedgerRow` (`StrategyId` = family, `StrategyHash` = trial hash, `RunKey` = the training-data id, `Method` `extension-compare`, `Version` 1) **before** calling the core, and passes the family's distinct hashes; the core **refuses** (`extensions.trial_not_in_ledger`) when its own trial hash is not among them, so no result can be computed before its row exists. N = the count of distinct hashes; F = `MultipleTesting.Factor(N)`; the primary comparison (all names against none) is one trial, each subset or recipe change another.

**Verdict (`ExtensionVerdictRule`, P13 preset; P15 values in brackets).**
| Verdict | When |
|---|---|
| NOT_EVALUABLE | evaluable folds < 6, or paired candidates in evaluable folds < 2,000 [1,000], or the lower bound is `unavailable`; names every missing quantity (`folds 4 of 6`, `paired candidates 1,240 of 2,000`) |
| KEEP | all: flips ≥ 300 [none]; lower bound of ΔR ≥ 0.02 R × F at the stated block **and** at the sensitivity block [season only]; ΔR > 0 in ≥ `ceil(2/3 × folds)` evaluable folds; pooled Δ log loss ≤ −0.005 × F; pooled Δ Brier ≤ −0.002 × F [not required]; ECE of B ≤ 5 pp |
| DROP | not KEEP and the upper bound of ΔR < 0.02 R (not widened; the larger of the two block bounds) |
| INCONCLUSIVE | otherwise |

Any criterion whose input is `unavailable` counts as **not met** for KEEP and **not met** for DROP (never a pass either way). Every threshold is an option, printed in the record.

**Hold-out (`ExtensionHoldOutCheck`).** Once, after a stored KEEP: both models fitted on all development rows, thresholds from all development out-of-fold scores, scored on the hold-out rows; **confirmed** iff ΔR has the same sign and B's log loss ≤ A's; NOT_EVALUABLE under 100 hold-out rows. "Once" is enforced by the store: a second record with `holdout_read` for the same family and version key is refused (`extensions.holdout_used`).

## Acceptance criteria
1. **Hand values.** A fold of 4 rows with R = [+1.0, −1.0, +2.0, −0.5], take_A = [1, 1, 1, 0], take_B = [1, 0, 1, 1] gives d = [0, +1.0, 0, −0.5], ΔR = 0.125, flips 2. Margins: N = 1 → 0.02 R, N = 4 → 0.03 R and Δ log loss −0.0075, N = 16 → 0.04 R. Fold rule: 6 evaluable folds need 4 positive. Bounds: B = 10,000 → positions 1,000 and 9,000.
2. **Identical inputs, identical verdict (property).** For 200 random seeds of synthetic rows, the same inputs give a byte-identical report and record id on repeated calls.
3. **Row order invariance (property).** Any permutation of the input rows (and of the session list) gives the same report and record id.
4. **A = B gives no gain (property).** When the extension adds columns equal to existing ones or constants (or zero names), every take decision of B equals A's: ΔR = 0 exactly in every fold and draw, flips 0, bounds 0; the verdict is DROP at ≥ 6 folds and ≥ 2,000 candidates, else NOT_EVALUABLE — never KEEP, for N = 1 and N = 16.
5. **Placebo and planted effect.** Extension values independent of the label: not KEEP at N = 1 and N = 16 (200 seeds, fixed). Extension carrying the label: KEEP with 7 test folds (6 evaluable); NOT_EVALUABLE with 6 test folds (`folds 5 of 6`).
6. **Paired by construction.** Model A never sees a column at index ≥ `BaseWidth` (a recording fake factory asserts the width); A and B receive the same train keys in the same order in every fold; a row with a different key set between A and B cannot be expressed by the API.
7. **Folds.** Monthly and quarterly hand calendars (with a holiday and a month starting on a weekend): window bounds, the embargo of 3 and 5 sessions, the purge, an incomplete last window dropped and counted, the first test fold not evaluable for ΔR but counted for log loss and Brier; rows in the hold-out refused.
8. **Bootstrap.** Equal `d` in every block → lower = upper = point; lower ≤ point ≤ upper for random cases; one block → `unavailable`; the 5-session sensitivity groups 5 consecutive sessions; a season block holds exactly one calendar quarter; the draws depend on the seed only (same seed, same draws on every run).
9. **Ledger first.** With a family hash list that lacks the trial hash, the core refuses `extensions.trial_not_in_ledger` and computes nothing (a counting fake factory shows zero fits). The trial hash and ledger run id are stable for equal definitions and change with any listed field.
10. **Honest states.** NOT_EVALUABLE and INCONCLUSIVE carry the named missing or failed quantities; an `unavailable` input never passes a rule; the record's evidence JSON never holds a number where the value is `unavailable` (P8-00 D3; render test of the JSON).
11. **`TrainingDataBuilder` additive.** Existing tests unchanged and green; a golden `TrainingData.Id` of a fixture built today equals the id after the change without a group; with a group the id differs, `DroppedNoExtension` counts, and no extension NaN is replaced.
12. **Migration.** `AddExtensionTables` creates both tables (Contract); `xd_app` has SELECT and INSERT and **not** UPDATE, DELETE, TRUNCATE on each (grants test, Timescale); `xd_exec`, `xd_mcp_read`, `xd_mcp_sql` have no privilege on either (`ExecGrantsTests` and `ReadOnlyRolesTests` gain the two tables); a second insert of the same key writes nothing; the hold-out partial unique index refuses a second `holdout_read` row; `Down` drops both. The migration text has no `GrantSchemaUsageToAppRole`, no `xd_exec`, no `xd_mcp`, and no function or trigger (if one is ever added it pins `SET search_path = pg_catalog, pg_temp`; the architecture test checks the text).
13. **No decision use.** Architecture test: the types of `XDrishti.Domain.Learning.Extensions`, the two ports and the table names are referenced only by the stores, DI, tests and (later) the P13-03/06, P15-05/10 handlers named in an exact allow-list; `XDrishti.Execution`, `XDrishti.Simulation`, `XDrishti.Strategies*`, `XDrishti.Domain.Selection`/`Planning`/`Checklist`/`LiveTrading`/`Paper`, `XDrishti.Application.Selection`/`Planning`/`Execution`/`LiveTrading`, `ScoreWithModelHandler` and the model registry's champion path reference none of them, and no file under those contains `trade_features_ext` or `extension_evaluations`. The no-order tripwire stays green.

## Decisions (researched)
1. **P13-05 owns both tables and their stores; P13-03, P13-06, P15-05, P15-08 and P15-10 only use them.** One writer of the schema, one migration, one grants test; built first because it needs no recorded data. Rejected: P15-05 creating the features table (two owners of one mechanism).
2. **A sees a column slice of B's rows.** Identity of rows, folds and seeds is then a property of the type, not of discipline.
3. **Per candidate, not per taken candidate.** It is the paired difference the power table and ADR 0075 use; a per-taken ratio can rise by taking fewer.
4. **Own calendar folds, embargo in sessions.** P13 needs monthly folds with a 3-session embargo and P15 calendar quarters; changing `ExitSelector.Windows` would move every P6 result.
5. **Day blocks with a 5-session sensitivity, KEEP needs both.** P13-00 asked for a day-block bootstrap; candidates on adjacent days share a regime, which day blocks miss. Taking the smaller bound costs one extra loop and cannot flatter. P15 uses seasons (P15-00: seasons are the independent units).
6. **The core checks the ledger, it does not write it.** Domain cannot reach `ITestLedger`; refusing a trial hash that is not in the family's list makes "ledger before results" structural.
7. **Hold-out once by a unique index**, not by a trigger: no function, nothing to pin.

## Risks and honest limits
- Ten or eleven months of depth is one regime; the 5-session block and the hold-out are the guard. P15 quarterly folds give wide intervals; NOT_EVALUABLE is the likely first answer for both.
- The recipe's determinism is relied on (ML.NET single thread, fixed seed); a non-deterministic recipe would break criterion 2, which the ML.NET check catches.
- Family ids with `:` cannot collide with draft strategy ids (`^[A-Za-z][A-Za-z0-9_]{0,63}$`, `DraftChecks`); whether every stored strategy id is held to that pattern is UNVERIFIED, so a test asserts no `lab.test_ledger` family other than `ext:*` contains `:`.
- Gross R unless the owner's charge sheet is stored (ISS-25); survivorship (ISS-22).
