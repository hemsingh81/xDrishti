# P1-12a — Scheduled end-of-day run and gap backfill

- **Status:** Approved (owner, 2026-10-12) · decision [ADR 0017](../adr/0017-trading-calendar-eod-schedule-quality-adjustments-and-csv-undo.md) §2–§3 · **Phase:** P1 — the scheduling part of **P1-12** (editable schedules stay with P1-13) · depends on P1-11a
## Backend
1. Hosted service `DataEodService` (pattern of `DailyRefreshService`/`DailyRefreshRunner`): options `Data:Eod:Enabled` (default true), `TimeIst` (default 15:50), waits in ≤ 1-minute slices re-reading the clock, runs only on trading days (calendar), starts the existing job with steps `dhan, aggregate` (+ `quality` once P1-14a exists — leave the hook) and trigger `daily`; **catch-up** at start-up when today's session closed, the scheduled time passed and no `daily` job exists for today; skipped without error when a job is running or the Data account is not connected (recorded as a skipped run once per day with the reason); job rows carry `trigger manual|daily` (+ `GET` shapes: `trigger` on `DataJobView`).
2. Gap detection and backfill inside the Dhan phase (ADR 0017 §3): `market.bar_gaps (instrument_id, date, expected, found, attempts, last_attempt_at, status open|filled|unfillable)`, lookback `Data:Gaps:LookbackSessions` (default 30), expected minutes from the calendar, windows merged ≤ 90 days, per-instrument errors retried next run, `unfillable` after a refetch that adds nothing (not retried by scheduled runs; retried by manual "Re-fetch gaps"); `POST /api/data/refresh` gains `refetchGaps?: bool` (also retry unfillable); overview gains `gaps {open, unfillable, filled, lastDetectedAt}`; `GET /api/data/gaps?status&instrumentId&page` lists them.
3. Notifications: a failed scheduled run, or a run that leaves open gaps, raises a notification through the existing notifications feature/store (look at how account/connection notices are produced); overview `eod {enabled, timeIst, nextRunAt, lastRun {startedAt, status, trigger}}`.
4. Tests with a fake clock: schedule edges (before/after 15:50, weekend, holiday, special day), catch-up, once-per-day, running job, not-connected; gap planning (30-session lookback, holiday not a gap, partial day, short special session), fill/unfillable transitions, merged windows, notifications; integration on TimescaleDB; contract; docs 05 §6 and 04 services table.
## Frontend (Data screen)
Under the header: **Automatic update** line ("Daily at 15:50 IST on trading days · next 13 Oct 15:50 · last automatic run succeeded 12 Oct 15:52", disabled state, last run failed/skipped with reason); pipeline Dhan step shows gaps found/filled/unfillable; coverage table gains a "gaps" indicator (count of open gaps) and a status filter value; menu item "Re-fetch gaps"; recent runs show the trigger (Manual / Automatic). Tests, a11y.
## Decisions taken in the backend build
Details the ADR and this spec leave open; object to any.
- **Skipped run = a job row** with status `skipped` (new value next to `running|succeeded|failed`; migration `AddEodRunAndBarGaps` widens the check), `trigger daily`, the reason as `error`, every phase `notRequested`; so it appears in the recent runs and in `eod.lastRun`, never counts as "the last Dhan phase", and is the "run of the day" for the once-per-day rule: no further automatic attempt that day, also not after a restart (the owner runs "Update data" by hand).
- **Run time = max(`Data:Eod:TimeIst`, end of that day's session)**: a run never starts before the session closed; a special evening session (Muhurat) moves its day's run to its end. A configured time before 15:30 therefore waits for the close.
- **Catch-up** = the same decision as the scheduled start (trading day, run time passed, no `daily` job started today, skipped ones included), asked once at start-up. A database error at the run time is retried 3 times a minute apart; after that the day waits for a restart or the owner.
- **Steps** = every pipeline step except `csv` (`DataEodSteps.Planned()`): when P1-14a adds `quality` to `DataSteps.All` the scheduled run includes it, after the aggregates, with no other change; the hook is tested.
- **Gap rows**: `market.bar_gaps` also has `detected_at` (first detection; set again when a filled session lost bars); the runtime role has SELECT, INSERT, UPDATE, no DELETE. A session is **recorded** before the fetch only if it lies before the ordinary fetch window (two days before the last bar); a partial session inside that window is fetched anyway and recorded only if the fetch does not complete it. A session counts as a **refetch attempt** when the job asked for it (open gap, or any gap with `refetchGaps`, or inside the ordinary window).
- **Counting** the bars of a day: `bars` of the 1D aggregate for days outside the instrument's dirty range, the 1-minute table (primary key range, grouped by India day) only inside it; hence a gap check costs one small read per instrument and never scans the history.
- **Old open gaps** (older than the lookback) are still retried until they are filled or unfillable; unfillable and filled ones are not looked at again except when a CSV load completes an unfillable session or an undone file empties a filled one.
- **Notices** are derived on read, like the account notices, from the stored state: `GET /api/data/notices` returns `{items:[{id, kind, severity, text, at}]}`: `data_run_failed` (error; the latest automatic run failed; id `data:run_failed:{jobId}`) and `data_gaps_open` (warning; open gaps exist; id `data:gaps_open:{lastDetectedUnix}:{open}`). Unfillable gaps and skipped runs raise nothing (the account notice already covers a disconnected account).
- **Contract**: `StartDataJobRequest.refetchGaps`; `DataJobView.trigger`, `refetchGaps` (status may be `skipped`); `DhanPhase.gapsFound|gapsFilled|gapsUnfillable`; `DataOverview.gaps`, `.eod`; `DataInstrumentRow.openGaps`; `GET /api/data/instruments?hasGaps=true`; `GET /api/data/gaps`; `GET /api/data/notices`. All additive.
- **Config**: `Data:Gaps:LookbackSessions` 1–250 (30), `Data:Eod:Enabled` (true), `Data:Eod:TimeIst` `HH:mm` (15:50); invalid values stop the start-up.
