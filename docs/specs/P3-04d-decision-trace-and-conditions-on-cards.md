# P3-04d — The decision trace and the "conditions at the decision bar" section of a trade card

- **Status:** Built 2026-10-25 (see ADR 0041 Amendment 5 for what differs from the text below: the trace is read from the scanner's existing candidate trace, with no `Observe` hook; the card lists at most 12 reads of a condition). Was: Draft (written 2026-10-24; decisions below were researched under the owner's delegation; the owner's Approved is still needed before an agent builds it). **Decision recorded: GO**, before P5 (D1).
- **Phase / roadmap row:** P3 — row P3-04d (Later, fourth part of the former row P3-04b); build order P3-04b1 → P3-04b2 → P3-04c → **P3-04d**.
- **Design refs:** docs/design/11-strategy-lab.md §2 (conditions, three-valued results, *Lags*) · docs/design/07-strategies.md §3 · docs/design/18-roadmap.md (P3-04d row, *Open owner decisions* 6) · specs [P3-04c](P3-04c-trade-cards-selection-chart-and-static-html.md) (C2, C3), [P3-04b1](P3-04b1-the-export-library-files-labels-and-folder-writer.md), [P3-04b2](P3-04b2-the-simulate-verb.md), [P3-09](P3-09-verification-pack-and-the-20-trade-check.md)
- **Needs:** built: P3-04c cards, `BuildTradeCardsHandler`, `TradeCardHtml`, `ISimulationEngine`, `InstrumentReplayer`, `EntryScanner`, `RunSimulationHandler`; ADRs 0037 (two-stage seam, R5: one list for the scanner and the walker), 0039 (Application reaches engines through ports), 0041 (Amendment 1: card rules), 0035.

- **Safety:** no. Read-only recomputation from stored bars; the output is a local HTML file of the existing kind.

## Goal
Every trade card answers "why did this rule fire here": for the decision bar of the trade, each condition of the setup, trigger and invalidate lists with its truth (true, false or unknown) and the value of every feature it read (including the lagged ones), computed by the same engine that made the trade. If the recomputation does not reproduce the trade, the export stops and says so.

## Scope
**In:** `ISimulationEngine.Explain`; `TradeExplanation` and its parts in `Domain.Research`; a trace hook in `EntryScanner` (internal, off unless asked); a value reader over the bound condition; the extraction of the full input reader from `RunSimulationHandler` into an internal helper that `BuildTradeCardsHandler` also uses; the equality guard and `simulation.cards_mismatch`; the new section of `TradeCardHtml`; the same section in the verification pack's cards; export format `xd-sim-export-4`; the hand-check protocol note.
**Out:** a trace for trades that have no card; a trace stored in `SimTrade.EntrySnapshotJson` or in the result store (that field belongs to doc 09 §3 and P6-04's side table); a chart of the features; any new endpoint or screen; explanations for the exit (the exit is a rule table, shown by the timeline already); costs.

## Acceptance criteria
1. **Section on the card.** Given a trade of ORB BUY (trigger only), when the card is built, then it shows under "conditions at the decision bar" the decision time, the evaluation timeframe, and for each of `setup`, `trigger` and `invalidate` that exists: the mode, each item's text, its truth, and for each feature read, its canonical name, its lag, and its value (invariant culture, up to 6 significant digits, `unknown` for not ready). For ORB: `close > or_high(or_min) and close[1] <= or_high(or_min)`, true, with `close` (lag 0), `or_high(15)` (lag 0), `close` (lag 1), `or_high(15)` (lag 0).
2. **Hand values.** Given a fabricated ORB BUY day written for this test (opening range high 101.20, previous 15m bar closing at 100.90, trigger bar closing at 101.60; the numbers are this spec's, the fixture is the build's), then the section prints the trigger item true and the four reads `101.6`, `101.2`, `100.9`, `101.2` (ORB has only a trigger, no setup or invalidate).
3. **Same engine, same list.** The values come from the replay's own frame and bar list (ADR 0037 R5), not from a second implementation: a test that changes the feature values the frame reports (a stub feed) changes the section.
4. **The guard.** Given the recomputation does not produce the recorded trade (every field of `SimTrade` equal except `Costs` and `Costing`, which are applied after the window cut and are not recomputed here), when the cards are built, then the export fails with exit 1, nothing is written, and the error `simulation.cards_mismatch` names the instrument and the first field that differs; given the setup is not true, the trigger is not true, or the invalidate is true at the recorded decision bar, the same error with that reason.
5. **Unknown is shown.** Given a condition that is unknown at the decision bar of a trade (it cannot be for a trigger that fired, but can for an `invalidate` or an `any` list item), then the section prints `unknown` and the value `not ready` for the feature, and the rule "unknown never fires" is stated once on the card.
6. **No second read per card.** The explanation is computed once per instrument in the same second read as the chart (C2 of P3-04c): one bar read, one input build, one replay with the trace asked for all the chosen trades of that instrument.
7. **Caps.** A card with the section stays under the 150 KB page limit; a condition list is capped at 100 items and a condition at 64 distinct reads (the compiler's own limits), so the section cannot exceed a few KB; a test with the largest allowed strategy checks the size.
8. **Inert, escaped, deterministic.** The section passes the C5 rules (no script, link or image; every dynamic string through `Html.Text`); two builds of the same run give byte-identical cards; no clock, no path.
9. **Every card writer.** `simulate --cards` and the verification pack (`VerifyPackCommand`) both write the section; the old line "conditions at the decision bar: not in this export (P3-04d)" no longer exists in the code (a test greps the rendered output of both).
10. **Refusals stay.** A strategy the engine cannot run still fails before cards; a run whose strategy needs the market context (`simulation.needs_context`) is not run at all, so no card exists for it.
11. **Cost.** For `--cards 200` over about 200 instruments the added time is under the read time (the replay of one instrument is about 34 ms, ADR 0037 Amendment 3 and the benchmark `Replay_phases_for_synthetic_instruments`); for `--cards 5` under 1 s.
12. **Format and docs.** The export format string becomes `xd-sim-export-4`; the manifest, the run key and the exit codes of P3-04b1/b2/c are unchanged; ADR 0041 gets an amendment (card rules); doc 11 and the P3-09 hand-check note mention the section.

## Contract
- **Port (Application, Domain values only):** `ISimulationEngine.Explain(IPreparedStrategy strategy, InstrumentReplayInput input, IReadOnlyList<ExplainRequest> requests) → ExplainResult`. `ExplainRequest(TradeKey, DecisionEpochSeconds, Side)`; `ExplainResult(InstrumentReplay Replay, IReadOnlyDictionary<string, TradeExplanation> ByTradeKey)`. Pure, synchronous; the errors of `Replay` apply; a request that matches no candidate returns no entry for its key (the handler turns that into the mismatch).
- **Domain (`Domain.Research`):** `TradeExplanation(DecisionEpochSeconds, Timeframe, IReadOnlyList<ConditionSectionTrace> Sections)`; `ConditionSectionTrace(SectionName (setup|trigger|invalidate), ListMode Mode, IReadOnlyList<ConditionItemTrace> Items)`; `ConditionItemTrace(Path, Text, TruthState (True|False|Unknown), IReadOnlyList<FeatureReadTrace> Reads)`; `FeatureReadTrace(Name (canonical, e.g. "or_high(15)"), Timeframe, Lag, double? Value)` (null = not ready). All records compare by value.
- **Engine (`XDrishti.Simulation`/`Strategies`):** `EntryScanner` gets an internal `Observe(Action<DecisionTrace>)` set by the replay when requests exist; at each decision step it calls the hook only if `frame.LastBarTime` matches a requested decision epoch, after the normal evaluation, so a normal run allocates nothing extra. `CompiledCondition.Reads` (new, public, immutable) lists, in text order, each feature read with its lag and span (from the bound tree: the `BoundFeature` nodes); `BoundCondition.ReadValues(frame)` returns the value of each read through `frame[handle]` and `frame.At(handle, lag)`. The truth comes from the evaluation the scanner already did (`_truths`), not from a second evaluation. `InstrumentReplayer.ReplayCore` gets the observer parameter it already has for tests; `SimulationEngineAdapter.Explain` maps the port.
- **Application:** `InstrumentInputReader` (internal, `Application/Research`) extracted from `RunSimulationHandler.ReadInstrumentAsync` (`BuildTradeCardsHandler` has its own, different `ReadInstrumentAsync`; the new `InstrumentInputReader` extends that one and the run handler's reader is moved onto it) (bars read with `SimulationBounds`, factors, tick, the CSV-adjusted guard, calendar, options) with its tests moved unchanged; `RunSimulationHandler` and `BuildTradeCardsHandler` both use it. `BuildTradeCardsQuery` gains the prepared strategy and the `ReplayOptions`/calendar facts of the run (same process as the run: the verb holds them; a stored run read later has no strategy handle and gets no section, which the card says: "conditions: not recomputed for a stored run"); `TradeCardData` gets a last optional member `TradeExplanation? Explanation`. The input is built gross (`Costs` null): costing happens after the window cut and does not change a gross field (ADR 0042).
- **Errors:** `simulation.cards_mismatch` (conflict, `SimulationErrors.CardsMismatch(symbol, field, detail)`), beside `cards_stale`; exit code 1 as for stale; log event with the next free id at build time (4411 is taken).
- **SimExport:** `TradeCardHtml` renders the section (heading `conditions at the decision bar`; one table per section; columns: condition, truth, reads); `ExportFormat = "xd-sim-export-4"`; `PackIndexHtml`/pack cards use the same writer.
- **No API, data or settings change.** `scripts/gen-api.sh` not needed (no endpoint); the verbs' help text updated.

## Non-functional
One extra replay per instrument that has a chosen trade, in the order of the run's universe, one instrument's bars in memory at a time (as C2). Allocation: the unrequested path adds one null check per decision step (the allocation tests of the scanner stay at 0 bytes per step). Determinism: values are doubles printed by the shared number formatter. Security: HTML rules of C5; no path, no clock.

## Test plan
- **Unit (Strategies):** `CompiledCondition.Reads` for `close > or_high(or_min) and close[1] <= or_high(or_min)`, `crosses_above(close, vwap)` (the lag of the previous value is 1), `tf("1D").close > tf("1D").ema(20)`, a condition with no read (`time >= "09:45"`), a parameter-only read; read values against a hand frame.
- **Unit (Simulation):** the trace at a decision bar equals the scanner's own truths (all fixtures F1 to F17b of the simulator tests produce a section whose truths are consistent with the candidate: setup true, trigger true, invalidate not true); the observer is called once per requested decision and never otherwise; a request for a bar that is not a decision returns no entry.
- **Application:** `InstrumentInputReader` equivalence (the run record of a fixture run is byte-identical before and after the extraction); mismatch cases (a trade edited by hand in the record gives `cards_mismatch` naming the field; a changed stub bar list gives `cards_stale` first); one read per instrument.
- **SimExport:** golden cards for ORB BUY (criterion 1/2 values), ORB SELL, a `VWAP_PULLBACK` BUY with two lags of `vwap`, an `any` list with one unknown item; escaping of a hostile condition text; size of the largest strategy; byte-identical rebuild.
- **Pack:** `VerifyPackCommand` cards carry the section; the pack key changes with the format string.
- **Architecture:** Application still names no engine type (`ResearchLayeringArchitectureTests`); the port namespace holds interfaces only; no wall-clock or file reads in the adapter (IL scan).
- **Fixtures with hand numbers:** the ORB day of criterion 2, 15m bars 09:15 to 09:45 (opening range = the first bar: high 101.20), bar 09:30 close 100.90, bar 09:45 close 101.60 with a decision at 10:00 close; a flat day where the trigger is false for contrast.

## Decisions (researched)
**D1 — Go.** *Reasons:* the owner asked for rule intent to be checkable by reading (the early look at cards) and the roadmap says the check of `BASE_BREAKOUT` needs the conditions or a hand recompute; the automated gate (P3-09d) does not explain a trade, and the assistant of P9 will need the same trace to answer "why did this fire". The cost is about two days and it touches no stored data. *Rejected:* leaving a line on the card (P3-04c's stopgap; a reader cannot tell a mis-written rule from a correct one without it); storing the trace in `SimTrade` (a schema bump and a column in every run for a few hundred cards).
**D2 — Recompute with the engine, do not re-implement.** The trace is read from the replay's own frame after the normal evaluation, so it cannot disagree with the trade by construction, and a disagreement is a real signal (data changed, engine changed). *Rejected:* the feature extractor of P6-04 (`TradeFeatureExtractor`), which feeds sessions the replay leaves out and says so ("a warm-up can differ slightly"): a card must not be allowed to differ.
**D3 — Mismatch is an error, like stale.** The cards claim to explain the recorded trade; if the replay does not reproduce it, an export with a quiet "differs" note would hand the owner exactly the false comfort the project avoids. Exit 1, nothing written, the first difference named. *Rejected:* a warning on the card.
**D4 — Gross recompute.** Costs are applied after the window cut and never change entry, stop, target, exit or R exact (ADR 0042), so the guard compares everything but `Costs` and `Costing`; reconstructing the charge sheet is not needed.
**D5 — Values with lags, not only the current bar.** A rule such as `close[1] <= or_high(or_min)` is only checkable if the lagged value is printed; `FeatureReadTrace.Lag` carries it. The value of `crosses_*` operands is shown at lag 0 and at the lag the call adds.
**D6 — Stored runs get no section.** A run read back from the result store has no strategy handle and may have been made with a strategy version that is no longer the stored one; cards from it say so instead of recomputing with whatever is current (the hash in the run record would catch a different text, but the prepared handle is not in the record).
**D7 — Size.** The roadmap's 1.3 days assumed the trace; the extraction of the input reader, the mismatch guard and the pack path are the extra 0.7 (the row of P3-04d lists the extraction itself).
**D8 — Format bump.** `ExportFormat` is already `xd-sim-export-3` (the P4-01 legs), so the card section makes it `xd-sim-export-4`; the card bytes change for every run; `ExportKey` already covers the card hashes, so an old export is correctly "different", not "unchanged".

## Risks and honest limits
The section shows what the rule read, not whether the rule is a good idea; a true trigger on a well-formed rule is mechanics, not edge. A condition read through `tf("1D")` shows the daily value as of the last closed day, which is correct and can surprise a reader who expects today's. For a swing strategy the decision bar is the 15:29 bar of the day. Features of the market context are not shown because the simulator refuses them (`needs_context`, finding for the index). A very long condition list makes a long card (capped by the compiler limits).
