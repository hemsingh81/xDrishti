## Goal
The owner can run a built-in strategy over a few instruments or a basket from one command, `scripts/simulate.sh`, and gets under `data/exports/sim/<run-id>/` the files of b1 (`trades.csv`, `open_at_end.csv`, `run.json`, `README.txt`, `manifest.json`), the banner and a summary on the console, and the timing of the run. Nothing prints a performance statistic. The tick unit of the master list is checked before the first real run and before any bar is read. The verb adds no API, no table and no migration: it is a host around the handler of P3-04a and the library of b1.

## Definitions (decisions the tests pin)
All dates are India dates. Decisions below were open questions or hidden assumptions of the first drafts; the owner may revert any (recommended, the owner confirms at approval).

**D1 — The command line, the exit codes, the script.**
```
simulate --strategy <id> (--symbols <a,b,…> | --basket <name|id>) --from <yyyy-MM-dd> --to <yyyy-MM-dd>
         [--timeframe <5m|15m>] [--param <name>=<number>]… [--fills modelled|no-slippage] [--acknowledge-csv-adjusted] [--force]
simulate --list-strategies
```
Quote a symbol list in the shell: `--symbols 'M&M,RELIANCE'` (the usage text says so).
- **Parsing is strict** (pure, `SimulateOptions.Parse(args)` giving options or usage errors): `--flag value` and `--flag=value`; a flag at most once except `--param`; an unknown flag (`--cards` and `--symbols-file` are unknown here), a missing value, a repeat, none or two universe flags, a missing `--strategy`, `--from` or `--to` are usage errors. `--strategy` is **case-sensitive** as the factory is (`orb` is refused with the list of ids; the run id lower-cases it). Dates are `yyyy-MM-dd`, invariant, strict. A `--param` value is a finite number in the invariant culture (`NumberStyles.Float`; `NaN`, `Infinity`, hex and thousands separators refused); names match `[a-z][a-z0-9_]{0,31}`. `--to` has no default (a run names its window). `--timeframe` defaults to the registry's default for the strategy. `--fills modelled` (default) is `FillRules.Default` (entry limit +0.1 %, the slippage of doc 16); `no-slippage` is the same 0.1 % entry limit with `SlippageConfig.None`, **which also turns off the tick rounding of fills** (`FillBasis.Exact`), for the hand recomputation of P3-09; its label is `fills: modelled, no slippage, no tick rounding of fills` (b1 E5) so that "fills modelled" is never dropped; no other fill number is exposed. Flag names avoid `--urls`, `--environment` and the other keys the host reads.
- **Exit codes.** **0**: the files are written, or the identical export was already there and verified (`unchanged`); a run in which every instrument is skipped is a success with a warning line (the skip list is the answer). **1**: refused, nothing written: `simulation.invalid`, `simulation.strategy_invalid` (the problem list on stderr, one `path: code: message` per line, at most 20), `simulation.slippage_invalid`, `simulation.fill_rules_invalid`, `simulation.basket_not_found`, a symbol that is not found, ambiguous or invalid, a basket name that does not resolve, the tick gate, an existing different or modified export without `--force`, an existing `.previous` folder with `--force`, a symbolic link where the writer would write. **2**: the command line or the configuration is wrong (usage text on stderr, no stack): includes `Export:Directory` unset, not absolute, or with a missing parent. **3**: an unexpected failure (database unreachable, a file cannot be written, an exception of the engine): the writer's staging folder is removed; the message is the exception type and its message cut to 300 characters; the stack goes to the log only. **130**: cancelled with Ctrl-C (the conventional code for SIGINT): the staging folder is removed and no stack is printed; if the cancellation came after the final rename the export exists and complete, and the message says so. `--list-strategies` is 0.
- **The script** `scripts/simulate.sh` (macOS, in the style of `dev-api.sh`): `source _env.sh`, reads `Database__Password` from the Keychain item `xdrishti/db/app` (the only secret), exports `Export__Directory="$ROOT/data/exports"` and `DOTNET_ENVIRONMENT=Development`, `cd`s to `backend/src/XDrishti.Api`, and runs `dotnet run -c Release --no-launch-profile -- simulate "$@"`, returning the verb's exit code. It reads no broker vault key and no owner secret, does not echo the password and does not use `set -x`. The stack must be up (`deploy/xd-up.sh`) with the developer DB port (`compose.dev.yaml`, 127.0.0.1:5433, the default connection string of `appsettings.json`). The export root is configuration, never a flag.

**D2 — The host, the dispatch, the cancellation.** `Program.cs` is top-level code, so the logic is in testable classes. `VerbDispatch.Of(args)` (internal, pure) returns `Simulate` only when `args[0]` is `simulate`, and `Program.cs` tests it **first**, before `--healthcheck` and before the existing `args.Contains("migrate")` and `args.Contains("owner-reset")` tests (which match anywhere in `args` and are left as they are: a symbol list must not select them). `SimulateHost.Create(IReadOnlyDictionary<string, string?>? overrides = null, Action<IServiceCollection>? configure = null)` builds the host: `Host.CreateApplicationBuilder` (the generic host; `AddXDrishtiDefaults` accepts any `IHostApplicationBuilder`) with **no command-line arguments** (so `--key value` pairs never become configuration), `ContentRootPath = AppContext.BaseDirectory` (where the web SDK copies `appsettings.json`, so the default connection string is found whatever the working directory of `dotnet run` is; UNVERIFIED until the script smoke of AC 12), `AddApplication()`, `AddInfrastructure(configuration)`, no `AddApi()`, no `RequireBrokerVaultKey()`; the service provider is built with `ValidateOnBuild = true` and `ValidateScopes = true` (as `FeedHostTests` does: the two registrations are build-valid, so a missing service fails at build, not in the middle of a run); the host is built but not started (hosted services do not run, `ValidateOnStart` is not triggered). **Logs go to stderr** by configuration: the host sets `Serilog:WriteTo:0:Args:standardErrorFromLevel` to `Verbose` (the console sink of `appsettings.json` is element 0; UNVERIFIED that the override merges into that element), so stdout holds only the banner and the summary; the test asserts the configuration value, it does not redirect `Console`. `overrides` carries configuration values for tests and `configure` replaces services (a fake `IBarStore`, a hook) for the tests of the other slices. `SimulateCommand.RunAsync(args, services, console, exportRoot, ct)` returns the exit code, as `OwnerBootstrap` does. In `Program.cs` only, `Console.CancelKeyPress` sets `e.Cancel = true` and cancels the token, so the process does not die before the staging folder is removed.

**D3 — The built-in registry.** `BuiltInStrategies` (`XDrishti.Simulation.Replay`) is rebuilt around a table of entries `BuiltInEntry(Id, Description, AllowedTimeframes, DefaultTimeframe, Parameters[name, default, note], Build)` (`internal`); today one entry, `ORB` (5m and 15m, default 15m, `or_min` 15, `rr` 2.0). `Ids`, `Build` and `Prepare` read the table (the refusals for an unknown id or parameter are unchanged and P3-04a's tests are the safety net), and `Catalog` gives the entries. The port gains `IReadOnlyList<BuiltInStrategyInfo> BuiltIns` (a Domain value in `Domain.Research`); the adapter maps it. **P3-05 and P3-06 add one entry and their builder in `XDrishti.Strategies.BuiltIn`**; the verb, the script and the export do not change. The architecture test `SimulationArchitectureTests`, which lists the types of `XDrishti.Simulation.Replay` (lines 165 and 168 of today's file), is edited on purpose for `BuiltInEntry`, and `DomainResearchSurfaceTests` for `BuiltInStrategyInfo`. A test fails when an id is in `Ids` without an entry and when an entry does not prepare with its own defaults, and the id of every entry is accepted by `RunId.Of` (b1 E6: ids such as `VWAP_PULLBACK` and `BASE_BREAKOUT` contain `_`, written `-`). When P3-02d stores strategies, the port changes (ADR 0039 decision 2) and `--strategy` takes a stored name; this table is then the seed list.

**D4 — The universe** (exactly one flag; the handler's own validation of 1 to 2,000 ids still applies).
- `--symbols a,b,c` (commas or spaces; entries `[A-Za-z0-9:&._-]{1,40}`, since `M&M` and `BAJAJ-AUTO` are real instruments) goes through `ResolveInstrumentsQuery` (no new port): a ticker (`RELIANCE` means `NSE:RELIANCE`), a canonical symbol or the ISIN of a share or ETF, compared ignoring case. It reports `not_found`, `ambiguous` (an ISIN that does not name exactly one still-listed row; one listed and one retired resolves to the listed one) and `invalid`. **Nothing is guessed:** any unmatched entry refuses the run (exit 1) and lists every unmatched entry with its reason; duplicates collapse to the first and are counted. A retired instrument that matches is kept and marked in the summary. Every instrument type is accepted (one with no bars is skipped as `no_bars`). The run order is the order given. `Symbol` in the record is the canonical symbol with its exchange prefix (`NSE:RELIANCE`; `BarsInstrument.Symbol` is `canonical_symbol`).
- `--basket <name|id>`: a GUID is passed as it is (the handler refuses a portfolio, archived or unknown basket as `simulation.basket_not_found`); anything else is compared, ignoring case, with the names of the active **manual** baskets from `ListBasketsQuery(false)` (active names are unique ignoring case: index `ux_baskets_active_name_lower`). No match is a refusal that lists up to 20 manual basket names. The label is `members as of today`. An empty basket is an empty run that succeeds.

**D5 — The pipeline and the files.** Order: parse, check the configuration (`Export:Directory`), build the host, resolve the universe (D4), the tick gate (D7), run `RunSimulationQuery`, then with b1: `RunLabels.Of`, render `trades.csv`, `open_at_end.csv`, `run.json` (format string `xd-sim-export-1`) and `README.txt` through `ExportFolderWriter` into `<root>/sim/<RunId.Of(...)>/` with `ExportManifest`, the basket id from `Run.Universe.BasketId`, no extra lines; print the banner and the summary. P3-04c adds entries and extra lines and passes `xd-sim-export-2`; nothing here is modified for it. The decisions of the layout, the overwrite policy (`unchanged` after hashing, `--force` renaming to `<run-id>.previous`, one previous copy), the permissions and the path guard are b1 E7 and are not repeated. A refusal of the writer maps to exit 1, a configuration error to 2, an I/O failure to 3.

**D6 — The banner, the summary and the rule against statistics.**
- The **banner** is `RunBanner.Text(labels)` printed first; it is the same text as `labels` in `run.json` and as `README.txt`. The **summary** follows: the run key and the folder path; `database: <host>:<port>/<database>` (no user, no password: it shows that the configuration was found); the instruments run and skipped **by reason**; the candidates, the trades (one total), the trades the data cut short (`open at end`) and the entries a flagged day suppressed; the replay's ticks table (the distinct converted ticks with a count and one example symbol); the notes of the tick check for non-share types; the notice of leftover `.staging-*` folders; the phase times and instruments per second. **The summary prints only the phases the verb can observe (resolve and gate, run, render and write); the split of the run into validate and prepare, read, replay and assembly is the handler's finish line (event 4404) on stderr (ADR 0037 Amendment 5).** It does not print the trades split by exit reason or side (counts of stops and targets per side are a hit rate in words) nor any R value.
- **The scan that pins it** (b2 AC 9): case-insensitive, **whole-word** match on the exact token list of b1 AC 6 (`win`, `wins`, `winner`, `winners`, `winning`, `loss`, `losses`, `loser`, `losers`, `losing`, `hit`, `hits`, `expectancy`, `profit`, `profits`, `profitable`, `drawdown`, `average`, `mean`, `sum`, `total`, `percent`, `percentage`, `rate`, `ratio`), applied to the **console text (stdout and stderr) of a run** and, in P3-04c, to the text of the cards and the index; not to `run.json` keys (it has a `totals` object), not to the CSV. Whole-word matching is what keeps `window` (a word of the log line), `summary`, `consumed` and symbols such as `TATACONSUM` from being false hits, and the reworded `touch_is_fill` text no longer contains `winner`. The test fixtures use symbols from a fixed list that cannot collide with a token. A second check on the **summary part only** (not the banner, whose text is golden-pinned): no match of `\d\s?%`.

**D7 — The tick gate wiring, the one-time read, the measurement.**
- **What the code says (read 2026-10-18).** The importer stores the master's `TICK_SIZE` as parsed (`DhanMasterParser` → `MasterRow.TickSize` → `CatalogBuilder` → `COPY`; no conversion), `tick_size numeric(14,4)`; `BarsInstrument.TickSize` and `InstrumentSummary.TickSize` return it untouched, and `TickSpec.FromMasterPaise` divides by 100. So the stored unit is the master's unit, **paise per ADR 0038 item 6, which read the 75-row sample extract (`1.0000`, `5.0000`, `10.0000` for NSE shares of series EQ), not the stored table: UNVERIFIED.**
- **The gate, before the read.** Once the universe is resolved the verb knows every instrument's stored tick and type without reading a bar: `GetBasketMembersQuery` gives `InstrumentSummary.TickSize` and `Type`; for symbols one `GetInstrumentQuery(id)` per id gives `InstrumentDetail.TickSize` and `Type` (at most 2,000 small queries). `Type` is a string (`share`, `etf`, `index`, `future`); the verb maps it with `InstrumentTypeCodes.TryParse`, an unknown code is not gated and appears in the notes. It builds `TickProbe`s and calls `TickUnitCheck.Suspect` (b1 E8). A non-empty result is exit 1 before any bar is read, naming up to three instruments with the stored and converted values and pointing to ADR 0038 item 6. Index, future and option rows are not gated (b1 E8, with the fixture evidence).
- **The one-time read (an action of the owner, or of an agent with his stack, before the first real run; not a question).** With the stack up, read the tick of **three** real instruments by **one method, the Instruments page's tick column** (`GET /api/instruments/{id}` or `psql` are alternatives for an agent): **the share with the smallest stored tick, one ETF, and one other share** (the smallest stored tick separates the units: a stored `1.0000` is paise, a stored `0.0100` would be rupees), and write the three symbols, their stored values, the date and the method into ADR 0038 item 6, replacing "UNVERIFIED". If it cannot be done the slice can merge, no real run is quoted, and the gate is the net.
- **The measurement.** The summary prints the wall time of the phases the verb can observe (resolve and gate, run, render and write) from `TimeProvider`, and the read/replay/assembly split is the handler's finish line 4404 on stderr; they are logged and printed, never stored in a file. The owner runs the whole 214-instrument universe once (UNVERIFIED that a basket of them exists; otherwise `--symbols "$(paste -sd, tickers.txt)"` with the tickers of `data/Stocks_CSV`) and the figures replace the "about 32 s, UNVERIFIED" of ADR 0037 Amendment 3 in a new Amendment 5 (the estimate: 152 ms per instrument on invented data, the read 79 %). The merge does not wait for the owner's run. Timing and data-quality counts are not trading numbers; ISS-18 asks for them.

**D8 — Logging, secrets, failure.** Five `[LoggerMessage]` lines in `Simulate/SimulateLog.cs`, event ids 4405 to 4409 (4401 to 4404 are taken; the highest other id in `src` is 4324; `LogEventIdTests` keeps them unique): verb started (strategy id, universe kind, count, window), refused (error code, number of problems), export written (run id, files, bytes), unchanged (run id), failed (exception type). The handler's own lines 4402 to 4404 are emitted in the same run. Never a password, a connection string, a path outside the run id, a bar, a price or strategy text; the verb prints and logs no configuration value except the database host, port and name of the summary. The only secret in the process is `Database__Password`, which the verb's own code never reads. An unexpected exception ends the run with no partial export.

**D9 — Decisions that were assumptions, with their reasons** (the full text goes into ADR 0041, as built: P3-03d took 0040).
- **The pipeline is in the host, not in an Application handler**, because ADR 0039 forbids Application from referencing `XDrishti.SimExport` (a renderer is not a port) and a handler cannot touch the file system. This is a deliberate exception on the `OwnerBootstrap` precedent (a host step that calls handlers). Consequence: the Lab of P5 will call the same handlers and the same library but must re-order the pipeline itself; `SimulateCommand` therefore holds only the order (resolve, gate, run, render, write) and no decision that belongs to Domain (the gate, the labels) or to the library.
- **One previous copy (`.previous`) on `--force`, never deleted by the verb**, because a copy is up to a few hundred megabytes (b1 E4), unbounded growth is a disk problem, and deleting the owner's earlier export is not the verb's call (b1 E7).
- **The gate threshold is 0.01 rupee for shares and ETFs** (b1 E8): the smallest tick the NSE has for a share; a net for a unit mistake that `TickSpec`'s range (0, 1] cannot see.
- **The host is the generic host without `AddApi()`**, because the verb needs the handlers and the ports, not endpoints, authentication or the vault key, and a started web host with an empty vault key throws `OptionsValidationException` (as `BrokersApiTests` shows).
- **Exit 130 for Ctrl-C** (the shell's conventional code) and 3 for failures, so that a script can tell a cancelled run from a broken one.

## Acceptance criteria
Numbered, each testable. Fixture series are invented (P3-03's F-days; P3-04a's seeding through the real stores); nothing is read from `data/`. Tests are in `XDrishti.Api.IntegrationTests` (Testcontainers; the verb is called as `SimulateCommand.RunAsync(args, SimulateHost.Create(overrides).Services, console, tempRoot, ct)`, the way `OwnerBootstrapTests` calls `OwnerBootstrap`, with the suite's container connection string in `overrides`; the exact name the suite exposes for it is UNVERIFIED), `XDrishti.Simulation.Tests`, `XDrishti.Infrastructure.Tests`, `XDrishti.Domain.Tests` and `XDrishti.Architecture.Tests`. The dispatch, host and parsing tests need no database.
1. **Dispatch.** Given the argument tables of `VerbDispatch.Of` (`["simulate", …]`, `["migrate"]`, `["owner-reset"]`, `["--healthcheck"]`, none, `["simulate", "--healthcheck"]`, `["simulate", "--symbols", "migrate"]`, `["x", "simulate"]`) then only `args[0] == "simulate"` selects the verb (and `["simulate", "--healthcheck"]` is a usage error, not the health probe), the other verbs are selected as before, and `simulate --symbols migrate` does not select `migrate`.
2. **The host.** Given `SimulateHost.Create()` then it builds with `ValidateOnBuild` and `ValidateScopes` true, resolves `IQueryHandler<RunSimulationQuery, …>`, `ResolveInstrumentsQuery`'s handler, `ListBasketsQuery`'s handler, `GetInstrumentQuery`'s handler and `GetBasketMembersQuery`'s handler, validates no `BrokerVaultOptions` (an empty `BrokerVault:Key` does not fail), starts no hosted service, and carries `Serilog:WriteTo:0:Args:standardErrorFromLevel = Verbose` in its configuration; the process arguments `--urls` and `--environment` given to the test process do not reach its configuration.
3. **Parsing.** Given a table of at least 30 command lines (valid: both flag forms, repeated `--param`, each universe flag, `--fills no-slippage`; invalid: unknown flag including `--cards` and `--symbols-file`, repeat, missing value, two universes, no universe, missing strategy/from/to, `2026-13-01`, `2026-1-1`, `--param rr=NaN`, `rr=1e999`, `rr=0x10`, `rr=1,5`, `Rr=2`, `--fills fast`, `--fills exact`, `--strategy orb`, a symbol entry `$(x)`) when parsed then the valid ones give the options and the invalid ones a usage error naming the flag, identically under `de-DE` and `tr-TR`.
4. **Exit codes.** Given an unknown strategy id, an unknown parameter, `or_min` 20 on 15m, a symbol that matches nothing, an ambiguous ISIN, a basket name that matches nothing, a portfolio basket id, `From` after `To`, and a failing tick gate when the verb runs then the exit code is 1, the problem list is on stderr one `path: code: message` per line (at most 20), nothing is written under the export root, and **no bar was read** (neither `IBarStore` nor `IBarQueries` was called; the universe resolution and the gate may have read instrument rows, because the verb resolves the universe before the handler validates the request); a wrong command line, an unset, relative or missing-parent export root is 2 with the usage text; a host built with a connection string to a closed port (`SimulateHost.Create` override, not the started test factory) is 3 with no stack on the console and no folder left behind; **no stack frame text (`   at `) appears on stdout, stderr or the console log sink of a failure: the failure line is the type and the message cut to 300 characters, `SimulateLog.Failed` logs the type only (no exception object) and the host raises the EF Core logger to Fatal; a second Ctrl-C is not swallowed;** a token cancelled mid-run is 130 with no staging folder left, and a token cancelled by a hook after the final rename is 130 with the complete export present and the message saying so; a run in which every instrument is skipped is 0, writes the files and prints a warning.

## Non-functional
- **Performance:** no budget is asserted. The verb adds to P3-04a's run the gate's instrument queries (up to 2,000 small ones), one serialisation and the writes of b1 (hundreds of megabytes at the bound; b1 E4). The end-to-end figure for the owner's universe is the owner's run of D7: the estimate is about 32 s for the run (invented data) plus the export; UNVERIFIED.
- **Memory:** the run holds one instrument's bars at a time (P3-04a); the export streams (b1).
- **Security and privacy:** the verb connects as `xd_app` and writes nothing to the database; the script reads one Keychain item; no secret enters any file or line (AC 11); files `0600` in `0700` folders (b1).
- **Determinism and fail closed (NFR-3, NFR-4, NFR-7):** equal request and equal data give identical bytes; a gate failure, a refused overwrite or a failure writes nothing partial.
- **Observability:** the banner and the summary are the user-facing report; the five log lines are the operational one.

## Risks
- **The tick unit is wrong in the stored table.** A factor of 100 on every limit and slipped fill. The one-time read is the guard and the gate before the read the net; the gate catches rupees stored as paise, not another wrong factor.
- **The generic host without `AddApi()` lacks a service a handler needs, or the Serilog override does not merge.** UNVERIFIED until AC 2 and AC 12; the remedy is to register that service in `SimulateHost`, not to add `AddApi()`.
- **`dotnet run` from a script is slow to start**, and the content-root assumption (D2) is untested until the smoke of AC 12.
- **Merge conflicts with P3-03d and P3-03c** (columns, spellings, labels, flags, the ADR number): see *Hand-overs* and b1 *Merge order*.
- **A reader mistakes a clean file for a result.** Mitigation: the banner on the console, in `run.json` and in `README.txt`, with its engine line (what the oracle comparison showed and that charts were not checked, ADR 0047), no aggregate anywhere.
- **The gate's threshold (0.01 rupee) rejects a real share or ETF** with a finer tick: UNVERIFIED that the owner's data has one; the remedy is to leave it out of the universe.
