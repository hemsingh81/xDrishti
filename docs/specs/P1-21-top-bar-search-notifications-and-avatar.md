## Analysis
Prototype top bar, left to right: menu toggle (phones) · page title · **"Search or jump to… ⌘K"** button (command palette) · status pills (market open + NIFTY, services health) · **bell with unread badge → Notifications drawer** · theme toggle · **user button** (soft-indigo avatar with the owner's initial + name + chevron → menu).
Ours has: menu toggle, title, accounts status control (P1-16d), theme toggle, user menu. Missing: search/jump palette, notification bell + window, chevron on the user button. Bug: the avatar initials ("HS") are clipped — the avatar sits in the button's `startIcon` slot, where MUI forces a 20 px font and the two letters overflow the 28 px circle.
Data reality: market status/NIFTY need market data (P1-11/P1-12/P2-07) and services health needs the service framework (P1-13) — **not built yet, so not faked**; the header's accounts control stays as the status element until then. Notifications have no backend table yet, so this story derives them **only from real state we already have** (accounts' connection and API-key expiry) behind a small interface that later sources (plan tickets, alerts, services — P7/P2/P1-13) can feed.

## Goal
A complete, professional top bar that matches the prototype where real data exists: quick search/jump, a working notification bell and window, and a clearly visible avatar.

## Design decisions (defaults — object to any)
1. **Avatar:** prototype style — 28 px circle, `accentSoft` background, `accent` bold 13 px initials (contrast ≥ 4.5), not in `startIcon`; the button gets the name (shown from `lg`) + a chevron (from `sm`); accessible name "Account menu, Hem Singh". Initials from the display name (first letters of up to two words).
2. **Search or jump to… (⌘K / Ctrl+K):** a search-style button (min-width 240 px with the `⌘K` hint from `lg`; icon-only below `lg`) opening a lazy-loaded palette dialog: a text field, grouped results — *Pages* (every navigation item; planned ones marked with their phase and routed to their "coming soon" page), *Accounts* (each account → `/accounts?account={id}`), *Actions* (Toggle dark mode, Go to Accounts, Go to Settings). Arrow keys move, Enter opens, Escape closes, fuzzy-ish substring match on label/keywords, empty state "No matches". Global shortcut registered in the shell; does not fire inside text inputs except with the modifier.
3. **Notifications:** bell `IconButton` with unread-count badge (max "9+") opening a right-hand **Drawer** "Notifications": newest/most urgent first; each item = coloured icon chip (warn/error/info), text, relative time, and an **Open** link; header has "Mark all read"; empty state "You're all caught up". Items (derived, deterministic, no timers needed beyond the existing clock tick): per account — *not connected* ("Dhan · Main is not connected" → Connection tab), *token expired*, *token expires within 2 h*, *API key expires within 30 days / expired*. API-key expiry days are Indian (IST) calendar days: from 00:00 IST on the expiry day the key counts as expired. Item id = `{accountId}:{kind}:{discriminator}` so a changed situation (new expiry) is a new, unread notification. Read state is a per-viewer convenience kept in `localStorage` (try/catch, renders fine without it). Opening the drawer does not auto-mark read; "Mark all read" and following **Open** do.
4. **Architecture:** a `notifications` feature (`features/notifications/`: `api`/`lib` for the pure derivation `deriveNotifications(accounts, now)` from the accounts list, `components/NotificationBell`, `NotificationDrawer`, `index.ts` exporting a lazy bell) so later sources register without touching the top bar; the palette in `features/search/` (or `app/layout/`) lazy-loaded; the top bar stays in the initial bundle but both heavy parts load on first interaction (button shells are tiny). Feature imports only via `index.ts`; initial bundle ≤ 200 KB gzip (currently ≈ 190 KB — measure; if a shell is too large, load the bell lazily like HeaderAccounts).

## Acceptance criteria
1. Avatar initials fully visible in light and dark (test measures no overflow by structure: initials rendered in the Avatar child, font size explicit; visual check by screenshot), chevron present, name hidden below `lg`, menu unchanged (name, email, Sign out).
2. Palette: opens with the button, ⌘K and Ctrl+K; lists pages/accounts/actions; keyboard navigation; navigates with the router; closes on Escape/selection; focus returns to the trigger; accessible dialog (labelled, combobox/listbox semantics with `aria-activedescendant`).
3. Notification derivation is a pure function with unit tests for every kind, boundary times (exactly 2 h, 30 days, expired), multiple accounts, none; ordering (urgent first, then newest) and stable ids.
4. Bell shows the unread count; drawer lists items with icon chips, relative times and Open links; "Mark all read" and Open update the badge; read state survives reload (localStorage) and a changed expiry yields a new unread item; empty state; works with accounts loading/error (bell stays usable, no layout shift).
5. Top bar layout at 360 px, 768 px and ≥ 1280 px without overlap or horizontal scroll (accounts control collapses as today, the page title hides below `sm`, search becomes an icon and the name hides below `lg`; at 360 px the controls total about 350 px).
6. Docs: doc 13 gets "Top bar" in §1e (elements, what is real vs later), the prototype note that market/NIFTY/services pills arrive with P1-13/P2; delivery plan story P1-21.
7. Tests (Vitest + Testing Library/MSW): avatar, palette (open, filter, keys, navigate), derivation, bell + drawer (badge, mark read, persistence with a fake storage, link navigation), top bar renders all controls; existing suites green; `scripts/check.sh` green; reviewer no blockers/majors; deployed and checked in the browser (light + dark).

## Non-functional
No backend/API change, no new dependency. Accessibility: all controls labelled, focus visible, drawer traps focus and restores it, badge count announced via the button's accessible name ("Notifications, 3 unread").
