- **Status:** Approved (owner, 2026-10-11: "calculate profit/loss in number, percentage, XIRR … for each holding as well as the full portfolio") · decision [ADR 0012](../adr/0012-holdings-acquisition-dates-and-returns-model.md)
- **Phase / roadmap row:** P2 — Portfolio monitor (P2-05 XIRR/returns + the Portfolio screen part of P2-08) · design refs docs/design/12 §2–§4 · depends on [P2-01](P2-01-holdings-import-with-dates-and-auto-refresh.md)

## Goal
The Portfolio screen shows, for every holding and for any group (all, account, bucket), what was invested, what it is worth, profit/loss in ₹ and %, and XIRR — computed from the lots and dates in P2-01 — plus the controls to import, sync and fix dates.

## Calculation (pure, tested, no I/O)
- **Per holding:** invested = Σ(open lot qty × unit cost); value = qty × last price; unrealised P&L = value − invested; P&L % = P&L / invested; **realised P&L** from closed lots = Σ(close qty × (close price − unit cost)) (marked estimated); day change is "—" until a previous-close source exists (P2-07).
- **XIRR:** cash flows = −qty×unit_cost on each lot's `acquired_on` (closed lots also +close qty×close price on `closed_on`) and +current value on the valuation date (today IST, or the last price time's date); annualised internal rate solving Σ cf/(1+r)^((d−d0)/365)=0 with Newton from a good guess and bisection fallback on [−0.9999, 100]; tolerance 1e-9. Shown as "—" when there is no negative or no positive flow, when the first flow is within 30 days of the valuation date, or when the solver does not converge; values beyond ±1,000 % are shown as "n/m". **Verified against spreadsheet XIRR** on committed sample cash-flow sets (acceptance below).
- **Groups:** Total, per account, per bucket: sums of the above; group XIRR from the union of all member cash flows (not an average).
- **Not included in v1 and stated in the UI:** dividends, brokerage/taxes, corporate-action adjustments (splits/bonus change quantity/average cost in Dhan's data and appear as a quantity change at the next refresh — flagged as a possible corporate action when the ratio is a clean split/bonus factor).

## Design
- **API:** extend `GET /api/holdings` rows with `invested, value, pnl, pnlPct, xirr, xirrState (ok|insufficient|n_m|no_data), realisedPnl, realisedEstimated, lotCount, earliestAcquiredOn, usesDefaultDate`; `GET /api/holdings/summary?accountId&bucketId` (totals + XIRR + counts + last sync + `defaultDateLots` count); `GET /api/holdings/{id}/lots` with per-lot P&L/XIRR; calculations live in Application (pure functions), endpoints thin.
- **Portfolio screen** (route `/portfolio`, replaces "coming soon"; lazy; P1-19/20/21 look; the reusable `Grid` and `Typeahead`): header with account selector (All / each account) and bucket filter; **summary tiles** (Invested, Current value, Unrealised P&L ₹ and %, XIRR, Realised (est.), holdings count) with honest "—"/tooltips; **sync bar** (last sync time/result, next auto run, **Sync now**, auto-refresh settings popover: Off / Every N minutes (market hours) / Daily at HH:MM IST); **holdings grid** (symbol, name, qty, avg cost, LTP, invested, value, P&L ₹, P&L %, XIRR, acquired (earliest + "default date" chip + lot count), bucket; sortable, searchable, pagination/scroll, flags for "not in master list"; dates are set in bulk in the **Import** dialog (set for all / for selected) and edited per lot in the row drawer — a bulk date change from the grid itself is deliberately not built); row drawer with lots (edit date per lot, P&L/XIRR per lot); **Import holdings** dialog (AppDialog): step 1 fetch preview (needs a connected account; clear message otherwise), step 2 table of rows with a date input per row, **"Set date for all"** and **"Set for selected"**, default date 2025-01-01 pre-filled (today when the account already has holdings), per-row "already imported" state, confirm → import; empty state "No holdings yet — import them from Dhan"; number formatting in INR with Indian grouping, tabular figures, gain/loss with sign and ▲▼ (never colour only).
- Account → Portfolio tab: replace the P1-16e "dates come from Dhan automatically" note with the real behaviour (dates are set when importing; link to the Portfolio screen) and add the auto-refresh settings there too (same fields as the popover, one shared component).

## Acceptance criteria
1. Calculator unit tests (pure): single lot, multiple lots, closed lots, same-day, < 30 days, negative returns, zero price, extreme values, non-convergence, group XIRR from the union of flows; **XIRR matches spreadsheet results (≤ 1e-6)** for ≥ 6 committed sample sets (values computed with Excel/LibreOffice `XIRR`, documented in the test file).
2. API returns per-holding and summary figures consistent with each other (sum of holdings = summary for invested/value/P&L; group XIRR from union); read-only, paginated, projections; < 200 ms for 500 holdings.
3. Portfolio screen: import flow with per-row and bulk dates (default 2025-01-01 / today rule shown), sync now, auto-refresh settings, grid with all columns, lots drawer with date editing, tiles, empty/loading/error states, a11y, 360 px → 4K, initial bundle ≤ 200 KB gzip (lazy route).
4. Date edits and imports update every figure immediately after refetch; lots on the default date are visibly flagged and counted in the summary ("12 lots use the default date").
5. Docs: 12 §4 (formulas, exclusions), 13 (Portfolio screen), prototype note; `scripts/gen-api.sh`, `scripts/check.sh` green; reviewer no blockers/majors; deployed and verified by the owner with real Dhan holdings.
