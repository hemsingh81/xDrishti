# P9-04 — Assistant chat screen

- **Status:** Draft (written 2026-10-24; decisions below were researched under the owner's delegation; the owner's Approved is still needed before an agent builds it)
- **Phase / roadmap row:** P9 — AI assistant, slice P9-04 of [P9-00](P9-00-ai-assistant-plan.md)
- **Design refs:** docs/design/13-reports-and-ui.md (Assistant row: "chat over your data; answers show numbers, query and chart; streaming chat panel") · 14 §4(2) · frontend/CLAUDE.md (structure, bundle, a11y, tests) · P8-00 D3 (honest states), D6 (read-only by construction), D7 (bundle) · P8-01 / ADR 0098 (`@/shared/analytics`, `npm run size`) · P9-00 citation rule, D7, D8, D15
- **Needs:** P9-03 (contract: the stream, `status`, `settings`, conversations, tool-calls; generated `schema.d.ts`; the fixture `assistant-turn.sse`), P8-01 (built). `get_report` and the other tools of P9-05 only change what the stored rows look like; the screen is generic over envelopes.
- **Size:** 3 agent-days (stream hook, reducer, parser 0.8; messages, citations, marks 1.0; gate states, settings dialog, history 0.7; tests, a11y, bundle 0.5)
- **Safety:** no. The screen reads, and posts a question to the endpoint; the one change it can make is the owner-only settings change that P9-03 gates with the password in the body. It starts nothing (the model server is started by the owner in a terminal), exports nothing, caches nothing offline.

## Goal
The owner opens Assistant, asks a question about their data and watches the tool calls, then the answer arrive; every answer sits above its tool calls with the rows and the evidence behind it, a figure the server could not find in a tool result is marked, and every unavailable state (switched off, model not running, loading, tools down, busy, nightly running) says what it is and what to do, without a spinner that never ends.

## Scope
**In:** feature `frontend/src/features/assistant/` (`api/`, `components/`, `hooks/`, `lib/`, `index.ts`); one lazy route `assistant`; one nav entry; the SSE client; the plain-text renderer; citation chips with expandable rows; the grounding banner and marks; conversation history; the settings dialog (owner act); states; tests; the bundle check.
**Out:** any backend change (no backend change; one shared/api edit, see AC 12); Markdown, HTML, links or images from the model (P9-00 D15); starting or stopping the model server; voice; file attachments; a floating chat panel on other screens (a later slice may add a Today tile); deleting a conversation (none exists); the Suggestions screen (P9-08); briefing display (P9-06's own slice); real charts if the shared lazy chart module does not exist when this is built (table form ships).

## Acceptance criteria
1. **Route and bundle.** Given the app, when `/assistant` is opened then the page is a lazy chunk; the nav has one new entry `Assistant` (icon `ChatOutlined`, section Research, after Strategy Lab, no `phase`); `npm run size` shows the entry + modulepreload total grew by at most **0.5 KB gzip** (route definition + nav entry + one icon) plus the `passwordCheckPaths` edit of AC 12 (a few bytes, counted in the same measurement); if headroom is under 3 KB the slice first frees space as `frontend/CLAUDE.md` requires; the new lazy chunk is at most 40 KB gzip (measured and printed; UNVERIFIED target). No Markdown library is added.
2. **Gate states (one per status, icon + word + reason; never a blank or an endless spinner).** From `GET /api/assistant/status`: `enabled=false` -> "Assistant is switched off" and a "Turn on" button that opens the settings dialog; `llm.state=down` -> "Model server not running" and the command `scripts/xd-ai.sh start` in a copyable code block (the page says the app cannot start it); `loading` -> "Loading the model, usually 20 to 105 seconds" with elapsed seconds since first seen and a poll every 3 s; `misconfigured` -> "The model server rejected the API key"; `tools.state=down` -> "Tool server not running" with the same command; `busy` and `nightlyRunning` -> composer disabled with the reason as visible text; `ready` -> composer enabled. While not ready the status is polled every 5 s and the screen switches by itself. Each state has a test asserting its words and that no number is drawn.
3. **Evaluation banner.** `evaluation.state=not_yet_evaluated` -> a persistent "Not yet evaluated: answers have not been checked against the test set" line above the messages; `failed` -> a warning line with the date; `passed` -> a plain "Evaluated <date>" line (no success colour, no badge).
4. **Asking.** Given ready, when the owner types and presses Enter (Shift+Enter is a newline) or the Send button then the message appears at once as the owner's, the composer is disabled and shows Stop, the request is `POST /api/assistant/chat` with `{conversationId?, message}` (CSRF token via the shared client); an empty or whitespace message sends nothing; over 2,000 characters shows a counter and disables Send; the three example prompts of an empty conversation fill the composer and do not send.
5. **Streaming.** Given the stream `turn, status, tool_call, tool_result, token..., iteration_discard, token..., done`, then a "Working" line names the phase (reading, tool name, answering), each tool call appears as a chip as it starts and completes as its result arrives, tokens accumulate in the answer, text of a discarded iteration disappears, and `done` ends the working state; a stream that closes before `done` shows "The connection closed before the answer finished" with the partial text kept and marked incomplete; `ping` is ignored. A recorded fixture (`assistant-turn.sse`) drives the test through MSW.
6. **Stop.** Given a running turn, when the owner presses Stop or Esc then the request is aborted (`AbortController`), the composer returns, the partial text stays marked "Stopped"; no retry is made.
7. **Citations.** Under every assistant message the tool calls are listed, always visible, as buttons `#n tool · rows · as of · status`; activating one (Enter/Space/click) toggles `aria-expanded` and loads `GET /api/assistant/tool-calls/{id}` once (cached for good): arguments in a code block; the rows in the kit's `DataTable` (a cell shaped `{state, number, reason}` goes through `metricOf`/`MetricCell`, so an `insufficient` or `unavailable` cell prints its words and never a digit); the `evidence` in `EvidenceBlock`; "Showing 50 of 143 rows" when `truncated`; an error call shows its code and message. A `run_sql` call shows the SQL text and the label "Ad-hoc query, not checked by the report engine". A `make_chart` call renders its referenced columns as a table (and a chart through the shared lazy chart module only if it exists at build time; the table stays as the accessible alternative).
8. **Grounding marks.** Given `done.grounding.ungrounded` spans, when the answer is shown then each span is wrapped in a `mark` with a dotted underline and the visually hidden words "(not from a tool)", and a banner under the answer says "N figures in this answer were not found in any tool result" with a warning icon; `grounded` shows "Checked: every figure was found in the tool results above" (neutral, no success colour, wording says "checked" not "verified"); `no_numbers` shows nothing; `not_checked` shows "Not checked (stopped or failed)". Offsets are UTF-16 code units; a test uses an answer with an emoji before the span.
9. **Plain text only.** Given model text with `<script>`, `<img src=http://x>`, `[a](http://x)`, `![i](http://x)`, a table and HTML entities, then it renders as inert text (no element, no link, no image, no network request); only paragraphs, `- ` and `1.` lists and `**bold**` get structure. A test asserts no `a`, `img`, `script`, `iframe` or `table` element comes from model text.
10. **History.** The left list (`GET /api/assistant/conversations`, newest first, title, date) selects a conversation (`?c=<id>` in the URL, Back works); opening one loads `GET /api/assistant/conversations/{id}` and shows stored messages with their stored calls and marks exactly as live ones; on a 360 px screen the list is a drawer opened by a "History" button; "New conversation" clears `?c`. An empty list says "No conversations yet".
11. **Refusals from the endpoint** (race with status): 409 `assistant.disabled|busy|nightly_running`, 503 `assistant.model_unavailable|tools_unavailable`, 422 `assistant.invalid|too_long`, 429 each show their sentence in the thread as a system line (icon + words) and re-enable the composer when allowed; the typed text is kept.
12. **Settings dialog (owner act).** Opened from the banner or a "Settings" button: switches *Assistant* and *Portfolio data*, *Maximum tool calls* (1 to 12), a required *Reason* (1 to 500), a *Password* field shown and required **only when the change turns something on or raises it** (a change that only switches off or lowers needs no password and says "No password needed to turn off"); Save sends `PUT /api/assistant/settings` with `expectedSettingsId`; `password` is omitted for an off-only change; wrong password shows the field error and keeps the dialog; 423 shows the lock and the retry seconds; 409 `assistant.stale` reloads the status and says what changed; success closes, toasts "Settings saved" and refetches status. Portfolio data off by default is shown with the words "Off: portfolio questions answer 'not available'". The dialog never shows the password again and clears it on close. **401 handling:** the shared client treats every 401 as an ended session except the `passwordCheckPaths` (`/api/auth/step-up`, `/api/auth/change-password`; `shared/api/client.ts`), so a wrong password on `PUT /api/assistant/settings` would sign the owner out. This slice adds `/api/assistant/settings` to `passwordCheckPaths` (only for `auth.invalid_credentials`, as there) with a client test: a 401 `auth.invalid_credentials` from settings does not call `onUnauthorized`, any other 401 on it still does.
13. **Read-only otherwise.** A test fails if the feature calls anything but `GET` on `/api/assistant/*`, `POST /api/assistant/chat` and `PUT /api/assistant/settings`; no `localStorage` or `sessionStorage` holds a message or an answer (per-viewer convenience keys such as "history open" are allowed and wrapped in try/catch).
14. **Accessibility.** The thread is `role="log"` with `aria-live="off"` while tokens stream; a visually hidden `role="status"` (polite) announces "Assistant is working" and "Answer ready" once each, and the refusal sentences; the composer is a labelled textarea ("Ask about your data"); focus returns to it after an answer; chips are buttons with names like "Tool call 1, get_report, 12 rows, ok"; marks do not rely on colour; contrast of every new token pair is tested in light and dark; `prefers-reduced-motion` removes any animation; keyboard path: composer -> Send/Stop -> chips -> History -> Settings; jsx-a11y clean.
15. **Responsive and states.** At 360 px there is no horizontal page scroll (tables scroll in their own region), the composer is sticky at the bottom, the drawer works; loading and error of every query use `LoadingState`/`ErrorState`; the route has an `errorElement`.
16. `npm run check` and `scripts/check.sh` green (`npm run size` included); `npm run test:clock` run once (relative times use a pinned clock).

## Contract
- **API used (all from P9-03, generated types in `shared/api/schema.d.ts`):** `GET /api/assistant/status`, `PUT /api/assistant/settings`, `POST /api/assistant/chat` (stream), `GET /api/assistant/conversations`, `GET /api/assistant/conversations/{id}`, `GET /api/assistant/tool-calls/{id}`. No backend change; no `gen-api.sh` in this slice beyond confirming the types exist.
- **Stream client:** `api.POST('/api/assistant/chat', { body, parseAs: 'stream', signal })` so the CSRF and 401 hooks apply; the response `body` is read with a `TextDecoder` stream and a pure SSE parser (`lib/sseParser.ts`: lines, `event:`, `data:`, comment lines, partial chunks, `\r\n`). If `parseAs: 'stream'` does not return the body in openapi-fetch 0.17 (docs say it "skips parsing altogether"; whether middleware runs is UNVERIFIED), the slice adds `shared/api/streamPost.ts` using `fetch` with the token from the existing hook, imported only by this feature.
- **State:** `lib/turnReducer.ts` (pure): events -> `{phase, working, toolCalls[], iterations{n: text}, answer, done?, error?, interrupted}`; the live turn is local UI state and is replaced by the stored conversation (query) after `done`. Query keys `['assistant','status']`, `['assistant','conversations']`, `['assistant','conversation', id]`, `['assistant','tool-call', id]`; `staleTime` status 5 s (refetch every 5 s while not ready, 30 s when ready), conversations 30 s, tool-call `Infinity`.
- **Structure (each file <= 250 lines):** `AssistantPage`, `AssistantGate`, `StatusBanner`, `EvaluationLine`, `ConversationList`, `MessageList`, `UserMessage`, `AssistantMessage`, `PlainText`, `MarkedText`, `GroundingBanner`, `ToolCallChips`, `ToolCallDetail`, `Composer`, `SettingsDialog`; hooks `useAssistantStatus`, `useChatStream`, `useConversation`; lib `sseParser`, `turnReducer`, `markSpans`, `plainText` (the renderer's parser), `toolRows` (envelope rows -> kit columns). `index.ts` exports `AssistantPage` (lazy wrapper like `PlansPageLazy`). `PasswordField` is not exported from `features/auth/index.ts` (checked 2026-10-25): the dialog uses a small local field, or the slice adds the export to `index.ts`; either way the bytes are counted in AC 1.
- **Tokens and copy:** colours/radii from `theme/tokens.ts`; wording constants in one file (`lib/wording.ts`) so tests pin them; the examples: "What is the expectancy of 15m SELL setups by basket?", "Which cells have enough trades to rank?", "What is in tomorrow's plan?" (text only).

## Non-functional
First paint of the route chunk under 150 ms on the dev machine; the thread re-renders per token batched at most once per animation frame; the tool-call detail loads on demand; a 200-row result is rendered by the kit's table without layout shift (virtualise above 200 rows is not needed: the server caps at 200). Security: no HTML from the model, no link, no image (D15; the proxy CSP also blocks external loads); the password is held in the dialog only; no message text goes to a log, a toast or the URL (only the conversation id does). Privacy: nothing is persisted in the browser.

## Test plan
Vitest + Testing Library + MSW (unhandled requests fail). Unit: `sseParser` (chunk splits mid-line and mid-UTF-8, CRLF, comments, an unknown event, `data` over several lines), `turnReducer` (discard, tool order, interrupted, error), `markSpans` (emoji, adjacent spans, a span at the ends), `plainText` (inert-text table of nasty inputs), `toolRows` (metric-shaped cells, nested objects shown as text). Component/integration: every gate state of AC 2 with its words and the absence of digits; the full stream fixture; stop; refusal lines; history select and Back; settings dialog (wrong password, locked, stale, success); the read-only test; the a11y tests (roles, names, live regions, focus return); dark/light contrast. Fixtures through builders in `src/test/fixtures.ts` (a `statusBuilder`, a `turnSse` helper that makes a `ReadableStream`); the clock pinned (`pinClock`). Edge cases: a 2,000-character message, a tool call with `ok:false`, 0 rows (`empty` words), a conversation with 40 messages, two tool calls with the same name, a stream that never sends `done`, the session expiring mid-stream (401 -> the shared hook signs out), a very long unbroken token in the answer (wraps, no horizontal scroll).

## Decisions (researched)
**A full page, not a floating panel.** Doc 13 says "streaming chat panel"; a panel on every screen needs an eager component in the app shell and the entry chunk has 4.8 KB spare (ADR 0098). A lazy route costs 0.5 KB. A Today tile or panel can follow once the entry is split. Rejected: shell drawer now.
**SSE through `fetch`, parsed by our own 40-line parser.** `EventSource` cannot POST; a library (`@microsoft/fetch-event-source`) adds a dependency and its own retry policy, which would re-send a question on a dropped connection. We never auto-retry a turn. Rejected: SignalR streaming (P9-00 D8).
**Plain-text rendering by a small parser, no Markdown library.** `react-markdown` and a sanitiser add about 40 KB gzip and an XSS surface for no need; structure is paragraphs, lists and bold; tables come from stored rows. Rejected: Markdown with links and images disabled (the next configuration slip re-enables them).
**Marks are text, not colour.** Dotted underline plus a hidden phrase plus a banner; "grounded" is worded "checked" and is neutral, so the screen never reads as a guarantee (P8-00 D3 spirit; limit 2 of P9-00).
**Poll the status instead of a push.** One cheap endpoint, 5 s while not ready; no hub event is added for a feature used a few times a day.
**Conversation id in the URL, nothing in browser storage.** Back/Forward and links work; no answer text is kept in the browser.

## Risks and honest limits
1. A local model takes 10 to 30 s to the first token; the "Working" line with the phase is the only feedback, and the screen does not guess a time.
2. `parseAs: 'stream'` may not behave as assumed in openapi-fetch 0.17; the fallback is named.
3. Streaming text that is later discarded can flash; it is shown dimmed until `done` and removed on `iteration_discard`.
4. The mark depends on the server's check (P9-03 limits 1 and 2); an unmarked answer is not a verified answer, and the wording says so.
5. The 0.5 KB eager allowance is an estimate; if exceeded the slice stops and frees space first.
6. `make_chart` is shown as a table until the shared lazy chart module exists; the screen says "Chart shown as a table".
