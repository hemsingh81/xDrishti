- **Status:** Draft (written 2026-10-24; decisions below were researched under the owner's delegation; the owner's Approved is still needed before an agent builds it)
- **Phase / roadmap row:** P3 — row P3-02e (Later, "before P5"); gates user strategies that list SELL without a `sell:` block (P5-01 validate, P6-17b).
- **Design refs:** docs/design/11-strategy-lab.md §2 (rules language, strategy file, "SELL auto-mirrored unless a `sell:` block is given") · docs/design/07-strategies.md §3, §7 · docs/design/08-exits-and-risk.md §2 · docs/design/18-roadmap.md (P3-02e row, ISS-24)
- **Needs:** built: the parser and printer (`XDrishti.Strategies.Syntax`), the binder and catalog, the typed model (P3-02b), the strategy file and loading (P3-02c, P3-02d). ADRs 0034 (rules language; Amendment 8 lags), 0035 (per-session features), 0036 (model), 0037 and 0047 (SELL walk rules, oracle), 0041.
- **Size:** 3 agent-days (roadmap size kept): type algebra and rewrite table 1.0 · side mirror, expansion and printing 0.6 · compile and Lab integration 0.4 · corpus, properties, metamorphic tests 0.8 · docs 0.2.
- **Safety:** no. Pure library; no data, network, order or UI write. (A mirrored SELL changes what a user strategy trades only in simulation; nothing here places an order.)

## Goal
A strategy that lists `sides: [BUY, SELL]` and has no `sell:` block gets its SELL side by a mechanical, printed, tested rewrite of the BUY side, or a precise refusal that tells the author to write the SELL block. The result is never guessed: where a mirror has no single meaning, the author writes it.

## Scope
**In:** `XDrishti.Strategies/Mirror`: `ConditionMirror` (text to text on the syntax tree), `SideMirror` (a whole `SideRules`), `MirrorTable` (the closed table, version `mirror-1`), codes `strategy.mirror.*`; the expansion in the one place a stored text becomes a definition for a run (`StoredStrategies` and `StrategyCompiler`'s missing-sell branch); an information problem that prints the mirrored SELL; the version in the run identity; doc 11 and doc 07 text.
**Out:** swing SELL (already refused by `strategy.model.swing_sell_unsupported`, futures only); any change to the grammar; mirroring of exits by learning; a UI to edit the mirrored side (the author copies the printed block into `sell:` to own it); percent semantics beyond the table (D5).

## Acceptance criteria
1. **Golden against the stored strategies.** For each stored intraday strategy that has a hand-written `sell:` block (`ORB`, `VWAP_PULLBACK`, `GAP_FILL`, `GAP_GO`, `PDH_PDL_BREAK`, `PDH_PDL_REJECT`, `MEAN_REV_BANDS`, `EMA_PULLBACK`, `VWAP_RECLAIM`, `INSIDE_BAR_BO`), when its BUY side is mirrored, then every section (setup, trigger, invalidate, stop kind and fields, entry, exits, overlays) equals the hand-written one after parsing (tree equality of the printed condition texts, not string equality of the source).
2. **Involution.** For a corpus of at least 500 conditions (the stored conditions, the generated ones of `AstGenerator`, and 60 hand-picked) that the table accepts, `mirror(mirror(x))` equals `x` as a tree; for every refused condition the refusal is identical on repeat.
3. **Metamorphic (exact class).** Given a seeded random price series `p` and `p' = K − p` (K larger than every price; volume unchanged), when a mirrored condition of the exact class (D4) is evaluated on `p'` and the original on `p`, then the three-valued result is equal at every closed bar, for 200 seeds on 5m, 15m and 1h; a negative control (the table with `crosses_above` left unswapped) fails on at least 10 seeds.
4. **Sign class.** For the features of the sign class (`roc`, `gap_pct`) on `p'' = C² / p`, the sign of the feature is the opposite at every bar where both are ready (their magnitudes differ and the property says so).
5. **Table is complete.** A test enumerates `IndicatorCatalog` (all 56 names), the builtins and the dotted spellings and fails if a name has no row in the mirror table (class or refusal), so a new feature cannot be added unclassified.
6. **Refusals are pinned.** Each refusal below gives the code, the path, a message that names the offending text, and a suggestion ("write a `sell:` block"); at least 12 failing and 12 near-miss examples (the near-miss is the nearest text that is accepted).
7. **Expansion.** Given a text with `sides: [BUY, SELL]` and no `sell:`, when it is read for a run, then the definition handed to the engine has a `Sell` block (so `StrategyRecord.DefinitionJson` and its hash contain the mirrored SELL), `Check` and validate return one `information` problem `strategy.mirror.applied` whose message holds the printed SELL block, and the run labels carry `sell: mirrored (mirror-1)`; a text that has a `sell:` block is untouched; a text with only `sides: [BUY]` gets no mirror.
8. **Identity.** Changing `MirrorTable.Version` changes the definition hash of every mirrored strategy and so the run key; the stored file's own hash is unchanged.
9. **Literals are exact.** `rsi(14) > 55.1` mirrors to `rsi(14) < 44.9` (decimal arithmetic on the literal text, no `44.900000000000006`); a literal with more than 15 significant digits is refused (`strategy.mirror.literal_precision`).
10. **Per-session lags are preserved.** The mirror keeps every subscript and every `tf("…")` qualifier; the unknown (not ready) state is identical, pinned by the metamorphic property on `vwap`, `or_high` and `prev_day.*` conditions (ADR 0035).
11. **Speed.** Mirroring a side of 20 conditions takes under 2 ms warm; the compiler warm-up (`CompilerWarmup`) includes a mirrored strategy.

## Contract
- **Rewrite model.** Every numeric expression gets a *mirror type*: **Level** (a price: V = K − x, K an unknown constant), **Signed** (V = −x), **Osc** (V = 100 − x), **Plain** (V = x). A scalar (literal or parameter) has no type of its own; in a comparison it takes the type of the other side. `V` is the value the expression would have on the inverted market. A comparison `A op B` becomes `V(A) op V(B)` with the K terms cancelled; that is what produces the flipped operator.
- **Atoms** (name → mirrored name, type; the rows of `MirrorTable`):
  - Level: `open`, `close`, `vwap`, `sma`, `ema`, `bb_middle`, `supertrend`, `prev_day_open`, `prev_day_close`, `today_open` (same name); `high`↔`low`, `bb_upper`↔`bb_lower`, `highest`↔`lowest`, `pivot_high`↔`pivot_low`, `or_high`↔`or_low`, `prev_day_high`↔`prev_day_low`, `today_high`↔`today_low`. A `source=` argument swaps `high`↔`low` and keeps `open`, `close`; `highest(n)` and `lowest(n)` default sources swap with the names.
  - Signed (exact): `macd_line`, `macd_signal`, `macd_hist`, `supertrend_dir`, `engulfing` (same name). Signed (sign class, not exact): `roc`, `gap_pct`.
  - Osc: `rsi` (same name, same source rule).
  - Plain: `atr`, `adx`, `rel_volume`, `volume`, `prev_day_volume`, `inside_bar`, `nr`, `pivot_high_age`↔`pivot_low_age`, `plus_di`↔`minus_di`, `bb_width` (meaning-preserving, not exact), `time`, literals, parameters.
  - Refused (`strategy.mirror.context_name`): `day_of_week`, `is_expiry_day`, `index_trend`, `index_adx`, `index_vol_pct`, `vix`, `vix_pct`, `vix_chg`, `breadth`, `regime_trend`, `regime_vol`, `regime`, the builtin `regime()`, the dotted `index.trend`, `index.adx`, the constants `MON…SUN`.
- **Builtins.** `crosses_above` ↔ `crosses_below` and `rising` ↔ `falling` when the operands are Level, Signed or Osc (mirrored operands, literals per type); unchanged when Plain. `between(x, lo, hi)`: Level or Signed or Osc operands swap the bounds (`between(m(x), m(hi), m(lo))`); Plain unchanged. `min` ↔ `max` with mirrored operands for Level and Signed; Plain unchanged. `abs(e)` is Plain and keeps `e` unchanged when `e` is Signed or a Level difference, refused for a bare Level. `and`, `or`, `not`, parentheses, `true`, `false`: structural.
- **Arithmetic.** Plain ⊕ Plain, Plain ⊗ Plain → Plain. Level ± Plain → Level, and the sign of the Plain term flips (`vwap[1] + pull_atr * atr(14)` → `vwap[1] - pull_atr * atr(14)`). Level − Level (and Osc − Osc) → Plain, with the operands swapped and mirrored (`high - low` → `high - low`; `close - open` → `open - close`). Signed ± Signed, Signed × scalar → Signed. A scalar compared with Signed is negated, with Osc is `100 − s`, with Level is refused. Everything else is refused: Level + Level, Level × or ÷ anything, Level ÷ Level, Plain − Level, Signed ± Plain, a division whose divisor is not a scalar or Plain (`strategy.mirror.not_mirrorable` with the shape named; ratios of prices are percent semantics, D5).
- **Subscript over a call (mirror row).** A subscript over a call mirrors the call and keeps the lag: `highest(20)[1]` ↔ `lowest(20)[1]`, `tf("1h").ema(20)[1]` unchanged name, lag and qualifier kept (needs P3-02f Part B to parse; until then the row is inert). Golden: `close > highest(20)[1]` → `close < lowest(20)[1]`.
- **Signed against a scalar.** The scalar is negated and the operator flips: the scalar `gap_pct <= -gap_min` becomes `gap_pct >= gap_min` (the double negation `-(-gap_min)` prints `gap_min`).
- **Comparisons.** Both sides Level (or both Osc, or both Signed): flip `>`↔`<`, `>=`↔`<=`, keep `==`, `!=`, mirror both sides. Both Plain: unchanged. A Level against a bare number (`close > 100`): `strategy.mirror.absolute_level`. Mixed types (Level against Osc): `strategy.mirror.mixed_orientation`. A double negation introduced by the rewrite is removed (`-(-gap_min)` prints `gap_min`).
- **Side (`SideMirror`).** `Setup`, `Trigger`, `Invalidate`: item by item, `Mode` kept. `Entry`: kind kept. `Stop`: `swing_low`↔`swing_high`, `bar_low`↔`bar_high`; `fixed_pct`, `atr_mult`, `or_opposite` kept with all fields (a named quantity stays a name). `Exits` and `Overlays`: kept (the walker reads direction from the side: doc 08 §2, `STRUCTURE_TRAIL` uses the lowest low for BUY and the highest high for SELL). `TimeRules`, `Filters`, `Params`: shared, not mirrored.
- **Codes** (`MirrorCodes`, prefix `strategy.mirror.`): `applied` (information), `context_name`, `not_mirrorable`, `absolute_level`, `mixed_orientation`, `literal_precision`, `buy_missing` (SELL listed, no `sell:`, and no `buy` block to mirror), `unknown_name` (an atom the table lacks; cannot happen once criterion 5 holds). Severity error except `applied`. Paths: `sell` plus the section and item of the BUY text (`sell.trigger[1]`).
- **Where.** `StrategyMirror.Expand(StrategyDefinition) → (StrategyDefinition, IReadOnlyList<LocatedProblem>)` is called by `StoredStrategies.Read` (so `Inspect`, `Check`, `Prepare…` all see the expanded definition) and by `StrategyCompiler` for a definition that reaches it with `Sell == null` (the existing `sell_block_missing` error stays for a definition with no BUY to mirror). No API shape changes: `StoredIssue` already carries information problems.
- **Run identity.** `MirrorTable.Version` is part of the canonical definition when a SELL was mirrored (the expanded SELL block is in `DefinitionJson`); the label line is added to `RunLabels` only for such runs.

## Non-functional
Pure, no I/O, no clock, no static mutable state, every class sealed; `XDrishti.Strategies` still references `Domain` and `Indicators` only (architecture tests unchanged). Warm mirror of a side ≤ 2 ms. The printed block is the canonical printer's output (`ExpressionPrinter`), so it re-parses to the same tree.

## Test plan
- **Unit:** a table test per atom (name, type, mirrored name, an example condition); per builtin; per arithmetic shape; the refusals; the literal arithmetic (55, 55.1, 0.1 + 0.2 shapes, `-0`, large exponents); parameters (`rsi(14) > rsi_hi` → `rsi(14) < 100 - rsi_hi`).
- **Hand examples from the stored strategies** (BUY → SELL): `close > highest(20)[1]` → `close < lowest(20)[1]` (subscript over a call keeps the lag; golden row, P3-02f Part B); `gap_pct <= -gap_min and gap_pct >= -gap_max` → `gap_pct >= gap_min and gap_pct <= gap_max`; `crosses_above(close, bb_lower(20, 2)) and close > open` → `crosses_below(close, bb_upper(20, 2)) and close < open`; `low < prev_day.low and close > prev_day.low and close > open` → `high > prev_day.high and close < prev_day.high and close < open`; `inside_bar[1] == 1 and close > high[2]` → `inside_bar[1] == 1 and close < low[2]`; `low[1] < low[2] and low[1] <= vwap[1] + pull_atr * atr(14)` → `high[1] > high[2] and high[1] >= vwap[1] - pull_atr * atr(14)`; `tf("1D").close > tf("1D").ema(20)` → `tf("1D").close < tf("1D").ema(20)`; `rsi(14) > 55 and macd_hist > 0` → `rsi(14) < 45 and macd_hist < 0`; `supertrend_dir == 1` → `supertrend_dir == -1`; `adx(14) < adx_max` unchanged; `close > ema(20) * 1.01` refused `not_mirrorable`.
- **Property:** involution (criterion 2); metamorphic (3, 4); permutation of list items gives the same mirrored list; the mirror of a text that does not compile reports the compile problems of the original, not a mirror problem.
- **Integration:** a stored strategy with `sides: [BUY, SELL]`, no `sell:`, runs through `simulate` and the SELL candidates equal those of the hand-written `sell:` twin (same trades, same keys apart from the definition hash).
- **Mutation check by the builder:** swap one table row (`rising`↔`falling`) and see the golden and the property fail.

## Decisions (researched)
**D1 — Expand at read time, record the text.** The mirrored SELL is put into the definition before the run, so the run key and `DefinitionJson` hold the actual SELL conditions and the table version; the stored file is not rewritten. Alternative rejected: mirroring inside the compiler only (the run record would not show what SELL traded, and a table change would not change the key). Alternative rejected: writing the mirror into the stored text on validate (silent edit of the owner's file; the author can copy the printed block into `sell:` whenever they want to own it).
**D2 — Typed algebra, not a find-and-replace.** The golden corpus shows why: `gap_pct <= -gap_min` becomes `gap_pct >= gap_min` (a signed quantity against a parameter negates the parameter), while `adx(14) < adx_max` must not change, and `low <= ema(21)` becomes `high >= ema(21)`. A word swap cannot tell them apart; the V = K − x reading does, and K cancels only in the comparisons that mean the same thing mirrored.
**D3 — Refuse the market context and the calendar.** `regime()`, VIX, breadth, index trend, `day_of_week`, `is_expiry_day` describe the market or the date, not the instrument's price. Whether a SELL wants the opposite regime or the same filter is a trading judgment (a high VIX filter is the same for both sides; an up-trend filter is not), so the author writes it. Matches the roadmap's refusal list.
**D4 — Exact class and sign class.** Exact under `p' = K − p`: every Level, `rsi`, `macd_*`, `supertrend_dir`, `engulfing`, `atr`, `adx`, `plus_di`↔`minus_di`, `rel_volume`, `inside_bar`, `nr`, pivots. Not exact (percent semantics): `roc`, `gap_pct`, `bb_width`; they mirror by meaning (sign flip, or unchanged) and are tested for the sign property only. `rsi` is exact because Wilder smoothing is symmetric in gains and losses (RSI' = 100 − RSI).
**D5 — Percent rules are refused.** A BUY `close > ema(20) * 1.01` means one percent above; its SELL counterpart is `close < ema(20) * 0.99`, not `0.99 …` by reflection. Guessing between the two would change results silently, so any product or ratio of a price is refused and the author writes the SELL side. Source: the repo's own hand-written sells (none uses a ratio of prices except BASE_BREAKOUT, which is BUY only).
**D6 — Intraday only.** Swing SELL is futures only and refused by the model (`swing_sell_unsupported`, doc 07 §7); the mirror is not reachable for it. Cash-market intraday SELL is allowed (MIS).
**D7 — Exits kept.** The walker applies direction; a mirrored `FIXED_RR` is the same multiple of the risk (ADR 0037 D4 rows for SELL are the mirror of BUY and the oracle checks them, ADR 0047).
**D8 — Version string.** `mirror-1`; any change to a row or a refusal bumps it (a test pins the table's hash so a silent edit fails).

## Risks and honest limits
A mirrored SELL is a *symmetric* rule, not evidence that shorting works the same way: short-side behaviour in the NSE cash market differs (borrow-free intraday only, different gap risk, uptick and circuit effects). The mirror says nothing about edge. Percent features mirror by meaning, so a SELL that uses `gap_pct` is symmetric in sign but not in size (D4). The refusal list is long on purpose; the cost is that authors write a `sell:` block more often than they would like.
