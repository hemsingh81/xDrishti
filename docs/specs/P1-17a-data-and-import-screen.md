# P1-17a — Data & import: load the CSV folder, fetch from Dhan, aggregate every timeframe, manual refresh

- **Status:** Approved (owner, 2026-10-12, quote in [ADR 0016](../adr/0016-market-bars-csv-load-dhan-fetch-and-app-managed-aggregates.md); defaults chosen by me — object to any)
- **Phase / roadmap row:** P1 — pulls forward the manual parts of **P1-06** (storage), **P1-07/P1-08** (CSV load: one fixed profile, no preview/undo/profiles/folder-watch yet), **P1-09** (aggregates), **P1-12** (Dhan fetch, manual only) and the **Data/Import screen of P1-17**
- **Design refs:** docs/design/05 §2–§4, §6, §9; prototype Data & import page (`docs/prototype/` → Data & import); ADR 0016

## Goal
One simple screen: see what data the system has (per instrument: first bar, **last tick time**, bars, source, how far behind), load the CSV folder, fetch what is missing from Dhan's Data API, and aggregate to every timeframe — with one **Update data** button and live progress.

## Backend
1. **Migrations** (new; `xd_owner`; `xd_app` DML only, no DELETE on bars): `market.bars_1m` (hypertable on the bar-start instant, 1-month chunks, PK (instrument_id, ts), compression after 7 days segmented by instrument), `market.bars_agg` (instrument_id, timeframe, ts, o/h/l/c, volume, bars, complete; keyed (instrument_id, timeframe, ts)), `market.bar_coverage`, `market.data_jobs`, `market.csv_files`; grants; the timescaledb extension is already available in the image.
2. **CSV phase:** folder `Data:CsvFolder` (default `/data/csv`); files `^[A-Za-z0-9&-]+_1m\.csv(\.gz)?$`; header columns found by name, case-insensitive (`time`, `open`, `high`, `low`, `close`, `volume`; others ignored); `time` = epoch seconds UTC = bar start; stream each file (never held in memory), bulk-write with binary COPY into a staging table and merge in one transaction per file (`ON CONFLICT`: csv never overwrites dhan; same-source rows are updated); skip files already loaded unchanged (`csv_files` name+size+modified time) unless `force`; rules of ADR 0016 §4 with counts per file (read / inserted / updated / repaired / rejected + first 10 reasons per job); unknown symbols listed; auto-track, through `InstrumentTracking`, the instruments that have bars from CSV files (loaded now or earlier) **and have never had a tracking row** (an untracked instrument stays untracked); requires a loaded instrument master (else `data.master_missing`).
3. **Dhan phase:** the primary Data account's access token via the vault; for each tracked share/ETF/index with a Dhan id fetch `POST /v2/charts/intraday` (interval 1) from `lastBar − 2 days` (overlap, to reconcile with stored bars) — or `now − Data:Dhan:InitialDays` (default 365) when there are no bars — to now, in windows of ≤ 90 days, throttled to `Data:Dhan:RequestsPerSecond` (default 4), per-instrument errors recorded and the run continues, a 401/expired token ends the phase with `data.dhan_not_connected`; sanity-check the timestamp alignment (a bar must fall on an IST minute inside a session) and count overlap mismatches against stored bars (tolerance 0.05 %) as warnings; allow-list the one endpoint (ADR 0016 §7, test that nothing else is reachable). Skipped with a reason, never failing the job, when there is no connected Data account.
4. **Aggregate phase:** for every instrument and the date range touched by this job's CSV/Dhan writes (or everything when requested), rebuild 5m, 10m, 15m, 30m, 1h, 1D, 1W, 1M by set-based upserts (rules in ADR 0016 §6); then refresh `bar_coverage`. A unit/integration test recomputes buckets with an independent reference implementation over fixtures (incl. Muhurat day, partial 15:15 bar, week/month boundaries) and compares exactly.
5. **Job runner:** `POST /api/data/refresh {steps?: ["csv","dhan","aggregate"] (default all), forceCsv?: bool}` → `202` with the job; `409 data.job_running` while one runs; one job at a time (advisory lock + unique running row); progress per phase (done/total, rows); on API start a stale running job is marked failed (interrupted); history kept.
6. **Read API** (session, no step-up): `GET /api/data/overview` (csv: folder, files total/loaded/pending, rows, last load; dhan: data account {id,name,status}, can-fetch + reason, last fetch time and bars; aggregates: per timeframe bars and last bucket, last built; bars: total 1m bars, instruments, first and **last bar instant**, days behind, `stale`; running job; last job per phase), `GET /api/data/instruments?q&status&sort&page&pageSize` (symbol, name, first bar, last bar, 1m bars, source `csv|dhan|mixed`, status `current|behind|empty`, days behind), `GET /api/data/instruments/{id}/bars?timeframe=1m|5m|10m|15m|30m|1h|1D|1W|1M&take=` (latest bars), `GET /api/data/jobs?take=` and `GET /api/data/jobs/{id}`. "Behind" = last bar's IST date is before the last weekday whose session has closed (holidays refine it with P1-11). Problem details with `data.*` codes.
7. **Deploy:** `compose.yaml` mounts `${XD_CSV_DIR:-../data/Stocks_CSV}` read-only at `/data/csv` in `xd-api` and sets `Data__CsvFolder`; `deploy/xd-up.sh` creates the folder when missing; `deploy/README.md`/`deploy/CLAUDE.md` mention it (CLAUDE.md files only if the owner asks — update the README only).
8. **Tests:** unit (row rules, symbol mapping, bucket rules, window splitting, throttle, behind calculation), integration on real TimescaleDB (CSV load of fixtures incl. gz, idempotent re-run, precedence, repair/reject counts, aggregates vs reference, coverage, endpoints, 401/403, job exclusivity, interrupted job), Dhan client against a stubbed handler (request shape, windows, 401, allow-list), architecture tests; `scripts/gen-api.sh`; docs 05 (§4/§9 amended), 04 if audit events, plan-data-1.js.

## Frontend (screen `Data & import`, lazy route `/data`, nav entry without a phase)
Keep it simple, match the prototype's page style:
1. **Header:** title + subtitle; primary **Update data** button (runs all phases) with a small menu: *Load CSV files only*, *Fetch from Dhan only*, *Rebuild aggregates only*, *Re-import all CSV files*; disabled with progress while a job runs.
2. **Freshness strip:** the **Last tick** (last bar instant, IST, with "N days ago") highlighted — warning colour + text when behind, success when current — plus tracked instruments with data, total 1-minute bars, covered from – to, and the Data account state with a **Reconnect** link when the Dhan phase cannot run.
3. **Pipeline card:** three steps — *CSV files* (n of N loaded, rows, pending), *Dhan Data API* (last fetch, bars added, status/skipped reason), *Aggregates* (timeframes with bar counts) — each with last run time and result; while a job runs a progress bar per phase with counts.
4. **Coverage table** (shared Grid): symbol, name, first bar, **last bar**, 1m bars, source, status chip (current / behind N d / empty); search, status filter, paging; row click → drawer with the timeframe select and the latest bars table (OHLCV).
5. **Recent runs:** compact list (time, steps, result, counts); a failed run shows its message.
6. Loading/empty/error states ("No data yet — put your CSV files in `data/Stocks_CSV` and press Update data"), polling while a job runs, 360 px → 4K, a11y, honest placeholders only where data does not exist.
7. Tests (Vitest + MSW, stateful fake like the baskets one): overview states, run flow with progress, menu actions, 409, behind/current highlight, table/filter/drawer, errors; `check.sh` green; bundle ≤ 200 KB gzip (lazy route).

## Out of scope (stay in their stories)
Profiles/preview/undo/folder watch (P1-07/08), scheduled EOD + gap backfill (P1-12), quality checks (P1-14), adjustments (P1-10), calendar (P1-11), official daily candles, live feed (P2).
