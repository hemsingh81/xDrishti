21 — Glossary

Term Meaning
Account role What an account is used for: Data, Trading, Portfolio (one account can have several)
Action center List of portfolio positions needing a decision, generated by rules per account
Active set Instruments streamed live: open positions, armed tickets, context indices, pinned baskets
Approval Your decision on a proposed ticket or suggestion: approve, modify or reject
Armed ticket Approved ticket that passed the pre-open check and is being watched live
ATR Average True Range — average bar range; scales stops/targets to volatility
Auto-approval Ticket approved by the pre-open service at the cutoff because it meets your autonomy rule (P(win) threshold and every check passing)
Autonomy level How much the system decides alone: advisory, supervised (default) or autonomous within limits
Basket Named group of tracked instruments (manual, rule-based or system); an instrument can be in many
Bias timeframe Higher timeframe deciding the allowed direction for a lower-timeframe entry
Bucket (portfolio) Exclusive grouping of positions so portfolio totals add up
CAGR Compound annual growth rate
Calibration Adjusting model scores so predicted probabilities match observed frequencies
Capacity score How reliably a cell's tickets actually get filled (partial fills, rejections, missed triggers); used in selection
Cell (setup cell) Unit of learning: strategy × timeframe × side × style × exit policy × regime
Champion / challenger Current model/parameters vs a candidate running in shadow until proven better
Common random numbers Replaying candidate and current settings on the same trades/days so only the change differs
Conditional ticket Trade defined by trigger, validity window, stop, exit, size — executed only if triggered
Confluence Several strategies/timeframes agreeing on the same symbol and side
Continuous aggregate TimescaleDB materialised view that keeps derived bars (5m, 15m…) up to date
Control plane The UI/API where you record what you want; services do the work
CPR Central Pivot Range from the previous day's high/low/close
Data quality score Share of tracked instruments passing validation (warnings count half)
Deflated Sharpe Sharpe ratio adjusted for the number of strategies tried
Drift Live/paper performance moving away from backtest expectations
DSL The strategy rules language used by built-ins and the Strategy Lab
Embargo / purge Removing overlap between train and test data to prevent leakage
Entry window (learned) Best entry hour for a setup from walk-forward results; used as the ticket's validity window
Equity-curve throttle Risk is cut (default × 0.5) while the system's own equity is below its N-trade average
Execution gap Difference between results at plan prices and at actual fills (slippage, missed triggers, overrides, charges)
Expectancy (E[R]) Average result per trade in R after costs
Experiment (replay) Changing a learning knob and re-running walk-forward to compare with the current model before anything goes live
Fail closed On error, produce no plan rather than a possibly wrong one
Failover (data) Automatic switch to the standby Data account when the primary fails
FIFO lots Sells consume the oldest buys first; basis for realised P&L
Frozen-model counterfactual What a copy of last year's model would have done on the same days — the baseline for measuring learning progress
Graded on fills Results computed from executed prices, not plan prices; plan-price R is kept to measure the execution gap
Hangfire .NET background-job library (schedules, retries) using PostgreSQL storage
Heat Sum of open risk across positions as % of capital
Import profile Saved column mapping for a CSV file format
Lapsed A proposed ticket not reviewed before the cutoff — never armed
Learning health 0–100 score from data quality, calibration, execution, stability and evidence
Lens How results are grouped: all trades, by basket, by instrument, by trade, by strategy, by account
Lesson Record of a detected problem: what went wrong → diagnosis → fix → result, with revert
Loss tag Automatic reason attached to a losing trade (gap through stop, gave back open profit, against regime, …)
MAE / MFE Maximum adverse / favourable excursion during a trade
Market gate Learned rule deciding whether tomorrow is a normal, reduced or no-trade day (VIX, breadth, events)
Master list All instruments from Dhan's instrument master
MCP Model Context Protocol — standard way to expose tools to an LLM
Meta-labeling ML deciding whether to take a trade proposed by a rule strategy
Meta-labelling A second model that decides whether to take a signal and how big, trained on your graded trades
MIS / CNC Intraday margin / delivery product types (Indian brokers)
ML.NET Microsoft's machine-learning library for .NET; trains and scores our models in-process
NR7 Narrowest range of the last 7 bars
OOS Out-of-sample — data not used for fitting
ORB Opening Range Breakout
Paper trading Following the system without real money to validate it
PAV calibration Pool-Adjacent-Violators — isotonic calibration of model probabilities
Pivot builder Report that crosses any two dimensions with a chosen metric
Pre-trade checklist Automatic checks shown on each proposed ticket before you approve
Profit factor Gross profit / gross loss
Pyramiding Adding to a winner at set levels while capping total risk at the initial 1R
R / R-multiple Result divided by initial risk
Regime Market state (trend × volatility) used to condition statistics
Reserve list Next-best tickets used if a primary is invalidated
Rollback (automatic) Undoing an applied learning change when live results over the monitoring window fall below the previous version
Run-after chain A service scheduled to run when another service finishes successfully
Same bet Two tickets or positions whose 60-day returns are correlated above the limit; the weaker one goes to reserve
Service identity Background services act as the system, not as a logged-in user
Square-off Closing an intraday position before session end
Step-up auth Password re-entry before sensitive actions (role, credential, risk and autonomy changes)
Stored vs recomputed Validation comparing saved aggregate bars with bars rebuilt from 1-minute data
Suggestions inbox AI/engine proposals awaiting your accept/reject
Time stop Exit if no progress within N bars/sessions
Tracked instrument Instrument you've switched on for data collection, scans and analytics
Triple barrier Labelling by which is hit first: target, stop or time limit
VWAP Volume-weighted average price of the session
Walk-forward Repeated train-on-past / test-on-next-period evaluation
Weekly learning digest Weekly summary of progress vs the frozen model, automatic changes, items needing you and loss causes
XIRR Annualised return computed from dated cash flows (buys, sells, dividends, current value)
