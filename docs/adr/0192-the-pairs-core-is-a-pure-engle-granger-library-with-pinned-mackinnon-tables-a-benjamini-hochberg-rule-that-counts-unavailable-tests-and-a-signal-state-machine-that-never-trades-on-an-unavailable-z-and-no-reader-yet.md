# 0192 — The pairs core is a pure Engle-Granger library with pinned MacKinnon tables, a Benjamini-Hochberg rule that counts unavailable tests and a signal state machine that never trades on an unavailable z, and no reader yet

- **Status:** Proposed (built in P14-12 from the owner-Approved spec, 2026-11-03). Becomes Accepted when the owner has read it. **Safety slice: no** (pure functions: no I/O, no setting, no table, no route, no order).
- **Date:** 2026-11-03.
- **Relation to other ADRs:** [0191](0191-the-option-pricing-core-is-a-pure-black-76-library-with-fixed-units-a-closed-list-of-unavailable-reasons-and-no-reader-yet.md) (the model of a pure core; `NormalDist` moves out of it), [0059] (`MultipleTesting.Factor`, which counts the trials BH works on).

## Decision
1. **`Domain/Pairs`** holds the pure library: `LogSpread` (`Ln`, `Of`), `HedgeRatio.Ols`, `EngleGranger` (`Test` on logs, `TestPrices` on prices), `MacKinnonTables`, `HalfLife`, `ReturnCorrelation`, `ZScore`, `BenjaminiHochberg`, `PairSignal` (state in, step out), `PairsOptions`, `PairsResult<T>` (value or reason, never both; `default` is unavailable) and the closed `PairsReason` (`bad_input`, `too_short`, `degenerate_x`, `zero_residual_variance`, `not_mean_reverting`, `oscillating`, `short_window`, `flat_window`, `z_unavailable`). It depends on `System` and `Domain/Common` only (the spec allowed `Domain/Lab`; none is needed). An architecture test pins that, pins the absence of a clock and a random source, and pins that nothing outside the namespace references it (P14-13 loosens this with an exact allow-list).
2. **`NormalDist` moved** from `Domain/Options/Pricing` to `Domain/Common` (namespace `XDrishti.Domain.Common`): the pricing architecture test forbids any other Domain area from referencing Pricing, and the spec foresaw this move. Behaviour and tests are unchanged.
3. **Engle-Granger.** OLS of `ln y` on `ln x` with a constant; then `Delta e_t = gamma e_{t-1} + sum phi_i Delta e_{t-i} + eps` without a constant, `p = Lags` (default 1, fixed: a different `p` is a different trial). `m = n - 1 - p` equations, `k = p + 1` regressors, `s^2 = SSR/(m - k)`, `se^2 = s^2 [(X'X)^-1]_00`, `tau = gamma/se`. `X'X` is accumulated in index order and inverted by Gauss-Jordan with partial pivoting; a singular lag matrix, a first-stage `SSE <= 1e-20 SST` or a second-stage `SSR <= 1e-20 sum(Delta e)^2` is `zero_residual_variance` (never tau = infinity, never p = 0). The critical values are taken at `T = n - 1`, the observations of the unit-root regression (MacKinnon 2010, section 3; statsmodels `coint` uses nobs - 1); the result carries the SSR and `se(gamma)`; the p-value is always the asymptotic one. A series shorter than `max(MinObservations, 2p + 3)` is `too_short`.
4. **Honest states.** Nothing returns 0, NaN or infinity for an unavailable value and nothing throws on a number; invalid `PairsOptions` give `bad_input`. A half-life slope within `1e-12` of zero or above is `not_mean_reverting` (the half-life would exceed 1e11 bars).
5. **BH.** Sort ascending (ties by input index), largest `k` with `p_(k) m <= k q (1 + 1e-12)` (the slack keeps a p exactly on the line, such as 0.04 at `4 q / 5`, from being lost to rounding). A p-value that is not a number in [0, 1] and every unavailable test count in `m` with `p = 1`; there is an overload on `EngleGrangerResult` lists that does this.
6. **Signal.** As the spec. A flat position opens on `z <= -entry` or `z >= entry` whatever `stop` is; a position stops at `|z| >= stop` (checked first) or exits at `|z| <= exit`; an unavailable z holds with `z_unavailable` and never opens or closes by rule. Settings need `0 <= exit < entry < stop`.
7. **Tests.** Every hand value of the spec (recomputed in Python with `python3 -I` before it was pinned), the transition table, BH properties, size (57 of 1,000 seeds, 5.7 %, limit 8 %) and power (200 of 200, limit 180), p-value monotonicity, determinism on the thread pool, every reason reached, architecture.

## Plan errors recorded, not bent
1. **The 1 % `beta2` of the spec is right; statsmodels and arch are not.** Both libraries print `-33.527` for N = 2 at 1 %; the 2010 working paper prints `-22.527` (as the spec does). The spec's c(252) = -3.9403 and c(63) = -4.0760 are reproduced with the paper's value; with `-33.527` they would be -3.9404 and -4.0787. The paper's value is pinned and a test names the choice.
2. **The published p-value fit is not monotone at tauStar.** The small-p and large-p polynomials meet at -2.62 with a gap (the argument of `Phi` is -0.73997 on the small side and -0.74264 on the large side), so the raw function falls by 0.0007 across it, against spec criterion 4 (non-decreasing). Above tauStar the p-value is therefore `max(large(tau), small(tauStar))`: it differs from the published function by at most 0.0007 in p, over a stretch of about 0.005 in tau. No decision uses a p-value this close to 0.23 (BH works near 0.05). A grid test (step 0.001 from -25 to 5) pins monotonicity.
3. The spec's Inputs rule sends series of different lengths to `too_short`; the core does so (`HedgeRatio`, `ReturnCorrelation`, `LogSpread.Of`, and so `EngleGranger`).
4. Every other number of the spec was recomputed independently and matches (OLS, tau -2.792848, se 0.517194, the critical values to 1e-4, half-life 6.578813, z 3.794733, both BH cases).

## Consequences
- P14-13 can form, test and signal with one tested core. It must fix which series is `y` (counted in its trial text), convert half-life bars to sessions (`HalfLife.InRange`), pass the full candidate list to `BenjaminiHochberg` including unavailable tests, and count every `z_unavailable` step.
- The 252-point test runs in well under a millisecond; the 50 microsecond and 1 second per 2,000 pairs targets are UNVERIFIED and ungated (no benchmark test was added).

## Known limits
- Asymptotic p-values with finite-sample critical values printed beside them: the gap is visible, not removed. The test depends on which series is `y`. A daily-close cointegration p-value says little about a 5-minute spread; P14-13 judges that.
- Open point for P14-13 (recorded in its spec): an entry beyond the stop level (flat and `|z| >= stop`) opens and is stopped on the next bar, as P14-12's rule reads; P14-13 should open only when `entry <= |z| < stop`.
