# 0099 — The report engine: a pure core with one population rule, six honest states and a ranking by the credible lower bound

- **Status:** Proposed (spec [P8-05](../specs/P8-05-report-engine-core.md), approved under the owner's standing run instruction of 2026-10-22, every P8-00 question it touches taken as recommended; built 2026-10-24). Becomes Accepted when the owner has read it.
- **Date:** 2026-10-24.
- **Relation to other ADRs:** [0064](0064-cell-statistics-bayesian-shrinkage-recency-weights-and-point-in-time-snapshots.md) (cell statistics: the Beta shrinkage this reuses, and the one-run-per-cell rule this generalises), [0045](0045-the-result-store-sim-runs-and-sim-trades.md) (the stored runs and trades; exit and style are labels of a run), [0053](0053-the-same-entries-comparison-and-the-mae-mfe-diagnostics.md) and [0054](0054-the-per-cell-exit-choice-by-walk-forward.md) (the same entries under several exits), [0067](0067-validation-harness-and-baselines-purged-folds-and-an-honest-eligibility-rule.md) (honesty rules: few folds, no hold-out, "inconclusive" is an answer), [0097](0097-the-p7-phase-check-ten-consecutive-scheduled-sessions-from-stored-plan-runs-and-never-met-on-fewer.md) (MET / NOT MET / NOT EVALUABLE, limits always printed). ## Context
P8 asks one question of the stored research: what works, in which basket, on which timeframe, with which exit. The numbers must come from the server (the browser computes no statistic), every figure must carry what stands behind it, and on about 2.1 years of replayed history with no hold-out the likely and legitimate answer is "nothing has enough evidence yet". No code aggregated trades into reports; the only precedent is the per-cell statistics, which have no basket and refuse a second run per strategy.

## Decision
1. **A pure `Domain/Reporting` core.** `ReportPopulation.Create(runs, trades, options)` takes stored runs and their closed trades and returns a population or a typed refusal; `GroupBy`, `Pivot`, `FindWhatWorks` and `Insights` read it. No clock, I/O, random or framework (architecture test). The reader port, endpoints and screens are P8-06 and later.
2. **One population rule, enforced at creation.** (a) Identical repeated records of a trade in a run are kept once and counted in the evidence; a repeat with different values is refused. (b) Two runs with a shared strategy, the same universe, overlapping windows and the same style and exit are refused (`reports.run_overlap`). (c) One signal (the stored trade key and timeframe) in two runs with the same style and exit is refused, which catches overlap across universes. (d) Runs with and without charges are never in one set (`reports.mixed_basis`). (e) A net report needs `NetBasisConfirmed` (the owner's confirmation of the charge sheet, ISS-25, P8-00 Q19) and net R on every trade; otherwise it is refused; gross over costed runs uses the filled-price R. (f) One signal under different exit or style labels is allowed, since that is what an exit comparison is, but every grouping must then include the differing label, otherwise `reports.double_count`; the shrinkage prior of a group is then taken from the trades with the same labels only. The refusals do not depend on input order.
3. **Six states, one type.** `Metric` carries a `MetricState` (`Value`, `Provisional`, `Insufficient`, `Unavailable`, `NotEvaluable`, `Empty`) and a number only for the first two; it is built through factories, a non-finite result becomes `NotEvaluable`, so a consumer cannot read a digit out of a non-value. Below the minimum sample (30, the `min_trades` of the cells) every figure of a group is `Insufficient` and only the count is a number; a group with a coordinate no run recorded is `Unavailable`; a pivot cell with no trade is `Empty`; a run marked provisional makes the figures `Provisional`.
4. **KPIs and shrinkage.** Per group: trades, wins, win rate, average win and loss R, expectancy, profit factor (`NotEvaluable` without a loss), total R, maximum drawdown in R and longest loss streak (in exit order: date, run key, trade key), average holding sessions. The shrunk win rate and its credible bounds use `BetaShrinkage`, extracted from `CellStatsCalculator` and used by both, with the same prior hierarchy (the system rate, then the strategy rate when the strategy is a coordinate of the group), prior strength 20 and credible level 0.90; trades weigh 1 (no recency). A test pins equality with the calculator.
5. **The ranking figure.** `ExpectancyLowerR = p_lower x avgWin + (1 - p_lower) x avgNonWin`, with `p_lower` the lower credible bound of the shrunk win rate. It is monotone in the win rate and reduces to the plain expectancy at the raw win rate. **Limit:** it reflects the uncertainty of the win rate only, not of the size of wins and losses; every report says so in its limits. A cell with no win or no non-win has no such figure and is listed, not ranked. A bootstrap would add the second uncertainty but needs a random source; it is a recorded follow-up.
6. **"What works".** Cells with at least the minimum trades and a lower bound are ranked by the lower bound (ties: more trades, then the key text), the others follow with the reason (insufficient sample, not recorded, no lower bound), and the answer carries the number of cells looked at, the largest n, how many have a positive lower bound and a selection-effect sentence. When no cell qualifies the answer is `NothingQualifies` with the counts and "Nothing has enough evidence yet": an answer, not an error. The default cell is basket x strategy x timeframe x side x exit (plus style when it varies); a dimension nobody recorded is left out and named in the answer.
7. **Auto-insights are fixed templates.** Eight insights always in the same order (best and weakest strategy, basket gap, side bias, best exit, weekday, regime, calibration). A sentence with figures is written only when every group it compares has the minimum number of trades (15, doc 15 section 6) and there are at least two; otherwise a reason state with no figure ("no group has 15 trades yet"). Ties read "no difference". Regime is `Unavailable` (no market context is stored) and calibration `NotEvaluable` (no champion). When the runs hold the same signals under different labels, only the exit insight is evaluable. No language model; every number is a figure of a named cell.
8. **No composite score** (P8-00 D10, Q12). Nothing in the namespace is named for a health, quality or discipline score; an architecture test fails on such a name.
9. **Typed refusals** carry the codes the endpoints will use: `reports.invalid`, `reports.not_found`, `reports.run_overlap`, `reports.mixed_basis`, `reports.net_not_confirmed`, `reports.net_unavailable`, `reports.dimension_unavailable`, `reports.double_count`. Regime and account are named dimensions so a request for them is refused with the reason instead of returning nothing.

## Consequences
- The engine can say "no cell has enough evidence" and nothing else on thin data; with 30 trades needed per cell and a basket in the cell, most cells of the owner's data will be `Insufficient`.
- Basket totals are not additive; the grouping and the answer say so.
- The lower-bound figure is cautious about the win rate and silent about payoff variance; a cell with a lucky payoff can still rank high. The limit is printed with every report.
- The extraction of `BetaShrinkage` touches the cell statistics code; the existing tests and a new equality test guard it.
- Equity and drawdown series, R distribution bins, net rupees, Sharpe and Sortino, and exposure are not in the engine yet; they need fields the report trade does not carry (quantity, charges in rupees) and are `unavailable` until a screen needs them.
- Where the exit and style labels of a stored run come from is the P8-06 spike (P8-00 risk 2); until then they are inputs.
- Not run on the owner's stored runs in this slice (no reader exists yet).

## Alternatives considered
- **Reimplement the shrinkage for reports.** Rejected: two copies of the Beta maths drift; the shared internal function keeps one.
- **Rank by the raw mean or the shrunk mean.** Rejected: a thin lucky cell would top the list; the lower bound is what P6 already uses as confidence.
- **Refuse any second run of a strategy, as the cell statistics do.** Rejected for reports: the same entries under several exits are exactly the exit comparison the question needs; the split-by-label rule keeps them from being added.
- **A composite "learning health" number.** Rejected (Q12): no definition exists and a single number hides the sample sizes.
