# 0117 — The audit log screen is a read model over the six insert-only stores, merged by keyset in memory, with pattern redaction

- **Status:** Proposed (spec [P8-22](../specs/P8-22-audit-log-screen.md), built 2026-10-26). Becomes Accepted when the owner has read it.
- **Date:** 2026-10-26.
- **Relation to other ADRs:** [0083](0083-the-plan-record-insert-only-state-trails-owner-only-approvals-lapse-by-default-and-no-order-by-name.md) (the plan record and its trail); the read-only rule is P8-00 D6, [0091](0091-auto-approval-is-an-option-behind-an-owner-setting-default-off-a-new-approval-kind-the-database-checks.md) (autonomy rows stay distinguishable), [0073](0073-the-learning-changelog-and-the-cell-lifecycle-the-log-is-the-state.md) (learning changelog), [0098](0098-the-analytics-kit-draws-a-non-value-as-a-word-never-a-digit-and-the-first-load-javascript-is-guarded-at-200-kb.md) (honest-state kit). Design change: doc 03 section 5 and doc 04 section 5 named a table `ops.audit_log`; there is none.

## Decision
1. **A read model, not a new table.** The audit is six insert-only stores that already exist: `auth.audit_events`, `accounts.account_events`, `workflow.approvals`, `trading.plan_events`, `workflow.autonomy_settings`, `research.learning_changelog`. Each has a reader (`IAuditSource`, raw SQL, named columns, SELECT only). No writer changes; no `ops.audit_log`.
2. **Four GET endpoints** under `/api/audit` (`entries`, `entries/{id}`, `summary`, `kinds`), session required, `Cache-Control: no-store`, tag `Audit`. A refused input is `422 audit.invalid` naming the field; a missing or malformed id is `404 audit.not_found`.
3. **Merge in memory by keyset.** Every store is read with its own time index from the cursor, newest first, `limit + 1` rows; the matches are merged by `(time, source ordinal)`, and rows of one source keep the order of the database (`time desc, id desc`). The cursor is `base64url(time|ordinal|id|check)`; the check only catches a garbled value. A failing store does not fail the page: it is `unavailable` with the fixed reason `read_failed` in `sources[]`. Rejected: one `UNION ALL` (one failing store fails the page), offset paging (skips or repeats as rows arrive).
4. **Filters that only the application can apply** (actor kind, and `q`) are applied after redaction, in chunks of 500 rows per store up to 5,000 rows (`MaxScan`). When the cap stops a store the page ends at the last row that store looked at (the cursor is that place); with several capped stores the cut is the newest of their horizons, and when the retained rows fit one page the next cursor is the horizon itself, so no row is skipped or repeated (a test with two capped stores of different density and matches between their horizons proves it), and `limits[]` says the search covered the newest 5,000 rows of a store. Category, outcome and kind are pushed down to SQL as the list of stored kinds that have them.
5. **`q` searches only the redacted summary, the kind and the displayed actor**, never raw stored text, so the search cannot reveal what the redactor hides (`q=hunter` does not find `password=hunter2`; `q=redacted` does). `q` is never logged.
6. **Pattern redaction** (`AuditRedactor`, Domain) leans to masking: an `Authorization: Bearer|Basic ...` header (scheme and credential), URL credentials (`scheme://user:pass@`), connection-string parts (`Server=`, `Username=`, `Password=`, `Database=`), secret-like names with any prefix or suffix and a `:` or `=` (quoted and JSON forms too: password, passphrase, pw, secret, token, api key, private key, recovery code, refresh, cookie, credential, session, sid, client id, totp, otp, auth), "password is x", "token abc", "secret x" (unless the next word is plain prose), JWTs, bearer and basic credentials, argon2, bcrypt, scrypt and pbkdf2 hashes, recovery codes (`abcd-efgh-ijkl`), hex strings of 32 or more digits, base64 or url-safe runs of 40 or more characters and a bare six- or eight-digit code become `[redacted]`; the row stays and `redacted: true` is set. Every free text goes through it: summaries (which carry the reasons, the BrokerConnectFailed text and the approval, plan and learning reasons), the actor and every detail field (confirm reason included). A pattern that times out (200 ms) masks the whole text (fail closed), so a read never fails or returns "unavailable" for it. It is a second line behind the stores' own no-secrets rule, will mask some harmless text (a six-digit number, a word after "secret"), and cannot find a secret written in plain words; the screen says so. Also masked: consent ids, the broker field names as bare words (`dhanClientId 1000000123`, `access-token x`), `pwd`/`pin`/`api key` followed by a value, `password changed to x`, quoted values to their closing quote, a cookie header and a `password:` passphrase to the end of the line.
   **Shortcut (known false negatives):** cloud-provider key shapes (`AKIA...`, `sk-...`), PEM blocks and a secret in plain prose are not recognised; add a pattern and a test row when a shape turns up.
7. **Kinds are a table with an exhaustiveness test.** `AuditKinds` maps every `AuditEventType` (13) and `AccountEventType` (73) value to one of 12 categories and an outcome (`failed`: LoginFailed, StepUpFailed, BrokerConnectFailed; `refused`: AccountLocked, LoginRefusedLocked; else `ok`, meaning recorded, not verified); a Domain test fails when a value is added without a row. The other four stores have synthetic kinds (`approval.approve|modify|reject`, `plan.moved`, `plan.ticket_moved`, `autonomy.changed`, `learning.transition|designation|revert`). A name the table does not know is shown with category `other`.
8. **Who did it is a kind** (`owner`, `system`, `rule`, `cli`, `other`, `other_address`). A sign-in whose typed address is not the signed-in owner's shows no address (`other_address`). The owner's address is the session's, never from the request.
9. **Field policy.** The list never carries IP, user agent, confirm reason, raw modifications, hashes or the policy version; the detail of a sign-in adds IP address and user agent, an approval adds cutoff, confirm reason, a one-sentence modification (built from the parsed quantity changes, with the first 8 characters of an account id) and policy version, autonomy the four switch values, learning subject, from-to, before, after and evidence ids; all redacted. Never selected: password or hash, session or CSRF token, vault or broker secrets, `settings_hash`, `snapshot_hash`.
10. **Indexes only.** Migration `AddAuditReadIndexes` adds `ix_account_events_at`, `ix_approvals_decided_at`, `ix_plan_events_created_at`, `ix_learning_changelog_created_at`; `Down` drops them; grants unchanged. (`auth.audit_events` already had an index on `at`; the autonomy table is small.)
11. **Reading is not audited** (an `AuditViewed` row would break the read-only rule). Log events 4895 (`audit.read`: row count, number of unavailable stores, booleans) and 4896 (`audit.source_failed`: source, exception type).
12. **The screen** is a lazy route `/audit` (the nav entry loses its planned-phase flag). The URL holds the view (`range`, `from`, `to`, `source`, `category`, `kind`, `outcome`, `actor`, `account`, `q`, `entry`). Table from the `md` breakpoint, cards below with the filters in a bottom drawer; outcome and record as word plus icon; "Load more"; a drawer for the detail; no export, no copy-all (a source test fails on `Blob`, `clipboard` or a write call).

## Measured
- Test container, 100,000 account events and 20,000 sign-in and learning rows each: first page `GET /api/audit/entries` p95 about 33 ms over 20 calls (asserted under 300 ms); `summary` asserted under 500 ms. Every store query is bounded by the window and `limit + 1` (or a 500-row chunk when a post-redaction filter is set).
- Route chunk `audit`: 12.4 KB, 4.8 KB gzip (budget: measured + 10 % = 5.3 KB gzip). Eager bundle: the nav entry loses a field, the route adds one line; first-load JavaScript 196.4 KB of 200 KB, 3.6 KB to spare.

## Consequences
- **Shortcut:** migration `AddAuditReadIndexes` uses plain `CREATE INDEX` (SHARE lock, writes to the four tables wait while it builds), not `CONCURRENTLY`. The tables are small and migrations run with the stack stopped; revisit if a store passes millions of rows.
- Only what is recorded is shown: direct database changes, file changes, reads and anything older than the audit tables are absent; every response says so.
- A later writer slice (P8-18 to P8-21, P12, P7-20's acknowledgements) must add its kind to `AuditKinds` or the exhaustiveness test fails; a new store registers one more `IAuditSource`.
- Account names are read at display time. Keyset paging is stable, not a snapshot: a new event shows at the top of a fresh load.
- Sources of equal time are ordered by source ordinal, not by an id across stores; the order is stable on every call.
