# 0019 — Holdings quotes every few minutes, day change, and the first interval service

- **Status:** Accepted (owner, 2026-10-13: "approved as written") — builds on [ADR 0012](0012-holdings-acquisition-dates-and-returns-model.md) (returns), [ADR 0016](0016-market-bars-csv-load-dhan-fetch-and-app-managed-aggregates.md) (Dhan Data API, allow-listed endpoints) and [ADR 0018](0018-services-framework-and-editable-schedules.md) (services framework)
- **Date:** 2026-10-13

## Context
The Portfolio screen values every holding at the price Dhan returned at the last holdings sync, so the figures are as old as the last sync and **day change** (design doc 12 §3) does not exist. Design docs 05 §5 and 12 §6 give long-term holdings a *quote API poll every 5 minutes* (≤ 1,000 instruments per request) until the live feed (`xd-feed`, later) takes over for open positions. The Services framework (ADR 0018) has registered only daily jobs; schedule types `window` and `interval` are calculated and checked but no service uses them yet.

## Decisions
1. **Quote source and endpoint.** Dhan's market-quote REST call `POST https://api.dhan.co/v2/marketfeed/quote` (read-only despite the POST; JSON body `{"NSE_EQ":[<securityId>,…]}`; headers `access-token` and `client-id`; answer per security with `last_price` and `ohlc {open, high, low, close}`, where `close` is the previous session's close) with the access token and client id of the **primary Data account** (the same account and subscription as the bar fetch; no Portfolio account is used). It is added to the broker endpoint allow-list as the one new path (no query, no other marketfeed path); every other allow-list rule stays. Requests are throttled to the documented 1 per second and carry at most 1,000 securities. **Not verified against the real API** (headers, field names, previous-close meaning, rate limit) — the first real run is an owner check, and the client fails closed: an unexpected answer ends the run `failed` with a safe message and changes no price.
2. **What is quoted.** The distinct securities of every **open holding** whose instrument maps to an **NSE** instrument of the master list (`NSE_EQ` with the master's security id). Holdings that cannot be mapped (BSE only, retired) are not quoted; their count is reported in the run message and the Portfolio screen keeps showing their last synced price.
3. **Where the price goes.** The portfolio module owns the update: a `Holding` gets `PreviousClose` (new nullable column) next to the existing `LastPrice`/`LastPriceAt`, and `LastPriceSource` (`sync` | `quote`, new). A quote run updates every open holding of a quoted security across accounts in one statement per batch: `LastPrice = last_price`, `PreviousClose = ohlc.close`, `LastPriceAt = fetch time`, source `quote`; values that are missing, zero or negative are ignored for that security. A **holdings sync** keeps setting the price from Dhan's holdings list **except** when the holding's price is a quote of the same India day: then the quote stays (it is newer than anything the sync knows), and the sync never touches `PreviousClose`. A sync and a quote write are kept from overwriting each other: the holding carries a row version (`xmin`), a sync that read a holding before a quote was written into it is refused at its save and reads again once, and the quote statement skips rows a running sync holds (the next tick quotes them). Because XIRR, P&L and value all read `LastPrice`, every figure follows the new price without further change; the XIRR valuation date stays the India date of the price time (ADR 0012).
4. **Day change** (design doc 12 §3, "vs previous close"): per holding `qty × (last − previousClose)` and `(last − previousClose) / previousClose`; per group and in total the sum of the holdings' day changes, with the percentage taken on the sum of `qty × previousClose` (not an average of percentages). A holding without a previous close is **left out** of day change and counted ("Day change excludes 2 holdings without a previous close"); it is never shown as zero. A price from an earlier India day is flagged "as of {date}" and the day change next to it belongs to that session. Corporate actions between the previous close and now are not adjusted (a split makes a wrong day change for the ex-date; the existing corporate-action alerts apply).
5. **The service.** `holdings-quotes` is registered with the Services framework in the Portfolio module: schedule type `interval` (every 5 min from 09:15 to 15:30 IST, trading days only — so the last run is at 15:30, the closing price), only `interval` allowed, retries 0 (the next tick is the retry), timeout 2 min, catch-up off (a missed tick is not made up), notify on failure on. It is the first `interval` service, so the story completes the machinery ADR 0018 §8 left open for it: a tick that falls while the previous run is still going is **dropped with a log line and no run row** (no skipped-row spam), a tick is never made up after sleep, and run rows of an interval service are kept like others (about 76 a day; the list shows the latest 200). The service skips with a reason (a recorded skipped run) when the Data account has no usable token, and does nothing when there is no open holding. A manual **Run now** works at any time (also outside the window) and is how the Portfolio screen's *Refresh prices* button works.
6. **Contract and screen.** `GET /api/holdings` rows and `GET /api/holdings/summary` gain `previousClose`, `dayChange`, `dayChangePct`, `priceAt`, `priceSource`, and the summary `dayChange`, `dayChangePct`, `dayChangeExcluded` and `pricesAsOf` (oldest and newest price time of the open holdings). The Portfolio screen gets a **Day change** tile and column, a prices line ("Prices as of 10:35 IST · quotes every 5 min" / "As of 10 Oct · sync" / "Quotes off: …"), and *Refresh prices*; while the market is open and the page visible it re-reads the holdings once a minute (SignalR with the live feed comes later). No price history is stored: only the latest quote per holding.

## Consequences
- Portfolio figures are at most one tick old during market hours and the owner can change or pause the poll on the Services screen like any other service.
- The Data API subscription is now used by two features; a lapsed subscription shows as a failed service run and a bell notice, and the screen falls back to the synced price.
- One new endpoint is allowed on the Dhan HTTP client; the allow-list tests are extended so no other marketfeed path is.
- A holdings sync on a day without a quote moves the price while `previous_close` stays from an earlier session (only quotes write it), so the day change next to a `sync` price can span sessions; the rows expose `priceAt` and `priceSource` so the screen can show how old the price and its day change are.
- Day change is only as good as Dhan's `ohlc.close` (previous close) — verified once by the owner against the Dhan app; if it turns out to mean something else, one mapping function changes.
- Run history grows by ~76 rows a day for this service (no purge yet; trivial volume, revisited with the retention work).
