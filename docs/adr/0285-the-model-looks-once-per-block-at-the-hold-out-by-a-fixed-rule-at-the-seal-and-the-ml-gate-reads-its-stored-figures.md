# 0285 — The model looks once per block at the hold-out, by a fixed rule at the seal, and the ML gate reads its stored figures

- **Status:** Accepted (owner, 2026-11-13; spec [CF-10e](../specs/CF-10e-ml-influence-evidence-sources.md) part 3, after HO-01b).
- **Date:** 2026-11-13.
- **Relation to other ADRs:** amends [ADR 0217](0217-a-model-may-influence-a-decision-only-through-one-gate-whose-predicate-needs-an-unspent-hold-out-forward-evidence-no-calibration-alarm-and-the-owners-switch.md) (the source of the hold-out figures; the truth table, the bars and the switch are unchanged) and [ADR 0281](0281-the-ml-influence-gate-reads-forward-figures-from-insert-only-shadow-scores-and-the-calibration-alarm-from-the-stored-monitor-row-and-the-designate-verb-goes-through-promotion.md) (decision 6: the hold-out figures now have a source); builds on [ADR 0283](0283-the-hold-out-is-a-chain-of-fixed-blocks-released-by-an-owner-act-or-the-auto-option-and-every-cut-follows-the-block-in-force.md) (one fresh look per kind per block, the horizon rule, the seal steps) and [ADR 0282](0282-auto-mode-defaults-follow-the-owners-instruction-of-2026-11-13-on-where-no-evidence-is-lost-and-no-risk-is-widened.md) (`ml.holdout.auto_score` defaults ON).

## Decision
1. **The look.** `ModelHoldOutScorer` claims the model family's fresh look at the block in force (`ModelHoldOutLooks.ClaimAsync`: insert-only, burned even if nothing can be scored; refused `learning.holdout_reused` / `learning.holdout_unavailable` as before, and a model registered on or after the block's horizon is refused and not stored), runs the pass once and stores the figures in `research.ml_holdout_scores`, one row per model and block, insert-only for the runtime role. Only a pre-dated model is ever chosen.
2. **The pass** (`ModelHoldOutPass`, the second and only other reader of the block, pinned by an architecture test) runs the strategy versions of the model's training set (`sim-all:{job}` through the job's sweeps, or `runKey:style:exit` through the stored run headers) once over the block with the same simulation query as the training (default parameters, timeframe and exits, the stored charge sheet) over the instruments of the stored baskets. Features come from the P6-04 extractor given only bars before each decision, joined with the newest stored cash cell statistics whose as-of date is before the block. A candidate with no features or no cell statistics is dropped and counted, never imputed. A win is a realised R above zero.
3. **The figures** (pure `ModelHoldOutFigures`): the model's log loss against the better of two no-ML baselines read before the block (the N-weighted base rate of the cell statistics known before the block, and each row's own cell rate), the better being the one with the lower pooled log loss, so it is never chosen in the model's favour; the paired day-cluster bootstrap probability and interval of the mean gain (2000 draws, 90 %, at least 10 trade days, otherwise unavailable); and the effect of a fixed take rule (take a candidate whose probability is at least its own cell's rate, read before the block, always) on realised R per candidate. The take rule is fixed before any row is seen and never chosen from the hold-out's labels.
4. **The reading across blocks.** `ModelHoldOutLooks.ReadAsync` reads the model's newest fresh look and the figures stored for exactly that look; a later look is the one read, so a later fail beats an earlier pass; a look without figures is unavailable, never a pass. `ShadowMlInfluenceEvidence` still returns null hold-out figures; the gate takes them from the reading, and `MlInfluenceEvaluator` still passes them only for the look's owner.
5. **The seal step and the slot.** `ModelAutoLookStep` (order 30, `IHoldOutSealStep`) scores the current champion whose development verdict is Eligible, whose kept hold-out ends before the block and that was registered before the block's horizon, once per block, never at block 1 (its first look stays the owner's and sets the horizon) and never at a filling block, while `ml.holdout.auto_score` is ON. `ModelLookSlot` (`IHoldOutLookSlot`) reports `Used`, `Available` (an eligible pre-dated champion could still look) or `NoSubject`, so the auto release waits while a model look is available; a read error is `Unavailable` and keeps the block.
6. **The setting.** `ml.holdout.auto_score` is a name in `research.ml_switch_settings` with a seed row (actor `system:default`, reason `ADR 0282`, ON) written only by the migration into a name without rows; the runtime role cannot write that actor. No row reads OFF. Any change of it, OFF or back ON, is an owner act with a fresh password (`PUT /api/learning/ml-settings`, `autoHoldOutScore`). An automatic score is recorded as `auto` (actor `system:auto-score`) with a setting hash, and the database refuses an automatic row while the newest switch row is not ON.
7. **The owner path.** `POST /api/learning/models/{id}/holdout-score` (owner, CSRF, fresh password) answers 200 with `MlHoldOutScoreView`; 403 step-up, 401 wrong password, 404 `models.not_found`, 409 `learning.holdout_reused` / `learning.holdout_unavailable`, 422 `learning.holdout_no_rows`. `GET .../influence` gains the interval, the log losses, the baseline name and the mode.
8. **Nothing else changes.** `ml.influence.enabled` stays OFF, the gate's consumers stay pinned empty, the truth table and the thresholds are as they were, ML stays advisory, no order is placed and nothing references `XDrishti.Execution`.

## Consequences
- Migration `AddMlHoldOutScores` (raw SQL, no snapshot change): the table, its guard trigger, the widened shape check and stamp trigger of `ml_switch_settings`, and the seed row. `Down` drops the table and the seed.
- `shortcut:` the take rule is a fixed threshold, not `MetaPolicyEvaluator`, which needs the development folds the pass must not read. The universe is the stored baskets, not the exact instruments of the training runs. The 730-day bar window and the seam rule are those of the shadow scorer. The command line verb `xd learn holdout-score` is read only (an irreversible look needs the fresh password the command line cannot ask for).
- A model trained on a released block gets its look one block later (the horizon rule); in practice the gate stays shut until a pre-dated champion has looked at a sealed block.

## Amendment 2026-11-13 (review of the first build; coordinator, taking the reviewer's recommendation under the owner's instructions of 2026-11-11 and 2026-11-13)
- **Order of the act.** The block in force must be sealed (a filling block is refused `lab.holdout_filling`, 409, nothing written). A look this model already claimed and has no figures for is resumed; any other look of the family at the block is `learning.holdout_reused`. Then every input is **prepared** before the claim: no bar of the block is read, and a failure is `learning.holdout_unavailable` with nothing written (the seal step says "model N inputs unavailable"). Only then is the look claimed, the pass run and the figures stored. `ModelLookSlot` keeps the block while a champion may still take or finish its look (Available), so a missing input never reads as "no subject" and never lets a forfeit hide it.
- **Cells for a simulation-trained model** are rebuilt the way its training built them (`SimTrainingCells`, shared with the training): the job's closed trades that ended before the block, through `CellStatsCalculator` as of the day before the block, with the same thinning; the base rate is read from the same cells. A run-trained model reads the newest stored cash snapshot whose as-of date is before the block (a snapshot of the block's first day is never read). A run-trained model's requests are rebuilt by the LC-01 planner (the exact request that made the run), with the window replaced by the block; a run that cannot be rebuilt refuses the act before the claim. The pass names the training-run reader, so it joins the fenced list of readers of training runs (learning side, not evidence).
- **Resume.** A failed pass stores no figure, so it is not a second look: the same model may finish its own claimed look (the unlock is its own and fresh, no score row exists, and the block is still in force and sealed). A look is never given to another model and a finished look is never redone. The pass runs on the host's stopping token, not the request's, so a dropped connection does not cut it off; a transient failure after the claim (found by walking the inner-exception chain, since EF wraps the database exception) answers `learning.holdout_interrupted` (409). Turning `ml.holdout.auto_score` OFF during an automatic pass does not throw after the claim: the automatic act is declined and the owner's score finishes the look. While a claimed look has no figures the model slot reads Available, so the auto release waits (the owner can still release the block, which has a fresh look).
- **Take rule.** The threshold is always the row's own cell rate, fixed in advance. The spec asked for the P6-13 `MetaPolicyEvaluator`; it needs the development folds, which the pass must not read, so the fixed threshold is a recorded deviation (decided under the owner's take-the-recommendation instruction).
- **Stored.** The score row also holds the dropped count, the block's end, the look id and the setting row, and a database trigger requires the fresh `model` unlock of the same look key, block and look id. The input hash no longer contains the registry id, so it repeats on a fresh database.

## Amendment 2 2026-11-13 (second review; coordinator decisions)
- **A look is finished only when every planned version ran.** The plan of a simulation-trained model is the job's sweeps that finished a run (as the training used), costed as the job's trades were (all charged: the charge sheet; none: gross; a mix refuses at prepare). If any planned version fails to replay (the engine reports some transient reads as returned failures) the whole run fails, nothing is stored and the look stays open. The score row holds `versions_planned` and `versions_run` (a scored row has them equal) and both are in the input hash. The default timeframe of a version is one shared helper (`SimTrainingCells.DefaultTimeframe`) used by the job and the pass.
- **The look is the file's.** Whether a look has ended is read by look (look key, block, look id), never by registry row; `research.ml_holdout_scores` is unique by `(look_key, block_start)`, so a second registry row with the same file never finishes or redoes a look and never adds figures; it reads the figures of the look it shares. A resume re-checks that the kept hold-out ends before the block and that the model was registered before the block's horizon.
- **Only a failure that goes away is resumable.** A database or network failure, a stop of the host, a version that could not be replayed, and the setting turned off mid-pass leave the look open, for at most 7 days after the claim (about five evenings; `ModelHoldOutScorer.MaxResumeDays`). Everything else ends the look with a **terminal row** and no figures: `outcome = no_rows` (nothing to score), or `failed` with a code (a deterministic exception, a refusal by the database, the resume window elapsed). A terminal row means the slot reads Used, the gate reads the figures as unavailable (never a pass) and the release can go on. The shape check of the table allows exactly these two shapes (scored with every figure, terminal with a code and none), and a terminal row needs no switch.
- **Stall notice.** While a champion's own claimed look has not ended, the stalled-block notice adds "the model's claimed look keeps failing" (words only; the failure code is in the log, `learning.model.holdout_pass_failed`, not stored). A resume is logged (`learning.model.holdout_resumed`).
