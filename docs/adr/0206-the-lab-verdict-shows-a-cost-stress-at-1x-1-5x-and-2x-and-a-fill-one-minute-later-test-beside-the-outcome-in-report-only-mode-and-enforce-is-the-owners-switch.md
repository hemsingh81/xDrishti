# 0206 — The Lab verdict shows a cost stress at 1x, 1.5x and 2x and a fill-one-minute-later test beside the outcome in ReportOnly mode, and Enforce is the owner's switch

- **Status:** Proposed (built in CF-05 from the owner-Approved spec, 2026-11-03; stress gate, delay test and the slippage tier mechanics only, see "What is not built"). Becomes Accepted when the owner has read it. **Safety slice: no** (research-side numbers; no order, no broker, no network; with `Enforce` off the verdict outcome, the six gates and their reasons, the limits, the evidence, the run key and the keys of the stored runs are unchanged).
- **Date:** 2026-11-04.
- **Relation to other ADRs:** extends [0038](0038-fill-realism-the-entry-limit-gaps-slippage-ticks-and-the-order-inside-a-minute.md) (fill rules: one new optional field), [0042](0042-costs-and-sizing-the-charge-sheet-the-quantity-net-r-and-simtrade-schema-4.md) and [0044](0044-the-cost-choice-the-stored-charge-sheet-the-cost-sheet-verbs-and-the-bill-check.md) (the sheet and its bill check; no rate is added), [0059](0059-the-test-ledger-and-the-verdict-evaluator.md) and [0063](0063-the-lab-report-from-the-stored-result-a-deterministic-summary-and-an-inert-page.md) (the gates and the report; the new rows sit beside them), [0203](0203-effective-n-is-the-smaller-of-an-entry-session-cluster-estimate-and-a-serial-estimate-shown-beside-n-in-report-only-mode-and-power-and-minimum-track-record-are-printed-with-it.md) to [0205](0205-the-lab-verdict-shows-a-deflated-sharpe-ratio-from-stored-trial-statistics-and-a-session-level-stationary-block-bootstrap-beside-the-factor-and-the-monte-carlo-in-report-only-mode-and-gate-is-not-offered.md) (same mode rule: shown beside, decides nothing by default, settings recorded with the figure).

## Context
A retail edge that dies when costs rise by half is a cost-model artefact. The Lab judges net expectancy at the modelled costs only. The programme rule (CF-00): a new gate is report-only beside PASS/MARGINAL/FAIL until the owner turns its enforce setting on; `unavailable` is never a pass; a number that is not known is not invented.

## Decision
1. **The stress is a restatement of stored trades, not a new walk-forward.** For a costed trade `RExact`, `SlippageR = RFilled - RExact` (never positive) and `chargesR = RFilled - NetR` give the net R at multiplier `m` as `RExact + m x (SlippageR - chargesR)`, which is `RExact + m x (NetR - RExact)`: no charge line is needed and no rate is read. It is exact for charges and first-order for slippage (a harsher slippage could also stop a fill from happening; the delay test, not this line, covers that). It is applied to the out-of-sample trades the verdict was judged on, so selection is not repeated. Both statements are printed with the figure (`CostStress.Formula`, `CostStress.FirstOrderLimit`), with the note that scaling the total over-penalises a fixed brokerage cap. `SelectionTrade` gains an optional `RExact` (null for a gross trade; nothing in the choice of an exit reads it).
2. **Gates (proposals, settings).** 1x is the existing expectancy gate (its adjusted threshold and its verdict); 1.5x needs a mean of at least 0.08 R; 2x needs a mean greater than 0 R. The floors are not multiplied by the trial factor. "Tradable" is the worst of the three rows: `fail` if any row is a miss, else `unavailable` if any has no figure, else `pass`. No trades, a value that is not finite, a gross run (no stored sheet) or an unchecked sheet gives `unavailable` with the reason and never a number as a pass.
3. **The sheet must have been checked against a bill.** Until `cost-sheet check` has written the sheet's `checked` note, every row and the delay line read `unavailable: costs not checked against a bill: stress gates cannot PASS` (the figures are still shown beside it) and the report warns `costs_not_checked`. After the check the label is gone. The runner reads the one sheet the run was costed with; nothing writes it.
4. **Fill one minute later (`EntryDelayMinutes`).** `FillRules` gains `EntryDelayMinutes` (0 default, 0..5; `FillRules.Create(percent, slippage, delay = 0)`). The fill minute becomes the N-th minute that holds a trade after the first one, the fill window grows by N minutes, and the P3-03b rule is otherwise unchanged (the limit placed at the decision instant, open if within the limit, else the limit if the minute trades back to it, else `LimitNotReached`). The canonical JSON gets `,"entry_delay_minutes":N` only when N is above 0, so a run without it has the same text, the same run key and the same trades (the whole existing suite, including goldens, passes unchanged). `FillRulesInput` gains the same optional field.
5. **The delay test is per signal.** The robust stage runs the base once (the default exit over the whole window, the sweep's own base run, now keeping its trades) and one more pass with the delay. A signal is a base trade matched by instrument, side and decision instant; a signal the delayed run does not fill counts as 0 R; delayed trades with no base signal are not counted. Pass when the delayed mean per signal is at least 70 % of the base mean per signal; a base mean of 0 or less, no signal or a value that is not finite is `unavailable` ("not evaluable"). The comparison per fill is not computed. It is a robust-stage figure; the pass is on the default exit over the whole window, not on the walk-forward winners (printed). A failed delayed run is kept as its reason.
6. **Conservative slippage tiers: the mechanics, not the wiring.** `Slip` (internal to the walker) gains an optional `TierBps` (null = the default rule, bit for bit); nothing sets it yet, and it is not on `WalkRules`: amount `max(Ticks x tick, TierBps/10000 x price) + extraTicks x tick (stop exits) + BarRangeFrac x range`; a target stays free, the entry never passes the limit, fills lie on the grid, nothing improves a price (hand table and a 2,000-case property test). The bps applies to the price of the fill itself (so a stop exit at Rs 990 pays 0.297 where the spec's hand table, which uses Rs 1,000 for both, reads 0.30). `LiquidityTiers` (20-day median of close x volume, cuts as arguments; A, B, C, unavailable; C and unavailable are not priced) and `Capacity` (1 % of the fill minute, 0.5 % of the median; a missing figure is a breach) are pure Domain with the spec's numbers as tests.
7. **Modes and settings.** Section `Confidence:CostStress`: `Mode` (`Off` | `ReportOnly`, default `ReportOnly`; `Gate` is not a mode: enforcing is its own setting), `Enforce` (default false), `MidMultiplier` 1.5 (above 1, at most 5), `MidFloorR` 0.08, `HighMultiplier` 2 (above Mid, at most 5), `HighFloorR` 0 (both floors -1..1), `DelayMinutes` 1 (1..5), `DelayRetention` 0.70 (0.1..1). A value out of range stops the host at start. Every block stores `Settings` (the text of the values) and `SettingsHash` (its SHA-256), so a stored verdict says which proposals it was judged by. Changing a setting is the owner's act in configuration; the thresholds are proposals until the owner moves them.
8. **Enforce.** With `Enforce` on and a PASS, a stress gate (1.5x, 2x or the delay test) that is a miss or `unavailable` caps the outcome at MARGINAL and adds a limit naming which; a MARGINAL or FAIL is never raised or changed, the six gates are untouched, and `Capped` says so. With it off (the default) nothing but the new member changes: a runner test serialises the verdict with and without the member and compares the bytes, and the sim run keys of the two runs are equal. The scope of the cap is a little wider than the spec's "a failed 2x gate" (it also covers 1.5x and the delay line, the other two proposed gates of D1 and D3); this is the owner's to narrow.
9. **API and storage.** `GET /api/lab/runs/{id}` verdict and `/report` gain optional `costStress` (rows, tradable, delay, settings and hash, `costsChecked`, `capped`, formula, limit); the HTML report gets a "Costs and delay" section only when the block exists. The Lab screen (a lazy route) prints a "Costs and delay" block in the verdict panel and the report panel: the three rows with the status as a word, the delay line, the not-checked label and the printed limit. No migration: the verdict is a jsonb document and an old one reads null. `POST /api/lab/runs` is unchanged.

## What is not built (follow-up of CF-05)
- **Wiring the tiers into a run** (`slippage: conservative` on `POST /api/lab/runs`, the tier of each candidate from the replay's bars, tier C counted and excluded from the "tradable" evidence). Excluding tier C needs a counted no-trade reason, which touches the run record, the counters and the export; that is a change of its own.
- **Evaluating `min_turnover` and marking `capacity_breach` on a trade** (the pure rule exists), and the evidence count "excluded tier C and breaches".
- The `stress` request field. Until it exists the block is carried by `robust` runs only (mode on), where the delay line lives; `quick` and `full` documents are byte-identical to before (criterion 7).
- When the tiers are wired, the slippage preset must enter the `FillRules` canonical text (left out at the default) and so the run key, and `WalkRules` must carry the tier of each candidate.
- The owner's contract notes (below).

## Open owner questions
1. Five contract notes (three intraday, two delivery including a DP day) to fill the sheet's lines and run `cost-sheet check`; until then every stress row reads unavailable. 2. The tier cuts (Rs 100 crore / Rs 20 crore) and bps (3, 8) once they are wired. 3. Is dropping tier C from edge claims acceptable, or priced at 15 to 30 bps and kept? 4. When `Enforce` goes on (an owner act). 5. Should the cap cover only the 2x gate, as the spec words it, or all three stress gates as built?
6. The delay test's population is the default exit over the whole window including in-sample dates (not the walk-forward winners' out-of-sample signals), and a base signal blocked in the delayed run by the one-position rule counts as 0 R; is that acceptable, or should the pass be restricted to the winners' test windows?

## Consequences
Only robust runs carry `costStress` (a plain `full` run's stored document has no such member). Progress counts the delay pass: the robustness total is instruments x (1 + sweep points + 1). The block stores the sheet's rates hash beside the `checked` flag, both read once at the start of the run.
The default is unchanged in every stored number. A fresh install shows the block with every row `unavailable` until a bill check is recorded, which is the intended honest state. The delay pass costs one more walk of the whole universe in a robust run (progress counts it). The numbers are planning proposals, replaced by measurement from paper fills later.
