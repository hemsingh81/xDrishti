# 0159 - The pre-send checklist is one pure function over 34 checks with `unavailable` as a reject, stored insert-only, and wired as the real pre-send step over a closed facts source

- **Status:** Accepted (decided in P12-03 under the owner's instruction to build P12; spec [P12-03](../specs/P12-03-pre-trade-checks.md)).
- **Date:** 2026-10-29.
- **Relation to other ADRs:** builds on ADR 0155 to 0158 (`IPreSendCheck` was the closed default); follows ADR 0087 and 0091 (unavailable never passes; auto means every check passes). The data-side allow-list and `Infrastructure/Brokers/BrokerEndpoints*` are not touched; no other project references Execution.

## Context
`LegSender` asks an `IPreSendCheck` before every send and the default refuses. The spec asks for a real one: 34 checks with exact limits, stored results, a fresh re-run at the moment of the send. Most inputs (quote, margin, profile, calendar, plan, halts, stream) have no source inside the execution project yet, and the owner's limits stand: no call to Dhan, nothing sends by default, live refused, every new switch closed.

## Decision
1. **Pure function, facts in.** `ExecChecklist.Evaluate(kind, intent, account, market, system, limits, now, confirmation)` reads nothing and sends nothing. Facts are plain records; each Stamped fact carries the time it was read. A missing, null, NaN, infinite, impossible (negative where it cannot be) or too old or future-stamped fact makes exactly the checks that read it `Unavailable`. 26 Hard and 8 Soft in a fixed order; all are evaluated (no short-circuit); the result is deterministic. Stream liveness is the one check where "down and no fresh poll" is `Fail` rather than `Unavailable` (both reject).
2. **Hard cannot be overridden; Soft only by the exact owner confirmation.** The verdict is `Cleared`, `ClearedByConfirmation` (semi_auto only, `owner:` actor, a reason, codes equal to the run's Soft non-passes, no Hard non-pass) or `Rejected`. A confirmation is void when the Soft set differs in any way. `auto_live` has no human, so any Soft non-pass is a reject.
3. **Run kinds.** `full` authorises a send for `exec.check_valid_for_s` (10 s); `fast` (the seven time-critical checks) only confirms a still-valid full run; `advisory` shows `gate_open` as not applicable and never authorises.
4. **The pre-send step.** `ChecklistPreSendCheck` replaces the closed default in the sandbox composition. For an entry it loads facts, then runs a fast run if a cleared full run is still valid, else a full run that must itself clear, and stores the run before answering. Facts that cannot be loaded, limits that cannot be vouched for, a loader or store that throws: all refuse (`check_facts_unavailable`, `check_limits_unavailable`, `check_store_unavailable`). The refusal carries the first failing code. The facts loader is registered as the closed default (answers nothing), so **every entry is still refused** until real sources exist; the change is strictly not more permissive for entries.
5. **Exits are not judged here, and still refused.** Stops, targets, exits and flatten legs go to `IExitSendPolicy` and never touch the entry checklist (proved for each leg kind with a halted, over-limit, out-of-window account). The default policy refuses, so nothing but an entry can pass the pre-send step until P12-04's reduce-only rule supplies the answer. This keeps the default closed, at the cost that a protective stop cannot be sent yet; nothing can send at all yet.
6. **Record.** Migration `AddExecutionChecks`: `execution.check_runs`, `check_results`, `check_confirmations`, insert-only for every role including the owner (trigger), `xd_exec` INSERT and SELECT, `xd_app` SELECT only, shape and code constraints (owner of a run is an intent or a sheet, never both; an owner-only confirmation actor; non-empty codes). Details are capped at 500 characters; no token, client id or secret is stored (inputs are numbers and codes).
7. **Limits.** `ExecLimits` is read from the registry; five settings added with compiled ranges (`exec.max_loss_per_trade_inr` 1000, `exec.max_spread_ticks` 3, `exec.max_spread_pct` 0.25, `exec.min_depth_multiple` 2, `exec.check_valid_for_s` 10). No setting turns a check off. An out-of-range value in force makes the whole limits object unavailable (reject). Soft limits (1 % of average volume, 3 days, correlation 0.70) are compiled.
8. **Boundary tests unchanged.** The architecture tests did not need a change: everything is inside XDrishti.Execution, nothing references it, no order-write capability was added (the checklist is read-only decisions; the only write is insert-only check rows). The xd-api allow-list is unchanged.
9. **Moved, not built.** The facts loader (its sources: P12-05 halts, P12-06 streams, P12-11 token and IP attestation, P12-07 modes, plan and profile reads, broker quote/margin/profile reads that have no adapter yet), the read endpoint `GET /api/execution/intents/{id}/checks` with `gen-api` (nothing can have produced a run, and the screens are P12-10), advisory-run writes (P12-07), the state moves `checking>rejected` and the Soft-only wait (P12-08).
10. **Never verified against real Dhan or real data.** Needing real data: quote fields `upper_circuit_limit`, `lower_circuit_limit`, five-level depth and `last_price` (market quote); `POST /v2/margincalculator` fields (`totalMargin`, `insufficientBalance`); `fundlimit` `availabelBalance`; `GET /v2/killswitch`; whether the static IP is allowed (spec amendment: owner attestation); exchange freeze quantity for cash equity (no source: own cap applies, said in the detail). The spread/depth thresholds, the two-tick circuit margin and the collar are stated assumptions that only make the system stricter and are the first numbers to review after real sessions.

## Consequences
The decision that guards every entry is now a single tested function with a negative control for each check and an 80-row table of defective inputs, and the pre-send step stores what it decided. Nothing new can send: the loader is closed, the exit policy is closed, the send path itself is still behind sandbox and the second switch. Wiring real facts is the next work and each source arrives with its own slice.
