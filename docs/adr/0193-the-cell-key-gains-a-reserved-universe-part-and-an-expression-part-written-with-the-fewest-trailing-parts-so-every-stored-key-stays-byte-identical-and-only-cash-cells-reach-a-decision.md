# 0193 — The cell key gains a reserved universe part and an expression part, written with the fewest trailing parts, so every stored key stays byte-identical and only cash cells reach a decision

- **Status:** Proposed (built in P14-06 from the owner-Approved spec, 2026-11-03). Becomes Accepted when the owner has read it. **Safety slice: no** for trading; the rule it adds is that no decision path can read a non-cash cell. No order path, no setting.
- **Date:** 2026-11-03.
- **Relation to other ADRs:** [0058] (run identity), [0064] (cells and `research.cell_stats`), [0045] (insert-only research rows). Design change to doc 09 (the cell key). Depends on BK-11 decision 5 (`universe` is the seventh part, `expression` the eighth); BK-11 is not built.

## Decision
1. **`Expression`** (`Domain/Learning`) is a closed enum stored by name: `cash`, `future`, `option_buy`, `debit_spread`, `credit_spread`, `iron_condor`, `pair`, `basis` (`ExpressionNames.Code` / `Parse`, exact lower case).
2. **`CellId`** gains `Universe` (default `*`) and `Expression` (default `Cash`) after `Regime`. Every existing call site and every stored row is a `*`/`cash` cell without a change. `IsCash` is the one property the decision paths read.
3. **Canonical key text: the fewest trailing parts.** Universe `*` and cash: six parts, today's text byte for byte. Another universe and cash: seven. Any other expression: eight, universe explicit. Exactly one text per cell.
4. **Parsing** accepts 6, 7 or 8 parts. A seventh part must be a known universe (only `*` in this slice, so a seven-part key is refused until BK-11 adds `liq_high|liq_mid|liq_low`); `...|*` as seven parts and `...|*|cash` as eight are not canonical and are refused (`null`); an unknown expression, a ninth part, an empty part or a part over 64 characters is refused. `Problems()` refuses a `CellId` made with any universe but `*`: the reserved dimension accepts only its default.
5. **Expression profiles.** `ExpressionProfile` (kind plus parameters) has the canonical text `expression-profile/1`, `kind=<kind>` and the parameters sorted by name (`name=value`, invariant number formatting, no trailing zeros), joined by line feeds; `Hash` is SHA-256 of the UTF-8 text in lower hex. Names are `[a-z][a-z0-9_]{0,31}`, values at most 64 characters without control characters, at most 32 parameters. Cash takes none. `ExpressionProfile.Cash` is the identity profile and its hash is pinned. `Create` returns a `Result`; nothing throws on bad input. A profile belongs to the identity of a re-mark run and a ledger trial (P14-08, P14-09), never to a strategy version (P14-00 D4).
6. **Storage.** Migration `AddExpressionProfiles`: `lab.expression_profiles(profile_hash char(64) PK, kind, params jsonb, canonical_text, created_at)` with checks on the hash, the closed kind list and an object `params`; `xd_app` has SELECT and INSERT only (per-table grant, then `MakeAppendOnlyForAppRole`); `xd_exec`, `xd_mcp_read` and `xd_mcp_sql` have nothing. `IExpressionProfileStore` (append with `ON CONFLICT DO NOTHING`, get, list) reads a row back through `Create` and refuses (`InvalidDataException`) a row that does not hash to its key.
7. **`research.hypotheses.cell_key`** is widened from `varchar(400)` to `varchar(600)` (an eight-part key of 64-character parts is 519; the old longest six-part key was 389, so the old column was enough only for six parts). `Down` narrows it only when no stored key is longer than 400; the log is insert-only and a key is never cut. `research.cell_stats.cell_key` is `text` and needs nothing. The `paper.entries` and `trading.plan_items` key columns stay at 200: only cash cells reach them.
8. **The read-only view `aiv.hypotheses` selects the column, and Postgres refuses to alter the type of a column a view uses.** The migration drops the view, alters the column and creates the view again with the text and the grants of `AddAiReadAccess` (revoked from `xd_app` and PUBLIC, SELECT to the two read-only roles). `ReadOnlyRolesTests` still pass over the catalog.
9. **Reading cells back.** `CellStatsStore` builds the cell from the six stored columns and, only when the stored key has more than six parts, takes `Universe` and `Expression` from the key. A six-part key goes through exactly the old path.
10. **Cash only on the decision paths.** The store chooses the snapshot among cash keys (see Known limits). `CashCells.Only` then filters the rows read by `ShowSelectionHandler`, `StoredTicketSource` (the plan) and `ConfigSnapshotSource` (the paper configuration) and logs `non_cash_cell_skipped` with the count (event 4610); `TicketReplayer` grades a non-cash ticket as not gradable and `CapturePaperFillsHandler` skips it (`not_gradable`), both logging event 4610, `ConfigSnapshotSource` ignores a non-cash changelog subject. The cell-statistics source (`CellSourceReader`) builds every cell as `Expression.Cash` explicitly. The list and detail readers (`ListCellsHandler`, `GetCellHandler`, the overview, the assistant facts) show every cell with its expression.
11. **API.** `CellStatsView` and `CellStateView` gain `universe` and `expression` (additive; `scripts/gen-api.sh` run). The plan, ticket and paper views are cash-only and are not changed; they gain the fields when a non-cash cell can appear in them.
12. **Architecture tests** pin: a non-cash `Expression` value is named only in Domain/Learning, Domain/Options, Domain/Pairs, the learning and research stores; the expression types are named by no selection, planning, paper, live or execution code (nor the execution service); every reader of stored cell rows is decided in a list, and each decision path keeps to cash.

## Consequences
- P14-08 can write option and pair cells and profiles next to the cash cells with no change to any decision path; P14-09 counts every profile in N.
- BK-11 only widens `KnownUniverses` and must keep rule 3: always writing seven parts would change the canonical text of every stored key.
- Cells per expression multiply the cell count by the number of profiles.
- A stored non-cash row is visible in the cell list (`ListCellsHandler`) with `expression` set; no screen was changed.

## Known limits
- **Display readers show non-cash statistics.** `ProposalFacts` (the facts behind assistant proposals) and the cell list, overview and detail readers show option and pair cell statistics, with their expression. A proposal built on such a fact is a research proposal that the owner approves by hand; it cannot become a plan, ticket or order, because the decision paths take cash cells only.
- **Snapshot choice.** The decision reads (`ListLatestBeforeAsync`, `ListLatestCashAsync`, `NewestAsOfAsync`) choose their snapshot among snapshots that hold a cash key (exactly five separators), so a later snapshot of non-cash cells alone cannot hide the cash snapshot or change the paper configuration. A snapshot that mixes cash and non-cash rows is returned whole by `ListLatestBeforeAsync` and the handlers filter and count; `ListLatestCashAsync` returns the cash rows only. The display reads (`ListLatestAsync`, `FindLatestAsync`) are unchanged.
- **Corrupt rows.** A stored key of more than six parts that does not parse, or whose first six parts differ from the stored columns, is an `InvalidDataException` on read, never a cash cell.
- **Counting.** `non_cash_cell_skipped` is a log event (4610) from selection, the plan, the paper configuration, the ticket replay and the paper capture; there is no metrics counter in the code base.
- The `regime = '*'` filter of the store lists still returns non-cash rows to the display readers; only the decision paths filter. The architecture test makes a new reader a decision.
- The 10 % cost target for `TryParse` and `Key` is ungated; a smoke test keeps the hot path linear.
