# 0201 — The P14 reports are read-only counts, shares, dates and verdict words through one select-only reader whose name extends the table pins, and a figure with no source is the word unavailable with a closed reason

- **Status:** Proposed (built in P14-16 part A from the owner-Approved spec, 2026-11-03). Becomes Accepted when the owner has read it. **Safety slice: no** (GETs and one verb that read stored rows; no setting, no write, no order).
- **Date:** 2026-11-04.
- **Relation to other ADRs:** extends the reader pins of [0178](0178-the-option-archive-quality-checks-read-the-recorded-chains-and-rolling-bars-in-bounded-ranges-and-store-insert-only-verdicts-with-an-honest-unavailable-and-no-trading-use.md) (the option archive), [0196](0196-the-pairs-study-counts-every-candidate-in-the-ledger-before-any-test-walks-pairs-in-a-separate-pair-1-walker-on-the-simulators-fills-and-judges-them-by-protocol-s-where-a-gross-drop-is-valid-and-a-gross-keep-impossible.md) and [0197](0197-the-option-expression-simulator-re-marks-each-stored-cash-trade-as-one-long-option-on-a-fixed-strike-read-from-the-offsets-with-an-expiry-calendar-of-labelled-derived-dates-a-counted-model-price-fallback-and-every-unpaired-trade-counted-by-reason.md) (the run tables); reads the verdict records of 0183, 0186, 0198 and 0200 through the existing evaluation read port; the honest states of P8-00 D3 and [0099](0099-the-report-engine-is-a-pure-core-with-one-population-rule-six-honest-states-and-a-ranking-by-the-credible-lower-bound.md).

## Context
P14-16 asks for four summaries (option archive, expression runs, pair formations, every P14 verdict) as API and CLI, with no screen until a verdict is worth showing. Each needs a read of a table that an earlier ADR pinned to named readers.

## Decision
1. **One reader file, four reads, extended pins.** `OptionReportReader` (port `IOptionReportReader`) is the only new file that names `options.quality_results`, `research.expression_runs`, `research.expression_trades` and `research.pair_formations`; the pins of 0178, 0196 and 0197 gain exactly that file name. It issues SELECTs only; no column of price, premium, strike, IV, Greek, bar, quote or return is selected. Its queries are bounded: the underlying list by a session-date range and a limit, one run by id, the run counts by the ids read, the formations by a window range and a limit (one more than 400, so a longer answer says `truncated`), and the run list by newest-first with a limit (100). The chain-session counts are not read by SQL: the handler reuses `IOptionQualityStore.ChainResultsAsync` and the pure `ArchiveSessionFigures` (in the quality namespace, so the usable rule of 0178 is applied by its own code). The backfill key counts reuse `IBackfillFetchLog.LoadStateAsync` and `KeyState` (done includes empty and no-data answers, as the backfill progress counts it; given up is `KeyState.IsGivenUp`), so no new reader of the fetch log exists.
   **Shortcut, stated:** the archive summary is not fully bounded in time. `ChainResultsAsync` has no lower date bound (it reads every checked chain session of one underlying), the spread model is read once per underlying, and the backfill state is the same unbounded group-by the backfill loads each cycle. The loops are over at most 200 underlyings. A batched, date-bounded quality read would change the pinned quality port and is left until the cost is seen on the owner's database (the spec budget is 300 ms p95).
2. **No series.** The response types hold counts, shares, dates, words and bounds. A test pins every field name and fails on a price, IV, Greek, bar or quote token. Run counts and shares are over the whole stored run, hold-out included (flags, not returns).
3. **Honest states.** A figure is `{state, value, reason}`: `ok` with a value, or `unavailable` with no value and a reason from the closed list `not_recorded`, `no_model`, `no_runs`, plus two added here, `no_pairs` (a share or a distribution with no denominator: a run that paired nothing, a formation that selected nothing) and `no_rejection` (the Benjamini-Hochberg line has no last rejection). The printed form shows `unavailable (reason)`, never a digit.
4. **The Benjamini-Hochberg threshold** is the stored `rank * q / m` at the last rejected rank, read from the stored table; absent from the table it is `unavailable (not_recorded)`. No threshold is invented.
5. **Verdicts** are the newest record per family of the expression families, `pairs:intraday-1` and `ext:iv-1` (the basis families are not built and are not listed). No route: the verb prints them and the shared `GET /api/research/extensions` holds the evidence. `--cut` marks families as `cut` and does not read them; P14-17 will pass its own list.
6. **Names.** Types in `XDrishti.Application.OptionReports`, `Abstractions.OptionReports`, `Infrastructure.OptionReports` and `XDrishti.Domain.Options.Reports`; the handler that reads the quality rows and the spread model is named in the quality and cost pins.

## Prototype search
`docs/prototype/` was searched for options, expression or pairs screens: none exists (only roadmap rows in `delivery/plan-progress.js` and a regex in `assets/app-pages-7.js:131`), so part B has no prototype to match.

## Consequences
- No migration, no setting, no frontend code (the generated schema only). Part B waits for the first record that is not NOT_EVALUABLE.
- Every P14 report figure can say why it is missing; none can print a zero for it.
