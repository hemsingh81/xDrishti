# 0157 - The Dhan order adapter is a sandbox-only guarded client inside the execution project, and the send protocol writes ahead and resolves an unknown outcome by lookup, never by resend

- **Status:** Accepted (decided in P12-02 under the owner's instruction to build P12; spec [P12-02](../specs/P12-02-dhan-order-adapter-and-sandbox.md)).
- **Date:** 2026-10-29.
- **Relation to other ADRs:** continues ADR 0155 and 0156; the data-side allow-list of ADR 0097 and ADR 0133 is not touched.

## Context
P12-02 is the first slice whose code can send a request that places, changes or cancels an order. The owner required that nothing can send by default, that no test touches Dhan, that live stays refused, and that the data-side allow-list keeps refusing every order write.

## Decision
1. **Where.** The adapter is `XDrishti.Execution/Dhan/`, seven files. Only that folder may use `HttpClient`, name a host, or carry the `access-token` header; only `ExecutionEndpoints.cs` holds the order paths and the one host `sandbox.dhan.co` (taken from a third-party description, UNVERIFIED). `BrokerEndpoints` and the `xd-api` allow-list have zero diff and no project but the two test projects references Execution.
2. **Sandbox only, live refused twice.** `ExecutionEndpoints` passes nothing unless the environment is `sandbox`; `DhanOrderClient` and `LegSender` refuse to construct or send for any other environment; no live host string exists in the project (a test scans for it). Going live is a later ADR with its own owner act.
3. **Unreachable by default.** `AddExecution` composes the adapter only when `Execution:Environment` is `sandbox` (any other text reads as none). Without the owner's secret files `Execution__Sandbox__ClientId` and `...__Token` the client refuses locally (`execution.token_unavailable`) and makes no request. `LegSender` is not composed by the host at all in this slice: it needs a persistent `ISendJournal`, which is P12-02b, so there is no caller and no audit-less path to the broker. Every new setting defaults safe and nothing is switched on.
4. **Guard in depth.** The URI is built only by `ExecutionEndpoints.Build`; every request that reaches the socket passes `GuardHandler`, which compares the method and the exact URI to the table (https, exact host, default port, no user info, no query, no fragment, a plain-token id). Redirects are off, no proxy, 5 s connect timeout, per-request deadline (10 s). A refused request never reaches the inner handler (tested).
5. **Instruction shape.** Only LIMIT, DAY, INTRADAY, NSE_EQ bodies can be written; market orders, after-market flag, disclosed quantity, other products and slicing cannot be expressed. A stop or target leg and the super-order body are refused until P12-04 decides the structure. Price must be on the 0.05 tick (per-instrument ticks come with P12-03).
6. **Three-way outcome.** Acknowledged only for 2xx with an order id and TRANSIT or PENDING. NotSent for a failure before the connection carried the request, a 2xx REJECTED, or a 4xx with a parseable Dhan error. Everything else, including a timeout after sending, is Unknown. DH-905 with an IP message is `ip_not_allowed`.
7. **Exactly once.** Writes are never retried by the client. `LegSender` order: environment, account gate, entry halt, pre-send re-check (default closed), age, rate, write-ahead record (an exception means nothing is sent), second halt check (an entry is dropped, not sent), one request, outcome record. An Unknown is resolved by `LegLookup` (two empty lookups 2 s apart are absence; a failing lookup stays Unknown and is never absence). An entry is never resent; a stop, exit or flatten may be, under `ResendPolicy`, as a new attempt id.
8. **Secrets.** `DhanCredentials` prints redacted; the token is only the `access-token` header of one request; the only log line carries call, status, outcome and a reason code. A test captures the log and scans it.
9. **Reduced scope, stated.** The database audit table, persistent journal and day count, grants on the broker secret tables, the other read endpoints, the stateful FakeBroker, contract tests and sandbox smoke are P12-02b (spec amendments list them). Reason: each needs either a migration with its grants test or live credentials, and none is needed to prove the guard and the protocol.
10. **Event id** 6615. Settings added: `exec.exit_collar_pct`, `exec.send_timeout_s`, `exec.order_valid_for_s` (not yet read by the client, which uses the defaults).

11. **Review fixes.** (a) Only name-resolution and TLS faults are NotSent; a connection error can be a reset after the body was written, so it is Unknown. (b) A 404 on the lookup is absence only when its body is a Dhan error saying not found; any other 404 is a failed lookup. Because the lookup path and that answer are unverified, `ResendPolicy.MayResend` is false unless the owner-only setting `exec.lookup_verified` (default OFF) is true. (c) The lookup result must carry our correlation id, else the lookup failed. (d) One strict environment parser (`ExecEnvironmentParser`: exact name, any case, no trimming, no number, no list) is used by `ExecOptions` and `ExecServices`.
12. **Known limits.** No price, notional or quantity ceiling exists in the adapter (P12-03 supplies them). `exec.send_timeout_s`, `exec.order_valid_for_s`, `exec.exit_collar_pct` and the limiter caps 2/30/200 are hard-coded (10 s, 5 s, none, 2/30/200); wiring them to the settings snapshot is deferred to P12-02b. The registered `IBrokerOrders` (place, modify, cancel) bypasses `LegSender` (gate, halt, rate, journal): nothing in the host calls it, and P12-02b must register only `LegSender` or wrap the client so no caller can reach the raw adapter.

## Consequences
The code to send a sandbox order exists, is covered by fake-handler tests, and cannot run in any deployed host unless the owner sets the environment to sandbox and creates the sandbox secrets; even then nothing calls it until a later slice composes `LegSender` with a persistent journal. Real Dhan behaviour (field names, absence answers, de-duplication of a repeated correlation id) is unverified and is found only by the owner's sandbox smoke and the canary protocol.
