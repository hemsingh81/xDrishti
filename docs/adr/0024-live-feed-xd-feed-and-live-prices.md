# 0024 — Live feed in its own container, live prices in the holding price columns, and a SignalR hub for the screen

- **Status:** Accepted (owner, 2026-10-14: "approved as written") — builds on [ADR 0007](0007-accounts-credential-references-and-step-up.md) and [ADR 0008](0008-broker-credentials-vault-and-connection.md) (vault, Data account token), [ADR 0016](0016-market-bars-csv-load-dhan-fetch-and-app-managed-aggregates.md) (allow-listed Dhan endpoints), [ADR 0018](0018-services-framework-and-editable-schedules.md) (services), [ADR 0019](0019-holdings-quotes-day-change-and-the-first-interval-service.md) (quotes, day change), [ADR 0022](0022-action-center-and-price-alerts.md) (price alerts)
- **Date:** 2026-10-14

## Context
Prices on the Portfolio screen are at most five minutes old (ADR 0019) and alerts are checked on the same tick (ADR 0022). The roadmap's P2 exit criterion asks for live P&L during market hours, and the design (docs 03, 05 §5, 17) names `xd-feed` — a separate container that streams the active set from Dhan's WebSocket — and SignalR `/hubs/events` for the browser. Open positions and plan tickets, the other members of the active set, do not exist before P7/P12.

## Decisions
1. **Separate host.** `xd-feed` is its own container (`XDrishti.Feed`), not a hosted service in `xd-api`: a hung socket or an API deploy must not drop the feed, and the API does not need the Data token at runtime for it. It runs 09:00–15:35 IST on trading days as the service `live-feed` (type `window`, runs as `xd-feed`); `xd-api` shows and edits the schedule, `xd-feed` reads it every minute and owns the run. Status travels through a heartbeat row (`platform.service_heartbeats`), not a command channel.
2. **Active set in P2.** Open holdings that map to an NSE instrument, instruments of active price alerts, the benchmark, and NIFTY 50 / NIFTY BANK / INDIA VIX, built from providers so positions and tickets plug in later; capped at `Live:MaxWsInstruments` (200; cut order alerts, indices, holdings by value). One connection, subscriptions in messages of ≤ 100, ticker mode for indices and alert-only instruments, quote mode for holdings. The packet layout is from Dhan's documentation and **unverified** until the owner's first real session.
3. **Live prices go into the existing holding price columns** with a new `last_price_source = live` (migration `AddLiveFeed`), one statement per flush (every `Live:FlushSeconds`, default 2), so value, P&L, XIRR, day change, the Action center and the alerts keep reading one place. Precedence: a sync keeps a quote or live price of the same India day; a quote never overwrites a newer live price and vice versa; the row version protects against lost updates; `previous_close` is written only by quotes (a ticker packet has none; the previous-close packet is parsed but not trusted until verified). Instruments that are not holdings go to `market.live_quotes` (`UNLOGGED`, emptied each window). No price history, no live bars in this decision.
4. **The 5-minute `holdings-quotes` service stays** as the safety net and sole writer of `previous_close`. Prices received 09:00–09:15 are indicative and never replace a same-day quote.
5. **Alerts on live prices.** After each flush the active alerts of the flushed instruments are evaluated with the P2-09 evaluator; the conditional update on `status = 'active'` keeps a trigger single even when the 5-minute check runs at the same time. A spike between two flushes is not seen.
6. **Feed → API by `LISTEN/NOTIFY` and the database** (docs 03 §3 already names it): the feed sends `live_prices` (no payload, ≤ 1/s) and `active_set_changed`; the API reads what changed. No RPC, no second hub, a restart of either side loses nothing.
7. **SignalR hub `/hubs/events`** in `xd-api` (session cookie, owner only, same origin). The screen subscribes with its scope and holding ids and receives only those prices, coalesced to one message a second and bounded (≤ 500 instruments, ≤ 32 KB). The browser recomputes rows, groups and tiles with the same pure functions as the server and re-reads exactly every 5 minutes and on reconnect; without the hub it falls back to the once-a-minute re-read. Caddy proxies `/hubs` with the WebSocket upgrade.
8. **Credentials.** The WebSocket URL is one exact entry on the endpoint allow-list. `xd-feed` gets the vault key and the app DB password as read-only secret files (no environment secrets), reads the **primary Data account's** token only through the existing token port, never logs a token, client id, URL query or raw packet, and is on the `back` and `egress` networks with no published port.
9. **Two slices.** P2-10 (feed host, parser, active set, price sink, alerts, Services row, compose, migration) and P2-10a (hub, status endpoint, Caddy, live Portfolio screen).

## Consequences
- Portfolio figures and alerts are seconds old in market hours, and the screen says honestly when it is *Live*, *Delayed* or on quotes.
- A fourth container and a second secret consumer; the vault key is now mounted into two services.
- One UPDATE every 2 s during market hours on a few dozen rows; the row version and precedence rules keep sync, quote and live writers from fighting.
- Pre-open prices are recorded but labelled and never override a quote; a lapsed Data plan or refused token stops the feed visibly and the screen falls back to quotes.
- Packet shapes and the previous-close meaning are checked once by the owner; a wrong guess changes one mapping function.
- Out of scope and still to come: live 1-minute bars and their reconciliation with EOD bars, depth and tick recording (P13), positions and tickets in the active set, a pinned basket.

## Amendments (independent review, 2026-10-14)
- **Day change on live prices.** A live price on top of a previous close from an earlier session would show a two-session change as "day change". `portfolio.holdings.previous_close_at` (set by the quote poll with `previous_close`) is added, and for a holding priced by `live` the previous close counts only when it was written on the same India day as the price; otherwise the holding is excluded from day change and counted. Quote- and sync-priced rows keep ADR 0019's behaviour (and its known limitation).
- **Same-second ticks.** Trade times are whole seconds: a tick with the same time and a different price replaces the older one (written, alert-checked); same time and price is a no-op.
- **Where the pieces live.** The feed's heartbeat is a row (`xd-feed`) of the existing `platform.service_heartbeats` with new `state` and `details` columns, not a new table. `xd-api` lists `live-feed` but never starts it or recovers its runs (marker `IExternallyRunService`); the feed's supervisor reads the stored schedule row every 15 s. **Run now** writes `platform.app_settings` key `live-feed.manual_until` and answers a `queued` run with an empty id; Pause clears the marker. Failures that must raise the service notice (token refused, flapping, crash) end the run `failed`.
- **Load and hygiene.** The Action-center reconcile after a live flush is limited to once a minute; `market.live_quotes` is cleared once per window; the portfolio value-history cache of `xd-api` (60 s lifetime) bounds how stale the history's "today" point can be — the feed does not invalidate it.
- **Operations.** `xd-feed` has `stop_grace_period: 30s` and a minimal health probe (timeout 10 s). A `stopped` heartbeat is benign on the System status page for 10 minutes only.
