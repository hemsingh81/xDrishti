# 0277 — The cell-statistics refresh repeats the newest snapshot to the hold-out cut, fails closed, and resumes only with the owner's password

- **Status:** Accepted (coordinator's recommendation under the owner's standing instruction of 2026-11-11; every decision of spec LC-01 as recommended).
- **Date:** 2026-11-12.
- **Relation to other ADRs:** Amends [0252](0252-the-auto-switch-resumes-five-chain-services-follows-the-stored-switch-for-the-builder-and-restores-only-what-it-resumed.md) §1 (the chain becomes six services). Uses the recovery classes of [0240](0240-missed-days-are-recovered-by-one-dependency-ordered-pass-and-each-service-declares-how-it-can-be-recovered.md), the evidence fence and training embargo of [0243](0243-simulate-everything-is-training-data-fenced-from-the-hold-out-and-from-scorecard-evidence.md), CF-08 D6 (cell statistics do not ingest shadow grades) and the paper rule of ADR 0119 (P10-05), which this decision does **not** change.

## Context
Cell statistics were written only by the owner's `xd learn cells`. The nightly plan's selection-inputs gate fails when the newest snapshot is more than 5 sessions old, so Auto stopped the plan by itself in the second week (ISS-30). Spec LC-01 adds a scheduled refresh. It writes a decision input with no human in between, so it is bounded tightly.

## Decision
1. **Service.** `cells-refresh`, host `xd-api`, `After eod`, not before the session end, paused at first start, recovery class `LatestOnly`, catch-up same day. It is **not** in `nightly`'s `MustFollow`: a paused refresh must not block the nightly's recovery; the gate is the check.
2. **What it recomputes.** The newest snapshot is the template: its sources, options and the regime and universe splits it has. With none it fails with `cells_refresh.no_snapshot` (the first snapshot is the owner's). A source whose strategy version has a CF-06 pre-registration and whose window ends before the refresh end is simulated again over the exact request (proven by the replay planner) with only the end moved, stored as a `research` run; every other source is kept (`kept: up_to_date` or `kept: not_registered`). A newer version is never swapped in. The snapshot is then computed as of the last closed session.
3. **Refresh end** = the earlier of the last closed session and the hold-out start less one day less `HoldOut:TrainingEmbargoDays`. No block: `cells_refresh.no_holdout`, fail closed.
4. **Counted.** Each newly stored refresh run appends one `lab.test_ledger` row of kind `cells_refresh` (migration `AddCellsRefreshTrialKind`; `Down` refuses while such rows exist). It is in the total of looks (`TrialCounts.CellsRefreshes`) and is not a variant: the readers that take hashes skip it. A run stored already adds nothing.
5. **All or nothing.** Every simulation is made before anything is stored; any failure ends the run `failed` with its code and no snapshot, and nothing is re-stamped, so a failure never becomes a stale pass. The gate's rule is unchanged; when it fails for age, its reason adds the newest refresh state (`paused`, `failed on <date>: <code>`, `never ran`).
6. **Owner control.** `ServiceConstraints.ResumeIsOwnerAct` (true only here) makes `POST /api/services/cells-refresh/resume` need a fresh password in the body; a missing password is 403 `auth.step_up_required` and counts nothing (the CF-10/11/12 order, so the Services screen's dialog can ask first), a wrong one is 401 `auth.invalid_credentials` and counts toward the lockout. `ServiceView.resumeNeedsPassword` says so. Every other service still resumes with a session; pause needs a session only. Auto ON is already a fresh-password act and resumes it as the owner act it is (recorded in `planning.auto_switch_changes` like the others).
7. **Paper.** `cells-refresh` is added to `PaperConfigKeys.LearningWriterServices`, so it shows as a blocker while enabled in an epoch. **The P10 paper-epoch rule is unchanged: a refresh is a `frozen` change as today.** The owner has not decided roadmap open decision 9 (epoch freezes versions and rules but not the snapshot, or the snapshot stays frozen, or the age rule is raised); this ADR does not pre-empt it.
8. **Notice.** `cells_stale` is derived on read in the service notices: while `nightly` is enabled and the newest as-of date is at least `Learning:CellsRefresh:NoticeAfterSessions` (Internal, default 3, 1 to 4) sessions behind the last closed session; one per day.
9. **Fences.** The refresh types name no shadow, paper, execution, autonomy or live-trading type and read stored runs only through `IRunStore` (architecture tests). Every run message states "data through <end>; no new trades can enter until a hold-out block is released (HO-01)": before HO-01 a refresh re-stamps the same trades with a later date, the weights shrink uniformly and the posterior drifts toward the prior, so a passing gate is not newer evidence.

10. **Run now.** "Run now" still runs the service while it is paused (as for every service): an attended act by the signed-in owner, recorded with the owner as the actor. Only the schedule needs the password-protected resume.
11. **Auto and the paper epoch.** Auto ON resumes `cells-refresh`, and while a paper epoch is open each run is a `frozen` change that restarts the count. Turning Auto ON during an epoch therefore needs the owner's attention; this belongs to open decision 9.

## Consequences
With Auto ON the nightly plan survives past 5 sessions, on honest but not newer statistics until HO-01 releases a block. The owner's choice on decision 9 remains open. Shortcuts: up to 50 simulated runs are held in memory at once; the ledger row follows the store without a shared transaction (its id comes from the run key, so a repeat adds nothing).
