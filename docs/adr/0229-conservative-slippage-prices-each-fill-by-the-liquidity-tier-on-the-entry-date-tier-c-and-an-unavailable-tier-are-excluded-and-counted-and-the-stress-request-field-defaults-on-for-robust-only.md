# 0229 — Conservative slippage prices each fill by the liquidity tier on the entry date (tier C and an unavailable tier are excluded and counted), and the `stress` request field defaults on for `robust` only

- **Status:** Proposed (built as CF-05 follow-up, 2026-11-08). Becomes Accepted when the owner has read it. **Safety slice: no.** It only makes a Lab run more pessimistic when asked; no order is placed and nothing is on by default except what robust runs already carry.
- **Date:** 2026-11-08.
- **Relation to other ADRs:** completes two items of the "Still open" line of CF-05 after [0206](0206-the-lab-verdict-shows-a-cost-stress-at-1x-1-5x-and-2x-and-a-fill-one-minute-later-test-beside-the-outcome-in-report-only-mode-and-enforce-is-the-owners-switch.md) (the `Slip` tier floor) and [0223](0223-the-lab-verdict-counts-each-trades-liquidity-tier-and-capacity-breach-from-day-bars-report-only-and-readiness-row-14-reads-them-with-unavailable-as-a-fail.md) (the tier from day bars). `min_turnover` is not part of this ADR and stays open for the owner's threshold.

## Context
`Slip.Of(config, tick, tierBps)` existed but no run passed a tier, so `slippage: conservative` could not be asked for. The Lab also carried the cost stress block on every robust run with no way to leave it out or to ask for it on a full run.

## Decision
1. **`slippage: "conservative"`** on `POST /api/lab/runs` (also `"default"`; anything else is `invalid_input`). It sets `FillRules.ConservativeSlippage`; the Lab's request uses 1 tick, 0.10 of the bar range (D2) and 2 extra ticks on stop exits, with the floor `max(Ticks x tick, tierBps x price)`. Tier A 3 bps, tier B 8 bps (`TieredSlippage`, planning numbers, replaced by measurement from paper fills).
2. **Tier per instrument and entry date:** `EntryTiers` (behind the port `IEntryTierSource`) reads the instrument's day bars once per instrument and gives the tier from the 20-day median of close x volume over the sessions strictly before the entry date, with the cuts of `CostStressOptions` (the same rule as the verdict's tier block). The lookup travels as `InstrumentReplayInput.TierOn` to the walker (`WalkRules.TierOn`). The random-entry and placebo walks use the same lookup, so their fills match the strategy's.
3. **Tier C and an unavailable tier are never priced as tier A:** the walker returns the no-trade `TierExcluded` (a new `NoTradeReason`, counted in `WalkCounters.TierExcluded` and `RunFates.TierExcluded`, `tier_excluded` in the export). A conservative run with no lookup excludes every trade. Fewer than 20 sessions of history is unavailable. A failed day-bar read fails the run (no fallback to a price).
4. **Canonical text and key change only when the option is used:** the fill text gains `,"slippage_tiers":"conservative"` only when set; the Lab configuration hash gains `slippage=conservative` only then; the two new counters are omitted from the run record while 0 (a modifier in `SimExportJson`), so an existing run, key and record text are unchanged.
5. **`stress` request field:** `true` is the default for `robust`, `false` for `quick` and `full`, so no default changes a result. `stress: false` on a robust run leaves the block out (another key); `stress: true` on a `full` run adds it (without the delay test, which belongs to the robust sweep); `stress: true` on a `quick` run is refused (no out-of-sample trades). Spelling the default gives the same key as leaving it out.
6. **Storage:** one nullable column `lab.lab_runs.run_options` (migration `AddLabRunOptions`; `slippage=conservative;stress=on|off`, null when nothing was chosen) so the runner reads what the post chose.

7. **Beyond the spec, awaiting the owner's view:** the spec's rule (CF-05, D2) excludes tier C only. This ADR also excludes an **unavailable** tier (fewer than 20 sessions of day bars, or no usable median), because pricing it as tier A would flatter the run; the owner may prefer to price it at tier B or keep it. Until the owner has said so, both exclusions are counted and shown (item 9) and the choice is open.
8. **The hold-out is judged on the development's fills:** the hold-out pass builds its fills from the run's stored options (`LabFills`, the same helper as the quick test and the full test), so a conservative run is not unlocked on default fills against a conservative expectancy. This is a defence only: `HoldOutUnlocker.CheckAsync` refuses a run posted with non-default options (manual and auto), so a what-if run can never spend the version's single hold-out look or set scorecard row 12.
9. **The exclusion is carried, not hidden:** a conservative verdict has a `tierExclusion` member (candidates, tier-excluded, share), a limit line, and a report warning `tier_excluded`. Readiness row 14 and the tier C hard fail read a verdict with that member as unavailable, reason `conservative run`: its survivors are never clean tier evidence.
10. **Which run the scorecard reads:** the newest finished full or robust run **posted with the default options** (`LabRunView.options.isDefault`: slippage default and stress as the method's default). A conservative or stress-changed run is a what-if and never the scorecard's evidence basis, even when it is newer. `LabRunView.options` (`slippage`, `stress`, `isDefault`) is served.
11. **`stress: false` and Enforce:** a `robust` post with `stress: false` is refused (`invalid_input`) while `Confidence:CostStress:Enforce` is on, because leaving the block out would skip the cap. `stress: true` that cannot run (cost stress Off, or no stored sheet) adds a warning problem `lab.stress_not_run` to the run.
12. **Labels:** a post adds `slippage: conservative (tier C and unavailable excluded)` and, for an explicit off, `stress: off`.
13. **Stored options this code cannot read** (an unknown or repeated token) fail the run at validate with `lab.run_options_unknown`; they are never guessed at.
14. **Cost comparisons:** `FillCostComparison` (P6-11) refuses to compare two runs whose `slippage_tiers` differ: conservative tiering is a different rule, not a different amount.
15. **Shortcut:** the tier bps (3 and 8) and the range fraction (0.10) are constants (`TieredSlippage`) although the spec lists them as settings; to be replaced by measured values.

## Consequences
- A conservative run has fewer trades (tier C and unavailable are counted, not hidden); the owner reads the count in the fates.
- The pair walker (P14) is not wired: its fills are always `FillRules.Default`, so the option is unreachable there.
- Open: the tier cuts and bps, whether tier C should be priced (15 to 30 bps) instead of dropped, and `min_turnover` (waiting for the owner's threshold).
