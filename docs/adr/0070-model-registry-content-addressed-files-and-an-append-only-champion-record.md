# 0070 — The model registry: content-addressed files and an append-only champion record

- **Status:** Proposed (spec [P6-07](../specs/P6-07-model-registry-and-scoring.md), approved under the owner's standing run instruction of 2026-10-22, every open question as recommended; built 2026-10-23). Becomes Accepted when the owner has read it.
- **Date:** 2026-10-23.
- **Relation to other ADRs:** [ADR 0068](0068-the-ml-net-trainer-adapter-pav-calibration-on-a-held-back-slice-and-honest-explanations.md) (the artifact, `Load` with a hash, FastTree in production), [ADR 0067](0067-validation-harness-and-baselines-purged-folds-and-an-honest-eligibility-rule.md) (the verdict), [ADR 0066](0066-decision-time-features-a-side-table-and-the-training-set-record.md) (the training set). ADR 0071 belongs to another slice.

## Context
P6-06 produces model bytes and a hash; P6-05 says whether a candidate beats the baselines. Nothing yet keeps a model, ties it to the data and the verdict that justified it, or says which one the system would use. P6-00 owner question 7: the champion is advisory and unused until P7; question 8: files with a SHA-256, not `bytea`.

## Decision
1. **Files.** `data/models/<sha256>` (config `Models:Folder`), flat and content-addressed. A write goes to a temporary file in the same folder and is renamed into place; it is refused when the bytes do not hash to the name, and left untouched when the file is there and intact. A name that is not 64 lower-case hex characters never becomes a path. A read hashes the bytes and fails with `models.file_corrupt` (or `models.file_missing`). Size cap 64 MB (the loader's own).
2. **Never trust a file without its recorded hash.** The scoring path reads through the file port (hash checked) and loads through `IModelScorerLoader`, which wraps `MlNetModel.Load(bytes, sha256)` (hash checked again). `LoadUnverified` is not used by the registry. As in ADR 0068, the hash is integrity, not authenticity: whoever can replace the file and the database row can replace the model.
3. **Registry tables**, both insert-only for `xd_app` (`MakeAppendOnlyForAppRole`, grants test extended, `Down` drops them). `research.model_versions`: hash, registration key, trainer and note, `training_set_id` (foreign key to `training_sets.set_id`, added in SQL), feature catalog version and width, fit/calibration/train rows and dates, the hold-out start (or none), the verdict (`Eligible`, `CannotBeatBaselines`, `Inconclusive`) with folds, pooled calibration error, log loss and Brier, the reasons, the full report text with its limits, the parameters, the calibration table and the feature importance. `research.model_designations`: model, role (`challenger`, `champion`, `retired`), reason, who, when.
4. **Champion / challenger is an append-only record, not a flag.** A model's role is its latest designation. Registration appends `challenger`. Naming a champion appends `retired` for the previous champion and `champion` for the new one in one transaction under an advisory lock. Nothing is updated or deleted; the history is returned by `GET /api/models/{id}`.
5. **Only an Eligible model may be champion** (`ChampionRule`, Domain): a `CannotBeatBaselines` or `Inconclusive` model is registered (as a challenger, kept for comparison) but `models.not_eligible` (409) refuses it as champion. The verdict is immutable, so the check needs no lock. Enforced in the handler, not in the database (a cross-table check would be a trigger; not worth one for a single-owner system).
6. **Idempotence.** The registration key is the SHA-256 of the model hash, the training-set id, the parameters and the report text. The same inputs give the same key and a second registration writes nothing (`AlreadyRegistered`). The same bytes with another validation (other hold-out, folds or trials) are another registration sharing one file.
7. **Registration path = `TrainModelHandler`** (`xd learn model`): build the training data of stored runs (the loader shared with P6-04, extracted from `BuildTrainingSetHandler`), keep the training-set record, cut the hold-out (default last 6 months, as `xd learn windows`; 0 keeps none and the report says so), run the P6-05 harness for the candidate, train the final model on the development rows only, write the file, register. The hold-out is in neither the verdict nor the model.
8. **Layers.** Ports in `Application/Abstractions/Learning`: `IModelRegistry`, `IModelFiles`, `IModelTrainer`, `IModelScorerLoader` (Domain types in and out; no ML.NET type). Infrastructure implements them; it references `XDrishti.Learning.MlNet` but no `Microsoft.ML*` package, and the architecture tests assert that only Infrastructure references the adapter project and only the adapter references the packages.
9. **Production trainer is FastTree** (ADR 0068, decision 3: the container images carry no `libgomp1`; LightGBM is not proven there). The candidate and the final model use the same settings, so the verdict is about the stored model. Switching is one setting in `MlNetModelTrainer` once a container build shows LightGBM training.
10. **Scoring** is a handler (`ScoreWithModelQuery`: probability and top path-based contributions with feature names) for experiments and P7; there is no endpoint or verb that shows a score. **API:** `GET /api/models`, `GET /api/models/{id}` (read only); training and designation are the verbs `xd learn model` and `xd learn designate` (no screen yet, so no write endpoint).
11. Log ids 4520 to 4525 (ids, short hashes, counts, codes; no feature values).

## Consequences
- Whether any registered model beats the baselines on real trades is **unknown**; the registry stores what the harness said, with its limits, and every view carries that the model is advisory and that the data were seen (ISS-19).
- A champion changes nothing until P7; naming one is a record.
- Two registrations of identical bytes share a file; the file is never deleted by the registry (no retention yet).
- The API container's model folder is the relative default `data/models`; only the `xd` script and `scripts/dev-api.sh` set an absolute one. Nothing in the API reads a file today (scoring has no endpoint); mounting `data/models` into `xd-api` is for P7.
- Not verified here: that the ML.NET native helpers load in the chiseled container images (the adapter has no host in a container before this slice).
