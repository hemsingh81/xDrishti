# 0230 — The `min_turnover` filter passes on a 20-day median traded value of at least 20 crore; the tier bps and the range share are tighten-only settings; the defaults are judgment calls to be replaced by measured paper fills

- **Status:** Proposed (built as the last slice of CF-05, 2026-11-08; the threshold is the owner's decision of the same day). Becomes Accepted when the owner has read it. **Safety slice: no.** It only removes entries from a research run and makes costs larger; no order is placed.
- **Date:** 2026-11-08.
- **Relation to other ADRs:** completes CF-05 (D2, D4) after [0229](0229-conservative-slippage-prices-each-fill-by-the-liquidity-tier-on-the-entry-date-tier-c-and-an-unavailable-tier-are-excluded-and-counted-and-the-stress-request-field-defaults-on-for-robust-only.md). **Supersedes decision D3 of [ADR 0037](0037-simulation-conventions-and-the-two-stage-seam.md) for this one filter:** a strategy that names `min_turnover` is no longer refused with `simulation.filter_not_available`; the simulator evaluates it. Every other unknown filter is still refused.

## Context
`min_turnover` was accepted by the model but refused by the simulator for lack of liquidity data. The day bars (close, volume) are stored and `LiquidityTiers` / `EntryTiers` (ADR 0223, 0229) already read the 20-day median of close x volume. `WarmupStrategies` names the filter, so that strategy now runs. The slippage numbers of ADR 0229 (tier A 3 bps, tier B 8 bps, range share 0.10) were code constants flagged `shortcut:`.

## Decision
1. **The filter passes when** the 20-day median traded value (close x volume, the 20 sessions strictly before the entry date, the same rule and code as the tiers) is **at least** `Confidence:CostStress:MinTurnoverCrore` (default Rs 20 crore). Equality passes. Missing bars, fewer than 20 sessions, or a bar with no usable volume give an unknown median, which **blocks the entry and counts it**, never a pass. A host without the bar source blocks every entry.
2. **Counted like `TierExcluded`:** a new no-trade `TurnoverBlocked` (`WalkCounters.TurnoverBlocked`, `RunFates.TurnoverBlocked`, `turnover_blocked` in the export, omitted from the record while 0). Produced by the walker, before the fill is priced.
3. **The threshold is part of the run:** a strategy that names the filter is prepared with `FillRules.MinTurnoverCrore`; the canonical fill text gains `,"min_turnover_crore":N` only then, so the run key changes with the threshold and a run that does not name the filter keeps its text, key and export byte for byte. A simulator whose fill rules have no threshold refuses a side that names the filter (fail closed). The Lab configuration hash gains `min_turnover=Ncr` for a strategy whose text names the filter, and `tiers=A/B/R` for a conservative run whose floors differ from the defaults.
4. **Settings, validated at host start, tighten-only (raise, never lower):** `MinTurnoverCrore` 20..50, `TierABps` 3..5, `TierBBps` 8..15, `RangeFraction` 0.10..0.20. A value below its default is refused because it would loosen a gate. With the defaults, a conservative run has the same fill text, key and results as under ADR 0229.
5. **The defaults are judgment calls with no authoritative NSE source.** They are planning assumptions to be replaced by figures measured from paper fills (P11-02). Until then the Lab verdict does not rest on them being right, only on their being conservative.
6. **The 20 sessions are consecutive (turnover read only).** For the filter, the median is over the 20 consecutive trading sessions of the trading calendar before the entry date, each with a day bar of positive volume; a gap or a zero-volume day makes it unknown (blocked), so a gap cannot draw on older bars. The tier rule of ADR 0223/0229 (`LiquidityTiers.Median` over the last 20 bars stored) is unchanged, so default runs and stored tier results do not move; the stricter rule applies to `min_turnover` only.
7. **Verdict: fail closed.** A Lab verdict whose strategy names the filter has `turnoverExclusion` (candidates, blocked, threshold; null otherwise, so other stored verdicts are unchanged), a limit line and a report warning `turnover_blocked`. Readiness row 14 and the Lab tier set read unavailable with the reason `min_turnover survivors`, as for a conservative run: the trades left are survivors of a liquidity filter, not a clean tier sample.
8. **The Lab key** reads the parsed definition (`StrategyDescription.ReadsTurnover`), not the text, so a comment that mentions the filter does not change it; numbers in the keys are written with up to four decimals.
9. **Trade cards** replay with the same lookups (the tier source travels on `ExplainBasis`).
10. **Limits:** `ReplayBaselineReader` rebuilds only the entry limit and slippage, so a stored run with a delay, conservative tiers or a threshold is refused as a baseline (a `shortcut:` comment marks it). A `SimulateHost` CLI run, and any host that does not replace the singleton, uses the code defaults of `CostStressOptions`, not `Confidence:CostStress`; only the API host binds the section.
11. **Compile warning kept, reworded:** the model still emits `strategy.model.filter_not_evaluated` for `min_turnover` as a notice of the fail-closed rule (the code list of the model is unchanged).

## Consequences
The strategy of `WarmupStrategies` that names the filter is accepted by the simulator (it can still be refused for its other fields). No migration; the API shape is unchanged.
