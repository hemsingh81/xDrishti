# 0068 — The ML.NET trainer adapter: PAV calibration on a held-back slice and honest explanations

- **Status:** Proposed (spec [P6-06](../specs/P6-06-ml-net-trainer-calibration-and-contributions.md), approved under the owner's standing run instruction of 2026-10-22, every open question as recommended; built 2026-10-23). Becomes Accepted when the owner has read it.
- **Date:** 2026-10-23.
- **Relation to other ADRs:** [ADR 0067](0067-validation-harness-and-baselines-purged-folds-and-an-honest-eligibility-rule.md) (the port `IScorerFactory` and the eligibility rule), [ADR 0066](0066-decision-time-features-a-side-table-and-the-training-set-record.md) (the features). ADR 0069 belongs to another slice.

## Context
P6-00 D4: a model is used only if it beats the cell statistics and a logistic regression out of sample and is calibrated. The P0 spike showed ML.NET trains, saves and loads fast and deterministically on linux/arm64, and that its isotonic calibrator matches our PAV; it also showed LightGBM at AUC 0.571 against a logistic baseline of 0.734 on synthetic data (cause not investigated), so the model may well lose.

## Decision
1. **A new project `XDrishti.Learning.MlNet`** is the only one that references `Microsoft.ML`, `.LightGbm` and `.FastTree` (versions already pinned); it references Domain only. Architecture tests assert both, and that no ML.NET type is in a public signature. It implements the Domain port of ADR 0067 (`IScorerFactory`, name `meta_model`), so the harness, the registry and the baselines are not aware of ML.NET.
2. **Training.** Train rows are ordered by decision time. The earliest 75 % fit the trees; the latest 25 % are held back and fit only the calibration map; fit rows whose label horizon reaches the first held-back decision are dropped. Test rows never reach `Fit` (the harness guarantees it). Missing or non-finite features are replaced by the mean of the fit rows. One fixed conservative setting (100 trees, 8 leaves, rate 0.05, 20 rows per leaf), one thread, fixed seed, no grid (a grid would be more trials against 2 years of data).
3. **Trainer.** LightGBM first; if its native library cannot load (only `DllNotFoundException`, `BadImageFormatException`, `EntryPointNotFoundException`, `TypeInitializationException` are caught; macOS arm64 has none), FastTree is used and the model's note (with the exception type and message), its artifact and the report limits say so, including how many of the fold fits carried a note. Any other LightGBM error surfaces. The numbers are never to be read as LightGBM's. **Container:** LightGBM's native library needs `libgomp1`, which the chiseled noble runtime images do not contain; copying it from the build stage is possible but cannot be verified without a container build, and no host references the project yet. Decision: until a container build shows LightGBM training in the image (P6-07), production is **FastTree**, the container does not exercise LightGBM, and nothing may claim it does.
4. **Calibration.** Own PAV in Domain (`IsotonicCalibrator`): equal scores pooled, adjacent violators and equal neighbours pooled, linear between block means, flat outside; the probability is kept within [0.005, 0.995] so that a confident miss cannot have an unbounded loss. The P0 spike found it equal to ML.NET's isotonic.
5. **Explanations.** `Explain(row, top)` returns the largest per-feature attributions from ML.NET's tree-path calculator (positive pushes towards label 1). They are **path-based attributions, not exact, not SHAP, bias term not included**: they do not add up to the raw margin (a test checks that they follow it, correlation above 0.9, and nothing stronger). They are in raw-score units, before the monotone but non-linear calibration, and are stored with the score by the registry. A missing value is imputed to the fit mean and then appears as an ordinary contribution of that mean value; it is not flagged as missing. `Importance(rows)` is the mean absolute contribution. This replaces permutation importance (P6-00), which would need the test metric and a second code path per trainer.
6. **Artifact.** `"XDMODEL1"`, header length, JSON header, ML.NET zip re-packed with sorted entries, a fixed timestamp and no compression (so the bytes do not depend on the runtime's deflate); the SHA-256 is over all bytes. Same rows in any order give the same bytes. `Load(bytes, expectedSha256)` requires the hash and checks it first; `LoadUnverified(bytes)` is the explicitly named way without one. **The hash is integrity (these are the bytes that were stored), not authenticity**: whoever can replace the file can replace the hash. Loading is hardened: artifact at most 64 MB, header at most 1 MB, zip at most 64 entries and 256 MB unpacked, every header field validated (arrays present and equal in length, finite, a monotone calibration map, floor in (0, 0.5), width equal to the loaded model's input width, trainer equal to the loaded transformer's type), a first score and the contribution calculator are built at load, and any ordinary exception of the loader becomes `ml.bad_artifact`. **Residual risk:** ML.NET's deserialiser is not hardened against crafted tree payloads (a corrupt tree can throw on some rows or even spin), and it resolves a loader assembly by name from the bytes; so only bytes whose stored hash came from the registry are to be loaded, and `LoadUnverified` is for trusted bytes. Where the bytes are kept (`data/models/`) is P6-07.
7. **Failures.** `Train` returns `ml.too_few_rows`, `ml.one_class`, `ml.no_features`, `ml.bad_feature_width`, `ml.bad_options`; `Load` returns `ml.hash_mismatch`, `ml.bad_artifact`. `MlNetModel` keeps no prediction engine (scores go through a transform), so there is nothing to dispose. `Fit`, which has no failure channel, returns the smoothed base rate with a note.
8. No migration, API, CLI or log events (ids 4500 to 4509 unused). The Dockerfile copies the project file; no host references the project yet (P6-07 does).

## Consequences
- Whether the model beats the baselines on real trades is **unknown**; nothing here claims it. On synthetic noise it does not (tested); on a synthetic interaction the baselines cannot see it does (tested). The first real answer needs P6-04 features on the owner's trades and at least 6 folds.
- On this development machine (macOS arm64) only FastTree runs. The LightGBM success path is tested only where the native library loads (skipped with a reason otherwise) and is **not** exercised in the container images for now (see 3). The fall-back is tested with an injected failing fitter.
- The ML.NET platform-target opt-out properties moved to `backend/Directory.Build.props` so the future host gets them.
- The spike's AUC gap is not explained by this slice (it used one-hot synthetic features and defaults); the planted-signal tests here pass with FastTree.
- The calibration map is fitted on about a quarter of the train rows: with few rows it is coarse, and the harness's calibration error will show it.
