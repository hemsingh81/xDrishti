# 0254 — Index baskets are stored, read-only system baskets fed by an off-by-default, guarded fetch of NSE index lists, with forward-only dated membership

- **Status:** Proposed (BK-01, Approved spec 2026-11-03). Becomes Accepted when the owner has read the NSE / NSE Indices terms **and** done the owner acts below. **Safety slice: YES** (a network fetch of NSE files; no order, no trading configuration touched).
- **Date:** 2026-11-10.
- **Relation to other ADRs:** [0014](0014-portfolio-buckets-appear-as-system-baskets.md) (portfolio buckets as computed system baskets; the `baskets.system` 409), [0195](0195-the-nse-daily-history-is-an-off-by-default-fetch-behind-an-empty-owner-edited-allow-list-pattern-with-fail-closed-header-maps-and-a-daily-table-that-nothing-reads-yet.md) (the off-by-default NSE fetch pattern), [0010](0010-instrument-master-sources-and-scope.md) (master-data HTTP clients), ISS-22 (no historical index membership).

## Context
Official NSE index constituent lists (Nifty 50, 100, 500, sector and strategy indices) are public CSV files with one header (`Company Name,Industry,Symbol,Series,ISIN Code`). The owner wants them as baskets whose membership is dated from the first fetch on, without inventing history. The NSE terms of use for automated download and local storage were **not read** by the builder (UNVERIFIED), and the CDN's acceptance of a non-browser User-Agent is UNVERIFIED.

## Decision
1. **Stored system baskets.** `market.baskets` gains `kind` (`manual` · `index` · `list` · `derived`; the portfolio buckets stay computed) and `system` (`system = (kind <> 'manual')`, a check). `GET /api/baskets` lists them first, with `kind`, `system`, `membersKnownSince` and `source { state, lastOkAt, lastCheckedAt, unmatched }`. Every change route on one is 409 `baskets.system` (update, archive, members add/remove/order, a transfer into it or a `move` out of it); a **copy out** to a manual basket is allowed; the reorder of baskets lists the manual ones only.
2. **One generic fetcher over a catalogue table.** `market.basket_sources` holds, per basket, the url (host A `nsearchives.nseindia.com/content/indices/` or B `niftyindices.com/IndexConstituent/`), an alternate url, the file name, the expected row bounds and `enabled` (**default false**), the validators (`etag`, `last_modified`), the last `sha256` and the state (`never` · `ok` · `stale` · `rejected` · `failed`). The migration `AddSystemBaskets` seeds the **26** catalogue rows, all disabled; file names are data, never derived from the index name. `market.basket_fetches` is the insert-only fetch log (the runtime role has SELECT and INSERT only): counts, hash, status, outcome, a short reason, `forced`, the actor and the setting snapshot of a forced fetch; never file content.
3. **Off by default, zero requests.** `Baskets:System:Fetch:Enabled` defaults false. With it off **no HTTP client is registered** (the fetcher is a stub that never reaches the network), the handler returns `baskets.fetch_disabled` (409) before asking anything, and the scheduled service `system-baskets` (daily 07:30 IST, paused at first start, three retries) ends as `skipped: disabled`. An empty `Baskets:System:Fetch:UserAgent` refuses to run. The client goes through `BasketSourceEndpointGuard`: GET, https, default port, no query, only a plain `.csv` under `/content/indices/` on host A or `/IndexConstituent/` on host B; never `www.nseindia.com` or any `/api/*`; no redirect is followed, no cookies; 5 MB and 30 s caps.
4. **Fail closed, keep the last good.** One conditional GET per file per run (`If-None-Match` / `If-Modified-Since`); a 304 or the same sha256 is `unchanged`. A page that is not the file (404, wrong `Content-Type`), a wrong header, a row count outside the bounds, more than 20 % of rows without a master match, a removal of more than 50 % of the members (**tripwire**) or, outside the review windows, a change larger than `max(3, ceil(6 % x members))` is `rejected` with its reason; nothing is applied and the previous membership stays visible. The review windows (the 20th of March, June, September and December to the 7th of the next month) lift the change bound only. 403/429 and server errors, timeouts and no connection are `failed` (403/429 rest the source for 24 hours; the scheduler's retries do the rest); after 3 days without a good check the state is `stale`. A concurrent change is stopped by the unique index of open stays and reported as a failed fetch.
5. **Matching** is by ISIN, then by symbol (a warning is recorded), else the row is unmatched (listed in the fetch record, not a member; the basket shows "N members not in your instrument list"). A retired master instrument that NSE still lists stays a member (flagged in the record); only a fetch that no longer lists it closes the stay.
6. **Forward-only dated membership.** The effective date is the **India date of the first fetch that shows the change**, stored as the start of that day: a row with `valid_to = D` is not a member on D; a row with `valid_from = D` is. `detected_at` keeps the instant, `provenance = fetched`, `source_ref` / `source_kind` name the fetch. A date before the first `valid_from` is answered with the first known membership and `membersKnownSince` (never an empty list). Applying is one transaction (closed stays, new stays, the basket's revision, the fetch row, the source state and the audit event). The audit event `BasketMembershipChanged` carries counts only.
7. **Fetch now** is an owner act: `POST /api/baskets/system/fetch` needs a session and a step-up; `basketIds` names the sources it runs (and turns them on); `force` overrides **only** the tripwire and is recorded with the setting snapshot.

## Owner acts needed before anything is fetched
1. Read the NSE and NSE Indices terms of use for automated download and local storage; decide that personal local analysis is acceptable; accept this ADR.
2. Set `Baskets:System:Fetch:UserAgent` (a descriptive name and a contact) and `Baskets:System:Fetch:Enabled=true` (deployment configuration; the application must be restarted, no runtime toggle exists in this slice).
3. Choose the sources to start with (suggested: Nifty 50, Nifty 100, Midcap 150, Bank) with "fetch now" and resume the `system-baskets` service on the Services screen.

## Consequences
- A wrong file layout, a moved host or a rate limit shows as `rejected` / `failed` on the source; the membership never half-changes.
- Announced future changes are invisible (a change appears with up to a day of delay); no weights, no history before the first fetch; files are not kept in the repository.
- A basket created by the owner cannot take a system basket's name (names are unique among active baskets); the seeded names start with `NSE `.

## Known limits
- One run at a time: a database advisory lock (`baskets.fetch_running` 409 for fetch-now; the scheduled run ends as skipped).
- `fetchEnabled` and `derivedEnabled` on `GET /api/baskets` (spec review fixes) move to BK-04 (the screen); the list stays an array. Built in BK-04 as a small read-only route `GET /api/baskets/system/settings` -> `{ fetchEnabled, listFetchEnabled, derivedEnabled }` (the three switches; no setting can be changed through it).
- NSE terms and non-browser User-Agent acceptance are UNVERIFIED; Alpha 50 / High Beta 50 files are not seeded (link unknown).
- The exact retry times (5, 30, 120 minutes) of the spec are the scheduler's retries here (three retries, its own spacing); only the 403/429 rest is kept per source.
