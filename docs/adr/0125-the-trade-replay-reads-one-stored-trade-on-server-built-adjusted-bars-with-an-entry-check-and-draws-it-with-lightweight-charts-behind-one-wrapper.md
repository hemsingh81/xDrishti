# 0125 — The trade replay reads one stored trade on server-built, adjusted bars with an entry check, and draws it with Lightweight Charts behind one wrapper

- **Status:** Proposed (spec [P8-11](../specs/P8-11-drill-down-and-trade-replay-shared-price-chart.md), built 2026-10-26; the spec is still Draft, the library choice was decided by the owner on 2026-10-26).
- **Date:** 2026-10-26.
- **Relation to other ADRs:** [0100](0100-the-report-endpoints-read-the-stored-runs-through-one-query-model-with-an-evidence-block-and-net-only-by-the-owners-stored-confirmation.md)-style report reads (evidence block, honest states, read only), 0037/0040/0049 (the stored trade, legs), 0066 (feature rows), 0042 (costing), [0113](0113-plan-flags-are-stored-as-typed-json-beside-the-basis-and-the-ticket-chart-is-plain-svg-of-daily-bars-up-to-the-planning-session.md) (the ticket chart stays plain SVG).

## Decision
1. **Library.** `lightweight-charts@5.2.1` (Apache-2.0, pinned exact, one dependency), imported only by `shared/ui/chart/PriceChartCanvas.tsx` (ESLint `no-restricted-imports` and `boundaries.test.ts`), reached through a dynamic import in `PriceChart.tsx`. `PriceChartProps` does not name the library, so a swap touches one file. ECharts stays for analytics.
2. **Licence duty.** The chart's attribution logo is on (`attributionLogo: true`, the link to https://www.tradingview.com/); the replay page footer carries the NOTICE sentence and a link; the third-party notice is in `docs/engineering/README.md`. The NOTICE of v5.2.1 (read from the repository, the npm package ships no NOTICE file) reads `TradingView Lightweight Charts(TM)` / `Copyright (с) 2025 TradingView, Inc. https://www.tradingview.com/` where the "с" in "(с)" is the **Cyrillic** letter U+0441, not a Latin c; the code keeps it as published (`attribution.ts`). The spec's sentence has a Latin c and is corrected here.
3. **Bars are built on the server.** `GET /api/reports/trades/{runKey}/{ordinal}` reads 1-minute bars of the trade's window by range (`IBarStore.ReadAsync`), adjusts each bar by the factor of its India date (`IAdjustmentFactors`, the replay's rule), aggregates with the Domain `MinuteAggregator` to 1m, 5m, 15m, 1h or 1D, and returns them. The data endpoint (latest 1,000 bars, no range) is not changed. The browser computes no bar.
4. **Window.** `TradeReplayWindow` (pure): from the open of the session `before` sessions before the entry session to the close of the session `after` sessions after the exit session, counted on the trading calendar. Defaults: 1 and 0 sessions (1D: 20 and 20); limits 0 to 3 (1D: 0 to 60), else 422 `reports.invalid`. More than 5,000 bars is 422 `reports.window_too_large`: never thinned; the screen offers the next larger timeframe.
5. **Entry check, not a stream hash.** `ReplayCoherence` (pure): the first 1-minute bar at or after the entry minute must open within one tick of the stored entry (an entry at a limit: the limit must lie inside the bar's range). `ok`, `entry_mismatch` (both prices shown, the chart still drawn) or `no_bars` (no chart; events and facts still shown). It catches a later corporate action or a re-fetch, not every change.
6. **Costing and features.** Net figures and charges are returned only when the stored owner confirmation covers the run's charge sheet id and rates hash; otherwise only the sheet id (`confirmed: false`) and the page says "costed on sheet X, not confirmed as yours". Features come from `research.trade_features` only (catalogue tf-1, 36 values): a NaN is `unavailable` with a reason (every context feature: "market context not built (P3-01d/e)"), a missing row says to run `xd learn features`, a row made for another decision instant is not shown. Nothing is read from `entry_snapshot_json`.
7. **Addressing.** The trade list rows of `GET /api/reports/trades` carry `ordinal` (the stored place in the run); the replay is `/reports/trades/{runKey}/{ordinal}` (closed trades; `openAtEnd=true` for an open one). New read members `IRunStore.ReadTradeAsync` and `ITradeFeatureStore.ReadOneAsync`; no migration.
8. **Pages, not a drawer.** `/reports/cell?<filters>&cell=<title>` shows the cell's figures (the P8-06 endpoints with the filters), the 50-per-page trade list (infinite Grid by cursor) and the honest lines; `/reports/trades/:runKey/:ordinal` the replay. A cell is linked only if it is expressible as filters (basket, strategy, timeframe, side, style, exit); a month, weekday or instrument cell says its trades are not listed here instead of showing a wider set. Exit comparison and MAE/MFE link to their Reports views (P8-10 is built); the regime split is `unavailable` with the server's reason.
9. **Bundle.** Both pages and the canvas are lazy; the first-load number is unchanged (197.7 KB gzip, measured with and without this slice). `size.mjs` gains `lazyBudgets` that fail on breach: canvas 65,000 bytes (measured 54.9 KB), replay 15,000 (4.2 KB), cell detail 20,000 (1.7 KB).
10. **Not done.** The ticket chart of the Plans feature stays plain SVG (ADR 0113): switching it to `PriceChart` is P8-14. A trailing exit's level path is not stored and not drawn.

## Consequences
- Overnight gaps are not drawn to scale (the library's time axis is by bar index); the page says so for multi-session windows.
- Not measured here: the p95 of the replay endpoint on the seeded 13-session fixture (the integration tests prove the answers, not the timing); rendering in a real browser (P8-16 covers it).
