# 0112 — Entry-window and meta-policy studies are stored by the verb as kinds of the learning report table and the Smart rules tab only reads them

- **Status:** Proposed (spec [P8-13](../specs/P8-13-smart-rules-loss-tags-and-entry-window-evidence.md) criteria 8 and 9, built 2026-10-26 as "P8-13b"). Becomes Accepted when the owner has read it.
- **Date:** 2026-10-26.
- **Relation to other ADRs:** [0110](0110-the-frozen-model-counterfactual-is-stored-by-the-verb-in-a-generic-insert-only-report-table-and-the-journey-only-reads-it.md) (the table and the pattern, reused unchanged), [0111](0111-smart-rule-and-loss-tag-evidence-is-read-from-what-is-stored-and-the-rest-is-a-named-non-value.md) (the first half of P8-13, which deferred this half for want of the table), [0069](0069-learned-entry-windows-shrunk-bucket-runs-judged-on-purged-folds.md) and [0075](0075-meta-labelling-policy-thresholds-from-earlier-folds-and-does-not-help-as-an-answer.md) (the studies).

## Decision
1. **Two more kinds in `research.learning_reports`, no migration:** `entry_windows` and `meta_policy` (the kind pattern and the table were made generic in ADR 0110 for exactly this). Same insert-or-skip on (kind, input hash), same insert-only grants.
2. **Only the verbs write:** `xd learn windows ... --store` and `xd learn policy ... --store` (default off; without the flag nothing is stored, as before). They print `stored as #N` or `already stored as #N (same inputs)`. A study refits per fold, so it is a job; no GET starts one and no service runs one. **Nothing runs on the owner's data by itself: a real-data run is the owner's CLI act.** This slice ran no verb on the owner's data, so no real-data outcome is claimed (the owner's database held no run when 0111 was written).
3. **Stored JSON is the view DTO** (`schemaVersion` 1), not the domain record, so NaN cannot enter; a metric that cannot be computed is null. Per-fold bucket tables of the window study are not kept (bounded size); the cell rows, folds held of evaluable and required, pooled out-of-sample lift, reasons and limits are. The printed text is stored too and always holds a `limit:` line (the table requires it).
4. **A result that proposes nothing is a result:** a window study whose cells are all `NotEnoughEvidence`, `NoStableWindow` or `Inconclusive` has outcome `NoWindowProposed` and is stored and shown labelled by each cell's status; a `NoPolicy` evaluation (no champion, other trainer settings, other training set) is stored and shown like any other outcome (spec decision 7). Their dates are null when no trade was read.
5. **Input hashes:** windows: sorted runs (key, style, exit), every window knob, the hold-out months and the fold options. Policy: sorted runs, the effective policy knobs of the report (the champion's registry trial count may have raised them), hold-out, fold options, the trainer recipe line (name and parameters) and the `Champion:` limit line of the report (model id and hash), or the NoPolicy reason when there is none. Any changed knob is another row, because every re-run is another trial. The cost basis follows the run headers exactly as in 0110 (shared `ReportBasis`; gross and costed runs are never mixed, 422 `learning.invalid`).
6. **Read endpoints:** `GET /api/learning/entry-windows?id=` and `GET /api/learning/meta-policy?id=`, newest when no id; 404 `learning.entry_windows_not_found` / `learning.meta_policy_not_found` (also for an id of another kind). Read only; the row id, author and time are added on read.
7. **UI:** the Smart rules tab shows, inside the Entry windows and Meta-labelling cards, the stored study (window as `HH:mm to HH:mm`, kept share, win rate against the cell, lift, mean R inside and outside, folds held of evaluable and required, pooled lift, reasons and limits as text; for the policy the outcome word, reasons, kept and skipped out-of-sample R, thresholds marked as chosen in-sample). With none stored, or an unreadable one, it keeps the `not_evaluable` line and says which command stores one; a failed read shows the error. The tab computes nothing and calls no write. The two studies load only when the tab opens (lazy tab), so the first-load guard is unaffected.
8. Log events 4882 and 4883 (kind, flag, code only).

## Consequences
- Until the owner runs the verbs with `--store`, the two cards show `not_evaluable` with the command, as before; that is the correct display.
- Windows and policy results are optimistic where chosen on all development scores (0069/0075); the stored limits say so and the card prints them.
- The pooled and recent totals are the policy's out-of-sample figures; the proposed thresholds are in-sample and labelled so.
- Shortcut: the newest-first read and the id read need no list endpoint; a history list per kind can be added with `ListAsync` (already on the port) without a contract break.
