# 0190 — The P15 phase check reads stored verdicts for the current versions only, reports a filter in use without a KEEP, and is never MET on thin, stale or unreadable evidence

- **Status:** Proposed (built in P15-12 from the owner-Approved spec, 2026-11-03). Becomes Accepted when the owner has read it. **Safety slice: no** (read only: no setting, ledger or record is written, no model is called, no order is placed).
- **Date:** 2026-11-03.
- **Relation to other ADRs:** [0080](0080-phase-verdict-words.md) (MET / NOT MET / NOT EVALUABLE), [0097](0097-the-p7-phase-check-ten-consecutive-scheduled-sessions-from-stored-plan-runs-and-never-met-on-fewer.md) (stored records only, exit 0), [0182](0182-the-event-risk-filter-reads-the-results-calendar-in-the-simulator-and-behind-an-owner-switch-in-the-plan-and-the-results-loss-tag-describes-the-past-and-unavailable-is-never-a-pass.md) (the switch and the share lost to `no_upcoming_entry`), [0186](0186-the-p15-evaluation-protocols-f-x-p-and-l-count-each-trial-in-the-ledger-before-any-number-store-insert-only-verdicts-with-the-missing-quantity-named-and-feed-the-event-filter-only-through-the-verdict-port.md) (the records it reads).

## Decision
1. **`xd events phase-check [--cut F,...] [--json]`** calls one handler (`GetEventsPhaseCheckHandler`) that holds read ports only and hands plain facts to the pure `EventsPhaseCheck`. Two read-side ports were split out of existing stores so that the handler cannot be given a write member: `IExtensionEvaluationReader` (`ListAsync`) and `IEventFilterHistory` (`RowsAsync`); the stores and `IEventFilterDecisions` inherit them, so nothing else changes. `ISimulationEngineVersion` gives the engine version without the engine's run members. An architecture test pins the constructor parameters and the absence of write members (inherited ones included). The database test runs only the two stores it reads (`research.extension_evaluations`, `filings.event_filter_decisions`) through a SELECT-only role; the filings, calendar and bars ports are read-only by signature, not exercised under that role.
2. **Current versions.** The newest record whose recorded versions equal the versions in force counts; the family's older or unrecorded versions make it `stale`. Compared keys: filter: rule `evf-1` and lag; `ext:ev-1`, `ext:fu-1`: catalog, lag, and for `fu-1` the parser version; `ext:llm-1`: catalog; `pead`: the `engine` key of its sources. A key that is not recorded is stale, never current. The filter is read at the window N of the effective switch (a verdict for another N is not the verdict of the filter).
3. **Resolved** is KEEP or DROP with no named missing quantity and rows behind it; a KEEP or DROP without either is thin and open. `ext:llm-1` has two records: a DROP of the grade (protocol L) resolves it, a passed grade does not by itself, the feature comparison (protocol X) decides, and a grade stored without its comparison (a crash between the two writes) reads open: "the comparison (protocol X) is not stored".
4. **Overall.** MET needs every non-cut family resolved, no violation and a readable decision history. NOT MET needs a violation: the event filter ON without a current KEEP, printed with the decision row id and `owner` or `auto`. It is judged even for a family the owner cut, because it is a fact about the live switch. Everything else is NOT EVALUABLE with each open family and its missing quantity; with no record at all the line is "no P15 evaluation stored". An unreadable source (a missing table included) is NOT EVALUABLE or `unavailable`, never an error and never a MET; the filter ON with its verdict store unreadable is NOT EVALUABLE ("verdict unreadable"), not a violation. The hold-out column counts the current records only.
5. **Output.** The report prints seasons of bars held (calendar quarters the stored bars span) against the 20 that protocol P needs, filings coverage per kind, calendar coverage, the share lost to `no_upcoming_entry` of the newest F record, trials, the hold-out read or not, the cut list and the limits (gross R, survivorship ISS-22, stale versions). `--json` carries the same fields; a non-value is the word `unavailable`. Exit code 0 in every case; 1 for an unknown family, 2 for a bad line.

## Consequences
- On today's data the answer is NOT EVALUABLE (X and P need CF-04, L needs labels); the phase can close only when each open family is resolved or cut by the owner.
- Feature sets in scoring are printed as "not built": no switch exists, so there is no violation to find.

## Known limits
- Seasons of bars assumes the stored bars are continuous between the first and the last; it is a count of quarters spanned, printed for information and not a gate of its own (protocol P names the seasons it lacks).
