# 0130 — The owner-act forms are endpoints behind a capability, a fresh password and an audit row, over the existing handlers and state machines, and apply nothing

- **Status:** Proposed (spec [P8-19](../specs/P8-19-owner-act-forms-autonomy-revert-lesson-and-hypothesis-moves.md), approved by the owner on 2026-10-26; built 2026-10-26). Becomes Accepted when the owner has read it. **SAFETY slice: write actions from the UI, including the autonomy switches.**
- **Date:** 2026-10-26.
- **Relation to other ADRs:** [0128](0128-owner-act-capabilities-are-one-insert-only-log-with-a-generic-gate-by-name-off-by-default-and-switched-on-only-by-the-owner-with-a-fresh-password.md) (the capability gate; `learning_moves_ui` and `autonomy_form` were named there), [0129](0129-a-replay-job-started-from-the-screen-rebuilds-one-stored-run-with-one-field-changed-runs-the-existing-experiment-path-one-at-a-time-and-never-applies-anything.md) (the same order of layers and the same lessons), [0127](0127-the-owners-confirmation-of-the-charge-sheet-is-an-insert-only-log-written-only-by-the-owners-endpoint-after-a-fresh-password-bound-to-the-rates-hash-and-off-by-default.md) (`OwnerAct`), [0091](0091-auto-approval-is-an-option-behind-an-owner-setting-default-off-a-new-approval-kind-the-database-checks.md) (the autonomy settings), [0073](0073-the-learning-changelog-and-the-cell-lifecycle-the-log-is-the-state.md) (the changelog is the state: a revert is a new row), [0076](0076-the-hypothesis-loop-one-knob-checked-on-stored-runs-a-state-table-and-nothing-applied.md) and [0078](0078-lessons-a-finding-a-linked-fix-and-a-result-read-from-the-stored-experiment.md) (the state tables), [0083](0083-no-order-is-placed-before-phase-12-an-architecture-tripwire.md) (no order).

## Context
Five moves and one setting needed the terminal or the API: link, close and dismiss a lesson; approve, reject, expire and accept a hypothesis; revert the latest cell transition; change the autonomy switches. Their logic and their state machines are built and are the only authority. The owner asked that each be possible from the screen, each with a fresh password and an audit row, each switchable, and none able to apply a change, place an order or turn anything on by default.

## Decision
1. **No new rule, no new table.** The slice adds endpoints, a gate and forms in front of the six existing handlers. The state machines (`LessonLifecycle`, `HypothesisLifecycle`, `CellLifecycle.RevertRefusals`) decide; a refused move is the handler's 409 with the domain's sentence, shown as text. The five learning handlers are not changed (their source hashes are pinned in an architecture test); the autonomy handler gains one optional field (below).
2. **One flow, fixed order** (`OwnerActFlow`): the capability is asked FIRST (`learning_moves_ui` for the five moves, `autonomy_form` for the autonomy `PUT`; a switched-off act neither counts toward the sign-in lockout nor says anything about the password), then the owner types the password again for THIS act (`OwnerAct.AuthorizeAsync`, `Elevate:false`: the 5-minute step-up window is neither opened, extended nor used up), then the body is turned into the command with the actor `owner:<session e-mail>`, then `IOwnerActRunner` asks the gate again, calls the one handler and writes the audit row. A body names neither the actor, nor a state of a lesson, nor an autonomy level, nor a number: the close of a lesson reads its result from the fix's stored experiment, and the hypothesis move is `AutonomyLevel.Supervised` as a constant. The rate-limit policy `login` applies (10 password-checked calls a minute per address). No path exists without a password: there is no OFF-direction shortcut here (a move is not a kill switch).
3. **Why a runner and not the gate inside the handlers.** The five learning handlers and the autonomy handler are also what the command line calls (`xd learn ...`); the owner's terminal is not gated by a screen switch. The web-only gate and audit therefore live in `IOwnerActRunner`, called only by the two endpoint modules. There is no database layer: no table is added (the rows are the existing insert-only logs, whose `owner:` actor checks and grants are unchanged), so no trigger can check the capability; this is the one difference from ADR 0129's four layers.
4. **Audit.** The primary record is the move's own insert-only row (actor, reason, state change, database time). The cross-index is one `account_events` row after it, in its own unit of work, with ids and state words only (`lesson=12 link to=linked`, `hypothesis=3 to=approved`, `changelog=9 reverts=5 paper->candidate`, `settings=7 auto_approve=on reserve=off`): never a reason, an e-mail, a number of the evidence or a password. Four values are appended to `AccountEventType` (`LessonMoved`, `HypothesisMoved`, `ChangelogReverted`, `AutonomySettingsChanged`), stored by name in a column with no check constraint, and classified in `AuditKinds` (learning, learning, learning, autonomy). If the second write fails the move stands and the failure is logged by event (4922). Log events 4920 to 4922.
5. **A stale form is a 409.** `ChangeAutonomySettingsCommand` and the request gain the optional `expectedSettingsId` (0 means "nothing stored when the form was loaded"; absent means the current row is read at submit, as in P7-12). A different id writes nothing and answers `autonomy.stale`. The form always sends it and keeps the settings as it read them (no refetch under the owner's hands); a stale answer offers "Read the settings again".
6. **The surface.** Lazy pages of the owner-acts feature: the autonomy form on `/owner-acts` (drawn only while `autonomy_form` is ON) and one route `/owner-acts/:kind/:id` for `lesson`, `hypothesis` and `revert`. Only the moves in the record's `nextStates` are drawn (and for a hypothesis only approved, rejected, expired, accepted); the form states what it will not do. The password field is cleared and focused after every try, the mutation is dropped (`gcTime` 0, reset on settle), a wrong password is an answer and not a sign-out (the paths are in the shared client's list). The Learning and Autonomy screens stay read only: they show a plain link to the form while the switch is ON and the words and a link to `/owner-acts` while it is OFF. The five paths are on `ApprovedReportWrites` (the P8 phase check names them) and are named in one feature only (`writePaths.test.ts`).

## Consequences
- After deploy both capabilities are OFF: nothing can be written from a screen until the owner switches them on at `/owner-acts`; the autonomy switches themselves stay OFF until the owner turns them on.
- The existing `PUT /api/autonomy/settings` is gated by `autonomy_form`: a caller that used it with a session and a password now needs the switch (its tests seed it ON). The command line is unchanged.
- The owner can make about ten password-checked acts a minute; that is the sign-in limit, not a design target.
- Closed and dismissed lessons and rejected, expired and accepted hypotheses are final; there is no undo, the history keeps both rows.
- **Limit:** "owner" is a string; a process holding `xd_app` could insert rows (as before); the control is the single endpoint behind session, CSRF, capability, password and audit, plus the architecture tests (one module names the five commands, one flow, no body field for an actor).
- **Limit:** turning `auto_approve_tickets` ON still approves nothing today (the checklist inputs are not all wired, P7-12); the form shows the server's own text beside the switch.
- **Limit:** the audit cross-index row can be missing if its write fails; the primary row cannot.

## Alternatives considered
- **The capability inside the six handlers.** Rejected: it would gate the owner's terminal.
- **A database trigger on the learning tables.** Rejected: those tables are written by the command line and the services too; a capability trigger there would block them.
- **One transaction across the research database and the accounts unit of work.** Rejected: no shared unit exists; adding one is a larger change than the risk it removes.
- **A password only for ON-direction autonomy changes.** Rejected: every autonomy change is a new row the plan reads; one rule for all.
- **Three routes (`/lesson/:id`, `/hypothesis/:id`, `/revert/:id`).** Rejected: three eager route definitions for one lazy page; the first-load script has under 2 KB of room.
