# 0142 — A proposal is a row the model wrote in an inbox after the engine re-read its evidence and checked every rule; only the owner's accept, with a switch and a fresh password, writes a proposed hypothesis or changes a basket

- **Status:** Proposed (written in P9-08 under the owner's delegation; the spec was treated as Approved). Becomes Accepted when the owner has read it. **SAFETY decision: it decides what a model may cause in the hypothesis log and the baskets.**
- **Date:** 2026-10-27.
- **Relation to other ADRs:** [0076](0076-hypothesis-loop-one-knob-a-stored-baseline-and-a-hard-open-limit.md) (hypotheses), [0072](0072-experiments-same-entries-purged-folds-an-honest-rule-and-an-append-only-ledger.md) (trials), [0141](0141-a-strategy-draft-is-text-the-model-wrote-for-the-owner-to-read-the-lab-validator-and-four-checks-decide-if-it-is-offered-and-only-the-owners-confirm-with-a-switch-and-a-fresh-password-stores-a-version-or-starts-a-quick-test.md) (the same pattern: switch, fresh password, advisory lock, auto option recorded with the settings snapshot), [0140](0140-the-briefing-text-is-phrased-by-the-model-from-app-built-facts-and-a-deterministic-guard-rejects-any-figure-symbol-or-claim-it-cannot-verify-the-fixed-format-text-is-the-fallback.md) (the text guard), [0138](0138-the-assistant-endpoint-runs-the-tool-loop-in-the-application-streams-events-marks-figures-not-found-in-the-tool-results-and-stores-every-turn-insert-only.md) (ground only against engine results).

## Context
Doc 14 lets the local model propose hypotheses and basket changes. A model is good at noticing a pattern in a table and bad at keeping numbers and at knowing which ideas the system can test. Every judged hypothesis is a trial that raises the bar for the next, so the inbox must not be flooded; and the model must never be the one who changes a basket or the hypothesis log.

## Decision
1. **Pack in, JSON out, no tools.** The engine selects a pack (at most five cells with enough trades, their stored baseline run, parameters and grid values; the owner's manual baskets with their weakest members; tracked instruments in no basket with the strongest figures). The model answers with `{"items": [...]}`, at most three items, each `{kind, subject, payload, reason, evidenceRefs}`. It supplies no figure of evidence.
2. **The engine decides.** Every reference is read again through the same stores and handlers the screens use (`IProposalFacts`), the evidence is built from that, and `ProposalChecks` (pure) judges: the hypothesis rules (parameter knob only, baseline run stored with the knob at the stated value, candidate within 50 % with the same sign and at most six significant digits, cell with at least 30 trades, fewer than 3 open and 3 pending, no duplicate, not recently rejected) and the basket rules (manual, not archived basket; an instrument that is already tracked; membership; at least 15 trades from the report engine). An input that is unavailable is never a pass. The model's own subject is not shown: the engine builds it from the payload.
3. **The reason is checked against the evidence.** `TextGuard` runs with the evidence figures and the proposal's subject as the only facts; a claim word without a figure of its kind, an instruction-like phrase, markup, advice or a forecast refuses the item. The candidate value of a hypothesis is part of the subject (it is the thing proposed and has passed the bounds); no other number is allowed.
4. **The model's only write is an insert-only inbox row** (`workflow.assistant_proposals`; decisions in `workflow.assistant_proposal_decisions`, one per proposal, insert-only for the runtime role, with a check that ties the auto flag and the auto actor both ways). The generation job holds the insert port and the read ports only; one type (`ProposalApplier`) names the hypothesis and basket commands; only the accept and the auto handlers use it; an architecture test enforces this and that nothing of the proposal code names tracking, backfill, paper, live, brokers or planning.
5. **Accept is the owner's act.** Session, CSRF, the capability `allow_proposal_accept` (off; asked before the password), a fresh password on every call (not the step-up window), the actor from the session. Under one advisory lock it re-runs every check against today's data (`assistant.proposal_stale`), applies, and writes the decision (retried once, logged if it still fails). A hypothesis is written `proposed` with source `assistant`; approve, start and judge stay the owner's. A basket change goes through the owner's own basket commands. The add command would track an untracked instrument, so the engine requires the instrument to be tracked in the same locked step (a race with an untrack is an honest limit).
6. **Auto option (owner's standing rule), hypotheses only, default OFF.** `auto_accept_hypothesis` is changed only by the owner through `PUT /api/assistant/settings` with the password. Right after generation the auto handler re-reads the setting under the decision lock, re-runs every check, accepts at most 3 per India date as actor `system:auto-accept`, and records `auto = true` with the settings row id and hash. Unavailable never passes. Basket changes have no auto option (deliberate: they change the populations of future reports on thin candidate evidence).
7. **Repeat block and limits.** The key is a SHA-256 over kind, cell, knob and normalised candidate (symbol and basket for baskets); the owner's reject blocks it for 30 days; an expired one may be proposed again; one row per key and India date. At most 3 per run, 10 pending, 3 pending hypotheses. Expiry is computed on read: hypothesis 7 days, basket 3 days.
8. **Migrations.** `AddAssistantProposals`; `AllowModelHypothesisSource` replaces `ck_hypotheses_shape` to allow source `model` (the stored code of `HypothesisSource.Assistant`: `research.hypotheses.source` is 8 characters wide and the view `aiv.hypotheses` depends on it, so the column is not widened). `Down` fails if a `model` row exists (the log is insert-only).

## Cut from this slice (the spec's cut order)
`next_day_focus` (no effect on any plan; needs the style insight and the next-session date), report insight references (`insight:<id>`; the pack states that insights are unavailable), and the "new trades since the last run" and drift triggers of the pack (the pack takes the cells with enough trades that are not open). Each is a later slice; none changes the safety rules above.

## Consequences
- Nothing happens without the owner unless the owner turned the auto option on, and then only a `proposed` hypothesis is written.
- The proposals are as good as the pack; today's data (about three usable folds) means an accepted hypothesis cannot yet be accepted as a finding. The panel states that each judged hypothesis counts as a trial.
- UNVERIFIED: no real model was run. The grammar-constrained JSON format is the model server's to offer; the answer is always re-read as data on our side.
