# 0180 — The point-in-time filing store keeps immutable envelopes and answers "what was known at an instant" from the broadcast time plus a lag and nothing else

- **Status:** Proposed (built in P15-02 from the owner-Approved spec, 2026-11-02). Becomes Accepted when the owner has read it. Safety slice: no (local files and its own tables; no network, no broker, no order), but it is the first reader of filings on a path that later feeds decisions, so the visibility rule is the guard.
- **Date:** 2026-11-02.
- **Relation to other ADRs:** [0179](0179-filings-come-from-a-local-inbox-folder-with-a-sidecar-that-carries-the-broadcast-time-the-adapter-is-read-only-and-the-public-page-fetcher-is-a-recorded-decision-not-to-build.md) (the port this ingests from), [0045](0045-the-result-store-sim-runs-and-sim-trades.md) and [0173](0173-the-trade-tick-recorder-stores-last-trade-updates-of-the-depth-set-when-cumulative-volume-rises-on-a-second-quote-socket-behind-three-gates-its-own-cap-and-no-reader.md) to [0178](0178-the-option-archive-quality-checks-read-the-recorded-chains-and-rolling-bars-in-bounded-ranges-and-store-insert-only-verdicts-with-an-honest-unavailable-and-no-trading-use.md) (insert-only discipline, disk guard, the no-reader tests), P15-00 decision D3 (point in time by broadcast time).

## Context
A backtest or a feature that reads a company's results must see only what the market knew at the time. Results are restated, some files arrive without a trustworthy broadcast time, and the file's date, the day it was ingested or the period it covers are all wrong answers to "when was it known". A look-ahead error here would make every later research number optimistic and be invisible.

## Decision
1. **Rule (D3).** A filing is *visible at t* iff its broadcast time is known and `broadcast_ts + lag <= t` (inclusive). Never `ingested_at`, never `period_end`, never a file date or name. `lag` is `Filings:LagMinutes` (5, range 0-60), a **deployment** setting, never owner-switchable: it changes research results, so any record that reads `AsOf` must store the lag it used (P15-05). The rule is pure code (`Domain/Filings/PointInTimeRule`) and is the only place that decides.
2. **Current filing.** Of the visible filings of one period, the one with the latest broadcast time is current (one per period; filings without a period stand alone; ties, which ingest refuses, fall to the lower id). A restatement therefore hides its predecessor only from its own `broadcast_ts + lag`; a filing broadcast after t, or without a time, changes nothing. `AsOf` returns `State` `value`, `none_visible`, or `unavailable` (no current row and at least one filing of that instrument and kind without a time), with `UnavailableCount`. Undated filings are never listed and their date is never substituted.
3. **Tables (`AddFilingsStore`), all insert-only for `xd_app`.** Schema `filings`: `filings` (the envelope), `result_facts`, `shareholding`, `announcements`, `calendar` (created empty here; P15-03 and P15-04 write them, a test pins that nothing else does). `GrantTableToAppRole` plus `MakeAppendOnlyForAppRole` per table; `xd_exec` and the read-only roles get nothing; `filings.extractions` waits for P15-08. The envelope id is the first 16 bytes of SHA-256 over `instrument_id|kind|period_end or ""|content_sha256`; `broadcast_ts` is **nullable** and null exactly when the state is `unavailable` (resolves the plan's contradiction); `content_sha256` is unique. The unavailable reasons are the P15-01 words (`missing`, `date_only`, `no_offset`, `unparsable`, `before_2000`, `broadcast_in_future`); the spec text `absent` is the same case as `missing`.
4. **Revisions are detected, not declared.** A new file of the same (instrument, kind, period) with different bytes and a later broadcast time is stored with `supersedes` = the group's latest filing; an earlier time is stored unlinked and counted `out_of_order` (visible by its own time, hides nothing later); an equal time is `ambiguous_order` and not stored. The database enforces the shape: a `BEFORE INSERT` trigger (`filings.check_supersede`, `search_path` pinned to `pg_catalog, pg_temp`, every name schema-qualified) refuses a supersede that is not a later filing of the same instrument, kind and period, and a partial unique index allows one revision per filing, so the chain is linear. Filings with no period (announcements) are never grouped.
5. **Idempotent and race-safe.** The same bytes are one row (`ON CONFLICT (content_sha256) DO NOTHING`); the same bytes with another symbol, kind, period or time are a `sidecar_conflict`, logged with both values and not stored (insert-only forbids rewriting a broadcast time). One file is one transaction at READ COMMITTED: the group is locked with `pg_advisory_xact_lock`, the stored envelope of the same bytes is read after the lock, the group's latest filing is read and the rule decides, then the row is inserted. Two hosts ingesting the same file or two revisions of one period cannot both win.
6. **Ingest.** `IngestFilingsHandler` (one use case, registered explicitly) lists the inbox through `IFilingsSource`, resolves each symbol by exact match among the tracked shares and ETFs (`unknown_instrument`, `ambiguous_symbol` otherwise), copies the file to `files/<sha[0..2]>/<sha>` (folders `0700`, files `0600`; written under a temporary name while hashed, re-read and hashed again, moved into place without replacing anything) **before** the row is inserted, and counts every outcome. A `.csv` marked `row_level_ts` is `deferred_to_loader` (P15-04). The inbox is never changed. Before each file the shared pure `DepthDiskGuard` checks the store folder against `Filings:MaxFilesGb` (5, 1-100) and the volume against `Filings:MinFreeGb` (20, 5-500): `disk_budget` / `disk_free` stop the run, with a warning at 80 %. **The app deletes no filing and no file**; the only file it ever deletes is its own half-written temporary copy.
7. **Service `filings-ingest`.** Registered **paused**, daily 17:05 India time on trading days, retries 1, notify on failure, no catch-up, "Run now" allowed (it touches only local files and its own tables). It runs in the scheduler of `xd-api`, the only host that has one (the spec said `xd-worker`, which has no scheduler); a failed run (disk stop, a failed file, an inbox problem) is reported failed. With the service paused nothing scans the folder.
8. **Reads.** `IPointInTimeFilings.AsOf(instrument, kind, t)` is the one read of filing rows for a question about an instant (the SQL narrows by instrument, kind and `broadcast_ts <= t - lag`, plus the undated rows to count them; the domain rule decides). `GET /api/filings/coverage`, `GET /api/filings` (optionally `asOf`, which needs an instrument and a kind and an offset) and `GET /api/filings/{id}` return counts and metadata only: no file content, no path, no `source_ref`; 400 `filings.invalid_query`, 404 `filings.not_found`; a kind with nothing stored answers `unavailable`, not zero.
9. **No decision use yet.** Architecture tests pin that `IPointInTimeFilings` is named only by the `asOf` list handler and its implementation, that the store, the reader and the files ports are named only by the ingest and the read handlers, that no decision layer, pure library or the execution service references a filings type, that nothing writes the four fact tables, updates or deletes a row, reaches a network or logs a path, and that visibility never reads `ingested_at`, a file name or the period. P15-04, P15-05 and P15-06 amend the allow-lists deliberately, naming the new caller.
10. **Deployment.** The compose file of `xd-api` mounts `data/filings/inbox` read-only and `data/filings/files` read-write and sets `Filings__InboxPath=/data/filings/inbox` and `Filings__FilesPath=/data/filings/files` explicitly (ADR 0179 asked for an explicit value because the defaults are relative); `Filings__LagMinutes`, `MaxFilesGb` and `MinFreeGb` come from `XD_FILINGS_*` variables. `deploy/xd-up.sh` creates both folders `0700`. `xd-backup` must include `data/filings/`: the files folder is the only copy.

## Consequences
- P15-03 (facts) and P15-04 (calendar, shareholding, loader) fill the fact tables and amend the architecture allow-lists; P15-05 stores the lag with each feature record.
- The check on `supersedes` costs one indexed read per revision insert.
- Coverage by quarter uses the period end, else the broadcast date, else the ingest date (India time), so undated filings still show up.

## Known limits
- A wrong broadcast time supplied by hand is invisible here; coverage shows only absence (ADR 0179).
- Revision detection assumes one results filing per period at a time; consolidated and standalone results of one period are for P15-03 to separate (a basis, not a new kind).
- A copied file whose row is then refused (`ambiguous_order`) stays in the store folder as an orphan; nothing is deleted. A re-run copies nothing again (the same bytes are found).
- A container user other than the owner of the `0700` folders cannot read the inbox; the mount ownership under Podman Machine is UNVERIFIED (see `deploy/CLAUDE.md`).
- Source references (`source_ref`) are not carried by the P15-01 listing, so the column stays null.
