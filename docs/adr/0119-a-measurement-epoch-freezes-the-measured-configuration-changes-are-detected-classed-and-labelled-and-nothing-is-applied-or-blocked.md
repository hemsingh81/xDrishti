# 0119 — A measurement epoch freezes the measured configuration: changes are detected, classed and labelled, and nothing is applied or blocked

- **Status:** Proposed (spec [P10-05](../specs/P10-05-config-change-governance-via-the-hypothesis-loop.md), built 2026-10-26; the spec is still Draft). Becomes Accepted when the owner has read it.
- **Date:** 2026-10-26.
- **Relation to other ADRs:** [0076](0076-the-hypothesis-loop-one-knob-checked-on-stored-runs-a-state-table-and-nothing-applied.md) (accepting applies nothing), [0073](0073-the-learning-changelog-and-the-cell-lifecycle-the-log-is-the-state.md) (the changelog), [0116](0116-paper-fills-are-the-grading-replay-captured-per-armed-allocation.md) (`IEpochGate`, epochs, `measured`/`straddle`), [0091](0091-autonomy-settings-and-auto-approval-are-owner-acts-recorded-in-an-insert-only-table.md) (autonomy), [0002](0002-configuration-lives-in-the-app.md) (configuration in the app).

## Decision
1. **Doc 09 section 5 and doc 18 P10 are amended: a measurement epoch freezes the measured configuration; any frozen change starts a new epoch.** "Changes only via the hypothesis loop" is enforced by detection and consequence, not prevention: the system cannot see an intention, only a result, and a block would be bypassed by editing a setting and would punish a safety action.
2. **A fingerprint of the configuration** is taken at every capture run: SHA-256 of the canonical JSON (keys in ordinal order, invariant culture) of flat components read through existing ports, once, without replay: the eligible cells with strategy hashes, the cell-statistics snapshot, every `Planning:*` setting, the autonomy settings and newest row hash, each paper account's facts with its effective limits, the selection rules and the smart-rule options, the champion, and the engine facts (engine and trade schema version, default fill rules, charge sheet id and rates hash, capital). A component named like a secret is dropped. The code revision is not in it (a stated limit).
3. **A closed classification.** `PaperConfigKeys` classes each key: `frozen` (restarts the count), `risk_down` (lower risk, a cell paused or retired, auto-approval off, a protective rule on, a limit lowered) or `free` (the autonomy row hash only). A key in no table is `frozen`, and a reflection test fails when a property of the typed settings (paper trading settings, risk profile and limits, smart-rule options, autonomy settings) is in neither a table nor the explicit allow-list with a reason. The selection rules and `Planning:*` are read whole, so a new one is frozen by its prefix.
4. **The gate.** `FingerprintEpochGate` replaces `SingleEpochGate`. Equal or only `risk_down`/`free` differences keep the epoch (changes stored as `noted`, sessions `measured`); a `frozen` difference starts a `detected_change` epoch on the next trading day after the newest session of the run and the sessions of the run are `straddle` (stored, shown, never counted, under the earlier epoch); no earlier snapshot claims no change; a snapshot with an unreadable group claims no change, logs `paper.config_unreadable`, and counts its sessions only within three trading sessions of the last full snapshot. Without epochs the gate creates `first` with the snapshot's hash. Asking for the epoch with no sessions reads nothing.
5. **Explained or not.** For a changed `cells.eligible` entry the explainer finds an accepted hypothesis (newest row accepted, accepted before detection, used once) by cell and value: an exit knob by the new exit label, a parameter knob by the stored parameter of the new version or the value in the new exit label; else a changelog row about the cell between the two snapshots; else the change is shown as unexplained. Settings, accounts and autonomy are never hypotheses: the owner attaches a note.
6. **The queue** lists accepted hypotheses no change row and no note names. It states that accepted means judged better offline, nothing was applied, and applying it starts a new epoch. The system never applies, proposes to apply or reorders it.
7. **Refresh jobs during an epoch.** `cells.snapshot` is frozen, so a run that stores a new snapshot restarts the count. `PaperConfigKeys.LearningWriterServices` (`cells`, `retrain`, `weekly`) are shown as blockers in the config view (CLI, API and the tab) when registered and enabled.
8. **Owner acts are CLI only** (`xd paper epoch restart --reason`, `xd paper epoch explain`, actor `cli:xd`); every HTTP route is a GET. A restart writes an `owner_restart` epoch effective the next trading day, refused without a reason of 10 to 300 characters or when the newest epoch already starts that day; nothing is edited or deleted.
9. **Storage.** `paper.config_snapshots` (unique per session day and hash), `config_changes`, `epoch_notes`, insert-only for `xd_app`, granted per table so the capture tables keep their append-only grants. Log ids 5240 to 5245. Read: `GET /api/paper/epochs`, `/epochs/{id}`, `/config`, `/config/changes`, `/queue`; verbs `xd paper epoch show|restart|explain`, `xd paper config`, `xd paper queue`; frontend tab **Governance** (read only).

## Consequences
- A change and its reversal between two captures is invisible. Matching a hypothesis to a change is by cell and value, not proof of intent. A code change that alters selection without touching the engine or schema versions is not seen.
- Resolved ambiguities: the smart-rule and selection options have no settings home today, so their code defaults are fingerprinted (a change arrives with a deploy and is seen); the numeric direction of an autonomy threshold follows its strictness (a higher minimum probability or a lower daily cap is `risk_down`); an owner note naming a hypothesis takes it out of the queue; the first epoch has the hash of the first full snapshot; a snapshot is stored at each run with its newest session date, so the blind-read rule can count sessions.
- Not verified: the stored shape of a strategy version's parameters (the explainer reads the first `params` object of its canonical JSON); the end-to-end run on the owner's data.
- The Governance tab is a stand-alone route `/paper/governance` until the paper screen (P10-02) hosts `GovernanceTab` as a tab. `xd paper epoch show` moved to this slice and lists the epochs; the P10-01 use case `GetPaperEpochHandler` is no longer reached from the verb.
