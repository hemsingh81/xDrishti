# 0202 — The P14 phase check reads stored verdicts for the current versions only, closes a family by a net DROP or a hold-out-confirmed KEEP, counts every expression dropped as MET, and finds a non-cash expression in use by a select of the stored cell keys

- **Status:** Proposed (built in P14-17 from the owner-Approved spec, 2026-11-03). Becomes Accepted when the owner has read it. **Safety slice: no** (one verb that reads stored rows; no setting changed, no verdict written, no switch touched, no order).
- **Date:** 2026-11-04.
- **Relation to other ADRs:** follows [0080](0080-the-phase-check-exit-criteria-from-stored-records-and-never-met-on-thin-data.md) (the three words, limits always printed) and [0190](0190-the-p15-phase-check-reads-stored-verdicts-for-the-current-versions-only-reports-a-filter-in-use-without-a-keep-and-is-never-met-on-thin-stale-or-unreadable-evidence.md) (current versions only, violations reported never blocked, cut families listed); reads the records of [0198](0198-protocol-o-judges-the-option-expression-against-cash-on-paired-out-of-sample-trades-after-counting-each-profile-in-the-ledger-first-with-the-hold-out-cut-before-any-number-and-no-gross-result-ever-a-keep-or-a-drop.md), [0200](0200-defined-risk-structures-are-re-marked-leg-by-leg-with-the-loss-capped-at-entry-each-is-its-own-family-credit-structures-are-gated-on-a-stored-regime-and-a-measured-spread-before-any-trial-or-bar-and-the-condor-is-judged-by-protocol-r.md), [0199](0199-the-iv-extension-iv-1-reads-the-option-archive-at-the-decision-instant-through-one-bounded-extractor-gives-every-unknown-a-closed-reason-and-is-judged-by-the-p13-05-comparison-on-quarterly-folds-with-no-scoring-use.md) and [0196](0196-the-pairs-study-counts-every-candidate-in-the-ledger-before-any-test-walks-pairs-in-a-separate-pair-1-walker-on-the-simulators-fills-and-judges-them-by-protocol-s-where-a-gross-drop-is-valid-and-a-gross-keep-impossible.md); extends the table pins of 0178, 0177, 0195-0197 as 0201 did.

## Context
P14's exit is "an option expression beats cash/futures OOS after costs, else stays disabled". P14-17 asks for one command that says so from the stored verdicts, per family and overall, and prints what makes a verdict weak.

## Decision
1. **Where the code lives.** The rule is pure and in `XDrishti.Domain.Learning.Extensions` beside `EventsPhaseCheck` (`OptionsPhaseCheck`, the facts, the report with `ToText`/`ToJson`); it is built from family-name constants, so it names no family list. The use case `GetOptionsPhaseCheckHandler` (`XDrishti.Application.OptionPhaseCheck`) reads through ports only; the verb is `xd options phase-check [--cut ...] [--json]`; exit 0 whatever the verdict, 1 for an unknown family in `--cut`, 2 for a bad line. P15's `xd events phase-check` is not touched (its text and JSON for fixed facts are pinned by hash).
2. **Families.** `expr:option_buy`, `expr:debit_spread`, `expr:credit_spread`, `expr:iron_condor`, `ext:iv-1`, `pairs:intraday-1` and `basis:carry-1`. The basis family is not built (P14-14/15): it reads `none stored`, which is open, unless the owner cuts it. Cut families are listed and not read or counted. Only the newest 100 records of a family are read and only the newest 10 that can decide are judged.
3. **Which records can decide.** Expression families: protocol O (R for the condor) records of the pre-registered primary profile only (`primary_profile = true` in the stored sources); a secondary profile is counted in N and never decides (0198). Pairs: protocol S. IV: protocol X. The newest development record for the current versions is the family's word; a hold-out record (`holdout_read`) for the current versions confirms or does not confirm a development KEEP.
4. **Stale means any of these differs or is not recorded.** For the expression families: the re-mark version (the run's `remark_version` against `RemarkRunId.Version`), the engine (the stored cash run's `engine_version` against the engine now; the condor has no cash run), the spread models (the newest model id of each underlying the re-mark used, against the newest now), the cost sheet (the run's recorded rates hash against the hash of the sheet now: the cash run's sheet, or `Options:Remark:CondorCostSheetId` for the condor), the profile (the record's profile against the family's pre-registered primary: the "profile set"), the version key (`expr-1`), and the archive watermark: the highest `options.fetch_log` id the re-mark (or, for `ext:iv-1`, the extraction: `sources.archive_watermark`) read. The archive must not have moved on from it by more than `Options:PhaseCheck:StaleAfterDays` (90, 7 to 730): the newest finished fetch's `ended_at` minus the watermark fetch's `ended_at` is compared with the bound, not the clock, so a verdict does not age while the archive is stopped, which keeps "stays disabled" MET (a watermark of 0 or `unavailable` read no fetch and cannot be old; an id with no row, or no fetch stored at all, is stale). The `ext:iv-1` record also compares its version key. A credit-structure gate record (no run, `expression_run` is `none`) compares only its version key and profile and reads NOT_EVALUABLE with the gate's missing quantity, not stale. Pairs: the version key, the fill engine and the sheet hash. IV: the catalog version and the version key. The walker version of the pairs study is covered by its version key, not compared by itself (no read port names it). A record whose run or inputs cannot be found is stale, never current.
5. **A family is resolved only by sound evidence.** A **DROP** is resolved when it has no named missing quantity, rows behind it, and the net basis the protocol requires (O and R need net; S may DROP gross, 0196; X, the comparison, states no basis: its costs print `unavailable (protocol X may be gross)`, a DROP stands, and a KEEP closes the family only when the record's sources store `net`). A **KEEP** is resolved only when a hold-out record for the current versions is KEEP with the same soundness and was read for that very development record (its `sources.development_record` names it; otherwise `hold-out read for record X, not for the newest development record`, open): a development KEEP is a candidate (`hold-out not read`), a hold-out that was read and did not confirm leaves the family open with its verdict and missing quantities. A gross or mixed record, a thin one (missing quantities, no rows), INCONCLUSIVE, NOT_EVALUABLE, stale, none stored and unreadable are all open. The rule applies the hold-out requirement to every family, not only the expression ones (open question 2).
6. **Overall.** NOT MET iff a violation exists. Otherwise NOT EVALUABLE when every family is cut, when no P14 evaluation is stored (`no P14 evaluation stored.`), when any counted item is open (each named with its status and missing quantity), or when every expression family is cut. Otherwise MET: with an expression family KEEP (hold-out confirmed) and every counted family resolved, or with every counted expression family DROP and every counted family resolved, which says `option expressions stay disabled`. Nothing missing, gross, stale, thin or unreadable is ever MET.
7. **The violation scan.** A non-cash expression in use is a stored `trading.plan_items` row (a plan ticket) or `paper.entries` row (a paper capture) whose `cell_key` has eight parts or more and an eighth part other than `cash` (P14-06: the eighth part exists only for a non-cash expression). **Shortcut, stated:** the scan is unindexed (a `string_to_array` over each table, cut at its first rows) and `max(ended_at)` of the fetch log is unindexed too; both tables are small. The read is a `string_to_array` count, ordered by id and cut at 21 rows per table; the report lists 20 and says when there are more. The rows are named by table and id. If the rows cannot be read the check is NOT EVALUABLE with that item open, never MET. The plan runs table has no cell key and the execution schema stores none, so they are not scanned; the plan items are the tickets.
8. **Always printed.** Years of underlying bars held (first to last bar, 365.25-day years) against the 5 needed; usable chain sessions per underlying against 60, and the backfill keys done and given up (the P14-16 archive summary handler, called through its query); costs net or gross, N, the hold-out read or not, the derived-expiry share and the model-price fallback share per family (from the stored expression run, over its paired rows; the fallback share is the whole run's, including the hold-out trades, as 0198 already says); the cut list; the staleness bound; the limits block (survivorship ISS-22, the unverified derived expiry weekdays, the gross rule, the expected NOT EVALUABLE). When every counted expression family is DROP, whether the recorder and backfill switches are still ON: `archive still recording after DROP: owner may switch it off`, information and not a violation. A figure with no source is the word `unavailable`, never a digit. The JSON carries the same fields in a fixed order.
9. **Read only, proved.** The handler takes read ports only (an architecture test lists them and fails on any interface member that starts with a write verb). Three adapters are the read side of an existing store alone and call one method each: `CostSheetHashes` (`FindAsync` of the sheet store), `CashRunHeaders` (`FindAsync` of the run store), `SpreadModelIds` (`LatestAsync` of the model store). One new select-only reader, `OptionsPhaseReader`, has five reads (run inputs by id, fetch end time by id, the two switches' newest row, the non-cash cell rows), each bounded by an id list or a limit and selecting no price, IV, Greek, bar, quote or return column. An integration test runs the whole check on a real TimescaleDB as a role with SELECT only on the eight tables it reads, proves a write is refused and the row counts are unchanged.
10. **Pins extended, deliberately.** The exact-set pins gain the new reader or handler where it must name an existing type or table: `options.fetch_log` (0178/0177 pins) gains `OptionsPhaseReader.cs`; `research.expression_runs` (0197 pin) gains it; the users of the evaluation namespace (0198 pin: the handler names the primary profile hash), of the extension types (0196/0186 pin) and of the application expression namespaces (0197 pin: the condor sheet id setting) gain `GetOptionsPhaseCheckHandler` (and `OptionsPhaseCheckView`); the cost-type reference list (0194 pin) gains the adapter `SpreadModelIds`. No rule is relaxed.

## Open questions for the owner
1. **Which families to cut.** Default: none at build. Recommended: `basis:carry-1` first (not built), then `expr:iron_condor` and `expr:credit_spread` if no regime tagger is built.
2. **The hold-out for every family.** The spec's decision 2 names the expression families. The rule applies it to `pairs:intraday-1` and `ext:iv-1` too (a development KEEP is a candidate). Default: yes, uniformly.
3. **A hold-out that was read and did not confirm.** The family stays open with the hold-out's verdict, because the hold-out is spent and the spec does not say it becomes a DROP. Default: open; say if a spent, unconfirmed hold-out should resolve as DROP.
4. **Some expression families cut.** MET (stays disabled) then says so for the counted expression families only; with every expression family cut the check is NOT EVALUABLE. Default as stated.
5. **The 90-day bound** is the spec's number, not a tuned one.
6. **What the bound is measured against.** The spec says "archive watermark age"; measured from the clock every verdict would expire 90 days after the archive stops and "stays disabled" would decay into NOT EVALUABLE. It is measured against the newest finished fetch instead (decision 4). Default as built; say if the clock is wanted.

## Consequences
- No migration, no API change, no frontend. One setting `Options:PhaseCheck:StaleAfterDays` (doc 16).
- Expected answer for months: NOT EVALUABLE (`folds 0 of 6` until five years of bars, `spread_unavailable` until 60 usable sessions, gross until the owner loads charge lines).
