# 0158 - The send path is composed only as `LegSender` behind the sandbox environment and a second default-off switch, with a persistent insert-only audit and the settings read at every send

- **Status:** Accepted (decided in P12-02b under the owner's instruction to build P12; spec [P12-02b](../specs/P12-02b-persistent-send-journal-audit-and-settings-wiring.md)).
- **Date:** 2026-10-29.
- **Relation to other ADRs:** completes ADR 0157 sections 9, 11 and 12; builds on ADR 0155 and 0156; the data-side allow-list (ADR 0097, 0133) and `Infrastructure/Brokers/BrokerEndpoints*` are not touched.

## Context
ADR 0157 left four known holes: no persistent audit or write-ahead, counts that a restart forgets, settings that were hard-coded, and a registered raw `IBrokerOrders` that bypassed the gate, halt, rate and journal. The owner's limits stay: no call to Dhan, nothing sends by default, live refused.

## Decision
1. **One order surface.** `IBrokerOrders` is not a service in any composition. `LegSender` (gate, halt, token, collar, rate, write-ahead) is the only registered way to a place call; `LegLookup` reads one order by our client id; `IBrokerReads` is a wrapper that exposes the four GETs and cannot be cast to the write port. An architecture test scans for a registration of `IBrokerOrders`.
2. **Two switches.** The adapter and sender are composed only when `Execution:Environment` is exactly `sandbox` **and** `Execution:SendEnabled` is the text `true` (default OFF, a host setting like the environment, never data and never changeable from the browser). The host still starts no hosted service that calls the sender; the sender needs the persistent journal, so a composition without the record cannot build it.
3. **Grants, minimal.** `xd_exec` gets INSERT and SELECT on `execution.broker_calls`, and SELECT on **three columns** (`account_id`, `status`, `expires_at`) of `accounts.broker_connections`. It gets nothing on `accounts.broker_secrets`: the vault is ciphertext and `xd_exec` holds no key, the sandbox token is a secret file, and live is refused. P12-02 criterion 10's "token from the vault" is therefore not built; the token check is the stored expiry. A later live ADR decides how the live token reaches the process.
4. **Audit, insert-only, codes only.** `execution.broker_calls` is refused UPDATE, DELETE and TRUNCATE by trigger for every role including the owner, and by privilege for the runtime roles. Check constraints fix the phase shapes, the environment to `sandbox`, the reason to a short code and the broker order id to a plain token. The journal stores a reason only if it already is such a code, else `reason_invalid`. Latency, HTTP status and the clock-skew column of criterion 9 are not stored yet (the client does not return them); the skew halt is P12-05.
5. **Write-ahead is a transaction.** The leg row (unique client order id) and the `begin` row commit together before the request; a duplicate begin throws, so one id is never sent twice. Intent state events for the send are not written here: P12-04 and P12-06 own the state moves, and an `intent_state` write is refused outside the event triggers.
6. **Counts from the table.** The first send after a start seeds the limiter from the `begin` rows of the last 24 h (dropped and unknown sends count: conservative). A history that cannot be read refuses the send. Limits are not per account (all accounts share them), as in the spec.
7. **Settings in force.** The heartbeat service refreshes an `ExecSettingsCache` every 10 s; `LegSender` reads the caps, the validity window, the collar and the token margin from it, `DhanOrderClient` reads `exec.send_timeout_s` at each write. Never read, or older than 60 s, means no settings and every send is refused `settings_unavailable`. `exec.exit_collar_pct` bounds an exit or flatten against a caller-supplied reference price (refused without one); the marketable price itself is computed by P12-04.
8. **Never verified against real Dhan** (unchanged from ADR 0157, plus): the field names of the four reads (`filled_qty`, `tradedQuantity`, `tradedPrice`, `netQty`, `availabelBalance`), that the sandbox serves those four paths at all, and the sandbox host. The reads are shaped from Dhan's pages and the FakeBroker from our reading of them; both can be wrong the same way. The explicit sandbox smoke and the contract run against the sandbox are not built (they would call Dhan); the owner runs them with their own credentials.
9. **Known limits.** No sender of the host calls `LegSender`; the pre-send check is still the closed default; the mode and halt sources are the closed defaults, so even composed it refuses every send until P12-03, 05 and 07. The `exec` network is still internal (no route out): the owner adds egress for `xd-exec` by a deploy change when they choose to run the sandbox smoke.

## Consequences
The send path now has a persistent, tamper-resistant record and honest limits, and still cannot run: it needs sandbox, the second switch, secret files, an egress route, an open mode source and a pre-send check that does not exist yet. A restart cannot reset the day count. The raw adapter cannot be reached through the container.
