# 0195 — The NSE daily history is an off-by-default fetch behind an empty, owner-edited allow-list pattern, with fail-closed header maps and a daily table that nothing reads yet

- **Status:** Proposed (CF-04 Part A, owner-Approved 2026-11-03 in chat; Parts B and C remain Draft and are not built). Becomes Accepted when the owner has read it **and** done the owner acts below. **Safety slice: YES** (network fetch, a new outbound host).
- **Date:** 2026-11-03.
- **Relation to other ADRs:** [0010](0010-instrument-master-sources-and-scope.md) and [0017](0017-trading-calendar-eod-schedule-quality-adjustments-and-csv-undo.md) (the master-data allow-list `MasterDataEndpoints`, GET only), the allow-list rule cited by the spec as "ADR 0097" (the app reads the list and never edits it; ADR 0097 itself is the P7 phase check, so the spec's number looks like a slip and is not relied on here), [0180](0180-the-point-in-time-filing-store-keeps-immutable-envelopes-and-answers-what-was-known-at-an-instant-from-the-broadcast-time-plus-a-lag-and-nothing-else.md) (the raw-SQL insert-only table pattern), BK-01 (an off-by-default NSE fetch with a parser that fails closed).

## Context
CF-04 Part A wants about 10 years of NSE's official end-of-day rows (price, traded quantity, delivery percent) and an as-of-date universe that keeps dead names, plus NSE's corporate-actions file feeding the existing import preview. The exact URL patterns, column names, the date of the format change and the archive's start were **not verified** (the research pages timed out); the NSE terms of use were not read.

## Decision
1. **Everything is OFF and refused until the owner acts.** `Data:History:Nse:Enabled` defaults to false. With it off, the job `history-eod` ends as `skipped` and the probe/load verbs return `history.disabled`: **zero HTTP calls** (handler tests with a substitute source; the service test never opens a scope). The service also starts paused.
2. **The allow-list is read, never edited.** `MasterDataEndpoints.IsAllowed` matched exact paths only, so dated archive paths need a pattern. `MasterDataEndpoints.Patterns` (host + full-match path regex, GET, no query) is added **empty**; `MasterDataEndpointGuard` reads it. The fetch therefore refuses before sending (`NotAllowed`, surfaced as `history.not_allowed`: "the owner must add the endpoint to the master-data allow-list"). An architecture test pins that no source file but the declaring ones creates an entry and that the shipped list is empty.
3. **One small table of unverified facts.** `EodArchive` (host, URL patterns, the 2024-07-08 switch date) and `EodFormats` (the two bhavcopy header maps, the delivery header, the actions header) are the only places that name an NSE file or column. **All of them are UNVERIFIED until `xd data eod-probe` has run**; the parser chooses the layout **by header, not by date**, so a wrong switch date only picks a wrong URL (a 404 is "absent"). The test fixtures (`EodFixtures`) are written from the best-known layouts and are marked "to be verified by the probe": when the probe has run, replace the header lines with the captured ones (rows stay synthetic).
4. **Fail closed.** A bhavcopy whose header lacks a required column of every known layout, a delivery file without its header, or an actions file without its columns is refused whole (`history.unknown_format`), and nothing is written for that day; a row dated other than the requested day refuses the file (`history.date_mismatch`). A row with an unreadable number is counted and skipped. A delivery figure above the traded quantity, or whose own percent is more than 0.01 points off the recomputed one, is rejected (the price row stays, without delivery). Percent = delivered / traded x 100, two decimals.
5. **Probe (step 0).** `xd data eod-probe --dates a,b,c` (at most 10 dates) fetches the bhavcopy and the delivery file of each date once, writes the raw bytes (unzipped) to `data/history-probe/` (git-ignored, 0600 in 0700) and prints only the header line, size, SHA-256 and whether a known layout matches. It is refused while the switch is off or the endpoint is not allowed.
6. **Load.** `history-eod` / `xd data eod-load [--from --to]`: weekdays in the range, newest first, one bhavcopy + one delivery request per day, a wait of `DelayMs` (default 1,500 ms, 250..60,000) between requests, at most `MaxPerDay` (2,000) requests per run, resumable through a ledger (`market.eod_files`: loaded or absent per day and kind), idempotent (the upsert skips an identical row). A day NSE has no file for (404) is recorded `absent`. A network failure or non-200 stops the run (`fetch_failed`, the job is `failed`; the next run continues there); a failed delivery fetch does **not** write the day without delivery. The load does not depend on the trading calendar (holidays come back as 404); Part B derives the calendar from these rows.
7. **Tables (migration `AddDailyEod`, Down included).** `market.daily_eod` keyed `(trade_date, series, symbol)`, with `isin` nullable, prices numeric(18,4), delivery quantity/percent both set or both null, checks, `file_sha256`; `market.eod_files`. Raw SQL; nothing maps them in the EF model. The runtime role has SELECT/INSERT/UPDATE and **no DELETE** on both (`NeverDeleteForAppRole`, a grants test on a throw-away server).
8. **Universe.** `market.eod_universe(as_of)` returns the securities whose span of rows `[first, last]` contains the date. This differs from the spec's "traded on that day" in one way: a halted day inside the span does not remove a name, and sparse loads still answer. A date after the last loaded day is read as that day; a date more than a week after it, or before the first loaded day, answers **empty** (an unloaded range is not answered from stale data). `in_catalog` says whether the ISIN is in the instrument master; nothing is added to tracked instruments. Series stored are `Data:History:Nse:Series` (default `EQ`); the owner's open question on other series and whole-market scope is left at its recommended default.
9. **Corporate actions: preview only.** `xd data eod-actions FILE` reads a **local** file (the file is not fetched in this slice, to keep the new host list to the two paths above), keeps split and bonus purposes, turns them into the existing import CSV (`symbol,exDate,kind,numerator,denominator`) and calls the P1-10a import handler with `Preview: true` fixed. A split "from face value A to B" is the ratio B:A reduced; a bonus "a:b" is a:b; anything else (dividend, rights) is counted and left out; a split or bonus whose text cannot be read exactly (a decimal face value, a missing ratio) is counted `unreadable` and **never guessed**. Nothing becomes `applied`; duplicates, unknown symbols and `adjustsCsvTwice` come from the existing path.
10. **Daily versus minute is a finding, never a gate.** `xd data eod-check --from --to`: the minute volume sum must be within `Data:History:Quality:DailyVolumeTolerancePct` (default 2) of the daily traded quantity; the daily high must not be below the highest minute high by more than one tick; the close is not compared. **Deferred:** the finding is printed by the verb; it is not yet a card in the Data quality screen (that screen stores its checks as JSON per instrument; wiring a new check into it is a separate change).
11. **Adjusted daily read.** The daily table stores raw values; a reader adjusts by `AdjustmentFactors` (a raw close of 1,000.00 before a 1:5 split reads 200.00; pinned in a test). No reader exists in this slice, and an architecture test pins that only the history slice, the wiring and the owner's verbs use the new ports.
12. **No API route is added** (no `gen-api` change); the verbs are the owner's surface. Criterion 17 (calendar first) belongs to Part B and is not built.

## Owner acts needed before anything is fetched
1. Read NSE's data policy and the bhavcopy/MTO terms; decide that personal local analysis is acceptable (spec decision 4). Accept this ADR.
2. **Add the allow-list entries** in `backend/src/XDrishti.Infrastructure/Market/MasterDataEndpoints.cs` (`Patterns`), GET only, no query, host `nsearchives.nseindia.com`, **after the probe confirms the paths** (the patterns below are the best-known ones, UNVERIFIED):
   - `^/content/historical/EQUITIES/\d{4}/[A-Z]{3}/cm\d{2}[A-Z]{3}\d{4}bhav\.csv\.zip$` (legacy bhavcopy)
   - `^/content/cm/BhavCopy_NSE_CM_0_0_0_\d{8}_F_0000\.csv\.zip$` (post-July-2024 UDiFF bhavcopy)
   - `^/archives/equities/mto/MTO_\d{8}\.DAT$` (delivery)
   Use a `Regex` built with a match timeout. Loosen the architecture test `No_source_file_but_the_declaring_ones_creates_an_allow_list_entry` to name `MasterDataEndpoints.cs`, and the "ships empty" fact, in the same change.
3. Run `xd data eod-probe --dates 2021-06-01,2024-07-05,2024-07-08` with `Data:History:Nse:Enabled=true`; compare the printed headers with `EodFormats`; correct the table and the fixtures if they differ.
4. Then enable the `history-eod` service on the Services screen (it starts paused). The actions file (NSE's corporate-actions CSV export) is downloaded by the owner and previewed with `xd data eod-actions`.

## Consequences
- A wrong layout cannot corrupt the table: the worst outcome is a refused file. A wrong URL pattern is a 404 (absent) or a refused request; the run reports counts, and the owner sees them.
- Free space is not checked in this slice (about 5 M rows over 10 years, UNVERIFIED size); Part B's disk guard is where that lives.
- `Data:History:Nse:UserAgent` empty means the client's own; if NSE refuses, the run is `failed`, and it is never worked around.

## Known limits
- URL patterns, column names, the format switch date, the archive start, the delivery header and the actions header are UNVERIFIED (see 3).
- The universe uses spans, so a security that stops reporting without a delisting looks alive until its last row; a re-listed symbol with a gap counts as continuous.
- The NSE terms of use were not read by the builder; that is the owner's act.
