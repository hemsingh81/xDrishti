# 0214 — A model's calibration is chosen by sample size (Platt below 500 calibration rows, isotonic from 500) and its error is reported with a day-cluster bootstrap interval

- **Status:** Proposed (built in CF-10 part 10a from the owner-Approved spec, 2026-11-03). Becomes Accepted when the owner has read it. **Safety slice: no** for this part (it changes how a model's probability is fitted and reported; nothing reads that probability for a decision, no switch, no rollback writer, no order). The safety parts of CF-10 (the influence predicate, champion / challenger, rollback) are 10c and 10d and are not built.
- **Date:** 2026-11-05.
- **Relation to other ADRs:** changes the calibration step of [0068](0068-the-ml-net-trainer-adapter-pav-calibration-on-a-held-back-slice-and-honest-explanations.md) (P6-06: PAV on the held-back 25 %); the eligibility rule of [0067](0067-validation-harness-and-baselines-purged-folds-and-an-honest-eligibility-rule.md) and the drift detectors of 0074 are unchanged. Follows the confidence programme rule of CF-00: a new figure is report-only.

## Context
The trainer fits the trees on the early 75 % of a fold's train rows and a pool-adjacent-violators (isotonic) map on the latest 25 %. With about two years of trades that is 100 to 300 calibration rows. An isotonic map can have one step per distinct score, so on 80 rows it has up to 80 steps and fits noise (the usual small-sample advice, Niculescu-Mizil and Caruana 2005, cited from memory and not fetched: UNVERIFIED). The harness reported an expected calibration error as a single number, with nothing said about how far it could move. Spec CF-10 D1 asks for the calibration to follow the sample size and for the error to carry an interval.

## UNVERIFIED resolved: is the score the isotonic map receives already Platt-calibrated by ML.NET?
**No.** `MlNetScorerFactory` fits LightGBM or FastTree through `ml.BinaryClassification.Trainers.*`, which return a transformer whose parameters are wrapped as `CalibratedModelParametersBase<..., PlattCalibrator>` (hence the type names in the code). Such a transformer writes three columns: `Score` (the margin of the trees), `Probability` (ML.NET's own Platt map of the margin) and `PredictedLabel`. `MlNetModel.RawScore` reads the **`Score`** column, so the map that the factory fits receives the raw margin, and ML.NET's Platt probability is never used. Evidence: the code (`Margin` reads `"Score"`), and a test that trains a FastTree and compares the two columns (the margin runs outside 0 to 1, the probability does not, and they differ by more than 0.1), and that the factory model's `RawScore` also leaves 0 to 1. Consequence: no double calibration existed before this change and none exists now; the new Platt map is the only map applied to the margin.

## Decision
1. **The calibration kind follows the number of calibration rows (`CalibrationChoice`, pure, Domain).** Rows are the rows with a finite raw score. None: the **constant 0.5** (kind `base_rate`, a name kept for the code; with no rows there is no rate to estimate). Fewer than `IsotonicMinRows` (500): **Platt**. 500 or more: **isotonic** as before. 499 gives Platt and 500 isotonic (unit test).
2. **Platt scaling (`PlattCalibrator`, pure, Domain, no package).** `p = sigmoid(slope x (score - center) + intercept)`; two parameters are fitted (slope, intercept), the centre is only the mean of the fit scores, kept so the arithmetic is well scaled and a score that is not a number reads as the fitted level at the centre. Targets are Platt's smoothed ones, `y+ = (N+ + 1) / (N+ + 2)` and `y- = 1 / (N- + 2)`, so the fit is finite when the scores separate the classes. The fit is a deterministic Newton iteration on the log loss with a backtracking step (at most 100 iterations, sequential sums). **The slope is never negative:** a fit that would fall with the score is replaced by the constant that fits best (the mean of the targets), so the map never reorders rows. Hand-worked tests: a constant score with 3 wins in 8 gives targets 0.8 and 1/7 and the fitted value (3 x 0.8 + 5 x 1/7) / 8 = 0.389286 where isotonic gives 0.375; two rows at scores -1 and +1 with labels 0 and 1 give a slope of ln 2 and probabilities 2/3 and 1/3.
3. **The map is one type to the model (`ScoreCalibration`).** It holds the kind, the map, the number of rows it was fitted on and the curve a reader plots (`Scores`, `Values`): the isotonic knots, or eleven points of the sigmoid across the fitted score range (one point for a constant). `MlNetModel.Calibration` is this type; the registry's `calibration_scores` / `calibration_values` columns hold the curve, so the Models screen draws either kind without a migration.
4. **The kind and the parameters are stored in the artifact header** (the model header of the spec): `CalibrationKind` (`isotonic` | `platt` | `base_rate`), `PlattSlope`, `PlattCenter`, `PlattIntercept`. The fields have defaults, so an artifact written before this change (no such fields) loads as **isotonic**, scores exactly as before, and its hash is untouched; the same rows still give the same bytes. **The format version says which:** an isotonic artifact stays version 1 (bytes and hash unchanged); a Platt or base-rate artifact is version 2, so a build older than this change refuses it instead of misreading it as isotonic. Version 1 must name the isotonic kind and version 2 a non-isotonic kind, otherwise the artifact is refused at load; so is an unknown kind or a negative slope.
5. **The error is reported with an interval (`EceInterval`, `CalibrationAssessment`, pure, Domain).** Whole trade days are resampled with replacement (the trades of one day are not independent), the expected calibration error over equal-mass bins is recomputed on each resample, and the interval is the percentile interval of the draws (default 1000 draws, 90 %; `ValidationOptions.EceDraws`, 0 turns it off). The generator is the Domain's SplitMix64 (`SeededRandom`), seeded from the scorer, the span and the row count, so a rerun on the same rows repeats. The assessment also carries the gap (mean predicted minus observed, in percentage points), its standard error (`sqrt(q (1 - q) / n)` with `q` the observed rate: 100 outcomes at 55 % predicted and 50 % observed give a gap of 5 pp and a standard error of 5 pp, one standard error, **not** a breach of the drift rule), and the log loss minus the log loss of the constant that is the observed rate of the same outcomes (the best constant, so a model that beats it is not flattered). The drift-rule reading of one set is not built here: AC11's numbers (12 pp breaches on n = 200, not on n = 100) are evidenced in 10d against `CalibrationDriftDetector`. If the interval cannot be computed the report prints `ece interval unavailable: <code>` and not nothing. The pooled result of each candidate in the validation report carries it, and the report text prints it under the pooled line. **It reports only: no verdict, no eligibility rule and no champion rule reads the interval** (the 5 pp bound of 0067 still reads the point estimate).
6. **Settings.** `Confidence:Calibration:IsotonicMinRows` (default 500, range 1 to 100000), bound and validated at start (the binding and the refusal of a bad value are tested); a key left out keeps the default; it reaches the trainer, whose parameter text now ends `isotonic_min_rows=N`. No mode and no enforce switch: the setting only chooses the smaller fit for few rows and changes no decision. The bootstrap draws and level are harness options (`ValidationOptions`), not host settings. As in CF-01 to CF-09 the spec's "versioned settings home" is the configuration section, not the database; a change takes a restart.
7. **Isolation.** No type of Planning, Selection or Autonomy (Domain or Application) names a calibration type (architecture test, with a control that the rule sees a real dependency); the calculators are pure (no clock, no I/O, no system random). `AdvisoryPWin` stays a display field.

## Changed behaviour (documented as the spec asks)
A model trained on fewer than 500 calibration rows is now calibrated by Platt scaling, so its stored probabilities, its artifact bytes and hash, its validation log loss and its calibration curve differ from a model trained on the same rows before this change; the model it replaces is not rewritten, and it still loads as isotonic. Existing P6 tests are unchanged except one: none pinned the isotonic kind (the tests that read the knots or the monotonicity pass for either kind), and the header-refusal test now uses format version 3 as its unknown version.

Knock-on effects of the new trainer parameter text (`isotonic_min_rows=500` is now part of `trainer.Parameters`):
- **A champion trained before this change reads as "no policy".** `EvaluateMetaPolicyHandler` requires the champion's stored parameters to start with `trainer: {trainer.Parameters}; `, so every such champion now fails it with "made with other trainer settings" until the model is retrained and re-designated. **Owner to-do:** retrain and designate the champion again (P6-08) before expecting a meta-labelling policy.
- **Recipe and trial hashes change.** The extension comparison hashes `trainer.Parameters` into its recipe hash (`ComparisonEvaluation`) and the meta-policy stored-report hash includes the recipe text (`StoredReportHandlers`): a rerun counts as one more distinct trial and writes a new row instead of deduplicating against the old one.
- **The extension comparisons and the counterfactual also switch to Platt**, because they train through the same trainer; their numbers on the same rows differ from before for calibration sets under 500 rows.

The ECE interval is not shown by an endpoint or screen: it is in the stored validation report text.

## Limits
- Platt assumes a sigmoid shape; a badly scaled margin can mis-fit (the reliability slope in CF-12 is the watch). With 500 rows or more the isotonic map is used even if a sigmoid would have generalised better.
- The bootstrap ECE carries the upward bias of the error on few rows; the interval says how far the figure could move, it does not remove the bias. Block length is one day, so serial correlation across days is ignored.
- The standard error here uses the observed rate (the spec's number); the P6-09 detector uses the variance of the predictions, which differs by a few percent for the same data.
- The cut 500, the 90 % level and 1000 draws are proposals.
