# 0123 — The paper phase check judges the P10 exit from stored records, with its caveats in the label, and only reads

- **Status:** Proposed (spec [P10-06](../specs/P10-06-paper-phase-check.md), built 2026-10-26; the spec is still Draft). Becomes Accepted when the owner has read it.
- **Date:** 2026-10-26.
- **Relation to other ADRs:** [0097](0097-the-p7-phase-check-ten-consecutive-scheduled-sessions-from-stored-plan-runs-and-never-met-on-fewer.md)-style phase check (three outcomes, caveat in the label, limits always printed), [0080](0080-the-phase-check-exit-criteria-from-stored-records-and-never-met-on-thin-data.md), [0116](0116-paper-fills-are-the-grading-replay-captured-per-armed-allocation.md) (capture rows), [0119](0119-a-measurement-epoch-freezes-the-measured-configuration-changes-are-detected-classed-and-labelled-and-nothing-is-applied-or-blocked.md) (epochs), [0121](0121-the-weekly-paper-review-and-the-discipline-report-are-deterministic-texts-over-stored-records-stored-once-per-week-and-epoch-and-apply-nothing.md) (pace, ETA, discipline lines), [0122](0122-backtest-versus-paper-is-a-composition-matched-bootstrap-of-the-pre-epoch-backtest-trades-computed-on-read.md) (E3, E4, `ICostConfirmationFact`).

## Decision
1. **Four exit criteria and one integrity criterion, each MET, NOT MET or NOT EVALUABLE** (a pure `PaperPhaseCheck` over plain `PaperPhaseFacts`). C1 duration and coverage: elapsed days of the current epoch (start to `through`, both included) under 84 is NOT EVALUABLE (`day k of 84`), else coverage (sessions with a published plan and a capture row that is done with nothing pending, over the epoch's trading sessions) under 0.80 is NOT MET. C2 counted trades (the P10-04 counted set): under 60 is NOT EVALUABLE (never NOT MET for being short), with pace and an ETA only when P10-03's rule allows. C3 and C4 are P10-04's verdicts and labels unchanged. I: a capture row with an integrity mismatch, or a pair still pending more than three sessions later, is NOT MET; no capture row is NOT EVALUABLE.
2. **Overall.** MET only when all five are MET; NOT MET when any is NOT MET; else NOT EVALUABLE. Before printing MET the code re-checks distinct tickets, n >= 60, elapsed >= 84, one epoch id throughout and `through` a trading session; a failure prints `NOT EVALUABLE (malformed window)` with the reasons among the blockers.
3. **Caveats are the label.** `MET (point estimate; 90% interval [lo, hi] includes 0; k risk-down changes: the population was censored; k of n counted trades were auto-approved; m manual runs of the nightly pipeline in the epoch; P7 phase check not met)`, each part only when it applies, stacked in one parenthesis. The same text is `exitCriterion`; `exitVerdict` is the bare word.
4. **`through` is rounded down to a trading session** (a Sunday counts as the Friday before) and must not be after the last closed session nor before the epoch start (422 `paper.invalid`); an unknown epoch is 404 `paper.not_found`. An epoch that has been followed by another ends the day before it.
5. **Resets are printed, never pooled.** Every epoch of the history is listed with start, kind, counted n and unexplained changes; only the current (or asked) epoch is judged.
6. **Printed, not judged.** The discipline lines, the plan-price sensitivity, the auto/owner split, plans with zero primary tickets, the P7 phase check outcome, the services `paper-capture`, `paper-review`, `nightly`, `preopen`, `plan-expiry`, `weekly`, the settings `Planning:OpenBook:UsePaperLedger` and `autonomy.auto_approve_tickets`, whether the charge sheet is confirmed, the blockers with whose act each is, and the five things never judged here (look-ahead, paper equals grading, determinism, the no-order rule, real fills) with the tests that prove them. The limits are always printed.
7. **Reads only.** One new read-only port `IPaperPhaseData` (capture rows of a window, one select); everything else reuses existing reads and the P10-04, P10-03 and P7 handlers. `GET /api/paper/phase-check?through=&epoch=` and `xd paper phase-check [--through DATE] [--epoch ID]` (exit 0 whatever the verdicts); frontend tab **Phase check** (lazy). No migration, nothing stored. Log ids 5219 to 5223.
8. **The review's backtest line (part B).** `IReviewComparisonLine` is now `BacktestReviewComparisonLine`, which reads P10-04's report: a placed mean prints with its position, the two verdicts and the unconfirmed-costs note; an `insufficient`, `unavailable` or `not_evaluable` report prints its state and reason and no mean, band or interval; it ends `Simulated on both sides; not an instruction to trade.` `ComparisonLineNotBuilt` is removed.
9. **Small read additions.** `CountedTrade` carries the ticket id and approval kind (`PaperCompareRow` the approval kind), and `StoredChange` the session of the snapshot that found it, so the week lines can place a change.

## Consequences
- A real MET is unreachable until the slice that writes the charge-sheet confirmation exists: E3 and E4 read `not_evaluable: costs not confirmed`, so the overall check is NOT EVALUABLE. The seeded 12-week test stands a stub fact in.
- Resolved ambiguities: the pending-pair rule of I reads the stored capture row, which cannot tell missing bars from a late replay, so a pair pending for more than three sessions is flagged either way; the `P7 phase check not met` caveat is added for any P7 verdict other than MET (and `unavailable` when it could not be read); coverage counts only sessions up to `through`, so the newest closed session whose capture has not yet run lowers it slightly; manual runs counted are nightly plan attempts started by a person; the ETA reuses P10-03's thresholds (10 trades, 3 weeks); epoch history `counted` is the stored entry count, not the P10-04 set; the 5-line "never judged" list names classes of tests, not single tests, where several prove one property.
- Not verified: the run on the owner's data (no epoch is expected, so every criterion reads NOT EVALUABLE); the cost of 85 plan-run and capture reads is one query each.
