# 0114 — The exit comparison and the stored walk-forward exit choices are read through a sibling port, and Monte Carlo is the Lab's stored bootstrap

- **Status:** Proposed (spec [P8-10](../specs/P8-10-catalogue-reports-the-stored-data-can-serve.md) part b, built 2026-10-26). Becomes Accepted when the owner has read it.
- **Date:** 2026-10-26.
- **Relation to other ADRs:** [0106](0106-the-report-engine-gains-excursions-entry-hour-and-sector-additively-and-mae-mfe-is-served-as-counts-in-bins.md) (part a), [0100](0100-the-report-endpoints-read-the-stored-runs-through-one-query-model-with-an-evidence-block-and-net-only-by-the-owners-stored-confirmation.md) (endpoints), [0053](0053-the-same-entries-comparison-and-the-mae-mfe-diagnostics.md) and [0054](0054-the-per-cell-exit-choice-by-walk-forward.md) (what is stored), [0062](0062-robustness-sensitivity-monte-carlo-by-year-and-a-sign-flip-baseline.md) (the stored Monte Carlo).

## Decision
1. **Two new read endpoints, GET only:** `GET /api/reports/comparisons` (header columns of `research.sim_comparisons`, never the CSV text) and `GET /api/reports/exit-selections` (the stored walk-forward choices of `research.exit_selections`). Both are listed with limits as text; neither takes a parameter.
2. **A sibling port `IReportComparisonSource`**, not new methods on `IReportTradeSource` (the spec's wording). Reason: the trade port has several fakes in tests and each would need a stub for methods they never use; a separate port keeps the trade stream unchanged and the two reads independent. Implemented by the internal `ReportComparisonSource` (plain reader, no change tracker).
3. **The numbers of a comparison come only from the report engine.** Choosing a comparison sets `runs=<its member keys>` on the screen and the table is `groups?lens=exit` (the engine requires the exit split for the same signals under several exits). The CSV is never parsed. The screen prints "n is the same for every row" only when the n of the rows are in fact equal; otherwise it says the rows are not like for like.
4. **The exit choice is read from the stored record** (`record_json`, ADR 0054 schema 1), not rebuilt: chosen exit or the reason for none, the default, the stability verdict with its reason and counts, the exact chance-pass probability, the pooled out-of-sample figures, each fold's winner and the record's own banner. A figure is a value only when the record has it and at least the minimum sample (30 trades) stand behind it; otherwise it is `insufficient` or `unavailable` with a reason and no number. A fold in which no candidate qualified is `empty`.
5. **Monte Carlo is the Lab's stored bootstrap** (decision 6 of the spec): the screen lists Lab runs (`GET /api/lab/runs`) and reads `GET /api/lab/runs/{id}/report` only when a run is chosen. A run without a robustness block, or without a report (409 `lab.no_report`), says so. A table of percentiles; no fan chart because the stored result holds no paths.
6. **Pointer entries** for Regime, Calibration, Selector effectiveness, Decisions, Backtest/paper/live, Discipline, Execution gap and Account comparison are catalogue entries with the missing input and the supplying slice or phase. Regime and Account use the server's own refusal text (the 422 of a lens by them). Selector effectiveness and Decisions link to Learning, Decisions. They render no chart and no figure.

## Consequences
- The comparisons endpoint carries `limits` (text) instead of the full `ReportEvidenceView`: it lists headers and counts no trades, so a population block would be empty or invented.
- The stored choice is in-sample inside the replayed history (a few folds); the screen and the endpoint say so and nothing is applied.
- The read of `exit_selections` parses one record per choice on each request; the table is small (one row per cell the owner chose to store).
