# 0250 — Training-simulation reports extend the report engine: only finished chunks as of one instant, cut before the hold-out, bounded, and labelled "not evidence"

- **Status:** Accepted by delegation (owner, 2026-11-09: unsettled decisions are researched, the best chosen, recorded here).
- **Date:** 2026-11-10.
- **Relation to other ADRs:** Builds on [0243](0243-simulate-everything-is-training-data-fenced-from-the-hold-out-and-from-scorecard-evidence.md) (training runs are not evidence; one non-evidence reader), [0248](0248-the-simulate-everything-job-is-a-resumable-table-driven-queue-of-training-chunks-that-yields-to-market-hours-disk-and-the-broker.md) (the job and its chunks) and [0249](0249-training-from-the-simulation-reuses-the-anchored-purged-quarterly-folds-with-a-session-embargo-keeps-the-hold-out-out-whole-and-registers-a-challenger-that-cannot-be-eligible.md) (the training record). Extends the report engine of [0100](0100-the-report-endpoints-read-the-stored-runs-through-one-query-model-with-an-evidence-block-and-net-only-by-the-owners-stored-confirmation.md) and [0106](0106-the-report-engine-gains-excursions-entry-hour-and-sector-additively-and-mae-mfe-is-served-as-counts-in-bins.md) without changing its mathematics.

## Context
The owner asked to see the simulation by stock or basket, for any from-to range, in several report types, while the job is still running. The report engine already has the types (summary, groups, pivot, equity, distribution, MAE/MFE, what-works, insights, trades, benchmarks); it reads evidence runs only, and must go on doing so.

## Decisions (researched, chosen by delegation)
1. **One engine, a second source.** The query gains `purpose=training` and `simJob`; the loader takes the trades from a new port `ITrainingReportSource`, whose one implementation hands over to `ITrainingRunReader`, the reader that carries the `purpose = 'training'` fence. The evidence source (`ReportTradeSource`) is untouched in what it reads (its filter code was moved into shared helpers). Alternatives rejected: a second set of nine handlers (duplicated mathematics, drift), and a `purpose` argument on the evidence source (it would put both purposes behind one fence, the thing 0243 forbids). Architecture tests pin that only the loader names the port, that the engine names neither the reader nor the training purpose, and that the reader's new statements carry the fence.
2. **Default is evidence, byte for byte.** Without `purpose=training` a report is what it was (golden tests); `simJob` without the purpose, any other purpose, net basis, named evidence runs and run labels (style, exit) with the training purpose are `reports.invalid`. The status is 422, as every `reports.*` refusal of the engine already is (the spec wrote 400; one status for one code is worth more than the digit, and the existing contract and tests say 422). An unknown job is 404 `reports.not_found`. A job id left out means the active job, else the newest.
3. **Completeness is part of the evidence block.** `evidence.completeness` (absent on an evidence report): kind `training_simulation`, the label "Training simulation, not evidence", job state, `complete` (job completed, every chunk done, none failed), chunks done / total / failed / running / pending, the as-of instant, the window, the range actually read, whether the asked range was cut and the sentence that says so, stocks asked for with no result, and the route of the training record (`/api/simulate-all/{id}/training`). The limits in the same block say that the latest strategy version is replayed over the past, so the figures are in-sample and no claim of out-of-sample performance or of freedom from look-ahead is made.
4. **Finished chunks as of one instant.** Counts are taken first, then the instant, and the trades are read only from chunks `done` with `finished_at <=` that instant, so a chunk finishing during the read is not half in. A chunk that finished between the counts and the instant can be read though not yet counted; the report is `complete: false` while the job runs anyway.
5. **The hold-out is never asked for.** The range is cut to `min(window end, hold-out start - 1 day)` before any statement is built, so no trade of the block is requested; a range wholly past it reads nothing and says the part before it is empty. This is a property of the request, not a filter on the result.
6. **Each run is its own universe.** One chunk is one strategy over one instrument, so the population rule is given the instrument as the universe: runs of different stocks are never mistaken for one population. The overlap check of the domain now forms pairs inside a universe only (same result, the first pair in order), because a stock report holds hundreds of runs and a basket report thousands.
7. **Bounded, and never cut.** The trades are streamed; above `Reports:Training:MaxTrades` (validated 10,000 to 1,000,000, default 500,000: the cap of the evidence reports, measured against the 1 GiB container in 0100) the report is refused with `reports.too_large` and the sentence to narrow it. The trade list keeps its page (limit 1 to 1,000, cursor bound to the report), and `GET /api/reports/sim-jobs` pages the jobs (limit 1 to 50). Counts of a job are an index-only count by state. **No pre-aggregation yet:** the spec allows it for a whole-universe report; a stock or basket report is the owner's ask, and a whole-universe report over a big job is refused until it is measured and needed.
8. **Indexes (migration `AddSimReportIndexes`).** `sim_all_chunks (job_id, instrument_id) INCLUDE (run_key, finished_at) WHERE state = 'done'` reaches the few runs of a stock; `sim_all_chunks (run_key)` links a run back to its chunk; a GIN index on `sim_trades.basket_ids` reaches the trades of a basket (the basket stored on the trade, as today). The GIN index adds write cost to the insert-only trade table; accepted, because a basket report would otherwise read every trade of the job.
9. **Not exported.** An export (CSV) of a training simulation is refused: a file leaves the labelled screen and could be taken for evidence. Benchmarks take the job: the range is cut to the training window and labelled; what a basket would have done by holding is market data, not a training result.
10. **Setting, not a constant.** The cap is a validated setting with its best default; changing it is a configuration change, not a code change.

## Measured
One stock over a store of 18,039 training trades (60 other stocks beside it): p95 30 ms, median 8 ms over 20 requests, HTTP hop included (`SimReportApiTests`). That store is small; the 500 ms target is **not yet verified on a production-sized store** (millions of trades). What is designed for it: the stock path reaches its runs through the `(job_id, instrument_id)` index and the trades through the primary key, the basket path through the GIN index, and nothing reads the trades of other stocks. Measure on the real store after the first full job and record it here.

## Consequences
A screen (AU-15) can show any stock or basket of a running job, labelled as it must be. The evidence path is unchanged, and the architecture tests keep training runs out of it. A whole-universe report of a large job needs a pre-aggregate (a later slice) or a narrower question.
