# 0139 — The "Ask your data" tools reuse the report engine and the reviewed views, the read role gets column grants on four report-source tables, and `calc` and `make_chart` take no number from the model

- **Status:** Proposed (written in P9-05 under the owner's delegation of 2026-10-26; the spec was treated as Approved). Becomes Accepted when the owner has read it. **SAFETY decision: it decides which stored data reaches the model's context (classes C1, C2 and untrusted text) and widens the grants of a database role.**
- **Date:** 2026-10-27.
- **Relation to other ADRs:** [0137](0137-the-assistants-tools-run-in-a-separate-read-only-server-under-two-database-roles-that-can-select-only-from-reviewed-views-and-the-switch-lives-in-the-database.md) (tool server, roles, runner, `aiv`), [0138](0138-the-assistant-endpoint-runs-the-tool-loop-in-the-application-streams-events-marks-figures-not-found-in-the-tool-results-and-stores-every-turn-insert-only.md) (the loop, the grounding check), [0100](0100-the-reports-read-the-stored-runs-through-one-query-model-and-the-owner-confirms-the-charge-sheet-before-any-net-figure.md) (report handlers, the charge-sheet confirmation).

## Context
The four tools of P9-02 can read views and run a SELECT, but a model asked "expectancy by basket" should not write its own SQL for a figure the app already computes with honest states. P9-05 adds eleven tools on the tool server and one local tool in the API, so that a figure in an answer is the figure on the screen, with its evidence, and a derived figure can be checked.

## Decision
1. **One definition of expectancy.** `get_report` and `list_runs(sim)` call the handlers of the Reports screen (`GetReport*Handler`, `ListReportRunsHandler`) through one port, `IAiReportReader`, and only reshape their views into rows, data and evidence. Nothing is recomputed. The handlers are registered for the tool server by `AddAiReadOnly` (through one public registration of the application), over the same `ReportTradeSource` adapter, now connected as `xd_mcp_read`. Rejected: calling `GET /api/reports/*` over HTTP (a service credential into the API, a new auth path); a second SQL path in the tool server (it would drift).
2. **Gross only.** The charge-sheet confirmation lives in settings no assistant role may read. The tool server registers an always-absent confirmation, so every report is gross; a `basis` other than gross is answered `reports.net_not_confirmed` ("net is not offered by the assistant yet"). A view that exposes only the confirmation is a later, owner-visible decision.
3. **Column-level grants, four tables.** Migration `AddAiToolAccess` gives `xd_mcp_read` (never `xd_mcp_sql`) `USAGE` on schemas `research` and `lab` and `SELECT` on exactly the columns the report reader names: 15 of `research.sim_runs`, 19 of `research.sim_trades`, 3 of `research.sim_comparisons` and 2 of `lab.strategies` (not the run record text, the entry snapshots, the costing columns or the comparison CSVs). A test lists the grants from the catalogue and a test runs the real reader as the role; if the reader later reads another column, the report tool fails and the grants test says why. `SELECT *` on any of the tables stays refused.
4. **The typed tools read the reviewed views only**, through one port, `IAiDataReader`, with parameterised SQL; no tool takes a table or column name from the model (kinds and group names are fixed enums; the learning SQL is built from constants). The portfolio tool reads the switch first and reads no portfolio row while it is off (`ok: true`, `data: null`, "unavailable: portfolio context is off"). New view `aiv.holding_groups` (account label, symbol, bucket name; C2, security barrier, context predicate) with the helper `ai.bucket_labels` (so that no `aiv` definition names the accounts schema) and the two revokes from `xd_app`; 36 views now.
5. **Portfolio figures are the screen's.** `PortfolioFigures` (Application) builds `HoldingData` from the view rows and calls `ReturnsCalculator.ForGroup`, the Holdings screen's own calculator (four decimals, away from zero, the same XIRR); a holding with no usable price has no value, profit or rate, and a group of such holdings says so; a holding held under 30 days gives XIRR `insufficient`. No cash or funds figure exists; accounts appear by label only.
6. **Free text in `data` is cleaned too.** The runner cleans, scrubs and counts a string of the `data` object whose property name ends in `Text` like a text cell, and `JsonNode` cells (metrics, level sets) are cleaned leaf by leaf. Text of the database is escaped (no markup the screen could render), instruction-like text is flagged and still delivered, and a PAN-like or account-like number is redacted. Run keys, hashes, ids and amounts are structured and never touched.
7. **`calc`.** A recursive-descent parser over `decimal` (numbers, `+ - * / ( )`, unary minus, `round abs min max`), at most 50 tokens and 200 characters, half away from zero, result as text; any identifier, `^`, `**`, string or exponent is `calc.rejected`, a zero divisor `calc.divide_by_zero`. It exists so that a derived number is fetched and therefore checked by P9-03's grounding.
8. **`make_chart` is local to the API** because it needs the turn's results, which the stateless tool server does not hold. The turn service adds its declaration to the tool list and runs it in the loop on the results of this turn by call number; it takes no number from the model (a reference to a column of an earlier successful call, numeric y columns, equal lengths, at most 200 points and 4 series, a title of 80 characters without markup) and its result is not a source of figures for the grounding check. A non-value state in a y column is a gap, never a digit.
9. **Honest states pass through.** A cell below 30 trades is `insufficient` with its `n` and wins and no rate; an unavailable input is a row with its reason; "nothing qualifies" is `ok: true` with its counts; the engine's `reports.*` codes pass through unchanged.
10. **Budget.** The 16 tools (15 on the server and `make_chart`) estimate at under 2,200 tokens at 3.5 characters per token; each description is at most 40 words; a golden file of all names, descriptions and schemas is committed and compared by a test. To fit, the schema omits `minLength` of 0 or 1 (the server still enforces it).
11. **Log events** 6120 (report call), 6121 (data call), 6122 (calc rejected, reason word) and 6123 (chart rejected, reason word): tool, status, rows, milliseconds; never an argument, a result or a text.

12. **Review fixes (independent review of b66cbade).** (a) `calc` echoes the number literals of its expression in `data.operands`; the turn counts a `calc` result as a source of figures only when every operand is found in an earlier result of another tool of the same turn or in the owner's question, so `calc("0.9+0")` cannot launder an invented figure and a `calc` result is never a source for another `calc`. The only literals allowed without a source are `0`, `1`, `100` and `0.5`. (b) `make_chart` refuses a digit in the title or a label. (c) The runner cleans every string of `data` at any depth unless its key is in a short structural list (ids, codes, dates, dimension names, the decimal `result`/`operands` of `calc`); the name-suffix rule is gone. (d) **Accepted slack:** `xd_mcp_read` keeps column `SELECT` on `research.sim_runs.created_by` because the report reader derives the experiment-candidate flag from it (`created_by LIKE 'experiment:%'`); only the boolean reaches an answer, and the column holds an `owner:<email>` or job label. Replacing it needs a generated column on an insert-only table; left for a later change.

## Consequences
- Added: ports `IAiReportReader` and `IAiDataReader`, 11 tool classes, `Calc`, `PortfolioFigures`, `ChartTool`, migration `AddAiToolAccess` (with `Down`), one manifest entry, the golden file. No API contract change, no frontend change (`make_chart` renders as a table until the shared chart module exists).
- The tool server now holds a copy of the report gate; it is a separate process, so it shares neither a cache nor the gate with the API (there is no report cache, only the gate).
- `get_report` on a very large stored run is bounded by the 10 s tool timeout and answers `tool.timeout`, never a partial number.

## Not verified in this build
- No real model was run: whether a 30B model picks the right tool and filters from these descriptions (P9-09 measures; the response to wrong-tool errors is fewer, broader tools, not more prompt).
- `get_report` timing on a large stored run and the memory per call were not measured here (the fixture is 45 trades).
- A report that mixes gross and costed runs was not exercised against the database in this slice (the engine's refusal is covered by its own tests); an overlapping pair is.

## Deviations from the spec text
- `get_portfolio` has no `asOf` argument (the valuation date is today); `tracked` is reported as `hasDailyBars` (whether daily bars are stored) because no reviewed view says what is tracked; `search_notes` does not search price-alert notes (no reviewed view holds them) and has no context-gated source today; `list_runs(sim)` ignores `strategy` and `limit` (the screen's list is returned whole, at most 200 rows).
