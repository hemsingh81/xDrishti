# 0131 — An export is one audited POST behind a capability that returns a research table as a CSV with its evidence, and keeps nothing

- **Status:** Proposed (spec [P8-20](../specs/P8-20-exports.md), approved by the owner on 2026-10-26; built 2026-10-27). Becomes Accepted when the owner has read it. **SAFETY slice: data leaves the app as a file on the owner's device.**
- **Date:** 2026-10-27.
- **Relation to other ADRs:** [0128](0128-owner-act-capabilities-are-one-insert-only-log-with-a-generic-gate-by-name-off-by-default-and-switched-on-only-by-the-owner-with-a-fresh-password.md) (the capability `exports`, OFF by default), [0130](0130-the-owner-act-forms-are-endpoints-behind-a-capability-a-fresh-password-and-an-audit-row-over-the-existing-handlers-and-state-machines-and-apply-nothing.md) (the same lessons: the gate first, the audit cross-index, no secret in an audit row), [0100](0100-the-report-endpoints-read-the-stored-runs-through-one-query-model-with-an-evidence-block-and-net-only-by-the-owners-stored-confirmation.md) (the handlers whose results are exported; the numbers are theirs), [0126](0126-the-p8-phase-check-reads-three-witnesses-and-is-never-met-on-what-it-could-not-read.md) (`ApprovedReportWrites`).

## Context
The owner wants to take a research table of the Reports screens out of the app as a CSV for a spreadsheet. Once saved, a file is outside every protection of the app, so the slice had to answer: what may leave, with what label, how a number is kept from being misread, how the app can keep from being used as a leak, and what the app records.

## Decision
1. **What may leave: five tables of the Reports screens, nothing else.** `report-groups`, `report-pivot`, `report-what-works`, `report-equity`, `report-trades`: the very views of the screens, made by the very query handlers with the same checked `ReportQuery` (there is no second implementation of a number; a test compares the file with the GET). `cells` and `experiments` of the spec are not built: their views carry no evidence block, and a table without its evidence is never exported. Nothing about accounts, portfolio, plans, journal, audit or the weekly pack is exportable; there is no kind for them.
2. **One route, one POST.** `POST /api/exports/{kind}` with `{format, query}`; a POST only because it writes an audit row. It is the one export route on `ApprovedReportWrites` (the phase check's GET-only rule for `/api/exports` stays meaningful: any other non-GET there is NOT MET). Response: `text/csv; charset=utf-8`, `Content-Disposition: attachment` with a server-made ASCII name `xd-<kind>-<yyyyMMdd>-<8 hex of the table hash>.csv` (India date of the export), `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`, no cookie. CSV only: the static HTML of the spec is not built (the owner's brief named the CSV).
3. **Layers, in this order.** (a) The endpoint asks the capability `exports` FIRST, so that OFF is always a 403 and never a rate answer; (b) the owner of the session (and the CSRF token); (c) the rate rule, in the endpoint and not in the middleware: 6 starts in any minute and one at a time (a refused or failed export still counts); (d) the handler asks the gate again, checks the kind and format against their lists, turns the query with the report whitelist and calls the screen's handler; (e) the audit row is written BEFORE the bytes are given. There is no database layer (nothing is written but the audit row).
4. **No password per export (spec D5, kept).** An export shows what the screen shows from the owner's own stored simulations. A hijacked session can read the same JSON, so a password per file would be friction without protection; the protection is the switch (turning it ON asks the password), the audit, the rate rule and the caps. This was weighed against the safer default of a fresh password and kept because the data is the owner's research output of stored runs, never accounts or secrets. If the owner prefers the password, the owner-act flow of ADR 0130 fits in front unchanged.
5. **The evidence is inside the file.** Comment lines `# ` before the table: basis (net names the confirmed charge sheet), the population rule and counts, date range, as-of (the last exit date in the DATA, never the time of the export), folds, every run, unavailable inputs, every limit, the legend of the figure columns, the table's own notes, "complete", `table-rows`, `table-sha256`; and `# end of export, rows N` after it (a cut file is visible). A figure is three columns, `x`, `x_state`, `x_reason`: a number only for `value` and `provisional`, empty for any other state (tests over every state; a non-finite number is an empty cell and the state `unavailable`).
6. **Deterministic bytes.** No timestamp, random value or machine fact is in the file; the same stored runs and the same query give the same bytes. Only the file name carries the export date. UTF-8 without a byte order mark (as every writer of the system; a BOM would break the `#` comment skipping of the common tools).
7. **Spreadsheet-injection hardening.** `CsvRow.Text` (shared with the existing exports) now also prefixes an apostrophe when the first non-space character of a cell is the full-width `＝ ＋ － ＠`, or `= + - @`, behind any whitespace (the old rule looked at the first character only). Numbers are written from numeric types only. The comment lines are cleaned: control, format and line-break characters become spaces (words do not join), `,` becomes `;` and `"` becomes `'`, so a line is one cell that begins with `#` and can never end the comment, start a data row or put a formula in a second cell.
8. **Caps, never silent.** 100,000 rows or 25 MB (`Exports:MaxCsvRows` and `MaxCsvBytes` may lower them, never raise them): 413 `exports.too_large` with the count and "Narrow the filters", no file, no audit row. A trade list is read in pages of 1,000 into one buffer and the count is checked from the first page.
9. **Recording.** One `account_events` row `ReportExported` after the file is made and before it is given: `kind=report-groups format=csv rows=42 bytes=1234 filters=2` (a count of filter fields, never a value, a symbol or a run key), actor `owner:<e-mail of the session>`, category learning in the audit screen. If the row cannot be written, no file is given (500 `exports.audit_failed`). Log events 4940 to 4942 take the kind, format, counts, milliseconds or a code; the log methods have no parameter that could carry a value (a test reads the parameter names).
10. **Where the code lives.** The writer (`ReportCsvBody`, `ReportCsvEvidence`, `ExportCell`) is in the pure `SimExport` library; the mappers and the handler are in `XDrishti.Api.Exports` (the views are `Application` types and `Application` may not reference `SimExport`). An architecture test: that namespace touches no account, portfolio, plan, auth, live, broker, file, network or process namespace, the mapper reads only the reporting views, no column name matches `account|client|token|email|balance|holding|quantity_held|password|secret`, one module has the route (one POST, in the order above), and the body has no actor, password or file name.
11. **The Lab's report downloads join the switch (the spec's D7 is changed, by the owner's rule that nothing leaves the app unless she switches it on).** `GET /api/lab/runs/{id}/report/html` and `/report/folder` now pass through the same delivery as the CSV (`ExportDelivery`): the capability `exports` first (OFF is 403 `capabilities.off`), the session owner, the same rate slot, the gate again, one `ReportExported` audit row (kind `lab-report-html` or `lab-report-folder`, format, bytes, no content) written before the bytes are given (no row, no file). They stay GETs so that a link opens the page or saves the folder; they are the one GET that writes an audit row, because a download is a data-leaving act, and they are outside the guarded `/api/reports` prefixes. The Lab screen draws the two links only while the switch is ON and otherwise says the downloads are switched off with a link to the switches. The report JSON the screen reads (`GET .../report`) is unchanged: it is a read of the screen, not a file.
12. **The caps are an options class.** `ExportOptions` (section `Exports`, `MaxCsvRows`, `MaxCsvBytes`) is validated at start (`ValidateOnStart`): a value above the ceiling or below 1 stops the host, so the configuration can only lower the caps.
13. **Free text and the audit redactor (decided against).** The free texts of a file (limits, unavailable inputs, notes, reasons, run labels) are fixed engine sentences and ids, not owner input, and they are already cleaned for control characters, commas and quotes. `AuditRedactor` was not applied to them: its hexadecimal rule would mask the 64-hex run keys the evidence block must print, and its other rules guard secrets that cannot be in these texts. The structural proof (no account, auth or secret namespace reachable; no such column) stands in its place.
14. **The screen.** `ExportMenu` (feature `exports`, lazy with the Reports screens) draws nothing while the switch is OFF or unknown; ON, it draws "Export CSV" and the sentence "A file will be saved on this device, outside the app's protection. It contains research tables only." The bytes are saved at once through a temporary link and the address is revoked; the mutation holds only the name, is dropped when unobserved, and nothing is in the query cache or storage. Failure shows the server's sentence as text.

## Consequences
- After deploy the switch is OFF: no file can be made until the owner switches `exports` on at /owner-acts; no setting makes an export happen by itself (there is no job, e-mail, upload, webhook or clipboard).
- The existing CSV exports of the Lab change only for a cell that begins with a newly covered trigger (a golden test proves it).
- **Limit:** a saved file is outside the app: it can be copied, synced or e-mailed by the owner's own tools; the switch and the audit record that a file was made, they cannot stop that.
- **Limit:** a defused cell is text with a leading apostrophe; a spreadsheet's later re-save can change that. The tests prove what we write.
- **Limit:** the research tables reveal the owner's research edge to whoever gets the file.
- **Limit:** the rate rule is per host (one owner), in memory: it resets when the app restarts.
- **Behaviour change:** the Lab's report page and zip, ungated before, now answer 403 until `exports` is switched on.
- **Limit:** a file name carries the export date, so the same table exported on two days has two names and the same table hash.

## Alternatives considered
- **A fresh password per export (the safer default).** Rejected for the reasons in decision 4; the flow exists if the owner asks.
- **XLSX or PDF.** Rejected: a library (supply chain) and macro/format surface for little gain over CSV.
- **The evidence in a second file or a zip.** Rejected: a CSV is copied alone and the evidence is lost.
- **A GET.** Rejected: a GET must change nothing and an export writes an audit row.
- **A rate limiter policy of the middleware.** Rejected: it would answer 429 before the capability is asked, hiding an OFF switch; and it cannot count a refused export as a start.
- **Letting the audit failure stand, as in the owner moves.** Rejected: a move that was made stands, a file that was not recorded has nothing to stand on.
