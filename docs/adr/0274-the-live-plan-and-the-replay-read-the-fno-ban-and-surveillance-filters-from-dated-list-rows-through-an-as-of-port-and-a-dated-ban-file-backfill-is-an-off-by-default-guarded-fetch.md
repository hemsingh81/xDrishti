# 0274 — The live plan and the replay read the F&O-ban and surveillance filters from dated list rows through an as-of port, and a dated ban-file backfill is an off-by-default guarded fetch

- **Status:** Proposed (spec [DATA-01](../specs/DATA-01-dated-nse-ban-and-surveillance-lists.md), approved 2026-11-11 as the coordinator's recommendation). Becomes Accepted when the owner has read it and NSE's terms.
- **Date:** 2026-11-12.
- **Relation to other ADRs:** uses the list baskets of [ADR 0256](0256-list-baskets-are-dated-read-only-system-baskets-from-the-dhan-master-flags-and-two-off-by-default-nse-fo-files.md), the NSE terms gate of [ADR 0254](0254-index-baskets-are-stored-read-only-system-baskets-fed-by-an-off-by-default-guarded-fetch-of-nse-index-lists-with-forward-only-dated-membership.md), the allow-list rule of [ADR 0195](0195-the-nse-daily-history-is-an-off-by-default-fetch-behind-an-empty-owner-edited-allow-list-pattern-with-fail-closed-header-maps-and-a-daily-table-that-nothing-reads-yet.md) section 2 and the replay of [ADR 0272](0272-the-system-replay-is-research-only-fenced-from-evidence-and-hindsight-labelled-and-runs-the-live-pieces-over-as-of-facts-in-memory.md). Fixes ISS-32.

## Decision
1. **One as-of port.** `IListFlagsAsOf.ForAsync(ids, banDate, surveillanceDate)` answers, per list, whether the date is covered and who is on it. `ListFlags.OnBan` / `UnderSurveillance` return `null` (unavailable) for an uncovered list, `false` only for a covered list that does not hold the instrument. No row means unavailable, never "not banned".
2. **Coverage is exact.** Ban: a dated day row exists for the date (written by the backfill as `archive`, or by the daily fetch of the ban file for its trade date as `daily`; an empty list is a covered day; a daily file with an unmatched symbol writes none). ASM/GSM: a good master refresh (applied or unchanged fetch row) was recorded on that India date (no archive is known; forward-only); members come from the dated stays. A gap day is not covered. Days before this change have no ban row and read unavailable.
3. **The live plan** (`SelectionPlanBuilder`, through `PlanListFilter`) sets `OnFnoBan` for the plan's date and `UnderSurveillance` for the build session, only while `Selection:ListFilters:Enabled` is on (default off; off = the plan and its hash are unchanged). A failing read is unavailable for everyone. The `fno_ban` and `surveillance` lines of "not applied" are dropped only when every candidate got an answer.
4. **The replay** passes the same filter to the same builder. Its `filters_without_history` label is kept for a session unless both lists are covered for it; a covered session requires the ban and surveillance filters (the event filter stays optional, labelled `event_filter_without_history`); an uncovered session keeps all three optional and a note names its date. The run label is the union over the sessions, so it clears only when every session is covered. The read side drops the parameter label only when stored sessions exist and none carries it (the run list, which reads no sessions, still shows it: it over-states, never hides).
5. **Dated backfill, ban list only.** `xd data lists-probe --dates` (at most 5 files, stores nothing) and `xd data lists-backfill --from --to [--dry-run]` fetch `fo_secban_DDMMYYYY.csv` from `nsearchives.nseindia.com` behind `Data:History:Lists:Enabled` (default off, zero requests) through the history client and the allow-list guard. The path is UNVERIFIED until the probe has run. A file is parsed fail-closed (`BanListParser`), must carry the requested date, and every symbol must match the catalogue, else the day is rejected and nothing is stored. A valid empty file stores a covered empty day. `MaxPerDay` and the CF-04 delay apply; weekends are skipped; a 404 is "no file"; the first failed request (403, 429, timeout) stops the run and says so.
6. **Insert-only storage, a deviation from "no new table".** The membership stays of `basket_members` are closed by UPDATE and cannot say "covered, empty", so migration `AddListDays` adds `market.list_day_coverage` and `market.list_day_members` (SELECT and INSERT only for `xd_app`; `source` = `archive`). Down drops both.

## Owner acts
Read NSE's terms; add `nsearchives.nseindia.com` with `^/archives/fo/sec_ban/fo_secban_[0-9]{8}\.csv$` to `MasterDataEndpoints.Patterns` (the app never edits it); run `xd data lists-probe`; then set `Data:History:Lists:Enabled`, run the backfill, and compare one nightly plan in a dry run (`xd plan run --dry-run`) before setting `Selection:ListFilters:Enabled`.

## Consequences
- Turning the live wiring on changes which candidates are held: until the ban and ASM/GSM lists are covered for the plan's dates, required filters hold every candidate (as before).
- The forward ASM/GSM list is covered only through the last master check, so a plan for a date after it reads unavailable for surveillance.
- Nothing places an order and no rule is loosened.
