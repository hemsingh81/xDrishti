# 0044 — The cost choice, the stored charge sheet, the `cost-sheet` verbs and the bill check

- **Status:** Accepted (owner, 2026-10-18: "yes to all recommendations" on [P3-03f](../specs/P3-03f-the-cost-choice-the-stored-charge-sheet-the-verbs-and-the-bill-check.md), the split from P3-03c, the recommended answers to its open questions and its size; the decisions the spec took on research when it was drafted — a required, closed `CostChoice`, the widening of the settings value to 8,000 characters rather than a row per schedule, the actor `cli:cost-sheet` and no audit event, a check that reads the original report files, the 64 KB cap and a check that never writes `checked` — are the owner's to revert). **The exit check of the slice is not met and is not claimed:** it needs the owner's own charge sheet and bills (plan question Q3, ISS-25), which have not been supplied. Everything below is built and tested against invented sheets.
- **Relation to other ADRs:** completes [ADR 0042](0042-costs-and-sizing-the-charge-sheet-the-quantity-net-r-and-simtrade-schema-4.md) (the sheet, the model, the sizing and the record; that ADR said the request, the store, the verbs and the check are this slice's), amends [ADR 0037](0037-simulation-conventions-and-the-two-stage-seam.md) (Amendment 8: the order of operations of the run), builds on [ADR 0041](0041-the-simulate-verb-the-export-library-and-the-pipeline-in-the-host.md) (the dispatcher, the generic host and the exit codes the second verb shares), [ADR 0039](0039-an-engine-module-is-reached-from-an-adapter-in-infrastructure-never-from-application.md) (a port for the store, an adapter in Infrastructure), [ADR 0029](0029-dhan-report-imports-and-source-precedence.md) (the global transaction report and its reader) and [ADR 0022](0022-action-center-and-price-alerts.md) (the `platform.app_settings` pattern), and carries out [ADR 0002](0002-config-and-strategies-in-app.md) for the charge sheet (configuration lives in the database).
- **Date:** 2026-10-19 (built the same day; migration `WidenAppSettingValue`, no API change).

## In short
- **A request names its cost choice in its type.** `SimulationRequest.Costs` is a required `CostChoice`: `Gross` (explicit, labelled `costs: none`) or `Sheet(id, capital, profile, maxCostR)`. A request cannot leave it out, a gross choice carries no capital, and a forgotten call site is a compile error. A bad choice is `simulation.invalid` with one field error per field (`costs`, `costs.sheet_id`, `costs.capital`, `costs.profile`, `costs.max_cost_r`), one code.
- **The sheet is one row of `platform.app_settings`**, key `research.cost_sheet.<id>`, value the canonical JSON; a new set of rates is a new id; `cost-sheet load --replace` overwrites an id. Every run embeds the canonical text (without `checked`) and the rates hash, so an overwritten row never changes an old record.
- **Three one-shot verbs** on the dispatcher and the generic host of ADR 0041: `cost-sheet load|show|check`, run on the host by `scripts/cost-sheet.sh`.
- **The bill check reads the owner's original report files**, line by line, classifies each row without guessing, compares it with the model, and prints classes, counts, differences and the rates the bills imply as a proposal. It writes nothing and prints no identifier.
- **A sheet that is unknown or begins after the window refuses the run before any bar is read.**

## Decisions
1. **D1 — `CostChoice`.** An abstract record with a private constructor and two sealed nested cases, `GrossChoice` and `SheetChoice`, built only by `CostChoice.Gross` and `CostChoice.Sheet(...)`. Defaults: capital 10,00,000 and profile `standard` (plan question Q4, taken 2026-10-18, the owner may revert), `max_cost_R` 0.10 (`selection.max_cost_R` of doc 16). `SimulationRequest` takes `Costs` after `BasketId` and before the defaulted members. Validation: `costs` null is `costs: required`; the id must match the pattern of `CostSheet` (made a public static `CostSheet.IsValidId`); the capital is in (0, 10,000,000,000]; the profile is `standard` or `conservative`; `max_cost_r` is in (0, 100]. Numbers are written so that NaN fails them.
2. **D2 — the order of the handler.** Validate (the choice included), build the fill rules, `Prepare`, **then** the sheet (one `ICostSheetStore.FindAsync`, only for a sheet choice), then every other port. Absent is `simulation.cost_sheet_not_found` (not found); an id that starts with `test-` is not found and the store is not asked; a first schedule after `From` is `simulation.cost_sheet_not_effective` (validation, field `costs.sheet_id`: the owner vouches for no date before it, so the window is refused, never extrapolated); a stored text that no longer parses passes its own code `costs.sheet_invalid` through. The same `CostContext` instance reaches every `Replay` and the `CostRecord` reaches the header. The start log line gains the sheet id or `gross`, no number.
3. **D3 — the store.** `ICostSheetStore` (`FindAsync`, `SaveAsync`) in `Application/Abstractions/Research`; `CostSheetStore` internal sealed in `Infrastructure/Research` over `AppSetting`; a read is a projection without tracking, a write is only collected and the caller saves it through `IPlatformUnitOfWork.TrySaveAsync`. A `test-` id is neither stored (`SaveAsync` throws: a caller error) nor found, even if a row was written by hand; a row whose text names another sheet than its key is `costs.sheet_invalid`.
4. **D4 — the migration `WidenAppSettingValue`.** `platform.app_settings.value` from `varchar(500)` to `varchar(8000)`; `AppSetting.MaxValueLength` is 8,000. A sheet of two segments and one schedule is about 600 characters, so the column had to grow; a sheet of the 12 allowed schedules fits the canonical limit of 8,000 of ADR 0042. Widening cannot lose data; the module that owns a key still checks its own values; the other keys are short and unchanged. Not chosen: one row per effective-dated schedule (several rows to keep consistent, and the hash and the label would be of a recomposition). The runtime role needs no new grant: the table is the one it already reads, inserts and updates. The migration is metadata-only on this small table; its `Down` fails loudly (SQL state 22001) once any stored sheet exceeds 500 characters, so it is not reversible once a sheet is stored.
5. **D5 — the verbs.** `VerbDispatch` selects `cost-sheet` only when it is the first argument and `Program.cs` tests it before `--healthcheck`, `migrate` and `owner-reset` (which match anywhere), so `cost-sheet load migrate` or a file named `owner-reset` selects nothing else. The host is the generic host of the `simulate` verb (no arguments bound to configuration, no `AddApi`, no vault key, validated on build, not started, logs on stderr), with its service name a parameter. `load <file> [--replace]`: a file is read through a bounded reader (a path that is not a regular non-empty file, such as a FIFO or `/dev/zero`, is refused unopened; a read stops one byte past the cap, so a file that grows is refused too), and a file over 64 KB is refused before it is read; `check` reads at most 10 report files and 50 MB together; the text goes to `CostSheetJson.Parse`; a `test-` id is refused; other rates under an existing id need `--replace` (the refusal names both hashes); the same rates with another label, source or `checked` update the description without it; an equal sheet is `unchanged` and writes nothing. The actor written to `UpdatedBy` is `cli:cost-sheet`. **No audit event is written**: `AuditEventType` is the authentication trail and has no member for a settings write; the trail of a load is the row's author and time and the log line. `show` prints the canonical JSON, the rates hash and the label. Exit codes as ADR 0041: 0, 1 refused, 2 usage, 3 failure or a concurrent write, 130 cancelled. Three `[LoggerMessage]` lines (ids 4412 to 4414) carry the id, the hash and counts, never a rate. `scripts/cost-sheet.sh` makes every argument that is an existing file absolute before it changes directory.
6. **D6 — the bill check.** `GtrRow` gains a last member `Lines` (the seven cells by column, a blank cell 0); `Charges` stays the rounded sum, so the importer is unchanged (a test compares its plan with and without the cells). Classification, never guessed: a row with a buy and a sell quantity is intraday equity (two legs); a one-sided NSE row whose brokerage cell is 0, while the sheet's delivery brokerage is 0, is delivery; a futures, options, commodity, currency or BSE row is skipped with its reason; anything else (a date before the first schedule, another exchange, a one-sided row with brokerage) is listed with its date and reason and not compared. A row with a negative Oth. cell is an adjustment line: counted with its sum and left out of the pass count. Comparison: `CostModel.Leg` per leg (the DP charge is not on this report), compared line by line and in total over the six lines (plus Oth. when the sheet's `other_pct` is above 0); a row passes when the total differs by at most 0.05 rupee. Output: classes with rows, passed, beyond and the largest differences; the ten largest differences as date, class and difference; the adjustments; the implied rates (minimum, median and maximum of `line / value` over the rows where the line is above 0, with the row count: a percent of the turnover, STT on the sell value of an intraday row, stamp duty on the buy value, SEBI per crore, GST on the brokerage, SEBI and transaction cells) as a proposal only; a suggested `checked` string when every compared row passes. **The check never writes**: not the stored transactions, not the sheet, not `checked`. It prints no bill number, scrip name, client code, quantity or value.
7. **D7 — the simulate verb's flags.** Exactly one of `--gross` and `--costs <id>`; `--capital`, `--profile` and `--max-cost-r` need `--costs`; neither or both, an orphan flag or a value out of range is a usage error (exit 2). The summary gains a `costs:` line (the label, the rates hash, the capital, the profile and `max_cost_R`, no rate). The export needed no change: the run record already carries the cost record and `trades.csv`, `run.json`, the labels and the banner already print it.

## Decided in the build
- **`CostChoice` cases have internal constructors**, not private: the abstract base's constructor is private, so nothing outside the type can derive from it, and `CostChoice.Sheet`/`Gross` are the only public ways to build a case. A reflection test checks that neither case has a public constructor.
- **The namespace of the verb is `XDrishti.Api.CostSheets`** (the folder is `CostSheet`): a namespace named `CostSheet` would hide the Domain type of that name in every file under `XDrishti.Api`.
- **`SimulateHost.Create` takes the service name** (default `xd-simulate`), so the second verb shares the host instead of copying it.
- **Two existing architecture rules were narrowed to make room for the store**, nothing else: the list of ports in `XDrishti.Application.Abstractions.Research` has a third member, and the "adapter does no I/O" rule of the engine adapter's namespace now excludes `CostSheetStore`, which is a database adapter by design (pinned by `CostSheetArchitectureTests`, with a sentinel that the scan does see its use of the context).
- **The check's classes are two** (intraday and delivery equity); a mixed row (a partial square-off the same day) shows as a large difference, not a hidden one.

## Consequences
- **Tests.** `scripts/check.sh` green on 2026-10-19: 22,804 backend tests (22,776 passed, 28 skipped by design, none failed) and 3,415 frontend tests. New: the handler and the request choice (26, `RunSimulationCostsTests`), the reader extension (5), the check on hand-calculated figures (13), `load` and `show` at the handler (11), the store, the verbs, the check through the verb and the migration against a real TimescaleDB (18 + 7 + 2), the dispatcher, host, parsers and script (57), the architecture rules with sentinels (8) and the domain additions (2). The hand figures of the check (a delivery buy of 10,000.00, a sell of 20,000.00 and an intraday round trip of 10,000.00 and 10,500.00 on the invented sheet) were calculated line by line before the code was compared with them; the run end to end is compared with W7 and W8 of ADR 0042, not with a golden file.
- **What is not done.** The owner's sheet and bills. Until then the roadmap exit check of P3-03c stays open, every real run is `--gross` and says `costs: none`, and the cost property of P3-08 and the net figures of P3-09 wait. The invented sheet `fixture-a` (the numbers of the TEST sheet under an id that is not `test-`) lives in `tests/Shared` and was never stored in the owner's database; no rate is written in `src/`, in a seed or in a script.
- **Handed on.** The exit check (criterion 14 of the spec, with the list the owner supplies in F6); the audit trail of a load, if the owner wants one (a later slice with its own enum member); reading the sizing profiles from `accounts.risk_profiles` instead of the two code defaults.
- **Limits that stay.** A sheet cannot hold a flat fee per order, a brokerage without a cap, or a DP charge that varies per ISIN and day (limits `no_flat_order_fees`, `dp_charge_is_flat`); the check cannot check a class that has no rows or a rate that was never billed.

## Alternatives considered
- **An optional `Costs` member with a runtime refusal.** A forgotten call site would compile and run gross by omission.
- **A row per schedule.** No migration, but several rows to keep consistent.
- **Comparing the stored transactions instead of the report files.** A stored transaction has one charge total, no bill number and no product, a two-sided bill is two trades with the charges split by value, and negative Oth. lines would make a flat tolerance on totals misleading.
- **An audit event for a load.** Needs a new member of the authentication trail's enum, an account-context change out of scope.
- **Writing `checked` from the check.** A command that judges its own result and writes it into the configuration; the owner puts the string into the sheet and loads it.
