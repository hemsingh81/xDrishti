# 0266 — Dated members are an opt-in basis of a basket run, a tier observation is proposed as a scope hypothesis and never applied, and the universe lens tags trades at read time

- **Status:** Proposed (spec [BK-11b](../specs/BK-11b-universe-dated-basis-proposer-hook-and-tier-pivot.md), approved 2026-11-11). Becomes Accepted when the owner has read it.
- **Date:** 2026-11-11.
- **Relation to other ADRs:** amends [ADR 0261](0261-the-liquidity-tier-is-the-one-universe-part-of-a-cell-key-tagged-from-bars-before-the-decision-date-and-a-tier-cell-is-only-ever-an-observation.md) points 10 to 12 (the labels, the trials and the reports lens it deferred to BK-11b); follows [ADR 0263](0263-relative-strength-features-are-stored-rows-of-the-previous-closed-session-with-a-closed-parameter-set.md) (a structured record and a run-key line only for a run that uses it); [ADR 0207](0207-a-strategy-version-is-pre-registered-the-ledger-counts-every-extra-look-and-a-locked-hold-out-is-fixed-at-the-first-post-and-read-once-by-an-owner-unlock-with-enforcement-and-the-honest-count-as-the-owners-switches.md) (a new universe is a re-plan row); [ADR 0076](0076-the-hypothesis-loop-one-knob-checked-on-stored-runs-a-state-table-and-nothing-applied.md) (the hypothesis loop); [ADR 0243](0243-simulate-everything-is-training-data-fenced-from-the-hold-out-and-from-scorecard-evidence.md) and [ADR 0250](0250-training-simulation-reports-extend-the-report-engine-read-only-finished-chunks-as-of-an-instant-cut-before-the-hold-out-and-labelled-not-evidence.md) (training runs are never evidence and never tagged).

## Context
BK-11 built the tier cells, the read of a tier against its all-shares parent and the settings, and deferred three things: the simulator replays a basket's members of one date (single snapshot, survivorship applies); a stable tier observation can only be noticed, not turned into a hypothesis; and the report engine refuses the `universe` dimension. The owner approved all three as one follow-up with the safety rule unchanged: a universe restriction stays a proposal.

## Decision
1. **Dated members are opt-in.** `SimulationRequest.MembersBasis` is null (every existing caller: the key, the record and every SimExport golden are byte for byte what they were), `single_snapshot` or `dated`. `dated` is refused for a list of instruments (`simulation.invalid`) and on a basket whose stored stays have fewer than two days of change or whose first day is after the window start (422 `simulation.members_not_dated`, naming the first dated day and saying the owner can rerun with `single_snapshot`). No run is ever labelled dated with today's members.
2. **The replay.** `IBasketQueries.StaysAsync` reads every stay of the basket once; `DatedMembers` (pure, in Domain) answers "a member at the end of day D" with the rule of the members read (added before the end of D, not removed before it). The simulator walks each instrument as before and the walker refuses an entry on a day that is not a member day (`NoTradeReason.NotMember`, a fate and a walker counter `not_member`, written to the record only when above zero, like `tier_excluded`). A position already open is closed by the normal exit rules, never force-closed by leaving; a leaver keeps no new entries (owner question 2 keeps the spec's default answer). The instruments of the run are those that are a member on some day of the window.
3. **Structured fields and the key line.** A run that names a basis stores `SimulationRun.UniverseBasis = {universe_basket_id, universe_params_hash, members_as_of, universe_basis, member_days_hash}` (null, and left out of the record text, otherwise) and adds one key line `umembers = basis | member_days_hash (dated) or members_as_of (single_snapshot) | params hash`. `member_days_hash` is the SHA-256 of the stays clipped to the window and ordered by (instrument, first day, last day): an equivalent, smaller encoding of the ordered (day, instrument) pairs. `members_as_of` of a snapshot is the India date of the run (the members are those of that day), so the key of a snapshot run changes from day to day, honestly. The parameter hash of a derived basket is that of the version in force at the window start. The label of a dated run is `members as of each day (dated); basket <id>; params <hash or ->`; the labels of a run say "point in time (dated members)" only for `dated` and "single snapshot, survivorship applies" for `single_snapshot`; the default label is unchanged.
4. **Trials.** A different basis is a different universe label, so a different plan hash and a re-plan row as ADR 0207 counts it. The universe trial count (`UniverseTrials`) counts distinct (basket, basis) pairs; a repeat counts once.
5. **A tier observation becomes one proposed hypothesis, by an act, and nothing is applied.** `ProposeFromUniverseLinkHandler` (the owner: `xd learn hypothesis propose --from-universe-link`, or `POST /api/cells/universe-links/{key}/propose` as a P8-19 owner act with a fresh password, the `learning_moves_ui` capability and one `HypothesisProposed` account event) proposes only when the stored link is an observation (tier read in place of the parent, at least `learning.universe_link_min_trades` trades, a stable hold-out); otherwise 422 `learning.not_an_observation` with the reason. The hypothesis has source `universe`, cell the `*` parent, knob `scan_scope` of the new kind `Scope`, baseline `*`, candidate the tier, the rationale built from the stored numbers, state `proposed`; the open limit applies; a second open proposal of the same (cell, tier) is 409 `learning.hypothesis_exists`. The migration `AddUniverseBasisAndScopeKnob` widens the check of `research.hypotheses` (source `universe`, kind `Scope`) and the key check of `research.universe_settings_changes`; no column is added (the basis lives in the run record, as `relative_strength` does).
6. **A scope hypothesis cannot run.** Starting it (`StartHypothesisHandler`) or judging it as an experiment (`RunExperimentHandler`) is refused 422 `learning.knob_not_runnable` ("a scope experiment is not built"). Accepting it records a verdict only. No file of the slice reaches a strategy store, a cell-state writer, the selection or a plan (an architecture test).
7. **The auto option, default OFF.** `learning.universe_link.auto_propose` is a stored Advanced owner setting (safer direction none, not learnable), changed only through `PUT /api/universe/settings` with a fresh password; no row is OFF. When ON, `xd learn cells --by-universe` proposes each observation that has no hypothesis yet, as the actor `auto` (never an owner), with the setting change id and hash in the rationale; the open limit applies; a tier with an insufficient or unavailable hold-out is never an observation, so is never proposed.
8. **The universe lens.** `ReportTrade.Tier` is attached in memory at read time (never stored), only when the lens asks for it, by the same `UniverseTagger` and the same decision date (`sim_trades.trade_date`, the field the cell statistics call `TradeDate`) as the cell statistics, from sessions strictly before that date, so a trade's report tier equals its cell tier and a later bar changes no tier. Buckets: `liq_high`, `liq_mid`, `liq_low`, `unknown`, `unavailable`; the server masks under 30 trades as in every P8 lens. With no tier source, or no date with the minimum of eligible shares, no trade carries a tier and the dimension is refused 422 `reports.dimension_unavailable`, "no liquidity tier for these trades"; a training simulation report refuses it with that reason and reads no tier; `regime` and `account` keep their refusals.

## Owner questions (recorded, defaults kept)
- ADR 0261 Q1 (terciles or the CF-05 A/B/C tiers) stays open; this slice uses whatever `UniverseTagger` returns.
- A leaver's open position is kept to its normal exit (point 2); the alternative is a forced exit at the next open.
- The web propose act exists beside the command line, behind the password and the capability; the screens are the Lab "Members" picker, a Setups list of tier links and the owner-act form `/owner-acts/universe/<tier cell key>`.

## Consequences
- A dated run is the first run that is honest about membership over time, but only as good as the stored history: a stored system basket has stays only from its first fetch, so `dated` refuses a window that starts before it.
- The Lab offers the basis too: `POST /api/lab/runs` takes `universe.membersBasis` (`dated` for a full or robust test only, because the quick test samples the members of one day; refused 422 `simulation.members_not_dated` as the simulate command is). A dated Lab run stores `membersBasis` in its universe, takes the instruments that are a member on some day of the window, carries the dated label (so its plan hash and key differ from the snapshot test and the ledger counts a re-plan), and every request it makes (the full test, the sweeps, the hold-out pass, the chance block) names the basket and the basis, never the list. The structured fields are in the run record and its export, and `membersBasis` is on the Lab run's universe.
- The controls follow the run. The random-entry walk draws only on the date of a real trade, which was a member day, so its member filter never blocks a draw (stated, tested); a placebo on a session where the instrument was not a member is no trade, as a dated run would take none there; the trade-card recomputation carries the run's membership (`ExplainBasis.Members`) and refuses the same entries.
- The `members_as_of` of a `single_snapshot` run is the run date, as the spec states (criteria 4 and 5: the run date for `single_snapshot`, the date in the key line), so the key of such a run changes from one day to the next. That is the spec's choice and is kept: the members of a snapshot are those of that day, and a repeat on another day is another look. A caller that wants a stable key names no basis (the key is then what it always was) or names `dated`.
- The not-member fate adds a counter to the engine's pinned shapes (`RunFates`, `WalkCounters`, the oracle's counters); it is zero, and not written, for every run that does not use dated members.
- Down of the migration keeps every row (the narrower setting-key check is added NOT VALID); it fails while a hypothesis of source `universe` or kind `Scope` exists, because hypotheses are never deleted.
