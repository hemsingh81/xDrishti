# 0292 — Features that wait on the owner are removed: the market context, the charge sheet and the pre-registered hold-out replay

- **Status:** Accepted (owner, 2026-11-14, in chat: "Drop every owner-input feature"; Q1 both automatic, Q2 gross forever, Q3 SR-03 removed). Spec: [DROP-OWNER-INPUTS](../specs/DROP-OWNER-INPUTS-features-that-wait-on-the-owner-are-removed.md).
- **Date:** 2026-11-14.
- **Relation to other ADRs:** Supersedes [0290](0290-the-context-inbox-loads-nifty-50-and-india-vix-daily-history-from-owner-dropped-nse-csvs.md) (the context inbox). Same style as [0288](0288-p13-tick-and-depth-features-are-dropped-the-depth-and-tick-recorders-are-removed-and-the-feature-set-comparison-stays.md) and [0289](0289-basis-carry-family-is-dropped-from-p14.md).

- **Build state (2026-11-14):** decisions 1 to 4 (the market context and its inbox) are built; decisions 5 and 6 (the charge sheet and SR-03) are decided and still to be built, see the roadmap.

## Context
The owner has given all the history he has (1m bars of 313 instruments, 2024-04-01 to 2026-11-13). Several features can only work with more owner input: the NIFTY 50 / INDIA VIX daily context needs a live Dhan probe or dropped CSV files; the charge sheet needs the owner to mark it `checked` against a contract note; the pre-registered hold-out replay (SR-03) needs that `checked` sheet. `market.context_daily` held **0 rows**, so every context feature already read "not ready" (a false condition): removing it changes no result produced so far.

## Decision
1. **Market context removed (R1, R2).** The table `market.context_daily` and the CSV side table `market.context_vix_csv` are dropped by the new migration `DropMarketContext` (the down step is a note: not reversible). Removed with them: the context data job and its upkeep step, the CSV inbox (ADR 0290: loader, setting `Data:Context:*`, folder, log events, `scripts/context.sh`, the `context` verb), `IContextFigures`, `ContextOptions`, the ten context features in the indicator library (`index_trend`, `index_adx`, `index_vol_pct`, `vix`, `vix_pct`, `vix_chg`, `breadth`, `regime_trend`, `regime_vol`, `regime`; the catalog has 54 names), the `index.trend` / `index.adx` spellings and the `regime()` builtin of the strategy language, the stored tracked-set breadth (it lived in `context_daily`), the regime labels and everything built on them (regime cells and their API `GET /api/cells/regimes`, the `--by-regime` flag of `xd learn cells`, the regime split of the Lab robustness block, the regime panel of the basket profile, `GET /api/data/context`, `GET /api/data/regimes`), the `data_context_stale` and `data_context_gap` notices, the evidence-preflight context item, and the replay and plan gate inputs that read the VIX and the tracked-set breadth (the gate now reads only the breadth of the owner's chosen basket, BK-08).
2. **Kept.** Weekly and monthly timeframes and the calendar features (P3-01c), the basket context (BK-06, `market.basket_context_daily`) and the shared breadth kernel (`BreadthCalculator`), the feature-set comparison core, the relative-strength features (BK-09), whose benchmark (the tracked Nifty 50 index bars) is now found by a small port `IBenchmarkIndex` instead of the context bar source. `RunHeader.ContextSha256`, `SkipReason.ContextUnavailable`, the eight retired context slots of trade-feature catalog `tf-1` (always unknown, so stored rows and trained models keep their shape) and the mirror table (`mirror-1`, so the run key of a mirrored SELL does not change) are kept as stored-data shapes.
3. **A strategy that names a removed context feature** now fails `POST /api/lab/validate` as an unknown name (422) with the name quoted; none of the seed strategies names one.
4. **Hold-out block 1 look and the eval baseline re-accept (Q1)** are decisions, not data: they stay, and become automatic under the ADR 0282 rule (the look is taken by the future SR-04 simulation; the eval baseline is re-accepted automatically only when no threshold regresses, recorded as auto with the setting snapshot). They are removed from the owner to-do lists.
5. **Costs are gross forever (Q2, option b).** The charge sheet (stored sheet, checked state, P8-23 writer, CLI verbs, settings screen), `CostChoice` and the net path, net R, the bill check and every net figure are removed, with their tables by a second new migration. Every run, report and replay labels its cost basis as gross; no screen or verb asks the owner to check a sheet.
6. **SR-03 (the pre-registered hold-out replay) is removed (Q3)**: code, its tables by migration, the UI card.

## Consequences
- Two new migrations (the context tables; the charge-sheet and SR-03 tables). The API contract and the generated client change (endpoints and fields removed).
- The golden run of the P3 pack and a SR-01 replay give the same result hash as before: a strategy that does not read a context feature never carried the context in its run key.
- Revisit only with a new spec if an index/VIX source is ever supplied or a cost model is wanted again.
