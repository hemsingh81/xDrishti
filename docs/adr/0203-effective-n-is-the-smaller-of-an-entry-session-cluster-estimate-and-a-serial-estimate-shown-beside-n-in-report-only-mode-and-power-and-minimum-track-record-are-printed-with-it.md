# 0203 — Effective n is the smaller of an entry-session cluster estimate and a serial estimate, shown beside n in ReportOnly mode, and power and minimum track record are printed with it

- **Status:** Proposed (built in CF-01 from the owner-Approved spec, 2026-11-03). Becomes Accepted when the owner has read it. **Safety slice: no** (no network, no order, no stored verdict changes; the default mode decides nothing).
- **Date:** 2026-11-04.
- **Relation to other ADRs:** extends [0064](0064-cell-statistics-bayesian-shrinkage-recency-weights-and-point-in-time-snapshots.md) (cell statistics; its "credible interval treats trades as independent" limit is stated, not changed here) and [0059](0059-the-test-ledger-and-the-verdict-evaluator.md) (the verdict and the gates); keeps the cash-only guard of [0193](0193-the-cell-key-gains-a-reserved-universe-part-and-an-expression-part-written-with-the-fewest-trailing-parts-so-every-stored-key-stays-byte-identical-and-only-cash-cells-reach-a-decision.md) (the new columns are read with the same rows, so the cash-key filter is untouched).

## Context
A cell with "34 trades" reads as 34 independent facts, but trades entered on the same session share one market move, and consecutive sessions are correlated. The programme rule (CF-00) is: show a new figure beside the old, change nothing by default, say `unavailable: <reason>` rather than invent a number.

## Decision
1. **Pure Domain.** `Domain/Confidence/`: `NormalDistribution` (cdf and quantile, accurate to 1e-7; tests 1.6449, 0.8416, 1.95996; CF-02 and CF-03 reuse it), `EffectiveSampleSize`, `PowerAnalysis`, `MinTrackRecord`, `DependenceEstimator` (builds the `DependenceAssessment` of a set of trades), `ConfidenceOptions`, `ConfidenceMode`.
2. **Effective n is the smaller of two estimates in trade units, never above N and never below 1.** Cluster: one-way ANOVA intra-cluster correlation clipped to 0..1, Kish `DE = 1 + (m_bar - 1) rho`, `n_eff = N / DE`; the cluster is the India **entry** session date. Serial: `N (1 - r1) / (1 + r1)`, `r1` the lag-1 autocorrelation of the date-ordered daily mean R (sessions without a trade omitted), needs 20 sessions, `r1 <= 0` gives N. Not multiplied (they describe partly the same dependence).
3. **Refusals instead of numbers.** Fewer trades than 5: nothing (`unavailable: n < 5`). Cluster estimate: fewer than 5 sessions, or one trade per session, is unavailable (N is not claimed); **one** session is the exception and reads 1 (all trades on one day are one observation, the conservative reading and the spec's AC 3). Both unavailable: effective n is `unavailable` and N is shown alone. Not finite R: unavailable. A row whose trades do not carry their entry date (an older caller built `CellTrade` with four arguments) reads `unavailable: entry dates not carried`: a cluster per exit date is not the entry cluster.
4. **Power** with sigma = max(sample SD, 0.5 R), alpha 0.05 one-sided, power 0.80, target edge 0.15 R (the gate's minimum expectancy when the setting is unset; in the verdict the gate's own value): trades needed `ceil(((z_a + z_b) sigma / delta)^2)` in effective trades (a lower bound: R is not normal), smallest visible edge `(z_a + z_b) sigma / sqrt(n_eff)`, years to evidence `needed / (n_eff / span years)` printed with "if the rate and the edge hold".
5. **MinTRL** is Bailey and Lopez de Prado in per-trade units with a one-sided 95 % confidence, SR* = 0, skew and kurtosis from the window at 20 trades or more, else normal (flagged "normal assumed"); it is an **iid** count, and `minTrlDependent = ceil(minTrl x DE)` is printed beside it. No edge (SR <= SR*) is `unavailable: no edge to detect`.
6. **Three modes, `Confidence:EffectiveN:Mode`, default `ReportOnly`.** `Off`: nothing computed. `ReportOnly`: shown on every cell row (`IndependentN`, `dependence`, eight stored columns) and in the Lab verdict (`evidence.dependence`); `Enough`, the outcome, the six gates and their reasons are exactly as before. `Gate` (the owner's switch, a deploy-time configuration change recorded in the snapshot key and in each stored row's `n_eff_mode`): the cell `Enough` flag and gate 1 compare `ceil(n_eff)`; an unavailable n_eff is not a pass.
7. **The verdict note is a note, not a limit.** The spec says the verdict "adds a limit line". A `Verdict.Limits` entry caps a PASS at MARGINAL, which would change a stored outcome; so the line goes into a new `Verdict.Notes` (and is appended to the served `limits` text of the Lab view after the outcome is decided). Worked: gate 30, 16 variants, 34 trades, n_eff 11: `ReportOnly` reads 34 vs 60 (missed, not hard) with the note "effective 11 of 60 needed"; `Gate` reads 11 vs 60, a hard miss.
8. **Data.** Migration `AddCellStatsDependence`: nullable columns on `research.cell_stats` (`n_eff`, `design_effect`, `n_eff_method` with a check in `cluster, serial, none`, `needed_trades`, `min_detectable_edge_r`, `min_trl`, `enough_by_n_eff`) plus four beyond the spec: `span_years` (years-to-evidence needs the span), `target_edge_r` (the edge the needed trades are about), `n_eff_mode` and `n_eff_note` (a stored row says its mode and why a figure is unavailable). The table stays insert-only for `xd_app` (no grant changed). The snapshot key gains `|confidence=<settings>` only when the mode is not `Off`, so a key computed without it is unchanged and a changed setting is a new snapshot. A row written before the migration reads "not computed" (null `dependence`). No migration for `lab.lab_results` (jsonb; the member is optional).
9. **Settings** are the configuration section `Confidence` (the existing settings mechanism: the host binds the section, `ValidateOnStart` refuses an out-of-range value); there is no stored, versioned settings editor yet, so "owner-tunable" means a configuration change.
10. **Where it is not used.** `PointInTimeCells`, `WhatWorksBuilder`, `MetaPolicyEvaluator` and every other `CellStatsCalculator` caller pass no options: byte-identical rows.

## Deviations from the spec, deliberately
- The spec's property test "adding an independent trade never lowers n_eff by more than 1" is **false** for the ANOVA estimator: on iid noise the intra-cluster correlation estimate moves a lot with one more trade (a drop of about 6 on 40 trades was seen in the seeded sets). The test asserts the bounds (1 <= n_eff <= N) instead and the noise is stated in the notes ("fewer than 20 trades: the correlation estimates are noisy").
- Four extra columns (decision 8) and `Verdict.Notes` instead of a limit (decision 7).
- Valid ranges of `MinTrl:Confidence` (0.5..0.999) and `MinTrl:BenchmarkSr` (-1..1) are technical bounds of the formula, not thresholds the spec gave.

- **EnoughByNEff in the Lab block** is judged in `VerdictEvaluator` against the adjusted minimum of gate 1 (30 x factor), not the configured 30; `Verdict.Dependence` carries it and the served block is taken from there. The Lab block also records the settings text that produced it.
- **Regression fixture (shortcut).** The spec asks for a checked-in real P5-04 `lab_results` document and P6-01 snapshot re-evaluated in Off, ReportOnly and Gate. No real stored document is available to check in, so the tests use a hand-written old-format JSON document (`LabVerdictDependenceJsonTests`), stored-evidence numbers re-evaluated in Off and ReportOnly (`VerdictEffectiveNTests`) and a legacy cell row simulated by nulling the new columns (integration). Replace with real exports when the owner supplies them.
- `NormalDistribution` uses a series and continued-fraction erfc (about 1e-13) with one Newton step, so tails stay accurate for CF-03.

## Open questions for the owner
1. Confirm the three modes and the `ReportOnly` default (spec question 1).
2. Power target alpha 0.05 one-sided, power 80 %, target edge the 0.15 R gate (spec question 2); 0.20 R is the alternative.
3. May `Gate` later replace n by n_eff in gate 1 only, or also in the evidence label (spec question 3). Not decided here: the evidence-label thresholds on n_eff (30, 60, 150; spec question 4) are **not built**, and no label changed.
4. The ReportOnly count of cells that would flip to "not enough" is visible as `enoughByNEff = false` beside `enough = true` on the rows; a counting verb was not added.

## Consequences
- API: `GET /api/cells`, `GET /api/cells/{key}` rows gain `independentN` and `dependence`; `GET /api/lab/runs/{id}` `verdict.evidence` gains `dependence`. All optional; contract regenerated.
- Screens: the numbers are in the API with a `summary` line ("n=34, effective 11; needs about 396 to see 0.15 R; smallest visible now 0.51 R"). The Learning cell table and the Lab report limits show the limits list already; a dedicated Learning column was not added (the eager bundle has 1.1 KB of its 200 KB budget left).
- Honest limits printed with the figures: n_eff is an estimate from the same thin sample; same-session and serial dependence only, not a regime across weeks; the entry-session cluster is coarse; power assumes roughly normal R (the needed number is a lower bound); a power statement says nothing about whether an edge exists.
