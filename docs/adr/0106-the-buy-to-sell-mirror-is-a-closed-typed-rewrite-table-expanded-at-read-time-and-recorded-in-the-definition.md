# 0106 — The BUY to SELL mirror is a closed, typed rewrite table, expanded at read time and recorded in the definition

- **Status:** Proposed (spec [P3-02e](../specs/P3-02e-buy-to-sell-mirror.md), built 2026-10-25). Becomes Accepted when the owner has read it.
- **Date:** 2026-10-25.
- **Relation to other ADRs:** [0034](0034-the-rules-expression-language-lint-and-compiler.md) (the language, Amendment 8 lags), [0035](0035-per-session-features-keep-the-history-of-the-session-only.md) (per-session features), [0036](0036-the-typed-strategy-model-and-the-compile-of-its-sections.md) (the model), [0037](0037-simulation-conventions-and-the-two-stage-seam.md) and [0047](0047-the-oracle-and-the-rule-table-gaps.md) (SELL walk rules, oracle), [0056](0056-stored-strategies-the-lab-tables-the-seed-and-loading-by-version.md) (stored strategies).

## Decision
1. **A typed rewrite, not a word swap.** Every numeric expression has a mirror type: Level (a price, `K - x` on the inverted market), Signed (`-x`), Osc (`100 - x`), Plain (`x`); a literal or parameter takes the type of the other side of a comparison. A comparison becomes the one that holds on the inverted market with `K` cancelled, which flips the operator (`gap_pct <= -gap_min` becomes `gap_pct >= gap_min`; `adx(14) < adx_max` stays). The table is `XDrishti.Strategies.Mirror.MirrorTable`, version `mirror-1`; a test pins its hash and another fails when a catalog name has no row.
2. **Refusals are precise and tell the author to write a `sell:` block.** Market context and calendar (D3), a price against a bare number, a price against an oscillator, products and ratios of prices (percent semantics, D5), a literal with more than 15 significant digits. Codes `strategy.mirror.*`.
3. **Expanded at read time and recorded.** `StoredStrategies` (so inspect, check and prepare) and `StrategyCompiler` (a definition that reaches it with `Sell == null`) call `StrategyMirror.Expand`. The expanded SELL is in the definition, so `DefinitionJson` and its hash hold it; `StrategyDefinition.SellMirroredWith` carries the table version and is written to the canonical JSON as `sell_mirrored`, so a new table is a new hash and a new run key. The stored text is not rewritten (a clone keeps it as written). The check adds one information problem `strategy.mirror.applied` with the printed block (the file writer's own layout), and a run's labels get `sell: mirrored (mirror-1)` only for such runs.
4. **Supertrend is not in the exact class.** The spec listed `supertrend` and `supertrend_dir` as exact under `p' = K - p`. The metamorphic test (200 seeds, 5m, 15m, 1h) showed they are not: the indicator starts in an up-trend whatever the market does, so it is not symmetric until its first flip. Both mirror by meaning (Level, same name; Signed, same name) and are marked not exact in the table; the exact-class property excludes them. Every other exact-class name passed on all 600 runs.
5. **Where it stops.** Intraday only (swing SELL is refused by the model). Exits and overlays are kept; the walker reads the direction. A subscript over a call (`highest(20)[1]`) has a mirror row in the spec but the parser does not accept it until P3-02f Part B: such a text is reported as unreadable (no mirror problem; the compile of the original reports its own).

## Consequences
- A strategy that lists SELL and has no `sell:` block now runs and its SELL trades are the mirror of its BUY; the author copies the printed block into `sell:` to own it. A new table version changes the hash of every mirrored strategy.
- `strategy.model.sell_block_missing` stays for a definition with no BUY block to mirror.
- A mirrored SELL is a symmetric rule, not evidence that shorting works the same way.
